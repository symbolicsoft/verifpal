# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Verifpal is a symbolic formal verification tool for cryptographic protocols. Users write protocol models in the Verifpal language (`.vp` files), and the engine checks security queries (confidentiality, authentication, freshness, unlinkability, equivalence) against a passive or active attacker, with each principal running two concurrent sessions by default (`--sessions k` to change it). Sessions are bounded: a passing query means no attack was found within that many sessions. It is a single Rust crate (`verifpal` 1.4.2, edition 2024, `rust-version 1.98`, GPL-3.0-only) building as a CLI binary and, separately, as a WASM library used by the Verifpal website and the VS Code extension. The [User Manual](https://static.verifpal.com/manual.pdf) is the language reference; `README.md` is the user-facing pitch. [*From Toy to Instrument: Seven Years of Verifpal*](https://eprint.iacr.org/2026/1654) is the paper — semantics, deduction rules, search, soundness theorem, termination bound and session model — and is the authority when this file and it disagree.

The engine is **sound but incomplete**: any reported attack must be genuine, but the search may miss attacks. Soundness is structural: the solver in `src/solve/` only ever *proposes* substitutions, and `validate.rs` re-executes each one concretely before any result can be recorded, so a solver bug costs a missed attack and never a false one. That is Theorem 4 of the paper, reduced to the facts `query.rs::tcb_tests` pins by reading the source (see "The soundness tests").

## The one rule about primitives

**A primitive is declared once, in `src/primitive/spec.rs`, and nowhere else.** Everything the engine knows about a primitive is a field of its `PrimitiveSpec` or `PrimitiveCoreSpec` entry: name, arity, outputs and argument names; decompose, recompose, rewrite, rebuild and reuse rules; bypass key, commutativity, key-derivation role, identifying positions, argument restrictions with their error notes; supported capabilities and what they reveal; tuple, projection, equality and divergence-filler roles; arity help; the documentation the editor shows. The engine only interprets those fields. Adding or changing a primitive means editing that one table and writing models, and nothing else in the tree moves.

Three things hold that line. The `PRIM_*` ids are re-exported only under `cfg(test)`, so engine code that names one does not compile. `primitive/mod.rs::the_engine_names_no_primitive_outside_its_spec` reads every non-test source file and fails on a `PRIM_` token or a quoted primitive name. And the parser's reserved words and the editor's documentation are read off the registry. When a new behaviour seems to need a `p.id == …` or a `name == "…"` in the engine, a field is missing from the spec: add the field and the generic interpreter for it, and declare the behaviour on the primitive. `ReuseRule` is the worked example: nonce reuse was first an AEAD-specific rule in four modules and is now `reuse: Some(ReuseRule { fixed, reveals, forgeable })` on `AEAD_ENC` plus one pair rule in the closure. The core primitives are the same: `CONCAT` is the one whose spec says `reveals_args`, `SPLIT` the one with `projection_of`, `ASSERT` the one with `equality`, and the solver asks the registry which those are.

| `forward_transitive_relay.vp` | `f1` | a guard says the attacker did not alter a message in transit, not that the sender held an honest value. `forward_relay_all_guarded.vp` (`f0`) guards the first leg too |

| `aead_nonce_reuse_forgery.vp` | `a1` | two ciphertexts under one key and nonce make the pair forgeable, and the agreement exemption cannot excuse it. `aead_nonce_distinct_forgery_holds.vp` (`a0` at `1`) is the counterweight |
| `threshold_sign_leaked_share_and_oracle.vp`, `threshold_sign_three_of_five_two_oracles.vp` | `c0c0a1` | a leaked share plus signing oracles reaching the threshold is a forgery; needs `solve_by_combination`. `threshold_sign_rogue_coordinator.vp` is the unauthenticated-channel case with no share at all |
| `threshold_group_key_from_shares.vp` | `c1c0` | the group key interpolates from enough verification shares |
| `threshold_sign_nonce_reuse.vp` | `c0c1` | a nonce reused under one share gives the share up |
| `aead_nonce_reuse_partner_unreached.vp` | `c1c1` | a reuse pair one of whose reads sits in a run the replay never executes: `pair_coheres` compares such a read against the reader's `execution_base` rather than refusing it |
| `blind_signature_attacker_unblinds.vp` | `c1` | unblinding is public: `rule_rewrite_build` lets the attacker assemble `UNBLIND` around a held blind signature from values it holds, where `rule_rewrite_forward` only rewrote terms a principal wrote |
| `equivalence_unused_received.vp` | `e1` | an `equivalence?` compares slots as held, so a received constant it names is controllable even where the recipient never uses it in a primitive (`ProtocolTrace::equivalence_queried`) |
| `relay_guard_transitive.vp` | `a1a1f1` | a guard on a relayed value is upstream of the substitution at every later hop: `mutatable_to` closes under relaying by a sender whose own copy was mutatable |
| `phase_second_delivery.vp` | `a0a1` at `1` | the second delivery of one constant is substitutable in its own phase, so a key leaked between the two forges the later one |
| `unlink_recognized_nested_message.vp` | `u1` | the recognized-secret witness follows a pinned argument into its own leaves, so wrapping a shared secret no longer hides it |

"Known to the attacker" is not "forgeable by the attacker" — `aead_replay_not_forgery.vp` and `piknik.vp` hold that down. `run_model` prefixes `examples/test/`.

CI (`.github/workflows/main.yml`) runs clippy, `cargo test --release` and the exhaustive sweeps on Ubuntu and macOS, plus a wasm clippy job. A single warning fails the build. **CI only runs when the commit title contains `[ci]`** (or on manual dispatch). Formatting is not gated in CI; `make lint` checks it locally, so keep the tree formatted.

```sh
cargo run --release -- verify examples/simple.vp             # full analysis
cargo run --release -- verify path/to/model.vp --result-code # appends the compact result code
cargo run --release -- verify path/to/model.vp --format html > report.html  # self-contained report
cargo run --release -- verify path/to/model.vp --format tex > report.tex    # LaTeX; tectonic report.tex
cargo run --release -- verify path/to/model.vp --sessions 1  # single-session; the default is 2 per principal
cargo run --release -- verify path/to/model.vp --saturate    # raise k until the verdicts stop moving
cargo run --release -- verify path/to/model.vp --auto-queries # replace the queries block with a generated one
cargo run --release -- pretty path/to/model.vp               # canonical formatter, to stdout
VERIFPAL_SOLVE_DEBUG=1 cargo run --release -- verify m.vp    # log every solver proposal to stderr
```

`verify` takes several models at once. `--result-code` only suppresses the banner; the code is the **last** line (`… | tail -1`), and it is refused beside `--format json|html|tex`. `--fail-on-attack` makes a found attack a nonzero exit; `-q`/`-v` and `--color` are the remaining flags. Other subcommands: `about`, `diagram <model>` (mermaid), `lsp`, `completion <shell>`, `man` (hidden). `internal-json` is **gone**, replaced by `verify --format json`. The json, html, tex and LSP outputs are all built from `src/report.rs`; `verifpal-vscode` and `verifpal-nvim` are thin clients of it.

Errors carry a `Span` into the model source and render as a Rust-style diagnostic; `VerifpalError::or_span` keeps the narrower span, and `.located(file_name, &model.source)` at an entry point makes plain `Display` show the position.

`VERIFPAL_SOLVE_DEBUG` is the first thing to reach for when an active-attacker result is wrong: it prints each proposal as `[solve] <Principal> ran=<bool> [slot=value …]`, including the ones `validate` rejected.

## Crate layout and features

- One crate: lib `verifpal` (`src/lib.rs`, `crate-type = ["cdylib", "rlib"]`) + bin (`src/main.rs`, requires the default `cli` feature). `main.rs` is CLI only; every stdout write there goes through the `out!`/`outp!` macros, which ignore a closed pipe rather than panicking.
- **Every engine module is `pub(crate)`**; the public API is what `lib.rs` re-exports. `#![warn(unreachable_pub)]` is on, so a stray `pub` on an internal item fails CI; write `pub(crate)`.
- There is no `tests/` directory: an integration-test target collides with the `cdylib` on one artifact name. End-to-end model tests live in `src/model_tests.rs`.
- Features: `cli` (default; clap, colored, ureq and `lsp`), `lsp`, `wasm` (wasm-bindgen; entry points `wasm_verify`/`wasm_pretty` in `lib.rs`, returning JSON strings and buffering all output through `info::wasm_messages_*`).
- `#![forbid(unsafe_code)]` is on: the soundness argument is about what the code can reach.
- `parallel.rs` is the one seam onto rayon, `cli`-only with a sequential `#[cfg(not(feature = "cli"))]` twin for WASM — **when you change one, change the other**, and run the wasm feature check. `map_ordered` maps a `Vec` on a private pool and returns the results in input order; `VERIFPAL_THREADS=n` sets the pool size and `VERIFPAL_THREADS=1` is the sequential engine, which `an_analysis_is_identical_under_one_thread_and_many` compares a four-thread run against. **A worker only evaluates.** It never calls `learn`, `attacker_put_with`, `attacker_note_reuse`, `emit_query_result`, `defer_replays`, `note_depth_cut`, `note_replication_rejection`, `analysis_count_increment`, `ctx.replayed` or anything in `info`, so learning order, and with it the primary derivation routes the coherence gates follow and the traces, is the sequential engine's. Workers start `Silent` and re-enter the caller's analysis generation. `VerifyContext` is interior-mutable and `Sync`, so it is safe to share; `everything_a_worker_borrows_is_sync` pins that for it and for every structure a worker borrows.
- Thread-local term caches (`REWRITE_CACHE`, `REDUCE_CACHE`, `CONES`) are `context::Generational`: `analyze_sessions_traced_cancellable` holds a `GenerationGuard`, which mints a generation, enters it on the calling thread and keeps it in `LIVE_GENERATIONS` until the analysis returns, and a cache clears itself on the first touch under a generation other than the one it was filled in. That replaces the resets that ran on one thread, which a pool outliving an analysis (the LSP, the tests) would never see, and it is what keeps one model's constants, same ids under another model's names, out of the other's rewrites. **An analysis parallelises internally only while it is the only live one**: `map_ordered` runs on the calling thread when `live_generations() > 1`, because several analyses in one process are already the parallelism, and a shared pool under ten of them was measured to add contention and nothing else (a closure parallelised per pass, since removed, cost the suite fifty seconds of wall clock that way; a cache per live generation on each worker was tried against it and moved nothing). `NEEDS` and `ANY_TAINT` keep the `Arc` they were computed from and need no generation; `MEMO` is installed and restored per `DeductionMemo::scoped`.
- Release profile: `opt-level = 3`, fat LTO, 1 codegen unit, `panic = "abort"`, `strip = "symbols"`. Always work with `--release`.

## The Verifpal language (enough to write test models)

```verifpal
attacker[active]                    // or passive

principal Alice[
    knows public c0                 // also: private
    generates a                     // fresh value
    ga = PUBKEY(a)                  // public key from a private value
    k  = DH_KEX(gb, a)              // DH shared secret; DH_KEX(PUBKEY(b), a) == DH_KEX(PUBKEY(a), b)
    generates n                     // an AEAD nonce: reusing one under a key is what the engine watches for
    e = AEAD_ENC(k, n, m, ad)
    x, y = SPLIT(CONCAT(m, n))      // multi-output primitives bind several constants
    s1, s2, s3 = THRESHOLD_SPLIT[2](k)  // t-of-n sharing; the bracket is t, the outputs are n
    p = THRESHOLD_SIGN(s1, n, cl, m)    // a FROST partial; THRESHOLD_JOIN(p, q) is SIGN(k, m)
    _ = HASH(m)                     // `_` is an anonymous constant (becomes unnamed_N)
    leaks something                 // hands value to attacker
]

Alice -> Bob: [ga], n, e            // [x] = guarded: attacker cannot replace it
                                    // `→` (U+2192) is accepted in place of `->`

phase[1]                            // phases must increment by exactly 1

principal Bob[
    d = AEAD_DEC(k, n, e, ad)?      // '?' = checked: failure halts this principal
]

scenarios[                          // optional, and it must come before `queries`
    Alice[gpeer = gb]               // run 1: Alice's peer is Bob
    Alice[gpeer = gm]               // run 2: Alice's peer is Mallory
]

queries[
    confidentiality? m
    authentication? Alice -> Bob: e
    freshness? x
    unlinkability? a, b             // ≥2 distinct constants
    equivalence? k1, k2             // ≥2 distinct constants
    // queries take an optional option block, e.g.:
    // confidentiality? k[ precondition[ Client -> Server: req ] ]
    // which restricts the query to executions in which that message is sent
]
```

Constraints enforced by the parser and `sanity.rs`:

- Nothing may follow the `queries` block, which must exist and come last. At most one `scenarios[…]` block, directly between the last principal or message and `queries`.
- ≤128 principals (`sanity.rs::MAX_PRINCIPALS`). Principal names are title-cased, every other identifier lower-cased, so the language is case-insensitive throughout.
- Argument restrictions are declared per primitive in `spec.rs` (`argument_restrictions`, each with the note its error prints) and enforced generically by `sanity_check_argument_restrictions`: no public key as `DH_KEX`'s second argument or `PUBKEY`'s argument, no `DH_KEX` inside `DH_KEX`, no `DH_KEX`/KEM term or public value where `KEM_ENCAP`/`KEM_DECAP` expect a key.
- Primitive names resolve case-insensitively against the spec registry, which also fixes arity, output count and whether `?` is allowed.
- A model file's name must end in `.vp` and be ≤64 characters (`parser.rs::parse_file`).
- Constants cannot shadow reserved words: `parser.rs::RESERVED`, every primitive name (the parser asks the registry through `names_a_primitive`), plus any name starting with `attacker` or `unnamed`. `queries` and `scenarios` are keywords.
- A constant cannot be assigned twice, generated twice, `knows`n two different ways, sent by someone who does not know it, or received by someone who already knows it. `leaks` requires the leaker to know the value. `_` may name only an assignment's output. `nil` cannot be the subject of a `confidentiality?` or `freshness?` query but may be compared in an `equivalence?`.
- Authentication queries are validated at load time: the sender must know the constant, the recipient must receive it and *use* it inside a primitive. A `precondition[P -> T: d]` option must name a message the model sends (`sanity_precondition`). `sanity_capabilities` rejects a capability the primitive does not declare or a `from phase N` the model never reaches.

Primitives (arity → outputs), all 25: ASSERT(2), CONCAT(2–5), SPLIT(1→1–5), HASH(1–5), HKDF(3→1–5), AEAD_ENC/AEAD_DEC(4), ENC/DEC(2), MAC(2), PUBKEY(1), DH_KEX(2), SIGN(2), SIGNVERIF(3), PKE_ENC/PKE_DEC(2), THRESHOLD_SPLIT(1→2–16), THRESHOLD_JOIN(2–16), THRESHOLD_SIGN(4), RINGSIGN(4), RINGSIGNVERIF(5), BLIND(2), UNBLIND(3), KEM_ENCAP(2→2), KEM_DECAP(2). `SHAMIR_SPLIT` and `SHAMIR_JOIN` are the old names; the parser's `RENAMED` table in `spec.rs` turns them into a diagnostic naming the replacement. Only primitives with a `definition_check` — ASSERT, SPLIT, AEAD_DEC, SIGNVERIF, RINGSIGNVERIF, KEM_DECAP — may take `?`. ASSERT, CONCAT and SPLIT are *core*: they live in `CORE_SPECS`, reduce through hand-written Rust, and several theory functions bail out on them (`primitive_is_core`). Everything else is data.

**Capability parameters.** A call site may carry bracketed weakening assumptions: `PUBKEY[weak](a)`, `SIGN[forgeable](sk, m)`, `AEAD_ENC[weak, forgeable from phase 2](k, n, m, ad)`. `from phase N` means *from phase N onward* and binds to the preceding capability; absent it, the capability holds from phase 0.

- `weak` — confidentiality is lost. Declared by `weak_reveals`/`weak_reveals_output`: `HASH` (every argument), `AEAD_ENC`, `ENC`, `PKE_ENC` (plaintext), `KEM_ENCAP` (shared secret), `PUBKEY` (the private key; the DH cascade falls out of `can_reconstruct_primitive`, `cap_weak_pubkey_dh.vp`).
- `forgeable` — authenticity is lost. Declared by `forgeable_secret`: `SIGN`, `MAC`, `RINGSIGN`, `AEAD_ENC`. `cap_forgeable_aead.vp` keeps it apart from `weak`.
- `malleable` — the ciphertext can be reshaped into another the recipient accepts, under a key the attacker never learns. Declared by `malleable_vary`: only `ENC` (position 1). It needs **two** cooperating halves, `solve/deduce.rs::solve_by_malleability` as a goal and `solve/validate.rs::malleable_positions` as the derivability exemption. `cap_malleable_enc.vp` against `cap_malleable_absent.vp` (`a1` against `a0`); `cap_err_aead_malleable.vp` and `cap_err_malleable_unsupported.vp` pin the errors.

`weak`, `forgeable`, `malleable` and `from` are **contextual keywords**, deliberately absent from `RESERVED`, so a model may use `weak` or `from` as a constant name.

**Threshold parameter.** The same bracket carries a bare number on a primitive whose spec declares `threshold: Some(ThresholdSpec { min })`: `THRESHOLD_SPLIT[3](k)`, mixing with capabilities as `[3, weak]`. It is **required** there and refused everywhere else (`err_threshold_missing.vp`, `err_threshold_on_hash.vp`, `err_threshold_twice.vp`, `err_threshold_one.vp`), and `sanity_primitive` refuses one above the number of outputs bound (`err_threshold_above_shares.vp`). The number lives on the term as `Primitive.threshold` and is part of identity: `primitive_hash`, `equivalent_primitives` and `structurally_identical_primitive` all read it, so a 2-of-n and a 3-of-n split of one secret are different values whose shares never combine (`threshold_thresholds_are_distinct.vp`). `Display` prints it whenever the spec declares one, and so does the narrator's own `head`. `n` is not on the term: it is the output count at the assignment, capped by `MAX_SHARES` (16), and an unbound projection is unobtainable without the secret anyway.

Comments (`//` and `/* */`) are captured into AST nodes so `pretty` round-trips them; a comment inside a bracket or argument list is attached as a leading comment of the statement being parsed. Primitives nest at most `MAX_NESTING` (64) levels; deeper is a parse error rather than a stack overflow.

## Architecture

### Pipeline

```
parse_file (parser.rs)              hand-written recursive-descent, comment-preserving AST
  → expand_scenarios (scenario.rs)  one model copy per declared peer scenario
  → expand_sessions (sessions.rs)   k copies of that, one per concurrent session
  → sanity (sanity.rs)              model validation; drives construct.rs
      → construct_protocol_trace    "km": ProtocolTrace — global immutable protocol description
      → construct_principal_states  one PrincipalState per principal
  → VerifyContext::new (context.rs) shared mutable state for the whole run
  → verify_passive (verify.rs) | verify_active (solve/mod.rs)      per phase
  → verify_end                      prints results, returns the results code
```

`verify::analyze(&Model)` is the **one** place that sequence exists; it is `analyze_sessions(m, DEFAULT_SESSIONS)`. The wasm entry points and the language server call `analyze`, so the CLI, the IDE and the website cannot disagree about what a model means — **do not give one entry point its own default.** Throughout, `km` is the `ProtocolTrace` and `ps` a `PrincipalState`.

### Parallel sessions (sessions.rs)

Every principal runs `DEFAULT_SESSIONS` (2) concurrent sessions unless `--sessions k` says otherwise. `expand_sessions` is a *front-end*: it clones every principal and message block `k` times in the parsed `Model` **before** `sanity` runs, so the expanded model is a legal model the user could have typed and inherits the engine's attack-soundness. `generates` constants and assignment outputs get per-session copies (`c#s`, rebanded via `value.rs::copy_value_id`, one index over the scenario-by-session grid; `MAX_COPIES` is 30, so `s*k <= 31`), while `knows` constants stay shared. Each written query is kept verbatim (session 1) and given per-session **variants** (`VerifyResult.variants`) resolving the same `query_index`; `verify_resolve_queries` and `goals_for_query` iterate original + variants.

Sessions make **injective agreement** expressible, and `authentication?` is injective: a received value equal (after the same resolve-and-reduce recipe as `reexec::attacker_authored`) to a session sibling's honest wire value is a cross-session replay, and a replay is an authentication failure even though nothing was forged. `query.rs::session_sibling_replay` classifies such a report so the narrator says "replays" rather than "replaces"; `ProtocolTrace::copy_siblings` groups every copy of a base constant across **both** expansion axes so `copy_sibling_replay` can label a cross-scenario replay too. It is consulted **after** `emitted_by_matching_run` has declined, never before: a cross-scenario replay of an honest run is exactly what the exemption excuses, so the copy axis can turn "replaces" into "replays" and never moves a verdict (`scenario_replay_is_a_replay.vp`). `solve/mod.rs::sibling_flight_substitutions` stays on the session axis.

**Expansion clones are runs, not agents, and a delivered value is not attacker-authored merely because it is not the one this run expected.** `install` stamps `ATTACKER_ID` on a slot's sender whenever the value differs from the recipient's pristine expectation, which conflates *rerouting* with *authoring*. `agreement.rs::emitted_by_matching_run` looks for a trace slot carrying the same base constant, created by a run **interchangeable with** the declared sender and sent to a run of the recipient's own agent, then *re-executes that run* with this recipient's own flight routed into it and confirms it emits the delivered value. Only re-execution decides — over `attacker_can_derive`, `TermBound` and `Controllable`, as `validate.rs` does — so a bug here costs a reported attack and cannot invent a hold. Both halves are memoised for the run: `forgeable_without_sender` per recipient, sender, target, phase, knowledge length and `routes_epoch`, and `Emission::emits` per origin, slot, installs, target and the same knowledge key, the full installs and target compared on a hit since a wrong `false` here is a false attack; the query is evaluated on every executed state and the same states recur every round. The pristine-sibling replay is tested **first**.

`ProtocolTrace::interchangeable` and `ProtocolTrace::actors` define "same run, same agent". Session clones are always interchangeable; scenario clones only where the scenario left *that* principal's bindings alone (`scenario.rs::peer_binding_key`). Canonicalising by base name instead would excuse Lowe's attack (`spore_ns_pk.vp` keeps `a1` on `Alice -> Bob: m1` beside the `a0` this rule earns on `Bob -> Alice: m2`). The recipient side is matched by **agent**.

`emitted_by_matching_run` runs at every session count and excuses nothing the attacker could have produced on its own: `forgeable_without_sender` takes every read off the sender's runs out of attacker knowledge, transitively, and if the delivered value is still `derivable` the forgery stands (`matching_run_forged_unguarded.vp`). Only reads of **assignment outputs** are taken away: a leak of a `knows` or `generates` constant is the attacker's own capability (`matching_run_leaked_generated_key.vp`). Past that gate there are three routes, each ending in a re-execution of the sender's run: the **mirror** installs into the sender the values the attacker handed *this recipient* on the wire (`delivered_to`), the **record** installs the tainted diffs recorded against the delivered value but only where that value was `Obtained` at the sender's own slot, and the **routing** route is the original sibling-flight one.

**A duplicate is reported, never silenced, and labelled.** `Subtype::DuplicateAcceptance` marks a replay the recipient could have distinguished because the value carries something it generated (`recipient_contributed`); `Subtype::ReplayableFirstFlight` marks one over a first flight it contributed nothing to. Suppressing the second kind silences forty verdicts, among them the 0-RTT replay of `tls13-0rtt.vp` that RFC 9846 §2.3 names, so a duplicate resolves the query and the label tells the reader to look at `--sessions 1`.

In `query_authentication_get_pass_indices` the `original ≡ value` guard runs first, so a value carrying no per-session freshness never reaches the sibling test. `--sessions 1` cannot report a replay at all, and that is the count at which the corpus's "this is not a forgery" models pin their original claim (`a_false_attack_pin_survives_at_one_session`). `k = 1` skips expansion entirely and is bit-for-bit the pre-sessions behavior; across `examples/test/` the corpus costs about 4.4s at one session against 79s at two.

At `k > 1` the active search runs in two passes, gated by `VerifyContext`'s `prefer_replication` / `replication_only` / `replication_rejected`: the first has `validate.rs` refuse any proposal whose term the principal itself produced *and* that carries its own fresh value (`replays_own_freshness`), the second runs with the flag off only if something was refused and queries remain. This decides which witness the user sees first and can neither find nor lose an attack. Fifty-five of the analysing models in `examples/test/` answer differently at one session and at two; re-measure both corpora before touching the default.

### Causal availability (reexec.rs::CausalOrder)

Deriving a term is not the same as holding it *in time*. `attacker_phase_update` publishes every wire value the phase reaches before any principal runs, which lets one run's traffic be routed into another regardless of block order but also lets the validator satisfy a check with a message the protocol only sends *because* that check already passed: `atemporal_forward_value.vp` is that cycle, and it is a false attack.

`CausalOrder::of(km, principal)` answers "what could this principal not yet have been handed". `influenced_from` is a fixed point over send events: the receive being attacked happens at `declared_at = at`, so `principal` is influenced from `at`, any message it sends at or after `at` influences its recipient from that point, and so on. A trace slot is **blocked** for that receive when its creator is influenced from at or before the slot's own `declared_at`, or when **every disclosure** of it, each send event and each `leaks`, is made by a principal influenced from at or before that event; `nil` and public constants excepted. Blocking by declaration alone let a key declared early but leaked only after the attacked check forge that check (`causal_late_leak.vp`). The same key was then spent by `try_guard_bypass`, so `bypass_is_constructible` is judged through `held_at`: the attacker knowledge restricted by `unreachable_before` at the **check's own** `declared_at`, cached per (principal, position) and per knowledge chain. Restricting the whole execution by the installed slots' orders instead lost `noise_xx_mutual.vp`, whose message-3 forgery legitimately spends a message-2 disclosure. The recorded bypass decisions carry the check's position so a recall re-judges them the same way, in both directions. `available` then walks attacker knowledge in learning order and keeps a value only when its `DerivationRecord` does not bottom out in a blocked slot. **It has to follow the derivation, not compare against pristine trace values** (`later_value_fed_back.vp`). `validate.rs` re-runs its own `derivable` against the restricted state, so a term the attacker can genuinely *build* from causally available parts is still admitted. Results are cached per (blocked set, attacker `known` vector), the vector held by `Arc` and compared by identity; a key on knowledge *size* once answered one proposal's question with another's restriction.

**A slot is substitutable once per delivery, in that delivery's own phase.** One constant may reach two recipients in two phases, and the knowledge a forgery of it may spend is the phase of the delivery it is aimed at, not the slot's first. `SlotMeta::delivery_phases` records, per recipient the slot is `mutatable_to`, the phase of its unguarded delivery there, or for a guarded one the phase at which its sender's own copy could be chosen, which is what keeps a guarded relay judged by the open leg it stands for (`phase_relay_guarded_delivery.vp`). `validate::attacker_can_derive` returns the earliest of those phases, at or below the executing principal's own delivery, whose knowledge builds the term; `install` stamps it on the slot and `PrincipalState::mutation_reaches` hides the value from any recipient delivered before it, so `compute_visibility`, `state_mentions` and `symbolic::reaches` all narrow together. Judging every delivery by the slot's first phase refused a forgery the later recipient's own phase admits (`phase_second_delivery.vp`, `a0a1` at one session), and `phase_second_delivery_later_leak.vp` is the counterweight where the leak follows both deliveries.

Session and scenario clones never message each other, so no cross-copy edge exists. Across `examples/` the guard moved exactly two verdicts to `a0`: `later_value_fed_back.vp` and `scuttlebutt.vp`'s `secretBox1Bob`; the disclosure rule then moved `signal_small_leaks.vp`, `signal_small_leaks_bob.vp` and `signal_small_nophase.vp` to `c0` at one session only, each a leak that follows the flight it would have enabled. `witness.rs::probe_with` applies the same order to each install it grounds.

### History coherence (reexec.rs::Coherence)

Attacker knowledge is global and monotone, and a re-execution installs into a pristine state, so one substitution can supply the knowledge while a *different* execution of the same principal supplies the values it is spent on (`incompatible_histories.vp`).

`Coherence::of(km, ps)` records, for each slot this principal receives from someone else, the value its creator honestly produces. `solve_principal` obtains it through `VerifyContext::coherence`, which keeps one per principal under the knowledge `Saturation` it was built against and rebuilds it only when that changes, so the `agreed` and `histories` memos inside it (under `Mutex`, since the context is shared) outlive the solving pass: they key on the identity of the `known` vector and of a `MutationRecord`, and within one saturation neither has changed nor been freed, which is exactly what makes those pointer keys exact. On `junglegym_threshold_ring.vp` rebuilding it every pass redid the `execution_agrees` replays each round. `compatible` walks attacker knowledge in learning order and refuses an `Obtained`/`Leaked` at one of those slots whose term is not the one being handed over. `validate.rs` uses the restricted state both for derivability and as the state `reexecute` runs against — the second half is not optional, because it is `try_guard_bypass` that spends the incompatible `na`.

**It has to be the derivation and not the `MutationRecord`.** A record is an *ambient snapshot*, not a set of necessary conditions: every resolved slot is a "diff", and reading those as preconditions costs `kem_direction_reflection.vp` its reflection and `forged_statement_rebuilt.vp` its `c1`. Reading only the `tainted` diffs is not the fix either.

`Coherence::execution_agrees` covers the case `forwards` cannot see: the revealing message went to a third principal. It takes the tainted diffs recorded against the held value, re-executes every principal the target is handed values from under the diffs observed in that principal's own state, and refuses the value if any slot the target holds from that principal, and this proposal is not itself authoring, comes out different. Results are memoised per (record pointer, authored set). `history_incompatible_knowledge.vp` against `history_compatible_oracle.vp` is the pair.

Three conditions keep it narrow. The slot must be one the principal **receives from another principal**. The read must have happened in the run of the slot's **creator** or in another run of the **executing principal itself**. And it is skipped where the proposal installs an **attacker-authored** value at that slot — but *not* where it reinstalls the honest value, which is a forward by another name (`incompatible_histories_mitm.vp`).

That skip is what let a run's **own later emission** come back to it: at two sessions `scuttlebutt.vp` routed Alice's flight into Bob#2, took his last box, and delivered it into her first-box slot, although Bob#2 sends that box only after receiving the reply Alice sends after accepting a first box, so the knowledge came out of one execution of her run and was spent against another. `validate.rs::spends_another_execution` closes it through the closure's own notion of a read's preconditions: for every install it asks `deduction::needs_of` (recursing into the arguments of a term the attacker does not hold outright) and refuses the proposal when a need names the executing principal at one of its **receive** slots with a value different from what this execution puts there, installed or honest. `history_own_later_emission.vp` (`a0`) against `history_own_early_emission.vp` (`a1`) is the pair; the refusal is keyed to receive slots so that a run's own outputs, which every cross-session routing reads, never count against it.

### Execution coherence in the closure (deduction.rs::combination_coheres)

`Coherence` and `CausalOrder` filter what the validator may install; the closure reads global knowledge, so a derivation that closes entirely inside it never meets either filter and can combine a value read out of one execution of a run with one that exists only in another. `learn` refuses such a combination. For a derivation with ingredients it collects the reads each ingredient bottoms out in (`Obtained`/`Leaked` leaves, each with the tainted substitution it was recorded under), merges those substitutions, and: refuses outright if two reads need **different values at one slot of one principal**; passes without a replay if the union is empty or every read carries the same substitution; otherwise replays the union (`reexec::replay_diffs`, cached in `VerifyContext::replayed`) and requires every read recorded under a different substitution to be *reached* there: the slot held, not behind a foreign halt, and its emission not withheld by the reader's own halt (`withheld_by_own_halt`). A union whose seeds cannot execute at all is refused (`closure_cyclic_union.vp`). Re-execution decides, so a bookkeeping error costs a deduction and never invents one, and the metamorphic sweeps are the ratchet against over-refusal.

**The walk follows primary routes only, and that is order-dependent.** `closure_cyclic_union.vp` at two sessions is `c1c1c0` with its queries as written and `c1c1c1` with `z` asked first: when `z1` and `z2` are solved first, the two MACs are learned out of two separate executions of Bob and their primary reads contradict each other at one slot, so `gather_reads` refuses the combination, although one execution that produces both was found later and filed only as an alternate route. Retrying the walk along alternate routes was built and reverted: it re-admitted `history_closure_incompatible.vp`'s pinned false attack even with equality required in the replay, so the refusal is doing soundness work the replay does not. The `rotate` property runs at one session, where every order agrees; at two it would report this one model.

Three things about the keys. A `SlotDiff` carries the **state** it was observed in, and a need is `(principal, slot, value)`: an execution that hands Bob `t1` and Carol `t2` over the same slot is one execution (`closure_two_recipients.vp`). A read's preconditions are keyed to the slot's **creator**, whatever state it was read from, because every state re-resolves other principals' values with its own installed inputs. And the union is built from the reads' cone-filtered needs plus the current state's ambient, never from the whole record of every visited term.

Two things were needed for the reads to be *found*. **The `obtainable` cascade rebuilds keys in place** without learning them; `collect_reads` asks the cascade which arguments it rebuilt from (`ReconstructResult::from`, `DecomposeResult::used`) and follows those. **An install is a boundary provenance did not cross**: `read_preconditions` follows each installed value in a read's cone into that value's own reads. The cone of a wire or leaked read runs up to the **emission** (`emitted_at`), not the declaration (`closure_halted_send.vp`). The minimizer asks `deduction::needs_of` for the creator-keyed needs of the value the trace claims and, where one slot needs different values at different principals, offers them as **addressed installs** (`witness.rs::Addressed`, a fourth `LADDER` rung tried only after the three shared-install rungs found nothing). `TRACE_IS_NOT_A_MINIMIZED_WITNESS` is empty, so any entry is a regression.

### Forward execution (reexec.rs::execute_forward)

Atomic replay re-executes one principal against accumulated knowledge, which cannot express a value whose only route to its recipient is the sender computing it. `execute_forward` runs the chosen principal, then delivers every message it sends to its recipient *as it actually came out* and runs those recipients too, to a fixed point bounded by the principal count. Only an emission that *differs* from the honest value is delivered, judged by `attacker_authored` against the trace. `validate.rs` and `witness.rs::probe_with` both go through it, which lets the minimizer pick the *origin* principal as a witness base and have the query resolve downstream.

A forwarded value is not an attacker choice and is not tested for derivability; it is justified by the sender having sent it, so `forwarded_installs` checks the send event, the phase, that the sender reached the send and did not halt before the slot (`a_forwarded_value_is_only_ever_what_its_sender_sent`). `install_forwarded` sets `attacker_tainted` and nothing else: taint makes the slot a **precondition** of whatever is learned downstream (without it `piknik.vp`, `ringsign.vp` and `mutual_auth_both_directions.vp` reported false attacks), while `sender`, `creator` and `original` stay honest (`forward_emission_is_not_a_forgery.vp`). Pure forwarders are controllable.

A forwarded state is faithful about what its principal was handed and unfaithful about the sender's private slots, so `PrincipalState::forwarded` gates `query_start` through `answers_for`: such a state answers only queries over constants it legitimately holds. Propagating the sender's private slots handed the Server the Client's session key (`precondition_foreign_halt.vp`); gating every state on `known` lost `concat_bomb_equiv.vp`.

### Peer scenarios (scenario.rs)

`scenarios[…]` instantiates a principal's counterparty differently across concurrent runs, which makes the role-confusion family (Lowe/Denning-Sacco) expressible. It is a **front-end expansion** run *before* session expansion, so `p` principals with `s` scenarios at `k` sessions analyse `p*s*k` principals, under `MAX_PRINCIPALS` (128) and `MAX_COPIES` (30).

An entry binds constants inside **one** named principal: `Alice[gpeer = gb]`. Scenario *k* is clone *k* of the whole model with only the named principal's bindings substituted, so N scenarios are N configurations, **not** a cross product. The bound `knows` declaration is dropped from the clone and the constant replaced everywhere in that principal, then freshened like any expansion copy (`gm@2`). An identity binding is a genuine no-op, which two metamorphic properties rest on. `sanity_scenarios` rejects an undeclared principal, a target it does not `knows`, an undeclared value, a target bound twice, and a target that travels over the wire.

**Corruption is inferred, not declared.** `compromised_constants` seeds from every secret (`generates` or `knows private`) that is leaked or that travels bare on a message, at that statement's phase, and from every assignment computable from public constants alone, at phase 0; it then closes over assignments mentioning a compromised constant. So `gm = PUBKEY(mk)` with `leaks mk`, with `Mallory -> Bob: mk`, or with `mk = HASH(seed)` over a public seed marks `gm` compromised, while `leaks gb` on a public key does not (`scenario_corrupt_by_wire.vp`, `scenario_corrupt_by_derivation.vp`). The identity binding the `scenario` property adds names a `knows` constant that does not travel, so neither seed can reach it. A scenario binding a compromised value is a **corrupt-peer run**, which decides two separate things:

- `VerifyContext::is_honest` gates the **honest-run check**. A corrupt-peer clone legitimately fails a checked primitive, so `generate_trace` partitions `perform_all_rewrites`' failures by the failing slot's *creator* and only raises `sanity_fail_on_failed_checked_primitive_rewrite` for honest creators. The suppressed ones still **halt** the clone through `reexec::halt_at_failed_checks`.
- `VerifyContext::claims_apply_to` gates **query evaluation** (`query_start` returns before touching a corrupt run's state), the analogue of Scyther's `prune_theorems.c:439`. A *confidentiality* break first noticed inside a corrupt run must still be reported against the honest ones, so both verifiers re-run `verify_standard_run` once at the end of each phase when relativisation is in force and queries remain.

Both read the same set but differ where it is `Some(empty)`: the honest-run check stays relaxed, query evaluation does **not**. `honest` is `None` with no `scenarios[…]` block, and every predicate answers `true`. The set is computed over the scenario-expanded model and **extended across session expansion** (`SessionExpansion::principal_clones`).

**Phase seeding is reachability-aware, and both halves are load-bearing.** `verify::honest_run_halts` derives the earliest failed checked slot per creator in the honest run (`reexec::creator_halts`), and `attacker_phase_update` withholds every wire or leaked slot at or past it. **Withholding alone loses attacks**, because a substitution can make the check pass (`spore_ns_pk.vp`'s `m3@2`), so `attacker_absorb_disclosed`, called from `compute_knowledge_closure`, re-publishes exactly the withheld slots *this* execution reached. `scenario_post_halt_no_oracle.vp` and `scenario_post_halt_leak_no_oracle.vp` (`c0`) pin the false attack shut against `scenario_pre_halt_oracle.vp` (`c1`).

Queries **are** cloned per scenario: `expand_scenarios` mints one `variants` entry per *honest* scenario, then `expand_sessions` session-clones each. A corrupt scenario gets no instance. The block is **normalised honest-first**, because the written query names scenario 1's constants and a corrupt scenario 1 made it unfalsifiable (`scenario_order_is_not_a_verdict.vp` against `…_swapped.vp`). Compromise is **phase-indexed**: a peer whose key leaks at phase 3 is honest for phases 0-2 (`scenario_peer_compromised_later.vp` against `…_throughout.vp`).

Models: `spore_ns_pk.vp` (`c1a1a0`, Lowe's attack, found rather than assumed) against `spore_nsl_pk.vp` (`c0a1a0`). That pair separating is the acceptance criterion for the feature. Do not add a scenario-free variant of either to `examples/`.

### Verdict envelope

Every `VerifyResult` carries an `Envelope { sessions, truncations }`, printed after a PASS line (`[search exhausted at 2 sessions]` / `[search truncated: term depth]`) and serialized into `QueryReport.envelope`. An attack is never qualified by the envelope, but may carry a `Subtype` (`AttackerSuppliedValue`, `DuplicateAcceptance`, `ReplayableFirstFlight`) printed as a bracketed qualifier on the FAIL line and serialized as `QueryReport.subtype`. The `Note:` lines a trace can end with live in `VerifyResult.notes` (`QueryReport.notes`); a query `--auto-queries` generated has no span and `QueryReport.generated` says so. Both fields are omitted from the JSON when empty or false, so the contract is additive. `Truncation` has one variant, `TermDepth`, recorded by `context.rs::note_depth_cut` **against the queries still unresolved at that moment**; `finalize_envelopes` stamps each result with only the truncations that could have cost it.

**"Exhausted" means the search space this engine defines was fully explored at these parameters, never that no attack exists.** Never let "proof", "verified", "correct" or "complete" into this output.

### `--auto-queries` and `--saturate`

`autoquery.rs::auto_queries` derives a query set and `--auto-queries` **replaces** the model's own block with it after `sanity` has validated the model as written. Three rules, each mirroring a sanity constraint (`generated_queries_all_pass_sanity` sweeps the corpus): `confidentiality?` for every `generates` and `knows private` constant with a trace slot; `authentication? S -> R: c` for every wire delivery whose recipient uses `c` inside a primitive; `freshness? c` for every constant actually sent and used. `unlinkability?` and `equivalence?` are skipped.

`verify::saturation_sessions` raises `k` from `DEFAULT_SESSIONS` to `SATURATE_MAX` (4) and stops at the first count whose result code equals the previous one, returning the **analysis** of that count. It starts at the default rather than one because an attack needing three runs leaves one and two reading alike (`saturation_never_stops_before_it_has_looked_above_the_default`); each run is wrapped in `info::InfoCapture`. `attack_disappeared` warns if an attack vanishes at a higher count, which is an engine bug.

### Core data model (types.rs)

- `Value` = `Constant` | `Primitive(Arc)`. Constants are interned per model (`value.rs`; `nil` is id 1); equivalence compares ids. DH uses ordinary `PUBKEY(sk)` and `DH_KEX(pk, sk)`; their commutativity is declared by `PrimitiveSpec::commutativity` and consumed generically by `equivalence.rs`, `hashing.rs` and `solve/matching.rs`.
- `Primitive` carries a `HashCell`: a term's hash is computed once, making `hash_value` O(1), and so is whether the term contains a solver variable, which `vars::contains_var` answers at every node `apply` visits. Terms are immutable once built; the single in-place mutation (`construct.rs`, setting a multi-output `output` index) clears the hash and leaves the flag, which the output does not affect.
- **Terms are DAGs, and anything that walks or rebuilds one as a tree is exponential in its sharing.** A TLS transcript hash holds the previous one twice, through the signature and the Finished MAC, a dozen levels deep, so a term of a few hundred nodes is a tree of hundreds of thousands. `vars::apply`, `vars::ground_free_as` and `resolution::resolve_trace_value` memoise per call on the input `Arc` and hand back one output per shared input, so what they build stays shared; `Value::equivalent` and `theory::structurally_identical` record the pointer pairs already found equal for the duration of the outermost comparison (`equivalence::memoised_pair`), since two equal terms built separately share no pointer and the hash-first check only rules out unequal ones. `tls13.vp` did not terminate in a day before these; the profile was `contains_var` under `apply`, then the two comparisons, each recursing twenty levels.
- **Invariant: `a.equivalent(b)` ⟹ `a.hash_value() == b.hash_value()`** (`hashing.rs` uses a commutative hash for DH exponents). `AttackerState::knows()` looks up by hash bucket first, so breaking this silently breaks attacker knowledge. Unit tests pin it.
- `Primitive.capabilities` is deliberately **not** consulted by `primitive_hash`, `equivalent_primitives` or `theory.rs::structurally_identical_primitive`: an annotated term and its twin are the same object (`cap_noop_annotated.vp` against `hmac_ok.vp`). The engine reads capabilities from the `CapabilityIndex` on `PrincipalState`, **never** off a held copy, because `AttackerState` dedupes by equivalence. `construct.rs` inserts each annotated call three ways: as written, resolved through the trace, and resolved then reduced, or a call whose argument reduces missed the bucket (`cap_weak_on_reduced_argument.vp`, `cap_forgeable_on_reduced_key.vp`). `can_break_weak` and `can_decompose` reduce what they reveal for the same reason.
- `SlotValues` holds **three values per slot**, the most important invariant in the engine: `original` (what the protocol honestly computed, what the principal *believes*), `pre_rewrite` (after mutation, before rewriting), `value` (after mutation and rewriting; what analysis uses). `PrincipalState::should_use_original`/`effective_value` and `resolution.rs::compute_visibility` decide which a principal sees; getting this wrong causes false authentication attacks. `bypassed: Option<Value>` holds the key a defeated guard was made to accept.
- `Provenance` rides alongside: `creator`, `sender` (`ATTACKER_ID` = 0 when injected), `attacker_tainted`, `bypass_injected`. The last two are **deliberately separate**: taint decides what a principal perceives, and a guard bypass must not change that, but the substitution must still be reportable.
- `SlotMeta` is the immutable half: `constant`, `guard`, `known`, `wire`, `mutatable_to` (recipients it reached *unguarded*), `known_by` as `(recipient, sender)` pairs, `declared_at`, `sent_at`, `phase`. `mutatable_to` is what `symbolic.rs::reaches` and `compute_visibility` consult.
- `PrincipalState::halted_at` records the `declared_at` of the earliest checked-primitive failure after mutation; `reexec.rs` sets it and truncates there, `deduction.rs::rule_equivalize` uses it to suppress `leaks` never reached.
- `AttackerState`: append-only `known` + `known_map` hash index + `mutation_records` and `derivations`, both parallel to `known`, plus `alternates`, every further `Route` that *reads a state* to a term already held, `routes_epoch`, bumped whenever `attacker_state_absorb` replaces a primary derivation or record, which is what lets memos keyed by knowledge length stay exact when knowledge does not grow but a route is upgraded, and `chain`, a process-unique id minted by `next_chain` for every state built from nothing (`attacker_init` per phase, `retain_known`, `attacker_without`) and inherited by clones. **A thread-local memo keyed by knowledge length is exact only within one chain**: the minimizer's scratch context re-seeds from the passive baseline and grows a second chain on the same thread inside the same `Generational` epoch, so `pair_vetted`, `origin_leaves`, `forgeable_without_sender`, `Emission::key`, `VerifyContext::replayed` and `held_at` all carry `chain`, and every key that reaches `reused` carries `reused.len()` too. `Coherence::histories` keys on the `known` vector it re-executed under, as `agreed` does. Derived routes are not retained (a `Fragment` route per `CONCAT` took `concat_split_replay.vp` from 4.5s to 53s), and the causal and history filters follow the primary route only: letting any recorded route stand in returns three pinned false attacks. A `MutationRecord` is the set of slot diffs that had to be in force for the attacker to hold that value, plus the principal and phase. A `DerivationRecord` says *how*: `Initial`, `Leaked`, `Obtained`, `Decomposed`, `Reconstructed`, `Recomposed`, `Fragment`, `Rewritten`, `Broken`, `Reused`, `ReusedForge`. Narration walks this DAG, so **a rule that adds knowledge without recording an honest derivation produces an unexplainable trace.**

### Provenance travels along derivation edges (context.rs)

`derivation_provenance` decides which `MutationRecord` attaches to a newly learned value: one **read out of a principal's state** picks up that state's ambient diffs; one **combined out of held values** inherits *their* records and adopts the session of the ingredient carrying the leverage; `Initial` gets an empty record. `attacker_state_absorb` also *upgrades* an existing record when the stored one explains nothing and the arriving one does; knowledge is unchanged, only the explanation.

**Cancellation has exactly one conversion point.** `VerifyContext` carries an `Arc<AtomicBool>` checked beside every `all_resolved()` short-circuit. Those loops only ever *stop*; the flag becomes `Err(ErrorKind::Cancelled)` at the foot of `analyze_sessions_traced_cancellable` and nowhere else, so an interrupted search reports nothing rather than reporting an unreached query as holding. `scratch_for_query` inherits the flag.

`VerifyContext` is the interior-mutability container shared by `&VerifyContext`. `attacker_put_with` dedupes new knowledge; `results_put` resolves each query at most once; `principal_states()` hands back every principal's pristine starting state; `scratch_for_query(i)` builds a disposable context that can only answer query `i` and cannot write back.

### Standard run (verify.rs)

`verify_standard_run` is shared by both attacker kinds — the active search uses it as its passive baseline. Per principal: **trace generation** (`generate_trace`: `resolve_all_values`, `perform_all_rewrites`, sanity checks — a failed *checked* primitive here is a model error unless its creator is a corrupt-peer clone, which halts), **knowledge closure** (`deduction.rs::compute_knowledge_closure`), **query evaluation** (`query.rs::query_start`). Closure never checks queries. Each phase resets attacker knowledge (`attacker_init`) and re-seeds from `principal_states[0]` resolved and rewritten (`attacker_seed_phase`, then `attacker_phase_update`): **every** public constant plus every wire or leaked value whose earliest phase has been reached (`public_constant_is_never_confidential.vp`).

### Knowledge closure (deduction.rs)

A monotone fixed point over three rule groups, each pass running all three over a snapshot of knowledge taken at its top: (1) over attacker-known values: `decompose`, `break_weak`; (2) over principal-assigned values: `reconstruct`, `recompose`, and `rule_rewrite_forward`; (3) over attacker-known values: `equivalize`, `concat_extract`. Termination is Knaster–Tarski. Every rule ends by calling `learn`, which records the value with its `DerivationRecord` and emits the `Deduction ›` line; its message argument is a closure because minimization re-runs the closure with output suppressed. `rule_equivalize` carries one guard: if the principal halted, a `leaks` it declared *after* that point never fired. A fourth step, `rule_reuse`, runs once per pass after the three groups: it buckets every held term whose spec declares a `ReuseRule` by that rule's fixed positions, and learns what the rule reveals for each member of a bucket holding two non-equivalent terms. Each rule in the table is marked by what it `Reads`: `decompose`, `break_weak`, `concat_extract` and `rule_reuse` read the state only through its capability index, so a pass over all knowledge with them is the same for every state of a principal, and `try_deduction_step` runs them only when `VerifyContext::knowledge_rules_saturated` says this principal has not yet seen this phase, knowledge length, recorded-pair count and `routes_epoch`, marking it afterwards; `reconstruct`, `recompose`, `rewrite_forward` and `equivalize` read slot values and run for every state. A skipped pass is a no-op and not merely a pass producing duplicates: every value it would learn is already held, and `attacker_put_with` on a held value reaches `attacker_state_note_route`, which returns for any derivation that does not `reads_from_state` (`rule_rewrite_build`'s `built: true` records are among those), so no record is upgraded and no alternate is recorded; the known-value branch of `attacker_state_absorb`, where upgrades live, is reached only from phase seeding and `attacker_absorb_disclosed`, which run for every state ahead of the rules. `Decomposed` is the one knowledge-class derivation whose *first* learn adopts the ambient record (a key it rebuilt in place), and that first learn happens in the saturating pass in both engines. Nothing about learn order changes; the counters that motivated it were 15 to 50 thousand `learn` attempts per success and one closure over all knowledge for each of tens of thousands of executed states.

`rule_rewrite_forward` is the one rule that reads a slot's `pre_rewrite` rather than its `value`: for a principal-assigned `pre_rewrite` that `can_rewrite` reduces and whose every argument is `obtainable`, the attacker learns the reduct (`DerivationRecord::Rewritten { of, using, built: false }`). For every rewrite but `UNBLIND` the reduct is already learned by `decompose` or `concat_extract`, so `learn`'s dedup makes this a no-op there. Its attacker-side half is `rule_rewrite_build`, a `Reads::Knowledge` rule in the first group: for a held term that no `decompose` opens and each spec whose rewrite consumes that term's head (`primitives_rewriting`), it fills the other positions from the values the rule's `matching` pins inside the term and their direct arguments, each `obtainable`, and learns any reduct that differs from the built term as `Rewritten { built: true }`, which `reads_from_state` treats as combined from held values rather than read off a state. `blind_signature_attacker_unblinds.vp` is the model; before it the attacker could only unblind where a principal wrote the `UNBLIND`.

### Query evaluation (query.rs)

`query_start` returns before touching a corrupt-peer scenario's state (`ctx.claims_apply_to`). Past that, each kind resolves differently, and `solve/mod.rs::goals_for_query` mirrors these exactly:

- **confidentiality** — the attacker knows the slot's resolved `value`. When that value differs from the honest one and, read through the state (`carries_a_secret`), holds nothing generated or private, the result carries `Subtype::AttackerSuppliedValue`.
- **authentication** — **injective agreement**, the only mode. Evaluated only while walking the recipient. Fails when the slot's `provenance.sender` is not the declared sender *and* the constant is successfully used inside a primitive the recipient computed (`query_find_constant_usage_indices`: no rewrite rule, or the rewrite passes, or unchecked) *and* no interchangeable run of the declared sender emits the delivered value (`agreement.rs::emitted_by_matching_run`). **"Used" is visibility-aware**: `resolution::state_mentions` counts an occurrence only where it *reaches* the owner of the enclosing term (`owner == ps.id || meta.mutatable_to.contains(owner)`, the predicate `compute_visibility` and `symbolic::reaches` share); walking the global trace instead counted a constant buried inside a blob the recipient never opened (`piknik.vp`). `sanity_queries_check_known` and `autoquery.rs` share the predicate through `resolution::principal_uses_constant`. A **substitution** and a **replay** carry the same `a1`; `session_sibling_replay` classifies, `narrate.rs` routes replays into `Step::Replay`, and `witness.rs` has a matching `replayed_from` candidate family. **A replay is reported only on a leg the attacker can touch.** Where every delivery of the slot from the declared sender to this recipient is guarded (`delivery_is_guarded`), the value that arrives is what the sender's own run emitted — the substitution stands for one made upstream, and `relays_are_forwarded` has already required the sender to reach the send under it — so a value equal to a sibling's is that run's own forwarding and not a sending accepted twice (`relay_guarded_replay_is_not_a_duplicate.vp` against `relay_guarded_replay_open_hop.vp`). Blaming the relay there reported the leg above it.
- **freshness** — the value transitively contains no `fresh` constant yet is used in a primitive. The solver never proposes anything for it.
- **unlinkability** — the attacker exhibits a *link witness* for some pair of the queried constants (`unlink.rs::find_link_witness`). Both must be observable and neither slot attacker-authored. Four witness kinds, cheapest first: **observed equality**, **identifying check** (a `definition_check` primitive with a declared identifying position succeeds over both under one participant's key, and that identifier must `depends_on_secret`, since a key every principal holds identifies nobody — `unlink_public_identifier.vp`), **common secret origin** (`origin_leaves`, which withholds each value from the attacker first), and **recognized secret** (`recognized_secrets`, whose pinned arguments are followed into their own `origin_leaves`, or a wrapper around a shared secret hides it — `unlink_recognized_nested_message.vp`). **The honest values must already share a secret-dependent subterm** (`share_secret_subterm`, on the unreduced trace resolution) before any witness is looked for: a substitution that gives two unrelated tokens a common ancestor manufactures the link one derivation below `attacker_supplied`'s reach (`unlink_forced_origin_derived.vp`), while a man in the middle that reveals a key two honest tokens already carry still links them (`unlink_active_links.vp`), and a blinding factor is shared unreduced where its reduct no longer shows it (`unlink_blind_active.vp`). The manual's two-world definition is the specification; this is a decision procedure, sound for attacks and incomplete.

  The identifying check names the input the **checking** primitive needs (`unlink.rs::check_input`): `KEM_DECAP` needs the private key (`unlink_kem_needs_the_private_key.vp` against `unlink_kem_leaked_private_key.vp`). `is_key_derivation` is structural: a `PUBKEY`-headed value names a participant, not a session. `origin_leaves` is memoised per principal, value, phase, knowledge length, recorded-pair count and `routes_epoch`, since it reads the state only through its capability index, the value compared by `structurally_identical` on a hit because the leaves it returns are subterms of the value as written; unmemoised it copied the attacker minus one value per witness attempt per executed state, 12.8 of `junglegym_threshold_ring.vp`'s 19.5 seconds. `recognized_secrets` exists because `origin_leaves` stops at any term the attacker can *test* but not *recompute* — `SIGN` and `RINGSIGN` under an unheld key: if the attacker holds the term and can supply every input the undoing check's `matching` pins (`check_input_held`), each pinned argument it independently obtains is confirmed to sit inside that term. The candidate must `depends_on_secret` and must not be a `bypass_key` constructor application, or `RINGSIGNVERIF`'s ring members would link every ring signature (`unlink_ringsign.vp` versus `unlink_signature_links.vp`); `unlink_signature_recognized.vp` pins the rule.

  **A link the attacker manufactured is not a link.** `find_link_witness` keeps an observed equality only where the honest values, `resolve_trace_constant` reduced once, are equal as well, and drops any witness whose value the attacker itself put on the wire (`attacker_supplied`, a tainted attacker-sent slot's `pre_rewrite`). Forcing both of Bob's inputs to `nil` and watching his two MACs coincide, or feeding Carol's nonce into Alice's slot and exhibiting it as a shared origin, says nothing about the honest tokens (`unlink_forced_equality.vp`, `unlink_forced_origin.vp`); a MitM that *reveals* the key two honest tokens share still links them (`unlink_active_links.vp`).

  **Observable is not "this constant appeared on a wire".** `carried_observably` asks whether the resolved value occurs as a subterm of some wire or leaked slot **and** whether the attacker holds it; without the second half two signatures under an unbroken key link on shape alone (`unlink_carried_in_ciphertext.vp`), and the subterm half is why a merely recomputed value does not count (`unlink_never_sent.vp`). The subterm has to be one the attacker could **open**: `opened_subterm` follows only paths through a tuple or a primitive whose `decompose` it can run, so a token recomputed from a leaked seed is not observed merely because the protocol sealed it inside a message under a key nobody gave up (`unlink_sealed_carrier_not_observed.vp` against `unlink_sealed_carrier_opened.vp`). It is closed under **tuple assembly**: `observed_value` admits a term whose spec says holding it reveals every argument (`primitive_core_reveals_args`) when the attacker holds it and every argument is itself observed (`unlink_reassembled_chunks.vp`, `unlink_reassembled_by_recipient.vp`), which is what makes `junglegym_threshold_ring.vp`'s two blind signatures `u1`.

- **equivalence** — the queried constants do not all resolve to equivalent values, using the *mutated* value. A `forwarded` state answers only over constants it holds (`answers_for`). It first requires that this state *hold* every queried value: comparing the bare-constant placeholder `resolve_constant` answers for a truncated slot is a divergence nobody computed (`concat_bomb_equiv.vp`, `triple_dh.vp`). It also refuses a **starved** slot (`PrincipalState::slot_starved`, filled by `reexec::starved_slots`): a principal that halts sends nothing after the halt, so a value built from what it never handed on was never computed, and the term the query would compare is one nobody produced (`equivalence_starved_by_foreign_halt.vp`). The set closes over definitions across principals but is read **here only** — `slot_unreached` decides what a principal *holds*, and starving it that widely costs `spore_ns_pk.vp` Lowe's attack.
- **precondition** — `Q[precondition[P -> T: d]]` restricts `Q` to the executions in which P reaches the send of `d` to T. `preconditions_reached` runs in every evaluator after the violation is detected and before `attack_trace`, and an unreached send returns with no verdict recorded, so the probe re-checks it through the same evaluator. The event is a `sent_by` entry with that sender and recipient, in a phase at or before the current one, that `event_reached` confirms the sender did not halt before. Adding an option can only remove violations (the `restrict` metamorphic property). A query whose precondition is not reached did not fail, so nothing prints; every renderer renders the conjunct, never an annotation. The `precondition_*.vp` models cover every query kind, a third party's halt, two recipients around a halt, several options on one query, a later phase and scenario expansion; the seven `err_precondition_*.vp` models pin the rejections.

When a query resolves, `attack_trace` minimizes the state (`witness.rs`) and narrates it (`narrate.rs`). A confidentiality query seeds the minimizer with the mutations recorded against the disclosed *value*, since the disclosure may have happened in another principal's execution; an authentication query seeds it with nothing, so `seeded_mutations` takes the answering state's own tainted slots and closes them over the histories of the values in them. Seeding it with the record of the *decryption result* at the use site, as it once did, handed the minimizer the installs of whatever unrelated execution first produced that result, and `scuttlebutt.vp`'s fifth and sixth queries came back unminimized.

### Equational theory (theory.rs + primitive/spec.rs)

All cryptographic behavior is **declarative data**: `PrimitiveSpec` entries define decompose (a rule yields a **set**, `Reveal::Argument(i)` or `Reveal::Output(i)`, and must describe everything the legitimate key holder learns — `KEM_ENCAP` reveals **both** shared secret and randomness, because ML-KEM's re-encryption check re-derives the coins), recompose, rewrite (with matching constraints and filters), rebuild and combine (`THRESHOLD_JOIN`), and guard-bypass key extraction. `theory.rs` interprets them (`can_decompose`, `can_reconstruct_primitive`, `can_rewrite`, `can_rebuild`, `can_combine`); `obtainable` is the shared "can the attacker get this argument at all" cascade. A rule consuming a multi-output primitive names the projection (`rewrite.from_output`, `decompose.output`). Recompose and rebuild carry no share sets: both count **distinct projections of one split against that split's threshold** (`shares_of_one_split`), so `THRESHOLD_JOIN(s3, s1)` and a join over more than t shares reduce without a table listing them.

A rewrite rule's `matching` is discharged as a **bijection**: `can_rewrite_primitive` assigns each outer position a *distinct* inner one. Only `RINGSIGNVERIF` has overlapping `inner_idxs`; before, a ring collapsed onto one member still verified (`ringsign_ring_collapse.vp`). `can_reconstruct_primitive` refuses a core primitive whose reduction is the term itself: `ASSERT` denotes a check. `SPLIT` reduces to a field and still reconstructs.

None of it carries a recursion cap, and reintroducing one is a regression: every `to` rule returns a subterm or reassembles strict subterms, so the descent is well-founded on depth. The memo is keyed on the term hash **alone**; keying on depth too took the suite from two seconds to six minutes. `can_rewrite` is the one reducer: it applies `can_rebuild` and then `can_combine` (both `THRESHOLD_JOIN`) to the argument-reduced term before the rewrite rule, and `rewrite.rs::reduce_term` is the state-walking wrapper over it; two reducers once disagreed on a term holding a join and the minimizer preferred an honest reinstall over the real forgery.

**To add a primitive, edit only `src/primitive/spec.rs`** — `build_primitive_specs` is the whole table; the nearest primitive is the template. Core primitives go in `build_core_specs` and need a `core_rule_*`. Then model tests; nothing else. Several spec fields are read as *direct* slice indices (`rewrite.from`, `recompose.reveal`, `rebuild.reveal`, `bypass_key`), so `every_spec_index_is_within_the_primitive_it_is_declared_on` (`primitive/mod.rs`) holds those to the *narrowest* declared arity and the bound-checked fields to the *widest*, and pins `arg_names` to the widest.

### Nonces (AEAD)

`AEAD_ENC(key, nonce, plaintext, ad)` and `AEAD_DEC(key, nonce, ciphertext, ad)`. `AEAD_ENC` declares `reuse: Some(ReuseRule { fixed: [0, 1], reveals: [Argument(2)], forgeable: [0, 1] })`. `theory::same_fixed` and `reused_pair` read that rule, so two non-equivalent held `AEAD_ENC` terms with equivalent key and nonce are a pair; two encryptions differing only in AD count, and the same message twice does not. Reuse has two consequences, faithful to AES-GCM and ChaCha20-Poly1305 and scoped to the reused nonce only.

**Recovery**: `deduction.rs::rule_reuse` learns what the rule reveals for every member of the pair, unconditionally, which over-claims the case where both plaintexts are unknown and reality yields their XOR; that is a modelling choice. A bucket whose fixed positions the attacker can `obtain` is skipped before any pair is vetted: a term it can already open gains it nothing from a reused nonce, since decompose reveals the same plaintext and forging under a held key needs no exemption, and every forged ciphertext the search installs under the attacker's own key lands in such a bucket. **A member the attacker could mint is skipped too** (`attacker_mints`): a reuse pair is evidence about the encryption function, and a term the attacker made itself repeats no keystream, so pairing a mint under a declared `forgeable` assumption with an honest ciphertext turned an authenticity assumption into a confidentiality one and collapsed `forgeable` into `weak` (`cap_forgeable_is_not_a_reuse_pair.vp`; `cap_forgeable_guard_never_adds_an_attack.vp` is the same model where adding a guard moved the verdict, which is the shortest proof it was wrong). On `THRESHOLD_SIGN` the same pairing recovered the very share its `forgeable_secret` exempts, a circle (`threshold_sign_forgeable_is_not_a_reuse.vp`). The question is asked of the term rather than of its `DerivationRecord`, because the attacker installs what it mints and reads it back out of the state it put it in. Vetting those cost `tls13.vp` 8844 `one_execution` walks and 7758 `pair_coheres` replays per closure pass after 100 seconds, over a bucket of 120 that grew with every proposal. The one trace the skip moves is `scuttlebutt.vp`'s, whose forgery under a key the attacker holds no longer cites a pair. `combination_coheres` is *reached, not equal* by design and admits a pristine read beside a tainted read of the **same slot**, two values of one slot from two executions of one run; pairing those recovered `kab` in `spore_otway_rees.vp` and `spore_yahalom.vp` and forged into `injective_recipient_nonce_unchecked.vp` and `injective_routed_emission_twice.vp`. So `rule_reuse` accepts a pair only past three tests: `reused_pair` (shape), `theory::one_execution` (two terms resting on different values of one slot are never paired; also re-run by both `tracecheck` arms), and `deduction.rs::pair_coheres`, which is `combination_coheres` with equality in place of reached-ness; a replay that cannot run refuses, while a reader the replay never executes is compared against its `execution_base`, since a run no seeded slot reaches holds its honest values (`aead_nonce_reuse_partner_unreached.vp`). A pair that passes is recorded by `VerifyContext::attacker_note_reuse` into `AttackerState::reused`, which every snapshot carries; `theory::reused` looks it up restricted to pairs both of whose members the snapshot still holds, and `theory::forgeable_by_reuse` turns a hit into the rule's `forgeable` positions, so the theory, the validator and the solver never pair anything the closure did not vet. The three tests are memoised per pair as `pair_vetted`, keyed by principal, the two terms, phase, knowledge length, recorded-pair count, `routes_epoch` and the knowledge `chain`, the pair compared by `equivalent` on a hit since the key carries only hashes: `one_execution` follows primary derivations and `pair_coheres` replays records, both fixed between changes of knowledge, and re-vetting every member pair of every bucket on every closure pass was 31 of `needham-schroeder.vp`'s 29 wall-clock seconds with 41 known values. The `needham-schroeder.vp` pair that forced the replay test rested on two different slots, so the structural half could not see it. `aead_nonce_two_executions_not_a_reuse.vp` (`c0` at both counts) pins the family.

**Forgery**: `AEAD_ENC(k, n, m', ad')` is derivable from held `m'` and `ad'` with the rule's `forgeable` positions exempt, in the three places `forgeable` lives (`can_reconstruct_primitive_directly`, which reports `Forged::Reuse` so the trace names the pair; `validate::derivable`; `deduce.rs::solve_by_reuse`). The agreement gate inherits it through `derivable` (`aead_nonce_reuse_forgery.vp`). Decryption is keyed on the key **and** the nonce (`given: [0, 1]`), so a model whose attacker must decrypt has to put the nonce on the wire. Session expansion gives a `knows` nonce to every session and a `generates` nonce to none, which is why `aead_nonce_reuse_sessions.vp` is `c0` at one session and `c1` at two, and why a model whose ciphertext must stay static (`otp_counter_freshness.vp`) declares its nonce while anything sealing a fresh plaintext generates one. A three-argument call is an arity error whose help line is the spec's `arity_help`.

### Threshold primitives (FROST)

`THRESHOLD_SPLIT[t](k)` is a dealer's Shamir sharing, `THRESHOLD_SIGN(share, nonce, commitments, message)` is RFC 9591's round-2 `sign` with the same inputs, and `THRESHOLD_JOIN` is Lagrange interpolation, which is why one join serves shares, partials and verification shares alike. What the join accepts is a `CombineRule` on its spec: every argument is `partial` with a projection of `split` at `share`, all agree at the `agree` positions, and the join reduces to `whole` over the secret followed by the `carry` positions; positions in neither set (the nonce) are free per partial. `THRESHOLD_JOIN` declares two: `THRESHOLD_SIGN` partials agreeing on commitments and message into `SIGN(k, message)`, and `PUBKEY(share)` values into `PUBKEY(k)`. The combined signature **is** a plain `SIGN`, so `SIGNVERIF` is untouched and a threshold signature equals a directly produced one (`threshold_join_agreement.vp`, `e0e0e1e1`); binding to the commitment list lives in the partials, where FROST's binding factor lives, so partials from two signing sessions never mix and the verifier's interface stays honest.

The rule runs in both directions. Forward, `can_combine` sits beside `can_rebuild` in the one reducer. Reverse, `can_reconstruct_primitive_directly` falls back to `combinable` when the ordinary argument route fails: it groups the attacker's held partials by split and agreed positions (`partial_groups`), extends each group with partials the attacker can *construct* over shares it holds (free positions filled with `nil`), and succeeds at the split's threshold, reporting `ReconstructResult { combined: true, from }`. That is a **reconstruct** rule and not a recompose one because the forgery target `SIGN(k, m')` on an attacker-chosen message is assigned by nobody. The validator inherits it through `derivable` → `obtainable`, and the agreement gate through `forgeable_without_sender`. The solver needs its own half, `deduce.rs::solve_by_combination`, beside `solve_by_reuse`: for a target with a combine rule into its head it takes every split the attacker has seen a share or partial of (`held_splits`), binds the secret, mints one shared fresh variable per agreed-but-not-carried position and one per free position per partial, and walks the outputs as a take-or-skip frontier that stops at the threshold, which is linear in `MAX_SHARES` times the frontier rather than a choice among subsets. The signing oracle itself comes from the Constructed pass's single-slot substitution at the participant; the goal is what lets the recipient's proposal spend it (`threshold_sign_leaked_share_and_oracle.vp`, `a0` without the goal).

A combined value is learned as `DerivationRecord::Combined { from }`, narrated as "combines … out of the partial signatures", and re-derived by `tracecheck` through `combination_holds`, which joins the named partials and checks the result. `Reconstructed`'s parts-are-arguments check would reject it, since partials are ingredients and not subterms. `Recomposed` no longer lists the split term among its ingredients: it is not held, and walking it dragged a share reconstructed *after* the secret into the trace ahead of it (`threshold_three_of_five.vp`).

`THRESHOLD_SIGN` declares `forgeable_secret: Some(0)` and `reuse: ReuseRule { fixed: [0, 1], reveals: [Argument(0)], forgeable: [] }`: two partials under one share and nonce, whatever else differs, surrender the share (`threshold_sign_nonce_reuse.vp` against `threshold_sign_fresh_nonces.vp`, and `threshold_sign_nonce_reuse_sessions.vp` for the cross-session case under `knows private`). RFC 9591 §7.3 forbids any reuse and calls the consequence a complete key-recovery attack; the rule is the plain-Schnorr reading of that, with one nonce standing for FROST's hiding-and-binding pair, so it fires at two uses where the exact algebra of a reused pair needs a third. Shares travel under pre-shared keys in every model, standing in for the confidential authenticated channel the RFC's dealer (Appendix C) requires, because a guard only stops substitution and a share on the wire is a share the attacker holds; binding the bundle to the group key with AEAD associated data is the model's own choice, without which a share replays into another session's key generation. Key generation is a dealer; a DKG is a principal that splits a `generates` key and never uses it.

Two metamorphic properties are the ratchet against over-refusal in the counting: `lower` decrements a written threshold and may lose no attack, `raise` increments one and may add none. Both skip models with `equivalence?` or `unlinkability?` queries, since a threshold is part of term identity and moving it legitimately changes what is equal.

### Active attacker search (src/solve/)

Goal-directed: the engine asks what the attacker would need in order to learn this and whether it can arrange that, solving backwards from each query; it does **not** enumerate substitutions forwards. Termination comes from memoisation, cycle cutting and a finite basis, never from a cap on how hard to look. The one bound on term *shape* is `reexec::TermBound`, **per slot**: the depth of the deepest term the protocol computes, plus the layers the recipient itself peels off that slot (`peel_depth`), with the room above the flat cap spendable only where the excess is carried by the protocol's own subterms (`depth_over_protocol`). Counting held terms as free let an oracle ratchet forever. `validate` refuses what the bound does not admit and `note_depth_cut` says so on stderr the first time. `TermBound::of` resolves every slot of the trace, so `VerifyContext::term_bound` builds it once per analysis; `agreement.rs` used to build one per `emitted_by_matching_run` call, once per authentication query per executed state.

Per phase: passive baseline, then rounds to a knowledge fixed point. Each round runs `Pass::Targeted` for every principal, then `Pass::Constructed` for every principal — never interleaved.

- `symbolic.rs` — the principal's computation with every attacker-controllable wire slot replaced by a variable, reduced as `perform_all_rewrites` would. `reexec::attacker_controllable`, reached through the `Controllable` token, decides controllability (guarded-unless-`mutatable_to`, self-created, wrong-phase, unused-by-this-principal; `nil` excluded). "Unused" is waived for a constant an `equivalence?` names, original or variant (`ProtocolTrace::equivalence_queried`), since that query compares the slots as held (`equivalence_unused_received.vp`). `mutatable_to` is closed under relaying in `construct_wire_index`: a guarded delivery by a sender whose own copy was already mutatable adds its recipient, so the guard exemption holds at every hop of a relay chain and not only the first (`relay_guard_transitive.vp` beside `relay_forward_before_check.vp`). A DH public key becomes `PUBKEY($x)`, so the MitM shape falls out of the representation. `reaches` mirrors `compute_visibility`.

  **The refinement search**: `build` replaces every controllable slot with a variable; `build_assuming_honest` leaves one slot at its honest value, because a search seeing only the variable cannot reason *through* the honest value (`relay_rewrap_oracle.vp` against `relay_rewrap_no_oracle.vp`). It runs **only after** `search_fixpoint` reaches its fixpoint with queries outstanding (`Search::Direct` then `Search::Refined`), **only in `Pass::Targeted`**, and **after** the unrefined pass — offered first it degrades `identity_misbinding_uks.vp` and `ringsign_ring_substituted.vp` into `TRACE_USES_A_GUARD_BYPASS`. `slots_blocking_reduction` picks candidates: for each primitive that cannot fire because a slot variable sits in the position its rewrite rule reduces, the group of that slot **and every bare slot variable in a position the rule's `matching` pins**, held honest together.
- `vars.rs` — attacker variables are interned `Constant`s in reserved id ranges (`ATTACKER_VAR_BASE = 0x8000_0000` for slots, `FREE_VAR_BASE = 0xC000_0000` for free choices). Free positions stay variables until materialisation; `ground_free` fills every one with the same `nil`, which is why `diverge::distinguish` exists.
- `matching.rs` — one-sided `match_value`, two-sided `unify`, and `merge`, all modulo DH commutativity as a closed two-case analysis. All three refuse a binding whose variable occurs in what it is bound to (`vars::occurs`); `merge` must repeat the check when it *overwrites* a binding.
- `deduce.rs` — the solver. Goals are discharged by: already-known, bare-variable (`nil`), **replay**, wire unification, oracle (restricted to the finite basis), rewrite-match, primitive-by-arguments, decomposition, `invert` (backwards through rewrite rules and `SPLIT`/`CONCAT`), and `satisfy_check`. `collect_stuck_splits` counts a `SPLIT` whose argument merely *carries* a variable, a bare slot variable included: where the whole bundle is the controlled wire slot its symbolic term is that variable, and requiring a primitive there left the plaintext unmaterialised, so the check's own shape was never solved against held terms and a bundle the attacker assembles from two values it holds was never proposed (`forged_bundle_from_held_terms.vp`, a certificate beside the key it certifies). Bindings from unification are put under obligation by `require_constructible`, which forces the DH substitution in a real MitM. **An obligation on a slot variable is the slot's wire term under the binding, not the raw binding**: a DH slot is `PUBKEY($x)`, so matching a recipient's check binds `$x` to the peer's *exponent*, and demanding that exponent refused every proposal that merely leaves the key share honest (`scuttlebutt.vp`'s reflection). Slot terms come from `SymbolicState::var_terms` (`Deducer::slot_terms`). The same widening lets the goal route bind a slot to a *sibling session's* honest value, so `propose` takes every proposal whose installs are all sibling honest wire values (`sibling_replay`) out of the Targeted pass (`VerifyContext::defer_replays`) and the Constructed pass offers it **after** its own families; ordering only, every proposal is still offered. Goals are memoised on the applied goal's hash, the bucket disambiguated by `equivalent`; results computed while a cycle was cut are not cached.

  **Inverting a rewrite solves an equation; it does not fill a hole.** `rewrite_shape_yielding` fills the positions `matching` leaves free with **fresh variables** and unifies `to(shape)` against `target`. Filling them with `target` nests it a level deeper on each inversion and enumerates `SIGN(SIGN(…))` chains to `TermBound` (`inverting_a_rewrite_solves_for_the_target_rather_than_nesting_it`).
- `diverge.rs` — equivalence queries. `solve_divergent` grounds the variables reaching only one side to `nil`. When both queried values are projections of one installed term, `distinguish` hands each free position its own value from `fillers()`: `nil`, then `HASH` at every declared arity. Every rung is derivable from nothing, and the ladder is injective across a `CONCAT`'s positions (both unit-tested). Gated on an unresolved `equivalence?`. Models: `equiv_forged_bundle_projections.vp` (`e1`), `equiv_forged_bundle_far_fields.vp`, `equiv_sealed_bundle_holds.vp`/`equiv_guarded_bundle_holds.vp`, `unlink_forged_bundle_not_a_link.vp`.
- `validate.rs` — **propose and dispose**, the only route from the search into query evaluation. Every proposal is materialised into a concrete `PrincipalState`, re-executed via `reexec.rs`, and re-checked against real attacker knowledge. Its guard order is load-bearing and asserted by `tcb_tests`: controllability, then derivability, then queue the install, then execute. Its `derivable` is an independent proof that knows nothing about the solver, so the capability exemptions (`forgeable_secret_position`, `malleable_positions`) are repeated here. `worthwhile` skips any proposal whose every install reduces to the honest value. **Executions are remembered** (`VerifyContext::remember_execution`/`recall_execution`): `dispose` dedups install signatures only within a round and the fixpoint re-offers the same substitutions every round, so 83 to 90% of validated proposals per phase repeated one already executed, and each repeat re-ran the whole principal. A remembered execution is its states as diffs against a resolved, rewritten pristine base per principal (`execution_base`), plus every `bypass_is_constructible` decision taken while it ran (`record_bypass_decisions`). Knowledge enters an execution only there and in `relays_are_forwarded`, which uses the same test, and the coherence-restricted knowledge it runs against is **not** monotone (`execution_agrees` can flip as a replay's own bypasses become constructible), so a recall is stale exactly when one of those decisions would come out differently under the governing attacker, in **either** direction, and it is then dropped and re-run; remembering only the misses was a gap the audit closed. Stored states are compared with the base, and signatures with each other, by `structurally_identical` rather than `equivalent`: a DH-commuted twin of a term prints differently, and the recalled state is what the closure reads and the trace names. The guards still run on every repeat, and `execute_forward(` still appears once in `validate`, after `installs.push(`, as `tcb_tests` require. The closure and the queries run over the recalled states unless the execution was last closed against knowledge identical to the current one: `validate` takes the `Saturation` (phase, knowledge length, recorded pairs, `routes_epoch`) before its closure and stores it on the execution afterwards (`note_execution_closed`), and a recall whose stored saturation is the current one skips `note_malleable_reshapes`, the closure and query evaluation, since every one of them is a function of the states and that knowledge and produced only duplicates the first time; it still advances the analysis counter once per state, so the printed analysis numbers do not move.

Proposal families, in offer order: goals from each unresolved query; `constraint_goals`; the **blanket** substitution (every controlled slot replaced by the attacker's own value); one single-slot substitution per controlled slot; and, only in `Pass::Constructed`, the **sibling flight** substitutions plus per-slot candidates drawn from held protocol terms and from shapes the recipient's rewrite rules demand — each alone, with the blanket, and with a **relay** forwarding every other slot unchanged. Every proposal still carrying free positions is then offered three more times through `fill_aligned_with`: `keyed_free`, `preserved_free`, and (only while an `equivalence?` is unresolved) `diverge::distinguish`.

`propose` runs its pure parts through `parallel::map_ordered` and its writes on the calling thread, so the proposal list is the sequential engine's list in the sequential engine's order: the per-query goals of the Targeted pass, the per-slot candidates of the Constructed pass, the two free-position fillers, `aligned_held_free`'s per-proposal walk and `distinguish` each map over indices into a borrowed list and are flattened in input order, while `constraint_goals`, the blanket and single-slot families, `sibling_flight_substitutions`, `goals_noted`, the replay partition and `defer_replays` stay sequential. Each parallel task solving goals gets a `Deducer` of its own, because the solver's memo is a `RefCell`, built by `Deducer::in_lane` over the one shared `Arc` basis: lane 0 is the sequential deducer and keeps the lower half of the free-variable space, lane *k* takes the *k*th `FREE_LANE_STRIDE` block from the top, `lanes` splits the items into at most `FREE_LANES` ranges so that a model with more pending queries or controlled slots than lanes shares a deducer within a range rather than aborting (a 4097-query model at the default did), and `fresh_var` asserts a lane is never exhausted, since two tasks minting one free variable would be misread by the fillers, which find free positions by id. Per-task deducers lose the goal memo across slots and queries; the corpus diff is byte-identical, so that is a cost and not a behaviour, and on `junglegym_threshold_ring.vp` alone on the machine the pool is neutral (19.8 s against 19.7 s). Parallelising the closure's rule evaluation the same way was built, measured and removed: a closure pass is thousands of dispatches of light work, and a `pool.install` handoff per pass cost more than it returned (a third slower on that model at a 256-item minimum, and on `tls13.vp` 8% of wall clock bought with 9% more user time and 350 s of system time in wake-ups). A caller that is itself a pool worker, so a pass is a `join` the caller takes part in, is the design that would have to be measured before that returns.

- `keyed_free`: **where the protocol put a public key, offer the attacker's own.** It keys only aligned positions: filling every free position costs 1.84x. `forged_key_swap_bundled.vp` (`c1c0`) is the regression, `witness_key_swap_bundled.vp` (`e0`) the same substitution by hand.
- `preserved_free`: **keep the field you are not attacking.** It fills each free position with the honest term's own argument where the attacker holds it. `forged_statement_rebuilt.vp` (`c1c1`, WalletConnect v2 One-Click Auth) was `c0c1` before; `forged_statement_on_wire.vp` is the counterweight and `witness_statement_rebuilt.vp` (`e0`) executes it by hand.
- `aligned_held_free`: **where a forged shape leaves a ciphertext position free, offer every held protocol ciphertext under the same key.** The basis is the protocol's own subterms (offering every held term took the suite from 136s to 747s), indexed once per `propose` by (head, output, arity, key hash). `pitoy_depth.vp` is the model.
- `sibling_flight_substitutions` makes injective agreement reachable: one proposal per sibling index installing that session's whole honest flight at once, because a replay pairing one session's key share with another's ciphertext fails the recipient's checks (`tls13-0rtt.vp`). **It belongs in `Pass::Constructed`**: offered early, `bypass_witness_narration.vp` degrades into a shallower replay.
- `constraint_goals` builds a **forged authenticated flight**, the shape of every server-impersonation attack. A `SPLIT` over a decryption it cannot reduce is discharged by materialising the plaintext as a `CONCAT` of the arity the projections demand (`satisfy_split`, `widest_projections`). The set is re-solved in **additive refinement rounds** under the bindings found so far, bounded by the number of checks. Rounds only ever **add** proposals, and `bind_from_shape` refuses a shape with an unbound position; both were tried the other way and cost real attacks (`forged_flight_mitm.vp`).

**The attacker's option set is the thing to be careful with, and narrowing it silently is this engine's characteristic bug.** At every position the options are `{honest value}` plus everything derivable. Four missed attacks came from replacing that set with one representative: `vars::ground_free` narrowed what the search **proposes**, `symbolic::build` narrowed what it can **derive**. The rule: **never commit to one representative where the commitment is unrecoverable; defer it and enumerate.** When a fifth is suspected, look first at whether the minimizer can already say something the search cannot: twice a family `witness.rs` had was a family the search lacked.

Proposals are deduped by what they would **install** (`solve/mod.rs::install_signature`), not by substitution identity, and not across rounds. Before the signature is taken, `leave_honest_slots` drops every binding whose installed value is the slot's honest one and that no other binding mentions; a proposal left empty by it is skipped. Variables the solver never bound are left free and `validate` skips those slots. **Skeletons are gone**: `skeleton.rs` handed the attacker each primitive's shape with secrets erased, and removing it changed no verdict and improved ten traces. Do not reintroduce a rule that hands the attacker a shape it did not derive.


### Re-execution (reexec.rs)

`reexecute` installs attacker-chosen values into a principal and runs it forward: install → check the slot graph is still acyclic → resolve → rewrite → then either bypass guards the attacker can defeat (`try_guard_bypass`, keyed on the spec's `bypass_key`; uncapped, since each round must flip a fresh `bypass_injected` flag) or truncate at the checked primitive that halts the principal and set `halted_at`. Bypass works from the *pre-resolution* state. It exists because substituting `PUBKEY(nil)` for an identity key fails a signature check while the attacker knows that private key.

`bypass_is_constructible` keeps that from becoming a licence: holding the `bypass_key` is necessary and **not** sufficient; every other position the rule's `matching` pins must be `obtainable` too. `KEM_DECAP` pins only the key; `AEAD_DEC` also pins the nonce and the AD, `SIGNVERIF` the message, `RINGSIGNVERIF` the ring and message. `bypass_needs_the_whole_check.vp` and `bypass_needs_the_signed_message.vp` pin the refusal; `…_ad_leaked.vp` and `…_wire.vp` are the counterweights. A `bypass_key` is declared only on a primitive that can take `?` (`a_bypass_key_is_declared_only_on_a_primitive_that_can_be_checked`). `honest_input_accepted` is the other half: a failed check that passes once its `rule.from` argument is restored to the honest value has every other argument honest, so the only terms it accepts are ones the sender's own value belongs to, and a bypass there would narrate a value the recipient already accepts from the sender as an attack (`bypass_needs_the_signed_message_public.vp`, `a0`). Any other accepting term the attacker can build is reachable by installing it directly.

Four guards decide what the search may touch, all travelling to `validate.rs` inside `Guards`: `Controllable` (`Controllable::of`, one per solving pass; fields private so nothing outside `reexec.rs` can mint one; `admits` re-checks principal and phase), `TermBound`, `CausalOrder`, `Coherence`.

`slot_graph_is_cyclic` is what lets `resolution.rs` carry no depth cap: `install` is the only thing writing a slot out of declaration order, and the search will offer a slot a value naming that same slot. A slot holding a primitive has an edge to every slot the primitive mentions; a slot holding another slot's bare name has an edge to that slot. This lives in one place because `validate.rs` and `witness.rs` **must agree exactly**.

### Attack traces (witness.rs + narrate.rs)

**`witness.rs::minimize_witness`** — a raw witness carries the union of the bindings for *every* goal the solver pursued. The minimizer picks a **candidate** per principal's pristine session: the canonical MitM (attacker's key wherever a DH public value arrived over the wire), then the recorded mutations, then those with public keys replaced by `PUBKEY(nil)`, taking the first that still resolves the query; then drops mutations one at a time while the query keeps resolving. If nothing replays it falls back to `unminimized` with `reproduced: false` and claims no attacker actions.

- **"First candidate that resolves" is not "the candidate that explains", so the choice is ranked.** `try_guard_bypass` defeats a checked decryption the moment the attacker holds its key, so `ciphertext := nil` resolves almost any authentication query. The minimizer prefers any witness where **no** bypass fired (`needs_guard_bypass`), and `drop_one` refuses a drop reintroducing one. `forged_from` **constructs** a bypass-free witness: it asks the recipient's own failed checks what shape they wanted (`perform_all_rewrites` plus `build_rewrite_shapes_with`) and offers that forged term for each controlled non-key slot. `payload_shapes` fills a rule's free positions three ways: `nil`, the honest term's own argument where the attacker holds it, and the attacker's own public key where the honest term carries a key derivation; the explanatory shapes are offered **before** any `nil`-filled one, and `attacker_can_build` keeps the family honest. This is ordering, not searching: every candidate still goes through `probe`.
- `examples/silly/cloudbackup.vp` is the model to read: a MitM on `g_file_alice_a_key` transiting Alice → Server → Bob unguarded while both long-term keys are guarded. If a change makes that trace mention `nil` again, it is a regression the verdict will not catch.
- A bypass is not automatically a smell: where the defeated check is a signature over a substituted identity key, the bypass **is** the attack. `TRACE_USES_A_GUARD_BYPASS` is **empty** at the default, so any entry is a witness that got a worse explanation. It held four until `forged_flight` stopped committing to the first shape the strict rule accepts at a slot: the climb collects every accepted shape and continues from the best by `(halts, bypasses, stuck)`, admitting no move the strict rule refused. Three relaxations of the acceptance key were tried first and each regressed another model, because a climb is one path and a different key is a different path. So the strict climb is untouched and a **second** climb runs after it, accepting only strict improvement under `(halts, bypasses, stuck)`, which is what lets a recipient's first check be forged when passing it exposes bypasses downstream (the strict key refuses every halt-to-bypass move). `flight_shapes` also offers each wanted shape substituted into every position of the slot's **current** forged term, so a signature a check wants inside a decryption reaches the ciphertext it is sealed in; `scuttlebutt.vp`'s `equivalence?` needed both.
- `narrate.rs::out_of_order_note` is a backstop earned by `out_of_order_harvest`. **No model earns it any more**, because `CausalOrder` refuses the install; if one does, that is a causally impossible trace `CausalOrder` missed.
- **An install may be addressed to one principal.** Shared installs are `(slot, value)` and go to every session controlling the slot; an addressed install `(principal, slot, value)` goes to that principal alone, and `others` on the `Witness` holds the sessions a probe executed under one. Only `split_recipients` mints them, from `needs_of` on the claimed value; keeping `others` empty otherwise is what keeps `forged_key_swap_bare.vp` intact.
- **The seed is bounded by the trace, not by the answering state.** `mutations` drops any seeded slot at or past `km.slots.len()`, not `ps.values.len()`: `ps` may be truncated at a halt (`spore_ns_pk.vp`).
- **A witness is an ordered sequence, and `grounded` is what says so.** `probe_with` walks the installs greedily: an install is ready when no install into a slot sharing a recipient with it and declared earlier is still pending, and it is taken when `attacker_can_derive`-able from knowledge established by the installs taken **before** it; the prefix is then executed and what it yields absorbed. Order is imposed only within one recipient's run, because session clones are concurrent and sorting every install by `declared_at` put a second session's whole run after the first's. `choose` prefers a grounded witness among the bypass-free ones, and `drop_one` refuses a drop losing groundedness (`the_lowe_witness_replays_through_bob_before_it_learns_the_nonce`).
- **The seed has to be transitively closed.** `seeded_mutations` closes the tainted diffs of the query subject's record (or the answering state's own tainted slots) over the histories of the values in it: each held **subterm**, then that subterm's tainted diffs, breadth-first, skipping values that `costs_nothing`. Without closure the Lowe witness's enabling install into Bob was in no candidate family; skipping cost-free values stops `PUBKEY(nil)`'s arbitrary ambient record winning the first-wins-per-slot race.
- The probe's baseline is **resolved and rewritten**, like `generate_trace`. Probes run against a **scratch `VerifyContext`** built by `scratch_for_witness`, re-seeded from the **passive baseline** rather than end-of-search knowledge; `in_minimization()` gates re-entry and `info.rs::InfoQuiet` gates output.

**`narrate.rs::narrate_attack`** renders the witness as numbered causal steps: `Mutations` (per wire message), `Gate` (a checked primitive that passed with an attacker-controlled input), and `Derive` (one line per `DerivationRecord`). `NameTable` compresses terms back to slot names, excluding the **shadowed** set (`shadowed_names`: installed slots and everything computed from them) at every depth, not only at the top level, or Lowe's forged `PKE_ENC(gb, d1)` printed `d1` for the very `CONCAT(ni@2, ga)` the attack is about. Steps are emitted **per message in the order the installs happen** (`mutation_groups`, keyed on the send event that carries the slot), so the derivation of each installed value directly precedes the step that installs it.

**Every renderer excludes the shadowed set.** `narrate_attack` computes `shadowed_names` once and hands it to the gate steps, the `via` clause of a carried-in value and the `Narration.shadowed` the query summaries read, so a forged term never prints as the honest slot it displaced (`PKE_ENC(gb, d1)` for Lowe's `PKE_ENC(gb, CONCAT(ni@2, ga))` was the summary-line form of the bug). A `Leaked` or `Obtained` step names the slot its record cites where that name is not excluded and still denotes the value (`compress_outer_preferring`), not the first equivalent slot in the table, which named Alice's `ka` for a leak of Bob's `kb`. A `Gate` step fires only for a check with an installed slot in its own dependency cone (`own_cone`), not for one whose argument equals an installed `nil`. A value the attacker installed is not then "observed on the wire" at that same slot (`CarriedIn::slot`). `Step::Replay` carries both `sibling` and `session`, and says "another scenario" where only the copy axis matched. `choose` ranks a witness by `(grounded, recipient did not halt)`, so a cross-session replay that Bob's later `ASSERT` rejects loses to the reflection he accepts (`spore_otway_rees.vp`). `DuplicateAcceptance` is also chosen where the witness had to install into a slot carrying a value the recipient generated (`forged_recipient_context`), since a replay that needs the recipient's own transcript forged is not one it takes twice unaided.

Three smaller rules: a **multi-output primitive carries its projection** (`|n`) wherever `NameTable` renders a term (`equivalence_names_the_projection.vp`), and `Display for Primitive` deliberately does not; a **declared weakening assumption must be named** — `Broken` displaces a derivation naming no assumption and `walk` refuses to override it (`cap_forgeable_names_its_assumption.vp`); `Initial` narrates as "it is public" **only at the root**.

**A step may claim only what its own operands establish, and "session" is the word this file gets wrong most easily.** *Which run* a derivation happened in is known only from the `MutationRecord`'s `principal_id`, so only `session_prefix` may name one, and nothing may call the other run *earlier*. *A cross-session replay* is established only by `copy_sibling_replay`, so `Step::Replay` carries a `sibling` flag and only that arm says "from another session"; the other arm says "unaltered". *A guarded slot being substituted* is not a guard bypass: `attacker_controllable` admits it only when the value reached the sender unguarded upstream, and `Step::Bypass` fires only where `try_guard_bypass` proved the key is held. An `Obtained` value is "on the wire" only when its slot has a `sent_by`.

### The soundness tests (query.rs::tcb_tests)

Theorem 4 of the paper is that a solver bug cannot produce a false attack, *whatever the solver does*, reduced to facts pinned by reading the source:

| fact | what it says | pinned by |
| --- | --- | --- |
| (i) | one write path: `results_put`, whose token constructor is private to `query.rs`, called once from `emit_query_result` | the `QueryVerdict` type + `a_query_result_has_exactly_one_write_path` |
| (ii) | reached only from query evaluation: five `emit_query_result` callers, one per query kind | `results_are_recorded_only_by_query_evaluation` |
| (iii) | the verdict comes from a state: an evaluator is handed a `PrincipalState` and an `AttackerState` and nothing that could carry a verdict | `a_query_evaluator_is_handed_states_and_nothing_else` |
| (iv) | every state it is handed was executed: three `verify_resolve_queries` call sites, nothing under `src/solve/` reaches evaluation directly | `query_evaluation_is_entered_only_over_an_executed_state`, `the_solver_cannot_reach_query_evaluation_except_through_the_validator`, `the_solver_holds_no_shared_cell_over_analysis_state` |
| (v) | every term the attacker installs was derivable *and causally available*, against knowledge restricted to compatible executions; `validate.rs` proves this before `execute_forward` runs and abandons the *whole* substitution on failure | `an_install_is_proven_controllable_then_derivable_before_it_is_executed` |
| (vi) | every slot the attacker installs into was controlled, tested *first*, against a `Controllable` only `reexec.rs` can mint | the same test, plus `controllability_is_minted_only_by_reexec_and_bound_to_one_session` |
| (vii) | a value that enters a state by forwarding is exactly what its sender sent: over a declared leg, in a reached phase, from a run that reached the send, with sender and creator left honest and taint set | `a_forwarded_value_is_only_ever_what_its_sender_sent` |

Two are about *order*: testing derivability after queueing an install, or letting a failed test `continue` to the next slot, executes a state the replay system does not permit. Keep `Controllable`'s fields private and `admits` checking both principal and phase. Adding a query kind touches (ii) and (iii): a sixth `emit_query_result` caller and a sixth arm in `query_start`, both counted.

### Supporting modules

`parser.rs` — byte-level recursive descent; comments captured into AST nodes so `pretty` round-trips them (idempotence is unit-tested). A leading byte-order mark is skipped by position, not stripped, so every span stays relative to the text the editor holds. `pretty.rs` — canonical formatter, golden-tested; `pretty_model` is a pure AST walk, infallible, and deliberately **not** gated on `sanity`. It owns the `Display` impls for `Value`/`Constant`/`Primitive`/`Query`/`Expression`, so every engine message and trace is rendered here.

`resolution.rs` — inlining, `compute_visibility`, and `state_mentions`/`principal_uses_constant`. A slot the attacker filled with another slot's *name* resolves through that name to what it holds (`resolve_ps_values` chases the alias chain with a cycle guard; `matching_run_two_inputs.vp`); only installs create such chains. It is unbounded otherwise, because the slot graph is acyclic. `rewrite.rs` — applies rewrite rules over a state, reporting failures as `(Primitive, slot)`. `equivalence.rs`/`hashing.rs` — the equivalence/hash invariant. `primitive::normalise_arguments` is the one place keeping the term space finite: where `argument_restrictions` forbids a key derivation in a position it unwraps it, so the solver cannot build `PUBKEY(PUBKEY(x))` forever. `construct.rs` — builds the trace and principal states, owns `clone_for_depth(purify)`. `info.rs` — all user-facing output, buffered into JSON under wasm; `InfoQuiet` silences hypothetical re-runs and `InfoCapture` buffers a run for `--saturate`. `capability.rs` holds `Capability`/`Capabilities` and `CapabilityIndex`. `util.rs` — small helpers plus `ColorChoice`. `update.rs` (`cli` only) — `verify` and `about` spawn a thread that GETs the GitHub tags API and prints one stderr line if a newer tag exists, read with `try_recv` so a slow network never delays a run; the only outbound call the tool makes.

`lsp/` — behind the `lsp` feature. `mod.rs` is the stdio loop, using `recv_timeout` as the validation debounce; `shutdown` and `exit` are handled in the loop rather than by `lsp_server::handle_shutdown`; analysis runs on a worker thread. **Both threads must call `info::set_verbosity(Verbosity::Silent)`**: `VERBOSITY` is thread-local, and engine chatter on stdout desynchronises every client's parser — the symptom is an analysis that never returns. The server never touches the filesystem; documents are keyed by URI. `docs.rs` is the language prose (`CC-BY-SA-4.0`): keyword and query entries are written there, primitive entries are the specs' own `doc` fields, capability entries are generated. `line.rs` converts byte offsets to LSP positions; `state.rs` holds `Documents`; `diagnostics.rs` turns errors or a finished `Analysis` into diagnostics; `language.rs` is every position-driven feature; `analysis.rs` owns the worker threads; `proto.rs` is the wire shape of the custom `verifpal/*` messages.

`report.rs` — the one serializable description of an analysis behind `--format json`, `--format html` and the LSP notification; ranges are byte offsets plus 1-based line/column, never LSP positions. `QueryReport.query` is `pretty::query_line`, so it carries the option block. `describe` draws a principal that **leaks** even if it never appears on a message (`leaks_without_a_message_is_visible.vp`). Each model is parsed exactly once for presentation in `Run::of`; the renderer never touches `crate::parser` (`the_html_layer_never_reaches_for_the_parser`).

`html/` — renders `Run` into the self-contained page. **No markup is written in Rust** (`no_markup_is_written_in_rust` rejects `"<`, `</`, `/>` and `class="` in `mod.rs` or `diagram.rs`); it lives in the `tpl/*.html` fragments, `report.css` and `report.js`, compiled in via `include_str!`. The engine is **`src/template.rs`**, shared with `src/tex/` and parameterised by a `Dialect` (HTML `{{…}}`, LaTeX `<<…>>`): `{{key}}` interpolates, `{{#key}}…{{/key}}` is a section, `{{^key}}` inverts, `{{>name}}` includes. **Escaping is a type**: `Val::Text` escapes and `Val::Raw` does not, chosen once where data is built. **Both directions of the template/data contract are a red build** under `cfg(test)`: a placeholder nothing supplies panics, and a supplied value the template never reads panics (`audit`). `every_model_in_the_corpus_renders_a_sound_page` renders all of `examples/test/` and pins that no `{{` survives, ids are unique, every `href="#…"` resolves, and tags balance. The golden page (`examples/test/golden_html/report.html`) is rendered from a **fixture** `Run`; re-bless with `VERIFPAL_BLESS_HTML=1 cargo test the_rendered_page`.

`tex/` — renders `Run` into the LaTeX document behind `--format tex`, compilable by tectonic as it stands. Same discipline: `no_latex_is_written_in_rust` rejects `\\begin{`, `\\end{`, `\\usepackage` and `\\documentclass` in `mod.rs` or `math.rs`; LaTeX lives in the `tpl/*.tex` fragments and `preamble.tex`. Every figure is delimited by paired `%% --- BEGIN verifpal … ---` / `END` markers and built only from `\\vp…` macros in the preamble, so it can be lifted into a paper; Rust emits logical rows and the `vpdiagram` environment lays them out. `listing_safe` withholds any source line carrying `\end{lstlisting}`, or `\input` could read arbitrary files into the PDF. `math.rs` re-parses the printed form of every term and falls back to escaped upright text. `the_document_never_claims_a_proof` rejects "proven", "is verified", "is complete" and "proof of correctness" and requires the disclaimer. `the_golden_document_compiles_under_tectonic` is gated on `VERIFPAL_TECTONIC=1` (`make test-tex` sets it); golden `examples/test/golden_tex/report.tex`, re-blessed with `VERIFPAL_BLESS_TEX=1`.

`msc.rs` — the sequence-diagram row model (`Row::{Wire,Phase,Leak,Activity,Mark,Run}`, `Value`, `Lanes`) serving all three renderers. `tokens.rs` — `TokenKind`/`Token`/`TokenIndex`; `parse_string_indexed` returns the index *even when parsing fails*. `Constant` carries no `Span` and must not gain one.

There is no process-global mutable state. `ValueNames` (`value.rs`) and `PrincipalNames` (`principal.rs`) are interners **owned by the `Parser`**, so ids are per-model; the unnamed-constant counter is a parser field and the analysis counter is thread-local. Both interners error rather than overflow into `ATTACKER_ID = 0`, the copy bands or the ranges `solve::vars` reserves. `inject.rs`, `mutationmap.rs`, `verifyactive.rs` and `skeleton.rs` are gone.

## Testing conventions

- Unit tests live in a `#[cfg(test)] mod tests` at the foot of the module they exercise. `src/testutil.rs` holds shared builders. `src/model_tests.rs` holds the end-to-end model tests: `run_model("foo.vp", "c0a1")` runs `examples/test/foo.vp` through `verify` at the **shipped default** of two sessions and asserts the code; `run_model_sessions("foo.vp", 1, "a0")` pins an explicit count. A model whose verdict depends on session count should be pinned at both.
- **Result code format**: one letter+digit per query in model order — `c`/`a`/`f`/`u`/`e` for the kind, `0` = holds, `1` = attack found.
- Adding an engine regression test: write a model in `examples/test/`, get the code via `cargo run --release -- verify examples/test/foo.vp --result-code | tail -1`, **verify by reading the trace that each 0/1 is actually correct**, then add a `run_model` test. Explain *why* the code is right in a `// Expected:` header comment — see `aead_replay_not_forgery.vp`.
- Golden pretty-printer files live in `examples/test/golden_pretty/` (6), compared byte-for-byte. `golden_html/report.html` and `golden_tex/report.tex` are rendered from fixtures and re-blessed with `VERIFPAL_BLESS_HTML=1` / `VERIFPAL_BLESS_TEX=1`.
- The test builders share one interner (`testutil::test_value_id`), so **unit tests must use unique constant names** (prefix per test, e.g. `cbw_m`). A test that both parses a model and builds a value by hand must take the constant from the parsed trace via `testutil::trace_constant`.
- A model *meant* to be rejected gets `run_model_err("foo.vp", "substring of the error")`.
- Every model in `examples/test/` is wired to a `run_model` or `run_model_err` test; keep it that way. The corpus is also swept through the HTML and LaTeX renderers.
- **The corpus diff** is the check for an engine change meant to move only the verdicts it names: build a binary before and after, run `verify` over every model under `examples/` at one session and at two, and diff the full output, not the result codes. **Leave `examples/transport-layer/tls13.vp` out of every such sweep**: at `b48f7f9` it did not terminate in a day; after the DAG and `rule_reuse` fixes described under "Core data model" it exhausts one session in 31 minutes and 3.2 GB, with the code its header predicts, and the default takes longer still. `signal_twelve.vp` is left out too, for taking a minute on its own. Neither is in the model-test suite.

### Checking *why* a verdict happened, not just that it did

A result code says nothing about the attack behind a `1`, so a battery of test-only checks sits underneath it. The sweep runs `examples/test/` (468 models) plus the seventeen in `SWEPT_MODELS_OUTSIDE_EXAMPLES_TEST`, which now cover `examples/hpke/`, `examples/messaging/` (`signal_twelve.vp` aside), `examples/simple.vp` and the contact-tracing models, since `scuttlebutt.vp` shipped two unminimized witnesses and `signal.vp` an unguarded identity key that no sweep looked at; sanity-error models are skipped. Re-measure the counts below after touching the corpus.

- **Witness replay.** Every `verify` under `cargo test` ends in `witness::assert_reported_attacks_replay`: for each resolved query it re-executes the reporting principal's pristine session with exactly the substitutions the minimizer kept, and fails if the query no longer resolves or the printed trace names *fewer* slots than the witness needed.
- **Narration shape.** `attack_traces_keep_their_shape_and_name_only_wires_that_exist` pins five exact sets: `TRACE_USES_A_GUARD_BYPASS`, `TRACE_IS_NOT_A_MINIMIZED_WITNESS`, `TRACE_IS_NOT_CAUSALLY_ORDERED`, `TRACE_FEEDS_BACK_A_LATER_VALUE` and `ATTACK_IS_REPORTED_WITHOUT_A_TRACE`. The bypass set is keyed on "does not halt", not "does not halt at", because a check bound to `_` has no slot name and was invisible to the ratchet. All five sets are empty. A new entry means an attack got a worse explanation; a missing one means an explanation improved and the pin should move. `cloudbackup.vp` is swept from outside `examples/test/` for exactly this.
- **Every step is re-derived** (`tracecheck.rs`). `Step` carries its structured operands under `#[cfg(test)]`, and every trace `narrate.rs` produces is checked before it is returned, ~560 attack verdicts and ~2400 steps at the default. **Well-foundedness**: each ingredient must be produced by an earlier step, installed by a mutation or replay, free (`Initial`), `theory::obtainable`, or assembled from justified parts; `obtainable` is asked against an attacker state **grown step by step** (`Grown`), because against the final knowledge it held for everything. A confidentiality trace must reach the claimed value; an authentication trace with steps must show the attacker on the wire. **Each claimed operation holds**, re-derived from the state: `Decomposed` re-runs `can_decompose`, `Obtained` must name a slot that travelled, leaked, is public, or holds the value, `Leaked` a slot the model leaks and this run reached, `Broken` a capability `in_force` at the trace's phase, `Gate` a checked primitive whose rewrite succeeds on an attacker-tainted argument, `Bypass` a key `theory::obtainable` confirms.

  A trace may also carry `Resolves`, `Static` and `Received` steps explaining a violation needing no attacker action. **These describe a state, so they must be built from the state the rest of the trace describes**: `attack_trace_with` takes them, and the **target** a `confidentiality?` trace claims, as closures evaluated against `witness.ps` *after* minimization. Building them from the answering state was the largest single fault source the metamorphic sweep ever reported.
- **Holds were searched** (`assert_holds_were_searched`): in an active model offering any controllable slot, every hold must have had `goals_for_query` called for it. Zero goals is fine; zero attempts is an untested claim. Freshness is exempt.
- **Holds are not stale** (`assert_holds_survive_final_knowledge`): every hold is re-evaluated at the end of the run against each principal's fresh trace with everything the attacker knew by then.
- **Both session counts.** The sweep verifies every model at one session and at the default; the narration-shape sets are measured at the default only.
- **Wire coherence and header intent.** The sweep rejects any step claiming the attacker replaced a value on a message the model does not have, or on a message every copy guards without a bypass, and requires each model's `// Expected:` line to match. 303 of the 429 analysing models state a code; the ceiling on the rest (`undocumented <= 126`) is a ratchet.

### The metamorphic harness (`src/metamorphic.rs`)

The checks above cannot see a *missed* attack. The harness transforms each swept model and asserts a relation between the two result codes; every property is a theorem about the **language**, so a violation is an engine bug. Transformations go parse → transform → `pretty_model` → **re-parse** → `analyze_sessions`. *Monotone* properties make the attacker strictly stronger, so no `1` may become `0`; *invariant* properties preserve meaning, so codes must match. All run at one session; `settle` refuses a pair count below the property's floor so a sweep cannot pass vacuously. Counts in parentheses are the `_exhaustively` twins.

| property | transformation | direction | compared |
| --- | --- | --- | --- |
| `unguard` | remove one `[guard]` | monotone | 292 (307) |
| `leaks` | add `leaks c` | monotone | 1425 (1481) |
| `weaken` | add `weak` / `forgeable` | monotone | 1768 (1858) |
| `sessions` | `--sessions 1` → `2` | monotone | 429 |
| `dephase` | delete the last `phase[N]` | monotone | 30 |
| `promote` | `passive` → `active` | monotone | 84 |
| `demote` | `active` → `passive` | monotone | 314 |
| `rotate` | reorder the `queries` block | invariant | 273 |
| `rename` | alpha-rename every identifier | invariant | 413 |
| `pad` | prepend an unused `knows private` | invariant | 429 |
| `scenario` | add `scenarios[ P[c = c] ]` | invariant | 385 |
| `scenarios` | add a second copy of that scenario | monotone | 266 |
| `restrict` | add `precondition[…]` naming the last message to every query | monotone | 336 |

`dephase` deletes the *last* boundary so nothing needs renumbering. `rename` and `pad` probe the interner and the reserved id bands; `rename` renames the `scenarios` block too. `scenario` is the no-op case for the scenario front-end; `scenarios` is `sessions` monotonicity over the other axis. `restrict` asks the weaker question, so it is compared the way `demote` is.

**Two ratchets, failing in *both* directions, both currently empty.** `KNOWN_MISSED_ATTACKS` once held `exa.vp` under `unguard`; `KNOWN_BAD_TRACES` once held 28 entries that turned out to be four bugs. A violation outside a list fails; an entry that *stops* violating fails too. Staleness is judged only over models a run exercised.

**A transformation that changes which runs are honest is not compared.** `asks_the_same_question` requires every scenario the original declares to keep its corrupt-from phase in the variant. This is a skip of the same kind as a variant failing `sanity`.

**Binding a subterm to a fresh local constant is not an invariant.** A `name_intermediate` transform was written and reported two false attacks; both were false positives, since a use lifted out of a failing check is a use in a primitive of its own (`auth_with_signing_false-attack.vp` pins that shape as a genuine `a1`). Do not add the transform, and verify any metamorphic "false attack" against the pinned corpus before touching a gate.

**Nothing is deferred and nothing is timed.** Every analysis runs to completion; the only skips are a file that does not parse or a variant failing `sanity`. Cost is bounded by `spread` running models across workers capped by `worker_cap()` (default 4, `VERIFPAL_METAMORPHIC_WORKERS`), by skipping models whose baseline holds no attack for monotone-stronger properties, and by `witness::MinimizingGuard` in `Sweep::Fast` runs, which skips minimization and narration. `unguard`, `leaks` and `weaken` run as `Sweep::Fast` under `cargo test` (the eleven `COSTLY_MODELS` left out); their `_exhaustively` twins carry `#[ignore]` and are what CI runs. `KNOWN_BAD_TRACES` is only asserted where traces are built (`settle_traces`); the missed-attack assertions run for every sweep.

Runtime explodes → a genuine bound. **The `loosened` column is a measurement with a date on it, not a property of the code**: five rows re-measured on 2026-09-05 had drifted, every one upward. ## Style and licensing

- Every source file starts with an SPDX header (`GPL-3.0-only` for code, `CC-BY-SA-4.0` for prose), including `.vp` test models.
- rustfmt with **hard tabs** and Unix newlines; clippy is a hard gate (`-D warnings`).
- **Do not write comments.** Reasoning belongs in the commit message and in this file, where it cannot drift silently against the source. `sessions.rs` keeps a module-level doc from before that rule, and `deduction.rs`, `reexec.rs`, `agreement.rs`, `context.rs` and `solve/mod.rs` carry item-level docs on the gates whose reasoning does not fit a name. Those are the register to match *if* asked for one; otherwise add none, including to code touched in passing. `.vp` test models are the exception — a new one must carry a `// Expected:` header arguing its code, since the `undocumented` ratchet cannot go up.
