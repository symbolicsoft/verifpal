# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Verifpal is a symbolic formal verification tool for cryptographic protocols. Users write models in the Verifpal language (`.vp`), and the engine checks security queries (confidentiality, authentication, freshness, unlinkability, equivalence) against a passive or active attacker, each principal running two concurrent sessions by default (`--sessions k`). Sessions are bounded: a passing query means no attack was found within that many sessions. One Rust crate (`verifpal` 1.4.2, edition 2024, `rust-version 1.98`, GPL-3.0-only) building a CLI binary and, separately, a WASM library used by the website and the VS Code extension. The [User Manual](https://static.verifpal.com/manual.pdf) is the language reference; `README.md` is the pitch. [*From Toy to Instrument: Seven Years of Verifpal*](https://eprint.iacr.org/2026/1654) is the paper, and is the authority where it and this file disagree.

The engine is **sound but incomplete**: any reported attack must be genuine, but the search may miss attacks. Soundness is structural: the solver in `src/solve/` only ever *proposes* substitutions, and `validate.rs` re-executes each one concretely before any result can be recorded, so a solver bug costs a missed attack and never a false one. That is Theorem 4, reduced to facts `query.rs::tcb_tests` pins by reading the source.

## The one rule about primitives

**A primitive is declared once, in `src/primitive/spec.rs`, and nowhere else.** Everything the engine knows about it is a field of its `PrimitiveSpec` or `PrimitiveCoreSpec` entry: name, arity, outputs, argument names; decompose, recompose, rewrite, rebuild and reuse rules; bypass key, commutativity, key-derivation role, identifying positions, argument restrictions with their error notes; supported capabilities and what they reveal; tuple, projection, equality and divergence-filler roles; arity help; editor documentation. The engine only interprets those fields.

Three things hold the line. `PRIM_*` ids are re-exported only under `cfg(test)`, so engine code naming one does not compile. `the_engine_names_no_primitive_outside_its_spec` fails on a `PRIM_` token or a quoted primitive name in any non-test source file. The parser's reserved words and the editor's documentation are read off the registry. When a new behaviour seems to need `p.id == …` or `name == "…"`, a field is missing: add the field and its generic interpreter, and declare the behaviour on the primitive. `ReuseRule` is the worked example — nonce reuse was AEAD-specific code in four modules, and is now one spec field plus one pair rule in the closure. Core primitives are the same: `CONCAT` is the one whose spec says `reveals_args`, `SPLIT` the one with `projection_of`, `ASSERT` the one with `equality`, and the solver asks the registry which those are.

`cap_forgeable_other_message.vp` (`c1` at one and two sessions) pins the solver's use of the secret index: a forgeable signature licenses another message under the same key. `cap_forgeable_other_key_holds.vp` (`c0`) keeps the key boundary. This also changes `cap_forgeable_cert_chain.vp` to `c1c1a1a1` and `ringsign_forgeable_cap.vp` to `a1a1`: both formerly protected messages use the same signing key as an annotated call. This is the existing semantics in [Definition 20 of the paper](https://eprint.iacr.org/2026/1654.pdf), not a new weakening rule.

`solver_constructible_reduct.vp` (`c1` at one and two sessions) pins deduction by choosing inputs that reduce: the attacker encrypts nil twice to Bob's public key, so Bob's two decryptions yield nil and his wrapping key is public. Constructing the unreduced decryption would require Bob's private key, which the attacker does not need. The solver uses the existing check-shaping and reduction machinery, then requires the reduct to be derivable. `solver_constructible_reduct_guarded.vp` (`c0`) guards the first input. The same route finds the receipt forgery in `junglegym_threshold_ring.vp`, now `c1c0c0a1a1a1u0u1u1f0f1e1e1` at both counts.

The replayable-first-flight notice is emitted only when `emit_query_result` records that subtype, after acceptance and precondition checks. Announcing it while classifying an installed sibling value could describe a duplicate even when the recipient rejected it and the query held (`threshold_sign.vp`). `duplicate_notices_belong_only_to_recorded_acceptances` checks that refusal and a real replay, including repeated reporting. The separate `origin_only` set is gone: the existing result-write gate already emits each verdict once.

The solver regressions `solver_rewrite_matching.vp` and `solver_weak_oracle.vp` both report `c1` at one and two sessions. The former needs the second commutative key alignment to satisfy the nonce as well; `solver_rewrite_matching_guarded.vp` keeps the first input honest and holds. The latter steers a hash oracle into the exact term declared `weak`, so its MAC argument becomes recoverable; `solver_weak_oracle_strong.vp` withholds the weakening and holds.

"Known to the attacker" is not "forgeable by the attacker" — `aead_replay_not_forgery.vp` and `piknik.vp` hold that down. `run_model` prefixes `examples/test/`.

CI runs clippy, `cargo test --release` and the exhaustive sweeps on Ubuntu and macOS plus a wasm clippy job; one warning fails the build. **CI only runs when the commit title contains `[ci]`** (or on manual dispatch). Formatting is not gated in CI, so keep the tree formatted with `make lint`.

```sh
cargo run --release -- verify examples/simple.vp             # full analysis
cargo run --release -- verify path/to/model.vp --result-code # appends the compact result code
cargo run --release -- verify path/to/model.vp --format html > report.html  # self-contained report
cargo run --release -- verify path/to/model.vp --format tex > report.tex    # LaTeX; tectonic report.tex
cargo run --release -- verify path/to/model.vp --sessions 1  # single-session; default is 2 per principal
cargo run --release -- verify path/to/model.vp --saturate    # raise k until the verdicts stop moving
cargo run --release -- verify path/to/model.vp --auto-queries # replace the queries block with a generated one
cargo run --release -- pretty path/to/model.vp               # canonical formatter, to stdout
VERIFPAL_SOLVE_DEBUG=1 cargo run --release -- verify m.vp    # log every solver proposal to stderr
```

`verify` takes several models at once. `--result-code` only suppresses the banner; the code is the **last** line (`… | tail -1`), and is refused beside `--format json|html|tex`. `--fail-on-attack` makes a found attack a nonzero exit; `-q`/`-v` and `--color` are the remaining flags. Other subcommands: `about`, `diagram <model>` (mermaid), `lsp`, `completion <shell>`, `man` (hidden). `internal-json` is **gone**, replaced by `verify --format json`. The json, html, tex and LSP outputs all come from `src/report.rs`; `verifpal-vscode` and `verifpal-nvim` are thin clients of it.

Errors carry a `Span` into the model source and render as a Rust-style diagnostic; `or_span` keeps the narrower span, and `.located(file_name, &model.source)` makes plain `Display` show the position. `VERIFPAL_SOLVE_DEBUG` is the first thing to reach for when an active-attacker result is wrong: it prints each proposal as `[solve] <Principal> ran=<bool> [slot=value …]`, including the ones `validate` rejected.

## Crate layout and features

- One crate: lib `verifpal` (`crate-type = ["cdylib", "rlib"]`) + bin (`src/main.rs`, needs the default `cli` feature). `main.rs` is CLI only; every stdout write goes through `out!`/`outp!`, which ignore a closed pipe rather than panicking.
- **Every engine module is `pub(crate)`**; the public API is what `lib.rs` re-exports. `#![warn(unreachable_pub)]` and `#![forbid(unsafe_code)]` are on — the soundness argument is about what the code can reach.
- No `tests/` directory: an integration-test target collides with the `cdylib` on one artifact name. End-to-end model tests live in `src/model_tests.rs`.
- Features: `cli` (default; clap, colored, ureq, `lsp`), `lsp`, `wasm` (`wasm_verify`/`wasm_pretty` return JSON strings, buffering output through `info::wasm_messages_*`).
- `parallel.rs` is the one seam onto rayon, `cli`-only with a sequential twin for WASM — **change one, change the other**, and run the wasm feature check. `map_ordered` returns results in input order; `VERIFPAL_THREADS=n` sets pool size, `=1` is the sequential engine (`an_analysis_is_identical_under_one_thread_and_many`). **A worker only evaluates**: it never calls `learn`, `attacker_put_with`, `attacker_note_reuse`, `emit_query_result`, `defer_replays`, `note_depth_cut`, `note_replication_rejection`, `analysis_count_increment`, `ctx.replayed` or anything in `info`, so learning order — and with it the primary derivation routes the coherence gates follow, and the traces — is the sequential engine's. `VerifyContext` is interior-mutable and `Sync` (`everything_a_worker_borrows_is_sync`).
- Thread-local term caches (`REWRITE_CACHE`, `CONES`) are `context::Generational`: a cache clears itself on the first touch under a generation other than the one it was filled in, which is what keeps one model's constants — same ids under another model's names — out of another's rewrites where a pool outlives the analysis (the LSP, the tests). **An analysis parallelises internally only while it is the only live one**: `map_ordered` runs on the calling thread when `live_generations() > 1`, since several analyses in one process are already the parallelism. `NEEDS` and `ANY_TAINT` keep the `Arc` they were computed from; `MEMO` is installed and restored per `DeductionMemo::scoped`.
- Release profile: `opt-level = 3`, fat LTO, 1 codegen unit, `panic = "abort"`, `strip = "symbols"`. Always work with `--release`.

## The Verifpal language (enough to write test models)
```verifpal
attacker[active]                    // or passive

principal Alice[
    knows public c0                 // also: private
    generates a                     // fresh value
    ga = PUBKEY(a)                  // public key from a private value
    k  = DH_KEX(gb, a)              // DH_KEX(PUBKEY(b), a) == DH_KEX(PUBKEY(a), b)
    generates n                     // an AEAD nonce: reusing one under a key is what the engine watches for
    e = AEAD_ENC(k, n, m, ad)
    x, y = SPLIT(CONCAT(m, n))      // multi-output primitives bind several constants
    s1, s2, s3 = THRESHOLD_SPLIT[2](k)  // t-of-n sharing; the bracket is t, the outputs are n
    p = THRESHOLD_SIGN(s1, n, cl, m)    // a FROST partial; THRESHOLD_JOIN(p, q) is SIGN(k, m)
    _ = HASH(m)                     // `_` is an anonymous constant (becomes unnamed_N)
    leaks something                 // hands value to attacker
]

Alice -> Bob: [ga], n, e            // [x] = guarded: attacker cannot replace it
                                    // `→` (U+2192) is accepted in place of `->`

phase[1]                            // phases must increment by exactly 1

principal Bob[
    d = AEAD_DEC(k, n, e, ad)?      // '?' = checked: failure halts this principal
]

scenarios[                          // optional, and it must come before `queries`
    Alice[gpeer = gb]               // run 1: Alice's peer is Bob
    Alice[gpeer = gm]               // run 2: Alice's peer is Mallory
]

queries[
    confidentiality? m
    authentication? Alice -> Bob: e
    freshness? x
    unlinkability? a, b             // ≥2 distinct constants
    equivalence? k1, k2             // ≥2 distinct constants
    // queries take an optional option block, e.g.:
    // confidentiality? k[ precondition[ Client -> Server: req ] ]
    // which restricts the query to executions in which that message is sent
]
```

Constraints enforced by the parser and `sanity.rs`:

- Nothing may follow the `queries` block, which must exist and come last. At most one `scenarios[…]`, directly between the last principal or message and `queries`.
- ≤128 principals (`MAX_PRINCIPALS`). Principal names are title-cased, every other identifier lower-cased, so the language is case-insensitive.
- Argument restrictions are declared per primitive (`argument_restrictions`, each with its error note) and enforced generically: no public key as `DH_KEX`'s second argument or `PUBKEY`'s argument, no `DH_KEX` inside `DH_KEX`, no `DH_KEX`/KEM term or public value where `KEM_ENCAP`/`KEM_DECAP` expect a key.
- Primitive names resolve case-insensitively against the registry, which fixes arity, output count and whether `?` is allowed.
- A model file's name must end in `.vp` and be ≤64 characters.
- Constants cannot shadow reserved words: `parser.rs::RESERVED`, every primitive name, plus any name starting with `attacker` or `unnamed`. `queries` and `scenarios` are keywords.
- A constant cannot be assigned twice, generated twice, `knows`n two different ways, sent by someone who does not know it, or received by someone who already knows it. `leaks` requires the leaker to know the value. `_` may name only an assignment's output. `nil` cannot be the subject of `confidentiality?` or `freshness?` but may be compared in an `equivalence?`.
- Authentication queries are validated at load time: the sender must know the constant, the recipient must receive it and *use* it inside a primitive. A `precondition[P -> T: d]` must name a message the model sends. `sanity_capabilities` rejects a capability the primitive does not declare, or a `from phase N` the model never reaches.

Primitives (arity → outputs), all 25: ASSERT(2), CONCAT(2–5), SPLIT(1→1–5), HASH(1–5), HKDF(3→1–5), AEAD_ENC/AEAD_DEC(4), ENC/DEC(2), MAC(2), PUBKEY(1), DH_KEX(2), SIGN(2), SIGNVERIF(3), PKE_ENC/PKE_DEC(2), THRESHOLD_SPLIT(1→2–16), THRESHOLD_JOIN(2–16), THRESHOLD_SIGN(4), RINGSIGN(4), RINGSIGNVERIF(5), BLIND(2), UNBLIND(3), KEM_ENCAP(2→2), KEM_DECAP(2). `SHAMIR_SPLIT`/`SHAMIR_JOIN` are the old names; `RENAMED` turns them into a diagnostic naming the replacement. Only primitives with a `definition_check` — ASSERT, SPLIT, AEAD_DEC, SIGNVERIF, RINGSIGNVERIF, KEM_DECAP — may take `?`. ASSERT, CONCAT and SPLIT are *core*: they live in `CORE_SPECS`, reduce through hand-written Rust, and several theory functions bail out on them (`primitive_is_core`). Everything else is data.

**Capability parameters.** A call site may carry bracketed weakening assumptions: `PUBKEY[weak](a)`, `SIGN[forgeable](sk, m)`, `AEAD_ENC[weak, forgeable from phase 2](k, n, m, ad)`. `from phase N` means *from N onward* and binds to the preceding capability; absent it, the capability holds from phase 0.

- `weak` — confidentiality is lost. Declared by `weak_reveals`/`weak_reveals_output`: `HASH` (every argument), `AEAD_ENC`, `ENC`, `PKE_ENC` (plaintext), `KEM_ENCAP` (shared secret), `PUBKEY` (the private key; the DH cascade falls out of `can_reconstruct_primitive`, `cap_weak_pubkey_dh.vp`).
- `forgeable` — authenticity is lost. Declared by `forgeable_secret`: `SIGN`, `MAC`, `RINGSIGN`, `AEAD_ENC`. `cap_forgeable_aead.vp` keeps it apart from `weak`.
- `malleable` — the ciphertext can be reshaped into another the recipient accepts, under a key the attacker never learns. Declared by `malleable_vary`: only `ENC` (position 1). It needs **two** cooperating halves, `solve_by_malleability` as a goal and `malleable_positions` as the derivability exemption. `cap_malleable_enc.vp` against `cap_malleable_absent.vp` (`a1` against `a0`); `cap_err_aead_malleable.vp` and `cap_err_malleable_unsupported.vp` pin the errors.

`weak`, `forgeable`, `malleable` and `from` are **contextual keywords**, deliberately absent from `RESERVED`, so a model may use `weak` or `from` as a constant name.

**Threshold parameter.** The same bracket carries a bare number on a primitive whose spec declares `threshold`: `THRESHOLD_SPLIT[3](k)`, mixing with capabilities as `[3, weak]`. It is **required** there and refused everywhere else (`err_threshold_missing.vp`, `err_threshold_on_hash.vp`, `err_threshold_twice.vp`, `err_threshold_one.vp`, `err_threshold_above_shares.vp`). It lives on the term as `Primitive.threshold` and is part of identity — `primitive_hash`, `equivalent_primitives` and `structurally_identical_primitive` all read it — so a 2-of-n and a 3-of-n split of one secret are different values whose shares never combine (`threshold_thresholds_are_distinct.vp`). `n` is not on the term: it is the output count at the assignment, capped by `MAX_SHARES` (16).

Comments (`//` and `/* */`) are captured into AST nodes so `pretty` round-trips them; a comment inside a bracket or argument list attaches as a leading comment of the statement being parsed. Primitives nest at most `MAX_NESTING` (64) levels; deeper is a parse error rather than a stack overflow.


## Architecture

### Pipeline

```
parse_file (parser.rs)              hand-written recursive-descent, comment-preserving AST
  → expand_scenarios (scenario.rs)  one model copy per declared peer scenario
  → expand_sessions (sessions.rs)   k copies of that, one per concurrent session
  → sanity (sanity.rs)              model validation; drives construct.rs
      → construct_protocol_trace    "km": ProtocolTrace — global immutable protocol description
      → construct_principal_states  one PrincipalState per principal
  → VerifyContext::new (context.rs) shared mutable state for the whole run
  → verify_passive (verify.rs) | verify_active (solve/mod.rs)      per phase
  → verify_end                      prints results, returns the results code
```

`verify::analyze(&Model)` is the **one** place that sequence exists; it is `analyze_sessions(m, DEFAULT_SESSIONS)`, and the wasm entry points and the LSP call it too — **do not give one entry point its own default.** Throughout, `km` is the `ProtocolTrace` and `ps` a `PrincipalState`.

### Parallel sessions (sessions.rs)

`expand_sessions` is a *front-end*: it clones every principal and message block `k` times **before** `sanity`, so the expanded model is one the user could have typed and inherits the engine's attack-soundness. `generates` constants and assignment outputs get per-session copies (`c#s`, one index over the scenario-by-session grid; `MAX_COPIES` 30, so `s*k <= 31`); `knows` constants stay shared. Each query is kept verbatim (session 1) and given per-session **variants** resolving the same `query_index`.

`authentication?` is **injective**: a received value equal to a session sibling's honest wire value is a cross-session replay, and a replay is an authentication failure even though nothing was forged.

- `session_sibling_replay` makes the narrator say "replays" rather than "replaces"; `copy_siblings` groups copies across **both** expansion axes so `copy_sibling_replay` can label a cross-scenario replay. It runs **after** `emitted_by_matching_run` declines, never before, so the copy axis relabels but never moves a verdict (`scenario_replay_is_a_replay.vp`). `sibling_flight_substitutions` stays on the session axis.
- **Expansion clones are runs, not agents.** `install` stamps `ATTACKER_ID` whenever a delivered value differs from the recipient's pristine expectation, conflating *rerouting* with *authoring*; `agreement.rs::emitted_by_matching_run` undoes that by finding a trace slot with the same base constant, created by a run **interchangeable with** the declared sender and sent to the recipient's own agent, then *re-executing that run* with this recipient's flight routed in. Only re-execution decides — over `attacker_can_derive`, `TermBound` and `Controllable` — so a bug costs a reported attack and cannot invent a hold. `Emission::emits` compares installs and target in full on a memo hit, since a wrong `false` is a false attack. The pristine-sibling replay is tested first.
- **A binding separates two clones only for the values that depend on it.** `interchangeable_for` asks, per slot, whether the resolved value mentions anything the scenarios rebind (`scenario_bound`); comparing whole binding sets withdrew the exemption from every clone (`scenario_binding_is_not_a_forgery.vp`), and canonicalising by base name would excuse Lowe's attack. The recipient side is matched by **agent**.
- The exemption excuses nothing the attacker could produce alone: `forgeable_without_sender` removes every read off the sender's runs, transitively, and a still-`derivable` value is a forgery (`matching_run_forged_unguarded.vp`). Only **assignment outputs** are removed (`matching_run_leaked_generated_key.vp`). Past the gate are three routes, each a re-execution of the sender's run: **mirror** (install what the attacker handed *this recipient*, `delivered_to`), **record** (install the tainted diffs recorded against the value, only where it was `Obtained` at the sender's own slot), and **routing** (the original sibling flight).
- **A duplicate is reported, never silenced, and labelled.** `Subtype::DuplicateAcceptance` where the value carries something the recipient generated (`recipient_contributed`); `Subtype::ReplayableFirstFlight` over a first flight it contributed nothing to. Suppressing the second silences forty verdicts, among them the 0-RTT replay of `tls13-0rtt.vp` that RFC 9846 §2.3 names.
- The `original ≡ value` guard runs first in `query_authentication_get_pass_indices`, so a value with no per-session freshness never reaches the sibling test. `--sessions 1` cannot report a replay at all, and is where the "this is not a forgery" models pin their claim (`a_false_attack_pin_survives_at_one_session`); `k = 1` skips expansion and is bit-for-bit the pre-sessions behavior (~4.4s over `examples/test/` against 79s at two).
- At `k > 1` the active search runs two passes (`prefer_replication` / `replication_only` / `replication_rejected`): the first refuses any proposal whose term the principal itself produced *and* that carries its own fresh value (`replays_own_freshness`); the second drops the flag only if something was refused and queries remain. Ordering only — it can neither find nor lose an attack. Fifty-five analysing models answer differently at one session and two; re-measure both corpora before touching the default.

### Causal availability (reexec.rs)

Deriving a term is not holding it *in time*. `attacker_phase_update` publishes every wire value the phase reaches before any principal runs, which lets one run's traffic be routed into another regardless of block order — but would also let a check be satisfied by a message the protocol sends only *because* that check passed (`atemporal_forward_value.vp`). `available_before_receive` finds the earliest delivery of a slot to the executing principal and `held_at` restricts knowledge to what is available there; deliveries and guard checks share this one filter, differing only in the position they ask about. `influenced_from` is the fixed point over send events that decides which trace slots are **blocked** for that position. The rules that are not obvious from the code:

- Block by **disclosure**, not declaration: a key declared early but leaked only after the attacked check must not forge it (`causal_late_leak.vp`). `nil` and public constants are excepted.
- Judge a guard bypass at the **check's own** `declared_at`; restricting the whole execution by the installed slots' orders lost `noise_xx_mutual.vp`, whose message-3 forgery legitimately spends a message-2 disclosure. Recorded bypass decisions carry the position so a recall re-judges them identically, **in both directions**.
- `restrict_known` must **follow the primary derivation** (`reachable_knowledge`), not compare against pristine trace values (`later_value_fed_back.vp`), keeping only terms grounded in unblocked reads and ingredient-free constructions. `validate.rs` re-runs its own `derivable` against the restricted state, so a genuinely buildable term is still admitted.
- **A slot is substitutable once per delivery, in that delivery's own phase.** `SlotMeta::delivery_phases` records the phase per recipient — for a guarded delivery, the phase at which its sender's copy could be chosen, so a relay is judged by the open leg it stands for (`phase_relay_guarded_delivery.vp`). `install` stamps the chosen phase and `mutation_reaches` hides the value from any recipient delivered before it, so `compute_visibility`, `state_mentions` and `symbolic::reaches` narrow together (`phase_second_delivery.vp` against `phase_second_delivery_later_leak.vp`).
- Caches key on position and `KnowledgeKey`; knowledge size alone is not an identity. Clones never message each other, so no cross-copy edge exists. Across `examples/` the guard moved two verdicts to `a0` (`later_value_fed_back.vp`, `scuttlebutt.vp`'s `secretBox1Bob`) and the disclosure rule moved `signal_small_leaks.vp`, `signal_small_leaks_bob.vp` and `signal_small_nophase.vp` to `c0` at one session only. `probe_with` applies the same order to each install it grounds.

### History coherence (reexec.rs::Coherence)

Attacker knowledge is global and monotone and a re-execution installs into a pristine state, so one substitution can supply the knowledge while a *different* execution of the same principal supplies the values it is spent on (`incompatible_histories.vp`). `Coherence::of(km, ps)` records, per slot received from someone else, the value its creator honestly produces; `compatible` walks attacker knowledge in learning order and refuses an `Obtained`/`Leaked` at such a slot whose term is not the one being handed over. `VerifyContext::coherence` caches one per principal under the knowledge `Saturation` it was built against, which is what makes its pointer-keyed memos exact.

- `validate.rs` uses the restricted state both for derivability **and** as the state `reexecute` runs against; the second half is not optional, because `try_guard_bypass` is what spends the incompatible value.
- **It has to be the derivation, not the `MutationRecord`.** A record is an ambient snapshot, not a set of necessary conditions: reading its diffs as preconditions costs `kem_direction_reflection.vp` its reflection and `forged_statement_rebuilt.vp` its `c1`, and reading only the `tainted` diffs is not the fix either.
- `execution_agrees` covers what `forwards` cannot see — the revealing message went to a third principal — by re-executing every principal the target is handed values from under the diffs observed in that principal's own state (`history_incompatible_knowledge.vp` against `history_compatible_oracle.vp`).
- Three conditions keep it narrow: the slot must be one the principal **receives from another principal**; the read must have happened in the run of the slot's **creator** or in another run of the **executing principal itself**; and it is skipped where the proposal installs an **attacker-authored** value there — but *not* where it reinstalls the honest value, which is a forward by another name (`incompatible_histories_mitm.vp`).
- That skip let a run's **own later emission** come back to it. `validate.rs::spends_another_execution` refuses an install whose cone-filtered needs (`deduction::needs_of`, recursing into the arguments of a term the attacker does not hold outright) name the executing principal at one of its **receive** slots with a value different from what this execution puts there. `history_own_later_emission.vp` (`a0`) against `history_own_early_emission.vp` (`a1`); keying to receive slots keeps a run's own outputs, which every cross-session routing reads, from counting against it.

### Execution coherence in the closure (deduction.rs::combination_coheres)

The closure reads global knowledge, so a derivation closing entirely inside it meets neither of the filters above and could combine a value read out of one execution of a run with one that exists only in another. `learn` refuses such a combination: it collects the reads each ingredient bottoms out in (`Obtained`/`Leaked` leaves with the tainted substitution each was recorded under), merges those substitutions, then refuses outright if two reads need **different values at one slot of one principal**; passes without a replay if the union is empty or uniform; otherwise replays the union (`replay_diffs`) and requires every read recorded under a different substitution to be *reached* there — slot held, not behind a foreign halt, emission not withheld by the reader's own halt (`withheld_by_own_halt`). A union whose seeds cannot execute is refused (`closure_cyclic_union.vp`). Re-execution decides, so a bookkeeping error costs a deduction and never invents one.

- **The walk follows primary routes only, and that is order-dependent**: `closure_cyclic_union.vp` at two sessions is `c1c1c0` as written and `c1c1c1` with `z` asked first. Retrying along alternate routes was built and reverted — it re-admitted `history_closure_incompatible.vp`'s pinned false attack even with equality required in the replay — so the refusal is doing soundness work the replay does not. The `rotate` property runs at one session, where every order agrees.
- A `SlotDiff` carries the **state** it was observed in and a need is `(principal, slot, value)`, so an execution handing Bob `t1` and Carol `t2` over one slot is one execution (`closure_two_recipients.vp`). A read's preconditions are keyed to the slot's **creator**, whatever state it was read from. The union is the reads' cone-filtered needs plus the current state's ambient, never the whole record of every visited term.
- For the reads to be *found*: `collect_reads` follows the arguments the `obtainable` cascade rebuilt keys in place from (`ReconstructResult::from`, `DecomposeResult::used`), and `read_preconditions` follows each installed value in a read's cone into that value's own reads, since **an install is a boundary provenance did not cross**. The cone of a wire or leaked read runs up to the **emission** (`emitted_at`), not the declaration (`closure_halted_send.vp`).
- Where one slot needs different values at different principals, the minimizer offers **addressed installs** (`witness.rs::Addressed`, a fourth `LADDER` rung tried only after the three shared-install rungs found nothing).

### Forward execution (reexec.rs::execute_forward)

Atomic replay cannot express a value whose only route to its recipient is the sender computing it. `execute_forward` runs the chosen principal, delivers every message it sends *as it came out* and runs those recipients too, to a fixed point bounded by the principal count; only an emission *differing* from the honest value is delivered (`attacker_authored`). This is what lets the minimizer pick the *origin* principal as a witness base and have the query resolve downstream.

- A forwarded value is justified by the sender having sent it, not by derivability, so `forwarded_installs` checks the send event, the phase, and that the sender reached the send without halting before the slot (`a_forwarded_value_is_only_ever_what_its_sender_sent`).
- `install_forwarded` sets `attacker_tainted` and nothing else. Taint makes the slot a **precondition** of whatever is learned downstream (without it `piknik.vp`, `ringsign.vp` and `mutual_auth_both_directions.vp` reported false attacks); `sender`, `creator` and `original` stay honest (`forward_emission_is_not_a_forgery.vp`). Pure forwarders are controllable.
- A forwarded state is unfaithful about the sender's private slots, so `PrincipalState::forwarded` gates `query_start` through `answers_for` — it answers only over constants it legitimately holds (`precondition_foreign_halt.vp`). Gating every state on `known` instead lost `concat_bomb_equiv.vp`.

### Peer scenarios (scenario.rs)

`scenarios[…]` instantiates a principal's counterparty differently across concurrent runs, making the role-confusion family (Lowe/Denning-Sacco) expressible. It is a **front-end expansion** run *before* session expansion, so `p` principals with `s` scenarios at `k` sessions analyse `p*s*k` principals. An entry binds constants inside **one** named principal, and scenario *k* is clone *k* of the whole model with only that principal's bindings substituted — N scenarios are N configurations, **not** a cross product. The bound `knows` declaration is dropped and the constant replaced everywhere in that principal, then freshened like any expansion copy (`gm@2`). `sanity_scenarios` rejects an undeclared principal, a target it does not `knows`, an undeclared value, a target bound twice, and a target that travels over the wire. An identity binding is a genuine no-op that two metamorphic properties rest on, and both `peer_binding_key` and `scenario_corrupt_from` skip one (`scenario_identity_binding_keeps_the_error.vp`).

**Corruption is inferred, not declared, and it is two questions.**

- `compromised_constants` — what the attacker can *compute*: seed from every secret (`generates` or `knows private`) leaked or travelling bare on a message, at that statement's phase, then close over assignments it could actually build (`computable_from`), where every constant must be `nil`, public or already compromised and the assignment is dated at the *last* of them (`scenario_corrupt_needs_every_ingredient.vp`).
- `scenario_corrupt_from` — whether a bound value *identifies* a peer the attacker controls, which is not computability: a certificate is signed by a CA, but one naming a key whose private half leaks is a corrupt peer all the same, so a binding is corrupt where the bound value is compromised **or** where the assignment it names mentions something that is (`scenario_corrupt_by_certified_key.vp`). Reading this question as the first made every scenario in `tls13.vp` honest and turned its client's hostname check, which is *supposed* to fail in the Mallory run, into a model error.

A scenario binding a compromised value is a **corrupt-peer run**, deciding two separate things. `is_honest` gates the **honest-run check**: a corrupt-peer clone legitimately fails a checked primitive, so `generate_trace` partitions failures by the failing slot's *creator* and raises `sanity_fail_on_failed_checked_primitive_rewrite` only for honest creators, the suppressed ones still halting through `halt_at_failed_checks`. `claims_apply_to` gates **query evaluation** (`query_start` returns before touching a corrupt run's state), the analogue of Scyther's `prune_theorems.c:439`; because a *confidentiality* break first noticed inside a corrupt run must still be reported against the honest ones, both verifiers re-run `verify_standard_run` once at the end of each phase when relativisation is in force and queries remain. Both read the same set but differ where it is `Some(empty)`: the honest-run check stays relaxed, query evaluation does **not**. `honest` is `None` with no `scenarios[…]`, and every predicate answers `true`.

- **Phase seeding is reachability-aware, and both halves are load-bearing.** `honest_run_halts` derives the earliest failed checked slot per creator and `attacker_phase_update` withholds every wire or leaked slot at or past it; withholding **alone** loses attacks, because a substitution can make the check pass (`spore_ns_pk.vp`'s `m3@2`), so `attacker_absorb_disclosed` re-publishes exactly the withheld slots *this* execution reached. `scenario_post_halt_no_oracle.vp` and `scenario_post_halt_leak_no_oracle.vp` (`c0`) against `scenario_pre_halt_oracle.vp` (`c1`).
- Queries **are** cloned per scenario, one `variants` entry per *honest* scenario, session-cloned after; a corrupt scenario gets none. The block is **normalised honest-first**, or a corrupt scenario 1 makes the written query unfalsifiable (`scenario_order_is_not_a_verdict.vp` against `…_swapped.vp`). Compromise is **phase-indexed** (`scenario_peer_compromised_later.vp` against `…_throughout.vp`).
- `spore_ns_pk.vp` (`c1a1a0`, Lowe's attack, found rather than assumed) against `spore_nsl_pk.vp` (`c0a1a0`) separating is the acceptance criterion for the feature. Do not add a scenario-free variant of either to `examples/`.

### Verdict envelope

Every `VerifyResult` carries an `Envelope { sessions, truncations }`, printed after a PASS line (`[search exhausted at 2 sessions]` / `[search truncated: term depth]`) and serialized into `QueryReport.envelope`. An attack is never qualified by the envelope, but may carry a `Subtype` (`AttackerSuppliedValue`, `DuplicateAcceptance`, `ReplayableFirstFlight`) printed as a bracketed qualifier on the FAIL line. `Note:` lines live in `VerifyResult.notes`; a `--auto-queries` query has no span and `QueryReport.generated` says so. Both are omitted from JSON when empty, so the contract is additive. `Truncation` has one variant, `TermDepth`, recorded **against the queries still unresolved at that moment**; `finalize_envelopes` stamps each result with only the truncations that could have cost it.

**"Exhausted" means the search space this engine defines was fully explored at these parameters, never that no attack exists.** Never let "proof", "verified", "correct" or "complete" into this output.

### `--auto-queries` and `--saturate`

`autoquery.rs::auto_queries` **replaces** the model's own block after `sanity` has validated the model as written. Three rules, each mirroring a sanity constraint (`generated_queries_all_pass_sanity` sweeps the corpus): `confidentiality?` for every `generates` and `knows private` constant with a trace slot; `authentication? S -> R: c` for every wire delivery whose recipient uses `c` inside a primitive; `freshness? c` for every constant actually sent and used. `unlinkability?` and `equivalence?` are skipped.

`saturation_sessions` raises `k` from `DEFAULT_SESSIONS` to `SATURATE_MAX` (4) and stops at the first count whose result code equals the previous one, returning that count's **analysis**. It starts at the default rather than one because an attack needing three runs leaves one and two reading alike (`saturation_never_stops_before_it_has_looked_above_the_default`). `attack_disappeared` warns if an attack vanishes at a higher count, which is an engine bug.

### Core data model (types.rs)

- `Value` = `Constant` | `Primitive(Arc)`. Constants are interned per model (`nil` is id 1); equivalence compares ids. DH uses ordinary `PUBKEY(sk)` and `DH_KEX(pk, sk)`, and commutativity is declared by `PrimitiveSpec::commutativity`, consumed generically by `equivalence.rs`, `hashing.rs` and `solve/matching.rs`.
- **Invariant: `a.equivalent(b)` ⟹ `a.hash_value() == b.hash_value()`** (`hashing.rs` uses a commutative hash for DH exponents). `AttackerState::knows()` looks up by hash bucket first, so breaking this silently breaks attacker knowledge. Unit tests pin it.
- **Terms are DAGs, and anything that walks or rebuilds one as a tree is exponential in its sharing.** A TLS transcript hash holds the previous one twice, a dozen levels deep, so a term of a few hundred nodes is a tree of hundreds of thousands. `vars::apply`, `ground_free_as` and `resolve_trace_value` memoise per call on the input `Arc`; `Value::equivalent` and `structurally_identical` record pointer pairs already found equal for the outermost comparison (`memoised_pair`). `tls13.vp` did not terminate in a day before these. Confidentiality subtype classification also uses the existing DAG-aware `constant_leaves` iterator, following constant aliases with its cycle guard; the 40-layer regression checks public terms, secret-bearing terms, aliases and cycles. A local release benchmark on 2026-09-08 over a 24-layer shared public term gave median classification time 65.0 ms → 4.7 µs across three interleaved runs; this measures that predicate, not whole-model analysis. A `Primitive`'s `HashCell` makes `hash_value` O(1) and caches whether the term contains a solver variable; the single in-place mutation (setting a multi-output `output` index) clears the hash and leaves the flag.
- `Primitive.capabilities` is deliberately **not** consulted by `primitive_hash`, `equivalent_primitives` or `structurally_identical_primitive`: an annotated term and its twin are the same object (`cap_noop_annotated.vp` against `hmac_ok.vp`). The engine reads capabilities from the `CapabilityIndex` on `PrincipalState`, **never** off a held copy, because `AttackerState` dedupes by equivalence. `construct.rs` inserts each annotated call three ways — as written, resolved, and resolved then reduced — or a call whose argument reduces missed the bucket (`cap_weak_on_reduced_argument.vp`, `cap_forgeable_on_reduced_key.vp`); `can_break_weak` and `can_decompose` reduce what they reveal for the same reason.
- `SlotValues` holds **three values per slot**, the most important invariant in the engine: `original` (what the protocol honestly computed, what the principal *believes*), `pre_rewrite` (after mutation, before rewriting), `value` (after mutation and rewriting; what analysis uses). `should_use_original`/`effective_value` and `compute_visibility` decide which a principal sees; getting this wrong causes false authentication attacks. `bypassed` holds the key a defeated guard was made to accept.
- `Provenance` rides alongside: `creator`, `sender` (`ATTACKER_ID` = 0 when injected), `attacker_tainted`, `bypass_injected`. The last two are **deliberately separate**: taint decides what a principal perceives and a guard bypass must not change that, but the substitution must still be reportable.
- `SlotMeta` is the immutable half: `constant`, `guard`, `known`, `wire`, `mutatable_to` (recipients it reached *unguarded*), `known_by`, `declared_at`, `sent_at`, `phase`. `halted_at` records the `declared_at` of the earliest checked-primitive failure after mutation; `reexec.rs` sets it and truncates there.
- `AttackerState`: append-only `known` + hash index + `mutation_records` and `derivations` parallel to it, plus `alternates` (every further `Route` that *reads a state* to a term already held), `routes_epoch` (bumped when a primary derivation or record is replaced, so memos keyed by knowledge length stay exact when knowledge does not grow), and `chain`, a process-unique id per state built from nothing. **A thread-local memo keyed by knowledge length is exact only within one chain** — the minimizer's scratch context grows a second chain on the same thread — so `pair_vetted`, `origin_leaves`, `forgeable_without_sender`, `Emission::key`, `ctx.replayed` and `held_at` all carry `chain`. Derived routes are not retained (a `Fragment` route per `CONCAT` took `concat_split_replay.vp` from 4.5s to 53s), and the causal and history filters follow the primary route only: letting any recorded route stand in returns three pinned false attacks. A `MutationRecord` is the slot diffs that had to be in force, plus principal and phase; a `DerivationRecord` says *how* (`Initial`, `Leaked`, `Obtained`, `Decomposed`, `Reconstructed`, `Recomposed`, `Fragment`, `Rewritten`, `Broken`, `Reused`, `ReusedForge`, `Combined`). Narration walks this DAG, so **a rule that adds knowledge without recording an honest derivation produces an unexplainable trace.**
- The rewrite cache uses `RewriteCache`: a weak input key, a result whose unchanged-value case owns no `Arc`, and a bounded window of 1024 recent inputs. Eviction affects recomputation only, never the search space.
- `value::subterms` visits each shared primitive pointer once in first-encounter order and is the walker for hash, solver-variable and constraint collection, unlinkability's shared-subterm search, narration's `constant_leaves`, `shadowed_names`, the `admissible` check, `collect_slot_references`, and the validator's `contains_failed_check`/`carries_own_fresh`. `Value::constant_leaves` feeds the freshness, recipient-contribution, scenario, dependency-cone and secrecy checks; the public `collect_constants` stays occurrence-preserving. Repeating an identical subgraph cannot change an existential answer, add a restriction violation or add a graph edge — but a failed check behind a shared prefix must still be found, and slot-reference collection keeps each slot's dependencies in original order. **Subterm collection must not prune on a repeated term hash**: equivalent DH terms have different public-key subterms, and distinct terms can collide. Pinned by the 40-layer shared-transcript tests, `shared_transcript_metadata.vp` (`c0f0`) and `shared_transcript_search.vp` (`c0`). This bounds metadata walks, not rendered output: `NameTable` can still expand a shared term into exponentially large text (a fourteen-layer example produced a 215 MB report).
- Grounding preserves a variable-free subgraph's `Arc`, including inside a term whose other branches contain free variables. Rebuilding an unchanged transcript for every proposal discarded sharing between proposals and the cached hashes on its nodes. `grounding_reuses_ground_subgraphs_between_proposals` checks that different fillers keep the same transcript while receive variables remain unbound.
- `NameTable` stores names in term-hash buckets, preserving insertion order within each bucket and checking full equivalence before choosing a name. Construction and lookup no longer scan unrelated terms. Hash collisions, alias order, exclusions and preferred names remain distinct cases (`name_table_disambiguates_collisions_and_preserves_alias_order`).

On 2026-09-08, five interleaved single-thread release CLI runs on a passive model with 10,000 named hashes and one confidentiality query took median wall time 0.601s before these grounding and naming changes and 0.262s after; CPU time was 0.57s → 0.24s. Median peak RSS was 71.5 → 72.5 MiB: the naming index trades some storage for lookup time. The same five-run comparison gave 3.152s → 3.182s for `scuttlebutt.vp` at two sessions, 0.828s → 0.821s for `simplex_smp.vp` at one, and 0.110s → 0.098s for `threshold_subset_search.vp` at two. The large gain is on name-table construction, not across all protocols.

On 2026-09-08, five interleaved single-thread release CLI runs of a sixteen-layer shared transcript followed by an unrelated authentication use took median wall time 0.752s before the `state_mentions` walk change and 0.0069s after. Median peak RSS was 11.0 → 9.1 MiB. The same comparison gave 2.140s → 2.149s for `scuttlebutt.vp` at two sessions, 0.885s → 0.884s for `simplex_smp.vp` at one, and 0.128s → 0.134s for `threshold_subset_search.vp` at two; CPU times for those three were unchanged at the timer's resolution. The gain is confined to repeated use checking, not a general protocol-analysis speedup.

### Provenance travels along derivation edges (context.rs)

`derivation_provenance` decides which `MutationRecord` attaches to a newly learned value: one **read out of a principal's state** picks up that state's ambient diffs; one **combined out of held values** inherits *their* records and adopts the session of the ingredient carrying the leverage; `Initial` gets an empty record. `attacker_state_absorb` also *upgrades* a record when the stored one explains nothing and the arriving one does; knowledge is unchanged, only the explanation.

**Cancellation has exactly one conversion point.** `VerifyContext` carries an `Arc<AtomicBool>` checked beside every `all_resolved()` short-circuit; those loops only ever *stop*, and the flag becomes `Err(ErrorKind::Cancelled)` at the foot of `analyze_sessions_traced_cancellable` and nowhere else, so an interrupted search reports nothing rather than reporting an unreached query as holding.

`VerifyContext` is the interior-mutability container shared by `&VerifyContext`. `attacker_put_with` dedupes new knowledge; `results_put` resolves each query at most once; `principal_states()` hands back pristine starting states; `scratch_for_query(i)` builds a disposable context that can only answer query `i` and cannot write back.

### Standard run (verify.rs)

`verify_standard_run` is shared by both attacker kinds — the active search uses it as its passive baseline. Per principal: **trace generation** (`generate_trace`: resolve, rewrite, sanity checks — a failed *checked* primitive here is a model error unless its creator is a corrupt-peer clone, which halts), **knowledge closure**, **query evaluation**. Closure never checks queries. Each phase resets attacker knowledge and re-seeds from `principal_states[0]` resolved and rewritten: **every** public constant plus every wire or leaked value whose earliest phase has been reached (`public_constant_is_never_confidential.vp`).

### Knowledge closure (deduction.rs)

A monotone fixed point over three rule groups, each pass running all three over a snapshot taken at its top: (1) attacker-known values — `decompose`, `break_weak`, `rewrite_build`; (2) principal-assigned values — `reconstruct`, `recompose`, `rule_rewrite_forward`; (3) attacker-known values — `equivalize`, `concat_extract`. Termination is Knaster–Tarski. Every rule ends by calling `learn`, whose message argument is a closure because minimization re-runs the closure with output suppressed. `rule_equivalize` carries one guard: if the principal halted, a `leaks` declared *after* that point never fired. A fourth step, `rule_reuse`, runs once per pass after the three groups. Recording a new reuse pair is progress even if every revealed payload was already public: it enables reconstruction under the pair's forgery exemption. `aead_reuse_public_payloads.vp` (`c1c0c0`) uses the forged term as the key to another encryption; the distinct-nonce companion stays `c0c0c0`.

- `try_deduction_step` spells the passes out in execution order — no rule table, dispatch, or `RuleDomain`/`Reads` metadata. The five rules reading the state only through its capability index run only when `knowledge_rules_saturated` says this principal has not yet seen this phase, knowledge length, recorded-pair count and `routes_epoch`; the four reading slot values run for every state. **A skipped pass is a no-op, not merely a pass producing duplicates**: every value it would learn is already held, and `attacker_put_with` on a held value records no route for a derivation that does not `reads_from_state`. Learn order does not change.
- `rule_rewrite_forward` is the one rule reading a slot's `pre_rewrite` rather than its `value`: for a principal-assigned `pre_rewrite` that `can_rewrite` reduces and whose every argument is `obtainable`, the attacker learns the reduct. For every rewrite but `UNBLIND` that reduct is already learned elsewhere, so `learn`'s dedup makes it a no-op there.
- Its attacker-side half `rule_rewrite_build` assembles a rewrite *around* a held term from values it holds (`blind_signature_attacker_unblinds.vp`), learning any reduct differing from the built term as `Rewritten { built: true }`, which `reads_from_state` treats as combined rather than read off a state. It skips a checked primitive whose fixed `RewriteTo` result is already held and which has no rebuild or combination rule — it can only fail or yield that result — which is how the two signature verifiers avoid a Cartesian product over the pinned-argument pool merely to rediscover `nil`.

State rewriting uses `theory::can_rewrite` directly. The second recursive reducer and `REDUCE_CACHE` are gone, and the remaining rewrite cache is a private concrete type. The state adapter still reports a failed outer check, retains partial argument reductions, and updates `original` exactly when the root or a descendant successfully rewrites. A failed check with no successful descendant leaves `original` alone; `failed_checks_preserve_originals_unless_a_subterm_rewrites` pins that distinction on cold and warm cache paths. The theory's existing tests retain the generation and eviction checks.

On 2026-09-08, five interleaved release microbenchmark runs over 3,000 distinct 24-layer ternary shared terms gave median state-rewrite time 28.0 ms → 11.7 ms and median process peak RSS 75.5 → 41.7 MiB. Inputs were built before timing and kept alive throughout. This isolates `PrincipalState::perform_all_rewrites`; a separate 1,000-slot passive full-analysis probe showed no material CPU-time change, so these numbers are not a whole-engine speedup claim.

### Query evaluation (query.rs)

`query_start` returns before touching a corrupt-peer scenario's state (`claims_apply_to`). Past that, each kind resolves differently, and `goals_for_query` mirrors these exactly:

- **confidentiality** — the attacker knows the slot's resolved `value`. When that value differs from the honest one and, read through the state (`carries_a_secret`), holds nothing generated or private, the result carries `Subtype::AttackerSuppliedValue`.
- **authentication** — **injective agreement**, the only mode, evaluated only while walking the recipient. Fails when the slot's `provenance.sender` is not the declared sender *and* the constant is successfully used inside a primitive the recipient computed (`query_find_constant_usage_indices`: no rewrite rule, or the rewrite passes, or unchecked) *and* no interchangeable run of the declared sender emits the delivered value. **"Used" is visibility-aware**: `state_mentions` walks shared primitive/owner pairs once, including through named definitions; the owner stays part of the visited key so an opaque occurrence cannot suppress a later visible one. `shared_transcript_usage.vp` (`a0`) puts an unrelated shared transcript before the actual use. The predicate `state_mentions` counts an occurrence only where it *reaches* the owner of the enclosing term, since walking the global trace counted a constant buried inside a blob the recipient never opened (`piknik.vp`); `sanity_queries_check_known` and `autoquery.rs` share the predicate through `principal_uses_constant`. A **substitution** and a **replay** carry the same `a1`; `session_sibling_replay` classifies and `narrate.rs` routes replays into `Step::Replay`. **A replay is reported only on a leg the attacker can touch**: where every delivery from the declared sender to this recipient is guarded (`delivery_is_guarded`), the arriving value is what the sender's own run emitted, so a value equal to a sibling's is that run's own forwarding (`relay_guarded_replay_is_not_a_duplicate.vp` against `relay_guarded_replay_open_hop.vp`).
- **freshness** — the value transitively contains no `fresh` constant yet is used in a primitive. The solver never proposes anything for it.
- **equivalence** — the queried constants do not all resolve to equivalent values, using the *mutated* value. A `forwarded` state answers only over constants it holds (`answers_for`). It first requires this state to *hold* every queried value, since comparing the placeholder a truncated slot resolves to is a divergence nobody computed (`concat_bomb_equiv.vp`, `triple_dh.vp`), and refuses a **starved** slot (`slot_starved`), since a value built from what a halted sender never handed on was never computed (`equivalence_starved_by_foreign_halt.vp`). The starved set closes over definitions across principals but is read **here only** — `slot_unreached` decides what a principal *holds*, and starving it that widely costs `spore_ns_pk.vp` Lowe's attack.
- **precondition** — `Q[precondition[P -> T: d]]` restricts `Q` to executions in which P reaches the send of `d` to T. `preconditions_reached` runs in every evaluator after the violation is detected and before `attack_trace`; an unreached send records no verdict, so the probe re-checks it through the same evaluator. Adding an option can only remove violations (the `restrict` property), nothing prints for an unreached precondition, and every renderer renders the conjunct, never an annotation. The `precondition_*.vp` models cover every query kind, a third party's halt, two recipients around a halt, several options on one query, a later phase and scenario expansion; seven `err_precondition_*.vp` models pin the rejections.
- **unlinkability** — the attacker exhibits a *link witness* for some pair of the queried constants (`unlink.rs::find_link_witness`). Both must be observable and neither slot attacker-authored. Four witness kinds, cheapest first: **observed equality**; **identifying check** (a `definition_check` primitive with a declared identifying position succeeds over both under one participant's key, and that identifier must `depends_on_secret` — `unlink_public_identifier.vp`); **common secret origin** (`origin_leaves`, withholding each value from the attacker first); **recognized secret** (`recognized_secrets`, for a term the attacker can *test* but not *recompute* — `SIGN`, `RINGSIGN` under an unheld key — following pinned arguments into their own `origin_leaves`, `unlink_recognized_nested_message.vp`). The manual's two-world definition is the specification; this is a decision procedure, sound for attacks and incomplete.

  - **The honest values must already share a secret-dependent subterm** (`share_secret_subterm`, unreduced) before any witness is looked for (`unlink_forced_origin_derived.vp`), while a MitM *revealing* a key two honest tokens already carry still links them (`unlink_active_links.vp`) and a blinding factor is shared unreduced where its reduct no longer shows it (`unlink_blind_active.vp`).
  - **A link the attacker manufactured is not a link**: an observed equality counts only where the honest values, reduced once, are equal too, and any witness whose value the attacker put on the wire is dropped (`attacker_supplied`) — `unlink_forced_equality.vp`, `unlink_forced_origin.vp`.
  - **Observable is not "this constant appeared on a wire".** `carried_observably` asks whether the value can be extracted from some wire or leaked slot **and** whether the attacker holds it — without the second half two signatures under an unbroken key link on shape alone (`unlink_carried_in_ciphertext.vp`), without the first a merely recomputed value counts (`unlink_never_sent.vp`) — and the extraction must be one the attacker could **perform** (`opened_subterm`: tuple arguments and what `can_decompose`/`can_break_weak` actually return; `unlink_sealed_carrier_not_observed.vp` against `unlink_sealed_carrier_opened.vp`). It closes under **tuple assembly only** (`observed_value`, `primitive_core_reveals_args`; `unlink_reassembled_chunks.vp`, `unlink_reassembled_by_recipient.vp`, which make `junglegym_threshold_ring.vp`'s two blind signatures `u1`). Decomposition does not expose every syntactic argument (`unlink_keys_not_carried.vp`) and a revealed projection need not be a syntactic subterm (`unlink_kem_carried_output.vp` against `unlink_kem_sealed_output.vp`). Capability extraction counts (`unlink_weak_carrier.vp` versus `unlink_strong_carrier.vp`), and so does reuse extraction, but only from a **vetted** pair with both members still held (`unlink_reused_carrier.vp` versus `unlink_distinct_nonce_carrier.vp`). Only declared `reveals` become observable, never the unrevealed key.
  - An identifying or recognized-secret witness must actually **execute** its check: `check_is_runnable` supplies every matching input from attacker knowledge, assigns distinct inner positions, and confirms the assembled check with `can_rewrite`. Pinned by `unlink_kem_secret_projection.vp`, `unlink_aead_missing_inputs.vp` versus `unlink_aead_complete_inputs.vp`, `unlink_signature_missing_messages.vp`, and `unlink_ring_missing_members.vp` versus `unlink_ring_complete_members.vp`; `KEM_DECAP` needs the private key (`unlink_kem_needs_the_private_key.vp` against `unlink_kem_leaked_private_key.vp`). A recognized-secret candidate must not be a `bypass_key` constructor application, or `RINGSIGNVERIF`'s ring members would link every ring signature (`unlink_ringsign.vp` versus `unlink_signature_links.vp`, rule pinned by `unlink_signature_recognized.vp`). `is_key_derivation` is structural: a `PUBKEY`-headed value names a participant, not a session.

When a query resolves, `attack_trace` minimizes the state (`witness.rs`) and narrates it (`narrate.rs`). A confidentiality query seeds the minimizer with the mutations recorded against the disclosed *value*, since the disclosure may have happened in another principal's execution; an authentication query seeds it with nothing, so `seeded_mutations` takes the answering state's own tainted slots and closes them over the histories of the values in them. Seeding from the *decryption result* at the use site handed the minimizer an unrelated execution's installs, and `scuttlebutt.vp`'s fifth and sixth queries came back unminimized.

### Equational theory (theory.rs + primitive/spec.rs)

All cryptographic behavior is **declarative data**. `PrimitiveSpec` entries define decompose (a rule yields a **set**, `Reveal::Argument(i)` or `Reveal::Output(i)`, and must describe everything the legitimate key holder learns — `KEM_ENCAP` reveals **both** shared secret and randomness, because ML-KEM's re-encryption check re-derives the coins), recompose, rewrite, rebuild, combine, and guard-bypass key extraction; `theory.rs` interprets them, and `obtainable` is the shared "can the attacker get this argument at all" cascade. A rule consuming a multi-output primitive names the projection (`rewrite.from_output`, `decompose.output`). Recompose and rebuild carry no share sets: both count **distinct projections of one split against that split's threshold** (`shares_of_one_split`).

- A rewrite rule's `matching` is discharged as a **bijection** — each outer position gets a *distinct* inner one. Only `RINGSIGNVERIF` has overlapping `inner_idxs`; before, a ring collapsed onto one member still verified (`ringsign_ring_collapse.vp`).
- `can_reconstruct_primitive` refuses a core primitive whose reduction is the term itself: `ASSERT` denotes a check. `SPLIT` reduces to a field and still reconstructs.
- **No recursion cap, and reintroducing one is a regression**: every `to` rule returns a subterm or reassembles strict subterms, so the descent is well-founded on depth. The memo is keyed on the term hash **alone**; keying on depth too took the suite from two seconds to six minutes.
- `can_rewrite` is the one reducer, applying `can_rebuild` then `can_combine` to the argument-reduced term before the rewrite rule; `reduce_term` is the state-walking wrapper over it. Two reducers once disagreed on a term holding a join and the minimizer preferred an honest reinstall over the real forgery.
- **To add a primitive, edit only `src/primitive/spec.rs`** — `build_primitive_specs` is the whole table and the nearest primitive is the template; core primitives go in `build_core_specs` and need a `core_rule_*`. Then model tests; nothing else. Several fields are read as *direct* slice indices (`rewrite.from`, `recompose.reveal`, `rebuild.reveal`, `bypass_key`), so `every_spec_index_is_within_the_primitive_it_is_declared_on` holds those to the *narrowest* declared arity and the bound-checked fields to the *widest*.

### Nonces (AEAD)

`AEAD_ENC(key, nonce, plaintext, ad)` declares `reuse: Some(ReuseRule { fixed: [0, 1], reveals: [Argument(2)], forgeable: [0, 1] })`, so two non-equivalent held `AEAD_ENC` terms with equivalent key and nonce are a pair; two encryptions differing only in AD count, the same message twice does not. Reuse has two consequences, faithful to AES-GCM and ChaCha20-Poly1305 and scoped to the reused nonce only.

**Recovery.** `rule_reuse` learns what the rule reveals for every member of the pair, unconditionally, which over-claims the case where both plaintexts are unknown and reality yields their XOR; that is a modelling choice. Skipped before any pair is vetted: a bucket whose fixed positions the attacker can `obtain` (it gains nothing, and every ciphertext the search forges under its own key lands there), and **a member the attacker could mint** (`attacker_mints`) — a reuse pair is evidence about the encryption function, so pairing a mint with an honest ciphertext collapsed `forgeable` into `weak` (`cap_forgeable_is_not_a_reuse_pair.vp`, and `cap_forgeable_guard_never_adds_an_attack.vp` where adding a guard moved the verdict) and on `THRESHOLD_SIGN` recovered the very share `forgeable_secret` exempts (`threshold_sign_forgeable_is_not_a_reuse.vp`). The question is asked of the term, not its `DerivationRecord`, because the attacker installs what it mints and reads it back out.

`combination_coheres` is *reached, not equal* by design and admits two values of one slot from two executions of one run; pairing those recovered `kab` in `spore_otway_rees.vp` and `spore_yahalom.vp` and forged into `injective_recipient_nonce_unchecked.vp` and `injective_routed_emission_twice.vp`. So `rule_reuse` accepts a pair only past three tests, memoised together as `pair_vetted`: `reused_pair` (shape), `theory::one_execution` (two terms resting on different values of one slot are never paired; re-run by both `tracecheck` arms), and `pair_coheres`, which is `combination_coheres` with **equality** in place of reached-ness — a replay that cannot run refuses, while a reader the replay never executes is compared against its `execution_base` (`aead_nonce_reuse_partner_unreached.vp`). A vetted pair is recorded into `AttackerState::reused`, which every snapshot carries, and `theory::reused` looks it up restricted to pairs both of whose members the snapshot still holds, so the theory, the validator and the solver never pair anything the closure did not vet. `aead_nonce_two_executions_not_a_reuse.vp` (`c0` at both counts) pins the family.

**Forgery.** `AEAD_ENC(k, n, m', ad')` is derivable from held `m'` and `ad'` with the rule's `forgeable` positions exempt, in the three places `forgeable` lives (`can_reconstruct_primitive_directly`, which reports `Forged::Reuse` so the trace names the pair; `validate::derivable`; `deduce.rs::solve_by_reuse`); the agreement gate inherits it through `derivable` (`aead_nonce_reuse_forgery.vp`). Decryption is keyed on the key **and** the nonce (`given: [0, 1]`), so a model whose attacker must decrypt has to put the nonce on the wire. Session expansion gives a `knows` nonce to every session and a `generates` nonce to none, which is why `aead_nonce_reuse_sessions.vp` is `c0`@1 and `c1`@2, and why a model whose ciphertext must stay static (`otp_counter_freshness.vp`) declares its nonce while anything sealing a fresh plaintext generates one.

### Threshold primitives (FROST)

`THRESHOLD_SPLIT[t](k)` is a dealer's Shamir sharing, `THRESHOLD_SIGN(share, nonce, commitments, message)` is RFC 9591's round-2 `sign`, and `THRESHOLD_JOIN` is Lagrange interpolation, which is why one join serves shares, partials and verification shares alike. What the join accepts is a `CombineRule`: every argument is `partial` with a projection of `split` at `share`, all agree at the `agree` positions, and the join reduces to `whole` over the secret followed by the `carry` positions; positions in neither set (the nonce) are free per partial. Two rules are declared: `THRESHOLD_SIGN` partials agreeing on commitments and message into `SIGN(k, message)`, and `PUBKEY(share)` values into `PUBKEY(k)`. The combined signature **is** a plain `SIGN`, so `SIGNVERIF` is untouched and a threshold signature equals a directly produced one (`threshold_join_agreement.vp`, `e0e0e1e1`); binding to the commitment list lives in the partials, where FROST's binding factor lives, so partials from two signing sessions never mix.

- Forward, `can_combine` sits beside `can_rebuild` in the one reducer. Reverse, `can_reconstruct_primitive_directly` falls back to `combinable`: it groups held partials by split and agreed positions (`partial_groups`), extends each group with partials the attacker can *construct* over shares it holds, and succeeds at the split's threshold. That is a **reconstruct** rule and not a recompose one because the forgery target `SIGN(k, m')` on an attacker-chosen message is assigned by nobody.
- The solver needs its own half, `solve_by_combination`: for a target with a combine rule into its head it takes every split the attacker has seen a share or partial of (`held_splits`), binds the secret, mints one shared fresh variable per agreed-but-not-carried position and one per free position per partial, and walks the outputs as a take-or-skip frontier stopping at the threshold — linear in `MAX_SHARES` times the frontier rather than a choice among subsets. The signing oracle itself comes from the Constructed pass's single-slot substitution; the goal is what lets the recipient's proposal spend it (`threshold_sign_leaked_share_and_oracle.vp` is `a0` without it).
- **The frontier must represent distinct choices, not distinct subsets of past outputs.** `remove_local_bindings` substitutes a partial's local free variables into every surviving binding and drops their entries, without forgetting a nonce constraint a wire choice depends on; `dedupe_counts` keeps one state per identical surviving substitution and count, in first-encounter order, since every future output differs from every processed one — but differing counts stay separate, because taking more later oracle contributions can add bindings concrete validation needs. `threshold_subset_search.vp` (`a0` at both counts) pins the 8-of-16 case, and the unit test reduces 12,870 subsets to one solution and refuses to pool counts across disagreeing commitments.
- The initial frontier retains **every key alignment**, too. A shared key can match both exponent orders while only the second matches the signed message. `solver_threshold_key_alignment.vp` is `c1` at one and two sessions: replacing `x, y` with `b, a` makes the response's wrapping signature constructible from two disclosed partials without revealing the signing key. Its guarded companion keeps `x` honest and is `c0`. Taking only the first `match_value` lost that attack; all alignments now enter the existing counting frontier.
- A combined value is learned as `Combined { from }` and re-derived by `tracecheck` through `combination_holds`; `Reconstructed`'s parts-are-arguments check would reject it, since partials are ingredients and not subterms. `Recomposed` no longer lists the split term among its ingredients: it is not held, and walking it dragged a share reconstructed *after* the secret into the trace ahead of it (`threshold_three_of_five.vp`).
- `THRESHOLD_SIGN` declares `forgeable_secret: Some(0)` and `reuse: ReuseRule { fixed: [0, 1], reveals: [Argument(0)], forgeable: [] }`: two partials under one share and nonce surrender the share (`threshold_sign_nonce_reuse.vp` against `threshold_sign_fresh_nonces.vp`; `threshold_sign_nonce_reuse_sessions.vp` cross-session). RFC 9591 §7.3 forbids any reuse and calls the consequence complete key recovery; the rule is the plain-Schnorr reading, one nonce standing for FROST's hiding-and-binding pair, so it fires at two uses where the exact algebra needs a third.
- Shares travel under pre-shared keys in every model, standing in for the confidential authenticated channel the RFC's dealer (Appendix C) requires, because a guard only stops substitution and a share on the wire is a share the attacker holds; binding the bundle to the group key with AEAD associated data is the model's own choice, without which a share replays into another session's key generation. Key generation is a dealer; a DKG is a principal that splits a `generates` key and never uses it.
- Two metamorphic properties ratchet against over-refusal in the counting: `lower` decrements a written threshold and may lose no attack, `raise` increments one and may add none. Both skip models with `equivalence?` or `unlinkability?` queries, since a threshold is part of term identity.

### Active attacker search (src/solve/)

Goal-directed: the engine asks what the attacker would need in order to learn this and whether it can arrange that, solving backwards from each query; it does **not** enumerate substitutions forwards. Termination comes from memoisation, cycle cutting and a finite basis, never from a cap on how hard to look. The one bound on term *shape* is `reexec::TermBound`, **per slot**: the depth of the deepest term the protocol computes, plus the layers the recipient itself peels off that slot (`peel_depth`), with room above the flat cap spendable only where the excess is carried by the protocol's own subterms (`depth_over_protocol`) — counting held terms as free let an oracle ratchet forever. `TermBound::protocol` also supplies the immutable protocol-subterm basis used by candidate generation, collecting subterms from every trace-resolved constant *and their reduced forms*; `VerifyContext::term_bound` builds it once per analysis, shared by active search, matching-run checks and witness minimization.

Per phase: passive baseline, then rounds to a knowledge fixed point. Each round runs `Pass::Targeted` for every principal, then `Pass::Constructed` for every principal — **never interleaved** (loosening the order fails 13 models). `solve_principal` asks the phase-specific `Controllable` token whether any slot is admitted before building symbolic terms, causality restrictions or execution histories; guarded relays whose upstream input remains controllable are still admitted.

- **Retain every successful `match_values` alignment** on the decomposition route as on the direct wire route, before solving the opening requirements: the first algebraically valid alignment can spend a disclosure too early while a later one is causal (`solver_dh_wrapped_causal_alternative.vp`; guarding the inputs or withholding the wrapping key keeps its companions at `c0`). Decomposition honors the spec's `output`, and rewrite matching its `from_output`, before attempting a route. The wire-rewrite route uses `build_rewrite_shapes_with` and `unifiers` too: all pinned positions are solved together, and unpinned positions keep their source arguments, so an oracle is not required to reveal its own secret before it can be used.
- `solve_decomposition_from` follows nested disclosures through decomposition rules and tuple `reveals_args`, retaining the required inputs at every enclosing layer; following just the first layer lost the same oracle under another publicly openable carrier (`solver_dh_nested_causal_alternative.vp`) or inside a tuple (`solver_dh_bundled_causal_alternative.vp`). It also interprets `ReuseRule::reveals` for a vetted pair — a proposal route only, since the replay must still emit the target and the closure must still establish the disclosure coherently (`solver_dh_nested_reuse_opens_key.vp`, `solver_dh_nested_reuse_opens_nonce.vp`). It also follows the registry's `weak_reveals` and `weak_reveals_output` when the capability is in force, with no opening inputs. That route must also match the entire carrier to the annotated term: matching only the revealed payload over-applies a term-scoped assumption and exhausts fresh variables on weakened SMP delivery envelopes. Both delivery variants run in the regular tests. A revealed output equal to the source projection is not recursed into.
- Those reuse models also pin the **minimizer's query scope**: each probe's `scratch_for_witness` keeps the concrete query being reported alone, without the sibling variants sharing its result index, or a trial could disclose another session's secret, be accepted as a smaller witness, and narrate the original secret. This narrows witness selection, not attack detection.
- **A witness probe schedules its installs against the knowledge of its replay, and `available_before_pending` starts the causal influence closure at every pending receive together**: checking each run separately admitted a cycle feeding each run the exponent the other would leak only after receiving it. Ready installs are removed in recipient order; a stalled schedule rejects the witness. The same check belongs to concrete history replay — `replay_diffs` groups installs by actual receiver and calls the shared `causally_grounded` before re-executing anything (`causal_oracle_cycle.vp`, `c1c1c0`@1 and `c1c1c1`@2; `causal_oracle_cycle_early.vp` admits it at either count). The trace-only `harvested_late` backstop checks the receiver too.
- **Knowledge filtering must follow ingredients reconstructed in place, not assume an ingredient absent from `attacker.known` is free** (`causal_derived_unblind.vp`, `a0`@1 and `a1`@2; its `_early` companion fails at either count). `theory::KnowledgeInputs` expands an unheld ingredient into held dependencies through the same `construction_inputs` recipes `obtainable` uses. Causal availability, `Coherence`, `collect_reads` and `forgeable_without_sender` all use `reachable_knowledge`, a dependency worklist rooted only in permitted source records and ingredient-free constructions rather than learning-order scans; a failed construction recipe refuses a combination rather than making an ingredient appear free.
- The reuse closure's `protocol_produced` follows honest terms into their subterms: a ciphertext computed inside another carrier is still honestly produced, and dropping the honest nested member would leave a later oracle response without a reuse partner once `attacker_mints` can rebuild it.

Modules:

- `symbolic.rs` — the principal's computation with every attacker-controllable wire slot replaced by a variable, reduced as `perform_all_rewrites` would. `attacker_controllable` (through the `Controllable` token) decides controllability: guarded-unless-`mutatable_to`, self-created, wrong-phase, unused-by-this-principal; `nil` excluded. "Unused" is waived for a constant an `equivalence?` names (`equivalence_unused_received.vp`), and `mutatable_to` is closed under relaying in `construct_wire_index` so the guard exemption holds at every hop (`relay_guard_transitive.vp` beside `relay_forward_before_check.vp`). A DH public key becomes `PUBKEY($x)`, so the MitM shape falls out of the representation.
  **The refinement search**: `build` replaces every controllable slot with a variable; `build_assuming_honest` leaves one at its honest value, because a search seeing only the variable cannot reason *through* the honest value (`relay_rewrap_oracle.vp` against `relay_rewrap_no_oracle.vp`). It runs **only after** `search_fixpoint` reaches its fixpoint with queries outstanding, **only in `Pass::Targeted`**, and **after** the unrefined pass — offered first it degrades `identity_misbinding_uks.vp` and `ringsign_ring_substituted.vp` into `TRACE_USES_A_GUARD_BYPASS`. `slots_blocking_reduction` picks the candidates: for each primitive that cannot fire because a slot variable sits in the position its rewrite reduces, that slot **and every bare slot variable in a position the rule's `matching` pins**, held honest together.
- `vars.rs` — attacker variables are interned `Constant`s in reserved id ranges (`ATTACKER_VAR_BASE = 0x8000_0000` for slots, `FREE_VAR_BASE = 0xC000_0000` for free choices). Free positions stay variables until materialisation; `ground_free` fills every one with the same `nil`, which is why `diverge::distinguish` exists.
- `matching.rs` — one-sided `match_value`/`match_values`, two-sided `unifiers`, and `merge`, modulo DH commutativity. **Retain both exponent orderings until the entire pending equation list succeeds**: a later tuple field can rule out the first ordering even when the shared-key field alone matches (`solver_dh_backtracking.vp`). Held-term and wire-oracle matching consume the lazy iterator, keeping further assignments for constructibility and validation (`solver_dh_causal_alternative.vp`). Checked equality inversion also consumes every unifier: the honest alignment can satisfy the equation while only the swapped alignment discloses the target (`solver_dh_checked_alternative.vp`, `c1` at both counts; `solver_dh_checked_ordered.vp` binds the first exponent separately and holds). Reuse and malleability carry every fixed-position match into the remaining matching and construction obligations; a nonce constraint or an unavailable plaintext can reject the first alignment and accept the second. `merge` queues all binding constraints into one equation list and yields every unifier, since both solving bindings one at a time and retaining only the first merged solution can fix a DH ordering too early. `combining_constraint_groups_keeps_alignments_needed_by_later_groups` pins the case where a third group requires the second alignment. All three refuse a binding whose variable occurs in what it is bound to (`vars::occurs`), and `merge` must repeat the check when it *overwrites* a binding.
- `deduce.rs` — the solver. Goals are discharged by: already-known, bare-variable (`nil`), **replay**, wire unification, oracle (restricted to the finite basis), rewrite-match, primitive-by-arguments, decomposition, `invert` (backwards through rewrite rules and `SPLIT`/`CONCAT`), and `satisfy_check`. Constraint collection includes a projection whose argument merely *carries* a variable, a bare slot variable included (`forged_bundle_from_held_terms.vp`). Bindings are put under obligation by `require_constructible`, and **an obligation on a slot variable is the slot's wire term under the binding, not the raw binding**: a DH slot is `PUBKEY($x)`, so matching a recipient's check binds `$x` to the peer's *exponent*, and demanding that exponent refused every proposal that merely leaves the key share honest (`scuttlebutt.vp`'s reflection). The same widening lets the goal route bind a slot to a *sibling session's* honest value, so `propose` defers all-sibling proposals out of the Targeted pass and offers them after the Constructed pass's own families — ordering only. Goals are reduced after applying the incoming substitution, before deduction or memoisation: a bound decryption that already yields a public value needs no new shape search. The unguarded `ekb` variant of `simplex_pqdr.vp` pins this in the regular suite; omitting reduction repeats symbolic work in its nested key schedule until a solver lane exhausts its fresh variables. Goals are memoised on that reduced goal **and the entire incoming substitution**, since a ground goal can still depend on bindings through a symbolic wire oracle (`solver_memo_oracle_bindings.vp`); results computed while a cycle was cut are not cached.
  **Inverting a rewrite solves an equation; it does not fill a hole.** `rewrite_shapes_yielding` fills the positions `matching` leaves free with **fresh variables** and unifies `to(shape)` against `target`; filling them with `target` nests it deeper on each inversion and enumerates `SIGN(SIGN(…))` chains to `TermBound`. Every unifier is carried into the remaining inversion or oracle obligation, including bindings of existing variables in the reduct. Fresh variables allocated only to shape this rewrite are existential: apply their bindings, then project them out before constructibility checks. Keeping only the shape loses the message binding in `solver_unblind_bindings.vp` (`c1` at one and two sessions); keeping the existential bindings as obligations instead loses `mac_then_encrypt_order.vp` at one session by requiring the hidden plaintext of a replay. `solver_unblind_bindings_guarded.vp` (`c0`) fixes the message and is the counterweight. The single-result `unify` wrapper has no callers and is removed.
- `diverge.rs` — equivalence queries. `solve_divergent` grounds the variables reaching only one side to `nil`. When both queried values are projections of one installed term, `distinguish` hands each free position its own value from `fillers()`: `nil`, then `HASH` at every declared arity — every rung derivable from nothing, the ladder injective across a `CONCAT`'s positions. Models: `equiv_forged_bundle_projections.vp` (`e1`), `equiv_forged_bundle_far_fields.vp`, `equiv_sealed_bundle_holds.vp`/`equiv_guarded_bundle_holds.vp`, `unlink_forged_bundle_not_a_link.vp`.
- `validate.rs` — **propose and dispose**, the only route from the search into query evaluation. The search materializes a substitution once into its concrete `(slot, value)` install signature, used for deduplication and handed unchanged to validation; the validator takes no `SymbolicState` or `Substitution` and does no symbolic application or grounding. It independently rejects out-of-range slots, residual variables and duplicate slots, then proves the concrete installs before re-executing them. **Its guard order is load-bearing and asserted by `tcb_tests`**: controllability, then derivability, then queue the install, then execute. Its `derivable` is an independent proof that knows nothing about the solver, so the capability exemptions (`forgeable_secret_position`, `malleable_positions`) are repeated here. Both derivability and own-run receive-history checks walk shared terms as DAGs. The history walk stops at held terms and checks their recorded needs immediately, without materializing a tree-sized list; derivability memoizes its own predicate per input pointer for one call and keeps the existing `DeductionMemo` alive for its `obtainable` subproofs. These predicates remain separate: malleability can make a term derivable even when `obtainable` refuses it. The 40-layer shared-term tests cover successful construction, unavailable secrets, and capability changes between calls.
  **Executions are remembered** (`remember_execution`/`recall_execution`): the fixpoint re-offers the same substitutions every round, so 83–90% of validated proposals per phase repeat one already executed. An execution is its states as diffs against `execution_base` plus every `bypass_is_constructible` decision taken while it ran. The knowledge it runs against is **not** monotone, so a recall is stale exactly when one of those decisions would come out differently under the governing attacker, **in either direction**, and is then dropped and re-run. Stored states and signatures compare by `structurally_identical`, not `equivalent`: a DH-commuted twin prints differently, and the recall is what the closure reads and the trace names. The guards still run on every repeat, and `execute_forward(` still appears once, after `installs.push(`. Closure and queries are skipped on a recall whose stored `Saturation` is current (`note_execution_closed`).

**Proposal families, in offer order**: goals from each unresolved query; `constraint_goals`; the **blanket** substitution (every controlled slot replaced by the attacker's own value); one single-slot substitution per controlled slot; and, only in `Pass::Constructed`, the **sibling flight** substitutions plus per-slot candidates drawn from held protocol terms and from shapes the recipient's rewrite rules demand — each alone, with the blanket, and with a **relay** forwarding every other slot unchanged. Every proposal still carrying free positions is offered three more times through `fill_aligned_with`: `keyed_free`, `preserved_free`, and (only while an `equivalence?` is unresolved) `distinguish`. The fillers share `aligned_free_positions`, an iterative walk over proposed/honest term pairs that skips ground branches and visits a repeated primitive pair once (`shared_transcript_replay.vp`).

- `keyed_free`: **where the protocol put a public key, offer the attacker's own.** Aligned positions only; filling every free position costs 1.84x. `forged_key_swap_bundled.vp` (`c1c0`) is the regression, `witness_key_swap_bundled.vp` (`e0`) the same substitution by hand.
- `preserved_free`: **keep the field you are not attacking** — each free position filled with the honest term's own argument where the attacker holds it. `forged_statement_rebuilt.vp` (`c1c1`, WalletConnect v2 One-Click Auth) was `c0c1` before; `forged_statement_on_wire.vp` is the counterweight, `witness_statement_rebuilt.vp` (`e0`) the hand-run version.
- `aligned_held_free`: **where a forged shape leaves a ciphertext position free, offer every held protocol ciphertext under the same key.** The basis is the protocol's own subterms (offering every held term took the suite from 136s to 747s). `pitoy_depth.vp` is the model.
- `sibling_flight_substitutions`: one proposal per sibling index installing that session's whole honest flight at once, because a replay pairing one session's key share with another's ciphertext fails the recipient's checks (`tls13-0rtt.vp`). **It belongs in `Pass::Constructed`**: offered early, `bypass_witness_narration.vp` degrades into a shallower replay.
- `constraint_goals` builds a **forged authenticated flight** by solving conjunctions of checks. `constraint_sets` follows declaration dependencies from sends, leaks, queried values and each principal's last check, retaining earlier execution prefixes separately since an oracle can emit before a later check fails; traversal stops at a controllable receive. The frontier starts with both the empty substitution and the independent solutions of each non-projection check, then refines through the conjunction in source order, dropping a ground contradiction unless its bypass key is obtainable. **Independent seeds preserve a replay or a key choice discovered later in the flight** (`piknik.vp`, `forged_flight_mitm.vp`); eagerly committing every branch to the first check's solutions lost attacks. `canonical_slots` keys the frontier by the applied receive-slot bindings, renaming existential variables in first-occurrence order while preserving variable sharing, never grounding a free position or merging two different equality constraints. The flight solver uses its own `Deducer` and excludes non-protocol reconstructed terms and directly injected receives from its **replay index**, or replaying every attacker-built flight into its own constraints becomes a feedback loop; **that restriction belongs only to the auxiliary flight search**, and applying it to query-directed and per-slot deduction lost the three-peer Lowe attack (`scenario_three_peers_multibind.vp`).
  The stronger inversion exposed two previously missed attacks. `ringsign_ring_permutation.vp` swaps two unguarded members of a correctly signed ring; the collapse regression now guards the other member, and the permutation fixture gives the signer's ring inputs and the verifier's receives separate constant names, since reusing one mutable slot couples their symbolic bindings — a remaining search limitation, not a reason to discard the finding. `userbase.vp` accepts a wrapping salt equal to the public login-token salt, letting the attacker use that token as the wrapping key and supply an entire key hierarchy; `hkdf_salt_substitution.vp` isolates the finding and `hkdf_salt_domain_separation.vp` fixes the info argument.

`propose` runs its pure parts through `parallel::map_ordered` and its writes on the calling thread, so the proposal list is the sequential engine's list in its order. Each parallel task solving goals gets its own `Deducer` (the memo is a `RefCell`), built once per solving pass and forked on demand by `Deducer::lane_factory`: the protocol basis, wire terms, shaped slot terms and held-term index are shared immutable `Arc`s, while memo tables and cycle state belong to the lane. The auxiliary flight search privately filters its replay index through `Arc::make_mut`, leaving other lanes untouched. This avoids rescanning all state slots and attacker knowledge for every query or candidate slot. For fresh variables, lane 0 keeps the lower half of the free-variable space, lane *k* takes the *k*th `FREE_LANE_STRIDE` block from the top, and `lanes` splits items into at most `FREE_LANES` ranges so a model with more queries or slots than lanes shares a deducer rather than aborting. Lanes are created inside the worker callback, so pending work retains lane numbers rather than allocating one mutable solver per pending query. Two tasks minting one free variable would be misread by the fillers, which find free positions by id, so `fresh_var` asserts a lane is never exhausted. Parallelising the closure's rule evaluation was built, measured and removed: a closure pass is thousands of dispatches of light work and the per-pass handoff cost more than it returned.

On 2026-09-08, five interleaved single-thread CLI runs before and after index sharing gave median wall times of 1.31s → 1.28s for a synthetic 1,200-query model, 1.95s → 1.95s for `scuttlebutt.vp` at two sessions, and 0.83s → 0.83s for `simplex_smp.vp` at one. This removes repeated setup and allocations; it is not a broad end-to-end speedup.

**The attacker's option set is the thing to be careful with, and narrowing it silently is this engine's characteristic bug.** At every position the options are `{honest value}` plus everything derivable. Four missed attacks came from replacing that set with one representative: `vars::ground_free` narrowed what the search **proposes**, `symbolic::build` narrowed what it can **derive**. The rule: **never commit to one representative where the commitment is unrecoverable; defer it and enumerate.** When a fifth is suspected, look first at whether the minimizer can already say something the search cannot: twice a family `witness.rs` had was a family the search lacked.

Proposals are reduced to their concrete transmitted values before being deduped by what they would **install** (`install_signature`), not by substitution identity, and not across rounds. Before the signature is taken, `leave_honest_slots` drops every binding whose installed value is the slot's honest one and that no other binding mentions. Variables the solver never bound are left free and `validate` skips those slots. **Skeletons are gone**: `skeleton.rs` handed the attacker each primitive's shape with secrets erased, and removing it changed no verdict and improved ten traces. Do not reintroduce a rule that hands the attacker a shape it did not derive.

### Re-execution (reexec.rs)

`reexecute` installs attacker-chosen values into a principal and runs it forward: install → check the slot graph is still acyclic → resolve → rewrite → then either bypass guards the attacker can defeat (`try_guard_bypass`, keyed on the spec's `bypass_key`; uncapped, since each round must flip a fresh `bypass_injected` flag) or truncate at the checked primitive that halts the principal and set `halted_at`. Bypass works from the *pre-resolution* state, and exists because substituting `PUBKEY(nil)` for an identity key fails a signature check while the attacker knows that private key.

- `bypass_is_constructible` keeps that from becoming a licence: holding the `bypass_key` is necessary and **not** sufficient; every other position the rule's `matching` pins must be `obtainable` too. `KEM_DECAP` pins only the key; `AEAD_DEC` also the nonce and AD, `SIGNVERIF` the message, `RINGSIGNVERIF` the ring and message (`bypass_needs_the_whole_check.vp`, `bypass_needs_the_signed_message.vp`, against `…_ad_leaked.vp` and `…_wire.vp`). A `bypass_key` is declared only on a primitive that can take `?`.
- `honest_input_accepted` is the other half: a failed check that passes once its `rule.from` argument is restored to the honest value has every other argument honest, so the only terms it accepts are ones the sender's own value belongs to (`bypass_needs_the_signed_message_public.vp`); any other accepting term is reachable by installing it directly.
- Four checks decide what the search may touch. `Guards` borrows `Controllable` (`Controllable::of`, one per solving pass; **fields private so nothing outside `reexec.rs` can mint one**; `admits` re-checks principal and phase), the shared `TermBound`, and `Coherence`. The fourth, causal availability, is asked through `available_before_receive` after derivability and before queueing an install.
- `slot_graph_is_cyclic` is what lets `resolution.rs` carry no depth cap: `install` is the only thing writing a slot out of declaration order, and the search will offer a slot a value naming that same slot. A slot holding a primitive has an edge to every slot it mentions; one holding another slot's bare name has an edge to that slot. This lives in one place because `validate.rs` and `witness.rs` **must agree exactly**.

### Attack traces (witness.rs + narrate.rs)

**`witness.rs::minimize_witness`** — a raw witness carries the union of the bindings for *every* goal the solver pursued. The minimizer picks a **candidate** per principal's pristine session (the canonical MitM — attacker's key wherever a DH public value arrived over the wire — then the recorded mutations, then those with public keys replaced by `PUBKEY(nil)`), takes the first that still resolves the query, then drops mutations one at a time while it keeps resolving. If nothing replays it falls back to `unminimized` with `reproduced: false` and claims no attacker actions. Probes run against a **scratch `VerifyContext`** re-seeded from the **passive baseline** rather than end-of-search knowledge.

- **"First candidate that resolves" is not "the candidate that explains", so the choice is ranked.** `try_guard_bypass` defeats a checked decryption the moment the attacker holds its key, so `ciphertext := nil` resolves almost any authentication query. The minimizer prefers any witness where **no** bypass fired (`needs_guard_bypass`), and `drop_one` refuses a drop reintroducing one. `forged_from` **constructs** a bypass-free witness by asking the recipient's own failed checks what shape they wanted and offering that forged term for each controlled non-key slot; `payload_shapes` fills a rule's free positions three ways — `nil`, the honest term's own argument where the attacker holds it, and the attacker's own public key where the honest term carries a key derivation — the explanatory shapes offered **before** any `nil`-filled one. This is ordering, not searching: every candidate still goes through `probe`.
- `examples/silly/cloudbackup.vp` is the model to read: a MitM on `g_file_alice_a_key` transiting Alice → Server → Bob unguarded while both long-term keys are guarded. If a change makes that trace mention `nil` again, it is a regression the verdict will not catch.
- A bypass is not automatically a smell: where the defeated check is a signature over a substituted identity key, the bypass **is** the attack. `TRACE_USES_A_GUARD_BYPASS` is **empty** at the default, so any entry is a witness that got a worse explanation. It held four until `forged_flight` stopped committing to the first shape the strict rule accepts at a slot: the climb now collects every accepted shape and continues from the best by `(halts, bypasses, stuck)`, admitting no move the strict rule refused. Three relaxations of the acceptance key were each tried and each regressed another model, because a climb is one path and a different key is a different path — so the strict climb is untouched and a **second** climb runs after it, accepting only strict improvement, which lets a recipient's first check be forged when passing it exposes bypasses downstream. `flight_shapes` also offers each wanted shape substituted into every position of the slot's **current** forged term; `scuttlebutt.vp`'s `equivalence?` needed both.
- **A witness is an ordered sequence, and `grounded` is what says so.** `probe_with` walks the installs greedily: one is ready when no install into a slot sharing a recipient with it and declared earlier is still pending, and taken when `attacker_can_derive`-able from knowledge established by the installs taken **before** it. Order is imposed only within one recipient's run, because session clones are concurrent and sorting every install by `declared_at` put a second session's whole run after the first's. `choose` prefers a grounded witness among the bypass-free ones, and `drop_one` refuses a drop losing groundedness (`the_lowe_witness_replays_through_bob_before_it_learns_the_nonce`).
- **The seed has to be transitively closed** — `seeded_mutations` closes the tainted diffs over the histories of the values in them, breadth-first, skipping values that `costs_nothing` — and **bounded by the trace, not the answering state**: `mutations` drops any seeded slot at or past `km.slots.len()`, not `ps.values.len()`, since `ps` may be truncated at a halt (`spore_ns_pk.vp`).
- **An install may be addressed to one principal.** Shared installs are `(slot, value)` and reach every session controlling the slot; an addressed install `(principal, slot, value)` reaches that principal alone. Only `split_recipients` mints them; keeping `others` empty otherwise keeps `forged_key_swap_bare.vp` intact.
- `narrate.rs::out_of_order_note` is a backstop earned by `out_of_order_harvest`. **No model earns it any more**, because causal availability refuses the install; if one does, the causal filter missed an impossible trace.

**`narrate.rs::narrate_attack`** renders the witness as numbered causal steps: `Mutations` (per wire message), `Gate` (a checked primitive that passed with an attacker-controlled input), and `Derive` (one line per `DerivationRecord`), emitted **per message in the order the installs happen** (`mutation_groups`), so the derivation of each installed value directly precedes the step that installs it.

- **Every renderer excludes the shadowed set** (`shadowed_names`: installed slots and everything computed from them) at every depth, not only at the top level — the gate steps, the `via` clause of a carried-in value and the `Narration.shadowed` the query summaries read — or a forged term prints as the honest slot it displaced (Lowe's forged `PKE_ENC(gb, d1)` printed `d1` for the very `CONCAT(ni@2, ga)` the attack is about).
- A `Leaked` or `Obtained` step names the slot its record cites where that name is not excluded and still denotes the value (`compress_outer_preferring`), not the first equivalent slot in the table, which named Alice's `ka` for a leak of Bob's `kb`. A `Gate` step fires only for a check with an installed slot in its own dependency cone (`own_cone`). A value the attacker installed is not then "observed on the wire" at that same slot.
- `choose` ranks a witness by `(grounded, recipient did not halt)`, so a cross-session replay that Bob's later `ASSERT` rejects loses to the reflection he accepts (`spore_otway_rees.vp`). `DuplicateAcceptance` is also chosen where the witness had to install into a slot carrying a value the recipient generated (`forged_recipient_context`).
- Three smaller rules: a **multi-output primitive carries its projection** (`|n`) wherever `NameTable` renders a term (`equivalence_names_the_projection.vp`), and `Display for Primitive` deliberately does not; a **declared weakening assumption must be named** — `Broken` displaces a derivation naming no assumption and `walk` refuses to override it (`cap_forgeable_names_its_assumption.vp`); `Initial` narrates as "it is public" **only at the root**.
- **A step may claim only what its own operands establish, and "session" is the word this file gets wrong most easily.** *Which run* a derivation happened in is known only from the `MutationRecord`'s `principal_id`, so only `session_prefix` may name one, and nothing may call the other run *earlier*. *A cross-session replay* is established only by `copy_sibling_replay`, so only the `sibling` arm of `Step::Replay` says "from another session"; the other says "unaltered". *A guarded slot being substituted* is not a guard bypass: `Step::Bypass` fires only where `try_guard_bypass` proved the key is held. An `Obtained` value is "on the wire" only when its slot has a `sent_by`.

### The soundness tests (query.rs::tcb_tests)

Theorem 4 of the paper is that a solver bug cannot produce a false attack, *whatever the solver does*, reduced to facts pinned by reading the source:
| fact | what it says | pinned by |
| --- | --- | --- |
| (i) | one write path: `results_put`, whose token constructor is private to `query.rs`, called once from `emit_query_result` | the `QueryVerdict` type + `a_query_result_has_exactly_one_write_path` |
| (ii) | reached only from query evaluation: five `emit_query_result` callers, one per query kind | `results_are_recorded_only_by_query_evaluation` |
| (iii) | the verdict comes from a state: an evaluator is handed a `PrincipalState` and an `AttackerState` and nothing that could carry a verdict | `a_query_evaluator_is_handed_states_and_nothing_else` |
| (iv) | every state it is handed was executed: three `verify_resolve_queries` call sites, nothing under `src/solve/` reaches evaluation directly | `query_evaluation_is_entered_only_over_an_executed_state`, `the_solver_cannot_reach_query_evaluation_except_through_the_validator`, `the_solver_holds_no_shared_cell_over_analysis_state` |
| (v) | every term the attacker installs was derivable *and causally available*, against knowledge restricted to compatible executions; `validate.rs` proves this before `execute_forward` runs and abandons the *whole* substitution on failure | `an_install_is_proven_controllable_then_derivable_before_it_is_executed` |

### Supporting modules

`parser.rs` — byte-level recursive descent; comments captured into AST nodes so `pretty` round-trips them (idempotence is unit-tested), and a leading byte-order mark is skipped by position, not stripped, so every span stays relative to the text the editor holds. `pretty.rs` — canonical formatter, golden-tested; `pretty_model` is a pure AST walk, infallible, and deliberately **not** gated on `sanity`. It owns the `Display` impls for `Value`/`Constant`/`Primitive`/`Query`/`Expression`, so every engine message and trace is rendered here.

`resolution.rs` — inlining, `compute_visibility`, `state_mentions`/`principal_uses_constant`. A slot the attacker filled with another slot's *name* resolves through that name to what it holds (`resolve_ps_values` chases the alias chain with a cycle guard; `matching_run_two_inputs.vp`); only installs create such chains. `rewrite.rs` applies rewrite rules over a state, reporting failures as `(Primitive, slot)`. `primitive::normalise_arguments` is the one place keeping the term space finite: where `argument_restrictions` forbids a key derivation in a position, it unwraps it, so the solver cannot build `PUBKEY(PUBKEY(x))` forever. `construct.rs` builds the trace and principal states and owns `clone_for_depth(purify)`. `info.rs` is all user-facing output, buffered into JSON under wasm, with `InfoQuiet` for hypothetical re-runs and `InfoCapture` for `--saturate`. `update.rs` (`cli` only) GETs the GitHub tags API on a thread read with `try_recv` — the only outbound call the tool makes.

`lsp/` — behind the `lsp` feature; stdio loop with `recv_timeout` as the validation debounce, handling `shutdown`/`exit` itself, analysis on a worker thread. **Both threads must call `info::set_verbosity(Verbosity::Silent)`**: `VERBOSITY` is thread-local, and engine chatter on stdout desynchronises every client's parser — the symptom is an analysis that never returns. The server never touches the filesystem; documents are keyed by URI. `docs.rs` is the language prose (`CC-BY-SA-4.0`): keyword and query entries written there, primitive entries the specs' own `doc` fields, capability entries generated.

`report.rs` — the one serializable description of an analysis behind `--format json`, `--format html` and the LSP notification; ranges are byte offsets plus 1-based line/column, never LSP positions. `describe` draws a principal that **leaks** even if it never appears on a message (`leaks_without_a_message_is_visible.vp`). Each model is parsed exactly once in `Run::of`; the renderer never touches `crate::parser`.

`html/` and `tex/` render `Run` into the self-contained page and the LaTeX document. **No markup is written in Rust** (`no_markup_is_written_in_rust`, `no_latex_is_written_in_rust`): it lives in the `tpl/*` fragments, `report.css`/`report.js` and `preamble.tex`, compiled in via `include_str!`. The engine is **`src/template.rs`**, shared by both and parameterised by a `Dialect` (HTML `{{…}}`, LaTeX `<<…>>`). **Escaping is a type**: `Val::Text` escapes and `Val::Raw` does not, chosen once where data is built. **Both directions of the template/data contract are a red build** under `cfg(test)`: an unsupplied placeholder panics, and so does a supplied value the template never reads. `every_model_in_the_corpus_renders_a_sound_page` pins that no `{{` survives, ids are unique, every `href="#…"` resolves and tags balance. Every LaTeX figure is delimited by paired `%% --- BEGIN verifpal … ---` / `END` markers and built only from `\vp…` macros, so it can be lifted into a paper; `listing_safe` withholds any source line carrying `\end{lstlisting}`, or `\input` could read arbitrary files into the PDF; `the_document_never_claims_a_proof` rejects "proven", "is verified", "is complete" and "proof of correctness" and requires the disclaimer. Goldens are re-blessed with `VERIFPAL_BLESS_HTML=1` / `VERIFPAL_BLESS_TEX=1`; `the_golden_document_compiles_under_tectonic` is gated on `VERIFPAL_TECTONIC=1`.

`msc.rs` is the sequence-diagram row model serving all three renderers; `tokens.rs` returns its index *even when parsing fails*; `Constant` carries no `Span` and must not gain one. There is no process-global mutable state: `ValueNames` and `PrincipalNames` are interners **owned by the `Parser`**, the unnamed-constant counter is a parser field and the analysis counter is thread-local, and both interners error rather than overflow into `ATTACKER_ID = 0`, the copy bands or the ranges `solve::vars` reserves. `inject.rs`, `mutationmap.rs`, `verifyactive.rs` and `skeleton.rs` are gone.

## Design simplification audit (2026-09-07)

A pass over the whole analysis path found the removable complexity to be duplicated representation around the gates, not the gates themselves: attacker knowledge grows across proposed executions while each concrete replay starts from a pristine state, so a globally held value says neither that it was available before this receive nor that its producing execution agrees with the one being replayed. What landed: one concrete proposal at the search/validation boundary, one cached causal restriction for receive and check positions, one knowledge-filtering operation, one immutable protocol basis and term bound per analysis; `RuleDomain`, `RuleGroup`, `RuleFn`, `Reads`, the dispatch table, `CausalOrder` and the three-field `Delivery` are gone. Validated by full-output corpus diff against `de21a3b` at one and two sessions (`tls13.vp` and `signal_twelve.vp` excluded), plus three-session and multi-worker runs; no model expectation, primitive declaration, query predicate, search family or search bound changed.

Consolidations that would change the analysis, and were **excluded**: causality against history compatibility against own-run receive needs (time, agreement with other runs, and the executing run's own input choices — `causal_late_leak`, `history_incompatible_knowledge`, `history_own_later_emission`); closure coherence against reuse-pair coherence (reachability under a compatible union against the two values actually coexisting); knowledge against constructibility against observability (`aead_replay_not_forgery`, `piknik`, `unlink_sealed_carrier_not_observed`); concrete primitive interpretation against symbolic deduction (making the latter authoritative in the validator would widen the trusted boundary); `original`/`pre_rewrite`/`value` and own halts against foreign halts against starvation; solver against witness minimizer; scenario against session expansion; pure term caches against execution caches. The primary-route choice and proposal ordering remain sources of incompleteness, including `closure_cyclic_union.vp`'s two-session query-order sensitivity. Replacing the global knowledge pool with explicit individual histories would be a different search engine, needing its own compatibility target and migration.

## Testing conventions

- Unit tests live in a `#[cfg(test)] mod tests` at the foot of the module they exercise; `src/testutil.rs` holds shared builders. `src/model_tests.rs` holds the end-to-end tests: `run_model("foo.vp", "c0a1")` runs `examples/test/foo.vp` at the **shipped default** of two sessions; `run_model_sessions("foo.vp", 1, "a0")` pins an explicit count. A model whose verdict depends on session count is pinned at both. A model *meant* to be rejected gets `run_model_err("foo.vp", "substring of the error")`.
- **Result code format**: one letter+digit per query in model order — `c`/`a`/`f`/`u`/`e` for the kind, `0` = holds, `1` = attack found.
- Adding an engine regression test: write a model in `examples/test/`, get the code via `cargo run --release -- verify examples/test/foo.vp --result-code | tail -1`, **verify by reading the trace that each 0/1 is actually correct**, then add a `run_model` test and a `// Expected:` header arguing the code (see `aead_replay_not_forgery.vp`). Every model in `examples/test/` is wired to a test; keep it that way. Golden pretty-printer files live in `examples/test/golden_pretty/` (6), compared byte-for-byte.
- The test builders share one interner (`testutil::test_value_id`), so **unit tests must use unique constant names** (prefix per test, e.g. `cbw_m`). A test that both parses a model and builds a value by hand must take the constant from the parsed trace via `testutil::trace_constant`.
- **The corpus diff** is the check for an engine change meant to move only the verdicts it names: build a binary before and after, run `verify` over every model under `examples/` at one session and at two, and diff the full output, not the result codes. **Leave `examples/transport-layer/tls13.vp` out of every such sweep** (one session takes 31 minutes and 3.2 GB; the default takes longer), and `signal_twelve.vp` too. Neither is in the model-test suite.

### Checking *why* a verdict happened, not just that it did

A result code says nothing about the attack behind a `1`, so a battery of test-only checks sits underneath it, sweeping `examples/test/` (512 models) plus the twenty-five in `SWEPT_MODELS_OUTSIDE_EXAMPLES_TEST` — `examples/hpke/`, `examples/messaging/` (`signal_twelve.vp` aside), `examples/simple.vp`, the contact-tracing models — since `scuttlebutt.vp` shipped two unminimized witnesses and `signal.vp` an unguarded identity key that no sweep looked at. Re-measure the counts below after touching the corpus.

- **Witness replay.** Every `verify` under `cargo test` ends in `witness::assert_reported_attacks_replay`: for each resolved query it re-executes the reporting principal's pristine session with exactly the substitutions the minimizer kept, and fails if the query no longer resolves or the printed trace names *fewer* slots than the witness needed.
- **Narration shape.** `attack_traces_keep_their_shape_and_name_only_wires_that_exist` pins five exact sets: `TRACE_USES_A_GUARD_BYPASS`, `TRACE_IS_NOT_A_MINIMIZED_WITNESS`, `TRACE_IS_NOT_CAUSALLY_ORDERED`, `TRACE_FEEDS_BACK_A_LATER_VALUE`, `ATTACK_IS_REPORTED_WITHOUT_A_TRACE`. The bypass set is keyed on "does not halt", not "does not halt at", because a check bound to `_` has no slot name and was invisible to the ratchet. **All five are empty**: a new entry means an attack got a worse explanation; a missing one means an explanation improved and the pin should move. `cloudbackup.vp` is swept from outside `examples/test/` for exactly this.
- **Every step is re-derived** (`tracecheck.rs`). `Step` carries its structured operands under `#[cfg(test)]`, and every trace is checked before it is returned — ~560 attack verdicts and ~2400 steps at the default. **Well-foundedness**: each ingredient must be produced by an earlier step, installed by a mutation or replay, free (`Initial`), `theory::obtainable`, or assembled from justified parts, with `obtainable` asked against an attacker state **grown step by step** (`Grown`), since against final knowledge it held for everything. **Each claimed operation holds**, re-derived from the state: `Decomposed` re-runs `can_decompose`, `Obtained` must name a slot that travelled, leaked, is public or holds the value, `Leaked` a slot the model leaks and this run reached, `Broken` a capability `in_force` at the trace's phase, `Gate` a checked primitive whose rewrite succeeds on an attacker-tainted argument, `Bypass` a key `obtainable` confirms.
  A trace may also carry `Resolves`, `Static` and `Received` steps explaining a violation needing no attacker action. **These describe a state, so they must be built from the state the rest of the trace describes**: `attack_trace_with` takes them, and the **target** a `confidentiality?` trace claims, as closures evaluated against `witness.ps` *after* minimization. Building them from the answering state was the largest single fault source the metamorphic sweep ever reported.
- **Holds were searched** (`assert_holds_were_searched`): in an active model offering any controllable slot, every hold must have had `goals_for_query` called for it. Zero goals is fine; zero attempts is an untested claim. Freshness is exempt. **Holds are not stale** (`assert_holds_survive_final_knowledge`): every hold is re-evaluated at the end of the run against each principal's fresh trace with everything the attacker knew by then.
- **Both session counts.** The sweep verifies every model at one session and at the default; the narration-shape sets are measured at the default only.
- **Wire coherence and header intent.** The sweep rejects any step claiming the attacker replaced a value on a message the model does not have, or on a message every copy guards without a bypass, and requires each model's `// Expected:` line to match. 303 of the 429 analysing models state a code; the ceiling on the rest (`undocumented <= 126`) is a ratchet.

### The metamorphic harness (`src/metamorphic.rs`)

The checks above cannot see a *missed* attack. The harness transforms each swept model and asserts a relation between the two result codes; every property is a theorem about the **language**, so a violation is an engine bug. Transformations go parse → transform → `pretty_model` → **re-parse** → `analyze_sessions`. *Monotone* properties make the attacker strictly stronger, so no `1` may become `0`; *invariant* properties preserve meaning, so codes must match. All run at one session; `settle` refuses a pair count below the property's floor so a sweep cannot pass vacuously. Counts in parentheses are the `_exhaustively` twins.
| property | transformation | direction | compared |
| --- | --- | --- | --- |
| `unguard` | remove one `[guard]` | monotone | 292 (307) |
| `guard` | add one `[guard]` | monotone | 1844 (1943) |
| `leaks` | add `leaks c` | monotone | 1425 (1481) |
| `weaken` | add `weak` / `forgeable` | monotone | 1768 (1858) |
| `sessions` | `--sessions 1` → `2` | monotone | 429 |
| `dephase` | delete the last `phase[N]` | monotone | 30 |
| `promote` | `passive` → `active` | monotone | 84 |
| `demote` | `active` → `passive` | monotone | 314 |
| `rotate` | reorder the `queries` block | invariant | 273 |
| `rename` | alpha-rename every identifier | invariant | 413 |
| `pad` | prepend an unused `knows private` | invariant | 429 |
| `scenario` | add `scenarios[ P[c = c] ]` | invariant | 385 |
| `scenarios` | add a second copy of that scenario | monotone | 266 |
| `restrict` | add `precondition[…]` naming the last message to every query | monotone | 336 |
`dephase` deletes the *last* boundary so nothing needs renumbering. `rename` and `pad` probe the interner and the reserved id bands. `scenario` is the no-op case for the scenario front-end; `scenarios` is `sessions` monotonicity over the other axis. `restrict` asks the weaker question, so it is compared the way `demote` is. So is `guard`, which is `unguard` read the other way: a guard only takes capability away, so the variant may lose an attack and may never gain one. It is the property that catches a verdict moving *up* while the model got weaker, and it is how the `forgeable` reuse pairing was found — `cap_forgeable_aead.vp` and `cap_aead_weak_forgeable_matrix.vp` both gained an attack from one pair of brackets.

- **Two ratchets, failing in *both* directions, both currently empty.** `KNOWN_MISSED_ATTACKS` once held `exa.vp` under `unguard`; `KNOWN_BAD_TRACES` once held 28 entries that turned out to be four bugs. A violation outside a list fails; an entry that *stops* violating fails too. Staleness is judged only over models a run exercised.
- **A transformation that changes which runs are honest is not compared**: `asks_the_same_question` requires every scenario the original declares to keep its corrupt-from phase in the variant.
- **Binding a subterm to a fresh local constant is not an invariant.** A `name_intermediate` transform was written and reported two false attacks; both were false positives, since a use lifted out of a failing check is a use in a primitive of its own (`auth_with_signing_false-attack.vp` pins that shape as a genuine `a1`). Do not add the transform, and verify any metamorphic "false attack" against the pinned corpus before touching a gate.
- **Nothing is deferred and nothing is timed.** Every analysis runs to completion; the only skips are a file that does not parse or a variant failing `sanity`. Cost is bounded by `spread` (workers capped by `worker_cap()`, default 4, `VERIFPAL_METAMORPHIC_WORKERS`), by skipping models whose baseline holds no attack for monotone-stronger properties, and by `witness::MinimizingGuard` in `Sweep::Fast` runs, which skips minimization and narration. `unguard`, `leaks` and `weaken` run as `Sweep::Fast` under `cargo test` (the eleven `COSTLY_MODELS` left out); their `_exhaustively` twins carry `#[ignore]` and are what CI runs.

## Style and licensing

- Every source file starts with an SPDX header (`GPL-3.0-only` for code, `CC-BY-SA-4.0` for prose), including `.vp` test models.
- rustfmt with **hard tabs** and Unix newlines; clippy is a hard gate (`-D warnings`).
- **Do not write comments.** Reasoning belongs in the commit message and in this file, where it cannot drift silently against the source. `sessions.rs` keeps a module-level doc from before that rule, and `deduction.rs`, `reexec.rs`, `agreement.rs`, `context.rs` and `solve/mod.rs` carry item-level docs on the gates whose reasoning does not fit a name. Those are the register to match *if* asked for one; otherwise add none, including to code touched in passing. `.vp` test models are the exception — a new one must carry a `// Expected:` header arguing its code, since the `undocumented` ratchet cannot go up.
