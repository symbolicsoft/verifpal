# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Verifpal is a symbolic formal verification tool for cryptographic protocols. Users write protocol models in the Verifpal language (`.vp` files), and the engine checks security queries (confidentiality, authentication, freshness, unlinkability, equivalence) against a passive or active attacker, with each principal running two concurrent sessions by default (`--sessions k` to change it). Sessions are bounded: a passing query means no attack was found within that many sessions. It is a single Rust crate (`verifpal` 1.4.1, edition 2024, `rust-version 1.98`, GPL-3.0-only) building as a CLI binary and, separately, as a WASM library used by the Verifpal website and the VS Code extension. The [User Manual](https://static.verifpal.com/manual.pdf) is the language reference; `README.md` is the user-facing pitch. [*From Toy to Instrument: Seven Years of Verifpal*](https://eprint.iacr.org/2026/1654) is the paper — semantics, deduction rules, search, soundness theorem, termination bound and session model — and is the authority when this file and it disagree.

The engine is **sound but incomplete**: any reported attack must be genuine, but the search may miss attacks. Soundness is structural: the solver in `src/solve/` only ever *proposes* substitutions, and `validate.rs` re-executes each one concretely before any result can be recorded, so a solver bug costs a missed attack and never a false one. That is Theorem 4 of the paper, reduced to six facts about this code that `query.rs::tcb_tests` pins by reading the source (see "The soundness tests").

False attacks and missed attacks are the worst possible regressions. These models pin past false attacks:

| --- | --- | --- |
| `auth_with_signing_false-attack.vp` | `c0a1a0` | the `signature` authentication query must hold while the `ciphertext` one legitimately fails |
| `concat_split_replay.vp` | `a0` | a `SPLIT(CONCAT(…))` reducing to the honest value is a replay |
| `wire_projection_replay.vp` | `a0` | projecting a wire value back onto itself is a replay |
| `aead_replay_not_forgery.vp` | `a0c0` | a fully attacker-known ciphertext under an unreachable key is not forgeable |
| `equivalence_halt_scope.vp` | `e0` | halting a principal is not a divergence: a state truncated at a failed check cannot answer an `equivalence?` over slots it no longer holds |
| `foreign_halt_no_oracle.vp` | `a0` | a state holds every constant in the model, so an upstream mutation re-resolves *other* principals' values too; `truncation_point` honors only a failed check whose creator is the principal being re-executed, `PrincipalState::foreign_halts` records a foreign failed check and `slot_unreached` suppresses the values behind it, or `rule_equivalize` harvests a MAC forgery oracle. `exa.vp` (`c1`) is the counterweight: the same shape with no failing check is a *genuine* decryption oracle |
| `equivalence_halt_at_slot.vp` | `e0` at `--sessions 1`, `e1` at `2` | `truncation_point` keeps the *failing* slot, still holding a decryption that did not decrypt; comparing that is the same false attack. The `e1` at two sessions is the genuine cross-feed |
| `examples/transport-layer/piknik.vp` | `c0a0a1a1f0` | a substitution the attacker cannot build is not an attack: forging under Client1's signature needs `signprivkey` (never leaked) and the plaintext `m`. The two `a1`s are injective-authentication **replays**; a trace saying *replaces* rather than *replays* is the regression |
| `session_replay_breaks_injectivity.vp` | `a1` at `--sessions 2`, `a0` at `1` | `authentication?` is **injective**: replaying another session's honestly-signed pair forges nothing, but one send is accepted twice, so the query must fail. At one session there is no sibling to replay from |
| `session_peer_run_matches.vp`, `session_nonce_cross.vp`, `session_sign_oracle_cross.vp` | `a0` at every session count | a matching run of the same agent is not an attack: routing Alice's challenge to Bob's *other* run and its answer back gives Alice one Bob run agreeing on the data, nothing forged, no send accepted twice. The three cover ASSERT, SIGNVERIF and a first flight the matching run must authenticate before answering |
| `kem_secret_does_not_reveal_randomness.vp` | `c0` | `KEM_ENCAP`'s decompose hands the key holder the shared secret *and* the encapsulation randomness, but it runs on the ciphertext; applied at either projection it let a leaked secret plus a leaked decapsulation key yield the randomness. `kem_decap_reveals_randomness.vp` (`c1c1`) is the counterweight, where the ciphertext travels |
| `kem_secret_is_not_a_ciphertext.vp` | `c0` | a shared secret is not a ciphertext: `KEM_DECAP`'s rewrite undoes only the ciphertext projection. `kem_real_ciphertext_still_breaks.vp` (`c1`) is the counterweight |
| `incompatible_histories.vp` | `a0` | knowledge derived under one execution of a principal may not be spent against another: delivering `PUBKEY(nil)` as `gb` opens `e` for `na` but changes `e` so Bob cannot decrypt it; the honest `gb` gives the attacker nothing. `incompatible_histories_mitm.vp` (`c1a1`) is the counterweight: unguard `ga` and the two halves land on *different* principals, a genuine man-in-the-middle |
| `concat_bomb_equiv.vp` | `e0…f0` at `1`, `e1…f0` at `2` | halting Bob is not a divergence, but feeding him another session's bundle under the same long-term key is one |
| `precondition_halt_before_send.vp` | `a1a0` at `2`, `a0a0` at `1` | a violation outside a query's precondition is not an attack on that query: the replayed `e` is accepted, but Alice halts at her second check before sending `m2`, and the gated query is restricted to executions that reach that send. `precondition_accepted_key.vp` (`c1c0c0`) is the confidentiality shape, a session key derived before the signature check that then fails |
| `matching_run_routing.vp`, `matching_run_two_inputs.vp`, `matching_run_nested_term.vp` | `a0` at `1` | a value the declared sender's own run emits under the attacker's flight is not a forgery: feeding `nil` to both deliveries of Carol's nonce makes Alice honestly send `MAC(k, nil)`, which Bob accepts once. `agreement.rs` re-executes the sender to confirm it, and `matching_run_forged_not_emitted.vp`, `matching_run_forged_unguarded.vp`, `matching_run_constructed_not_emitted.vp` and `matching_run_halts_before_send.vp` (`a1`) are the counterweights: a leaked key with the sender's input guarded and then unguarded, a term built from nothing, a sender that halts before its send. The two-input model also needed alias chains resolved (`resolution.rs`), or Bob's own check compared a *name* against a value |
| `history_closure_incompatible.vp` | `c0c1c1a0a1f0f1e1e1` | the closure-route version of the same rule, `junglegym_hybrid_pq.vp` without its phase-3 `weak`: `kem_seed` is learned where Bob was handed `PUBKEY(nil)`, `sealed` exists only where he was handed the honest key, and every step from one to the other is a closure rule with no install for the validator's filters to see. `deduction.rs::combination_coheres` gates the combination where it is made (see "Execution coherence in the closure") |
| `history_incompatible_knowledge.vp` | `a0` | knowledge derived under one execution of a principal may not be spent against another, even when the revealing message went to a third principal: `Coherence::execution_agrees` re-runs Alice under the substitution the knowledge was recorded against and finds her `e` differs from the one Bob holds. `history_compatible_oracle.vp` (`a1`) is the counterweight, the same shape with the sealing key simply leaked |
| `nonce_echo_reflection.vp`, `webauthn_origin_binding.vp` | `e0e1` | a state reached by forwarding another principal's execution may only answer queries over values it legitimately holds (`PrincipalState::answers_for`): the forwarded slot carries what the sender computed while its unsent sibling is resolved through the recipient's own view, and comparing the two is a divergence nothing executed |
| `halted_use_is_not_acceptance.vp` | `a0` | a recipient that halts is not credited with a use it made on the way to failing. Measured the other way: counting a reached use beside an unreached one turns `concat_split_replay.vp`, the third query of both `spore_ns_pk.vp` and `spore_nsl_pk.vp`, and `piknik.vp` into false attacks |
| `conf_attacker_supplied_value.vp` | `c1c0` | the verdict stands but carries `Subtype::AttackerSuppliedValue`: Bob's local `d` became public `nil` because the attacker put it there, and the honest `d` is not shown to be disclosed. `conf_forced_key_is_a_real_disclosure.vp` (`c1`, no subtype) is a forced session key that still carries Bob's own exponent |
| `closure_halted_send.vp` | `c0c1c1` | `history_closure_incompatible.vp` with `sealed` computed before Alice's checks and sent after them: a truncated run still holds the slot, so the closure gate asks whether the *emission* was reached, and a wire read's cone runs up to the send |
| `closure_cyclic_union.vp` | `c1c1c0` | two installs each genuine alone whose union defines each slot in terms of the other: a replay that cannot execute is refused, not admitted because no state came back to check |

And these pin **missed** attacks, the other worst regression:

| model | code | what it pins |
| --- | --- | --- |
| `forward_transitive_relay.vp` | `f1` | a guard says the attacker did not alter a message in transit, not that the sender held an honest value: replacing `x` on the one unguarded leg decides what Dave hashes two guarded relays later. `forward_relay_all_guarded.vp` (`f0`) guards the first leg too |
| `forward_computed_under_guard.vp` | `f1` | Alice authenticates `MAC(k, nil)` because the attacker handed her `nil`, and sends it guarded; the attacker cannot build the tag, so only Alice's own re-executed run emitting it and that emission being delivered reaches it. `forward_computed_guarded_input.vp` and `forward_halted_sender_emits_nothing.vp` (`f0`) are the counterweights, and `forward_emission_is_not_a_forgery.vp` (`a0f1`) pins that a delivered emission keeps its sender |
| `pitoy_depth.vp` | `c1` at `2`, `c0` at `1` | Arapinis and Duflot's Pi_Toy: the initiator's whole message nested inside the shape the responder unwraps, two layers deeper than the protocol builds. Needs the per-slot term bound and the `aligned_held_free` family; one responder run is not enough, as it is not for ProVerif |
| `injective_recipient_nonce_unchecked.vp`, `injective_routed_emission_twice.vp` | `a0` at `1`, `a1` at `2` | duplicates the recipient could have told apart, carrying its own challenge, reported with `Subtype::DuplicateAcceptance`. The first is also the matching-run exemption on a leg running *from* the recipient, which only the recorded-substitution route sees |
| `closure_two_recipients.vp` | `c1` | one constant delivered to two recipients, each handed a different value in one execution: the closure gate keys a read's precondition by `(principal, slot)` and to the slot's creator, or Bob's `t1` and Carol's `t2` read as a contradiction |
| `matching_run_leaked_generated_key.vp` | `a1` | a leaked *generated* key is the attacker's own forging capability: `forgeable_without_sender` strips only assignment outputs, since a generated value does not depend on what the attacker installs |
| `blind_signature_forgeable_with_factor.vp` | `c1` | unblinding is a public operation: a passive attacker holding the factor, message and blind signature builds `UNBLIND(r, m, bsig) = SIGN(sk, m)`. The closure never applied a rewrite forward over held values, so `UNBLIND` — the one rewrite whose reduct is neither an argument nor `decompose`-reachable — was unreachable. `rule_rewrite_forward` closes it; `blind_signature_safe_without_factor.vp` (`c0`) withholds the factor |

"Known to the attacker" is not "forgeable by the attacker" — `aead_replay_not_forgery.vp` and `piknik.vp` hold that down. `piknik.vp` is reached through `run_model_at`, which takes a full path; `run_model` prefixes `examples/test/`.

CI (`.github/workflows/main.yml`) runs clippy, `cargo test --release` and the exhaustive sweeps on Ubuntu and macOS, plus a wasm clippy job for `wasm32-unknown-unknown`. A single warning fails the build. **CI only runs when the commit title contains `[ci]`** (or on manual dispatch), so a green tree means nothing until you tag a commit. Formatting is not gated in CI; `make lint` checks it locally, so keep the tree formatted.

**Releases do not run in CI.** `.github/workflows/main.yml` is the only workflow; `scripts/release.sh` is the whole release, running the test battery, the version bump, the tag push, goreleaser and the crates.io publish on the operator's machine. It needs `GITHUB_TOKEN` exported and `goreleaser`, `syft`, `zig` and `gsed` on PATH. goreleaser's before-hook installs `cargo-zigbuild` unpinned again (the 0.23.3 pin, which worked around 0.23.4 mis-parsing the `-Wl,-exported_symbols_list <path>` pair rustc emits for a macOS `cdylib`, was removed once upstream fixed it). The version bump runs `cargo update --workspace`, which touches only this crate's own lockfile entry: regenerating the whole lockfile there shipped dependency versions the test gate never ran.

```sh
cargo run --release -- verify examples/simple.vp             # full analysis
cargo run --release -- verify path/to/model.vp --result-code # appends the compact result code
cargo run --release -- verify path/to/model.vp --format html > report.html  # self-contained report
cargo run --release -- verify path/to/model.vp --format tex > report.tex    # LaTeX; tectonic report.tex
cargo run --release -- verify path/to/model.vp --sessions 1  # single-session; the default is 2 per principal
cargo run --release -- verify path/to/model.vp --saturate    # raise k until the verdicts stop moving
cargo run --release -- verify path/to/model.vp --auto-queries # replace the queries block with a generated one
cargo run --release -- pretty path/to/model.vp               # canonical formatter, to stdout
VERIFPAL_SOLVE_DEBUG=1 cargo run --release -- verify m.vp    # log every solver proposal to stderr
```

`verify` takes several models at once. `--result-code` only suppresses the banner; the code is the **last** line (`… | tail -1`), and it is refused beside `--format json|html|tex`, whose document would otherwise have the code prepended to it. `--fail-on-attack` makes a found attack a nonzero exit; `-q`/`-v` and `--color auto|always|never` are the remaining flags. Other subcommands: `about`; `diagram <model>` emits mermaid `sequenceDiagram` source; `lsp` is a language server over stdio; `completion <shell>`; `man` (hidden) prints roff or writes one page per command with `--output DIR`. `internal-json` is **gone**, replaced by `verify --format json`. The json, html, tex and LSP outputs are all built from `src/report.rs`; `verifpal-vscode` and `verifpal-nvim` are thin clients of it. `--format latex` is an alias for `--format tex`.

Errors carry a `Span` into the model source and print as `file:line:col: kind: message` with the offending line and a caret. Parser errors get the position the parser stopped at; `sanity.rs`/`construct.rs` attach the span of the query or declaration at fault via `VerifpalError::or_span`, which keeps the narrower span. Call `.located(file_name, &model.source)` at an entry point so plain `Display` shows the position.

`VERIFPAL_SOLVE_DEBUG` is the first thing to reach for when an active-attacker result is wrong: it prints each proposal as `[solve] <Principal> ran=<bool> [slot=value …]`, including the ones `validate` rejected as indistinguishable replays.

## Crate layout and features

- One crate: lib `verifpal` (`src/lib.rs`, `crate-type = ["cdylib", "rlib"]`) + bin (`src/main.rs`, requires the default `cli` feature). `main.rs` is CLI only; its tests cover only argument handling. Every stdout write there goes through the `out!`/`outp!` macros, which ignore a closed pipe rather than panicking, since `verify … | head` is an ordinary way to run it.
- **Every engine module is `pub(crate)`**; the public API is what `lib.rs` re-exports — the `verify*` family, `VerifyReport`, the saturation trio, `pretty_print`/`diagram`, `html_report`/`tex_report`, `lsp_run`, `Run`, the `info` verbosity functions, `ColorChoice`, the update-check trio, the `types` module (glob-re-exported), and the wasm entry points. `#![warn(unreachable_pub)]` is on, so a stray `pub` on an internal item fails CI; write `pub(crate)`.
- There is no `tests/` directory: an integration-test target collides with the `cdylib` on one artifact name, and wasm-pack needs the `cdylib`. End-to-end model tests live in `src/model_tests.rs`.
- Features: `cli` (default; clap, colored, ureq and `lsp`), `lsp` (crossbeam-channel, lsp-server, lsp-types), `wasm` (wasm-bindgen; entry points `wasm_verify`/`wasm_pretty` in `lib.rs`, returning JSON strings and buffering all output through `info::wasm_messages_*`).
- `#![forbid(unsafe_code)]` is on: the soundness argument is about what the code can reach, and `unsafe` would let any of it reach anything.
- The engine is single-threaded. A new parallel code path must be `cli`-only with a sequential `#[cfg(not(feature = "cli"))]` twin for WASM — **when you change one, change the other**, and run the wasm feature check. `VerifyContext` is interior-mutable, so it is safe to share.
- Release profile: `opt-level = 3`, fat LTO, 1 codegen unit, `panic = "abort"`, `strip = "symbols"`. Always work with `--release`.

## The Verifpal language (enough to write test models)

```verifpal
attacker[active]                    // or passive

principal Alice[
    knows public c0                 // also: private
    generates a                     // fresh value
    ga = PUBKEY(a)                  // public key from a private value
    k  = DH_KEX(gb, a)              // DH shared secret; DH_KEX(PUBKEY(b), a) == DH_KEX(PUBKEY(a), b)
    e = AEAD_ENC(k, m, ad)
    x, y = SPLIT(CONCAT(m, n))      // multi-output primitives bind several constants
    _ = HASH(m)                     // `_` is an anonymous constant (becomes unnamed_N)
    leaks something                 // hands value to attacker
]

Alice -> Bob: [ga], e               // [x] = guarded: attacker cannot replace it
                                    // `→` (U+2192) is accepted in place of `->`

phase[1]                            // phases must increment by exactly 1

principal Bob[
    d = AEAD_DEC(k, e, ad)?         // '?' = checked: failure halts this principal
]

scenarios[                          // optional, and it must come before `queries`
    Alice[gpeer = gb]               // run 1: Alice's peer is Bob
    Alice[gpeer = gm]               // run 2: Alice's peer is Mallory
]

queries[
    confidentiality? m
    authentication? Alice -> Bob: e
    freshness? x
    unlinkability? a, b             // ≥2 distinct constants
    equivalence? k1, k2             // ≥2 distinct constants
    // queries take an optional option block, e.g.:
    // confidentiality? k[ precondition[ Client -> Server: req ] ]
    // which restricts the query to executions in which that message is sent
]
```

Constraints enforced by the parser and `sanity.rs`:

- Nothing may follow the `queries` block, which must exist and come last. At most one `scenarios[…]` block, and it must sit directly between the last principal or message and `queries`; anything else is a parse error naming the rule.
- ≤128 principals (`sanity.rs::MAX_PRINCIPALS`). Principal names are title-cased, every other identifier lower-cased, so the language is case-insensitive throughout.
- Argument restrictions are declared per primitive in `spec.rs` (`argument_restrictions`) and enforced generically by `sanity_check_argument_restrictions`: `DH_KEX`'s second argument may not be a public key (this makes CDH structural), `DH_KEX` may not nest inside `DH_KEX`, `PUBKEY` may not take a public key.
- Primitive names resolve case-insensitively against the spec registry, which also fixes arity, output count and whether `?` is allowed.
- A model file's name must end in `.vp` and be ≤64 characters (`parser.rs::parse_file`).
- Constants cannot shadow reserved words: everything in `parser.rs::RESERVED`, plus any name starting with `attacker` or `unnamed`. **Adding a primitive means adding its lowercase name to `RESERVED` too**; `queries` and `scenarios` are in there for the same reason.
- A constant cannot be assigned twice, generated twice, `knows`n two different ways, sent by someone who does not know it, received by someone who already knows it, or declared `knows` by someone who already received it. `leaks` requires the leaker to know the value. `_` may name only an assignment's output. A principal cannot be named after a keyword (`Queries`, `Phase`) since the block parser dispatches on those words; `Attacker` is left to `sanity`, which has its own message. `nil` cannot be the subject of a `confidentiality?` or `freshness?` query; it may still be compared in an `equivalence?`, which `ringsign_ring_order.vp` does.
- Authentication queries are validated at load time: the sender must know the constant, the recipient must receive it and actually *use* it inside a primitive; otherwise a sanity error, not a failing query. A `precondition[P -> T: d]` option must name a message the model sends (`sanity_precondition` looks for a send event with that sender and recipient on `d`'s slot); receipt and use are not required, because the event is the send. Its errors carry the option's own span, and an undeclared principal inside one gets the same error as one in a query or message.
- Capability parameters are validated by `sanity_capabilities`: a capability the primitive does not declare, or a `from phase N` the model never reaches, is a hard error, since an assumption that silently does nothing reads as a check that was performed.

Primitives (arity → outputs), all 24: ASSERT(2), CONCAT(2–5), SPLIT(1→1–5), HASH(1–5), HKDF(3→1–5), AEAD_ENC/AEAD_DEC(3), ENC/DEC(2), MAC(2), PUBKEY(1), DH_KEX(2), SIGN(2), SIGNVERIF(3), PKE_ENC/PKE_DEC(2), SHAMIR_SPLIT(1→3), SHAMIR_JOIN(2), RINGSIGN(4), RINGSIGNVERIF(5), BLIND(2), UNBLIND(3), KEM_ENCAP(2→2), KEM_DECAP(2). Only primitives with a `definition_check` — ASSERT, SPLIT, AEAD_DEC, SIGNVERIF, RINGSIGNVERIF, KEM_DECAP — may take `?`. ASSERT, CONCAT and SPLIT are *core*: they live in `CORE_SPECS`, reduce through hand-written Rust rather than a declarative rewrite rule, and several theory functions bail out on them (`primitive_is_core`). Everything else is data.

**Capability parameters.** A call site may carry bracketed weakening assumptions between the name and the arguments: `PUBKEY[weak](a)`, `SIGN[forgeable](sk, m)`, `AEAD_ENC[weak, forgeable from phase 2](k, m, ad)`. `from phase N` means *from phase N onward* and binds to the preceding capability; absent it, the capability holds from phase 0.

- `weak` — confidentiality is lost, so holding the term yields what it protects. Declared by `weak_reveals`/`weak_reveals_output`: `HASH` (every argument), `AEAD_ENC`, `ENC`, `PKE_ENC` (plaintext), `KEM_ENCAP` (shared secret), `PUBKEY` (the private key). `PUBKEY[weak]` is discrete log, and the DH cascade falls out of `can_reconstruct_primitive` with no DH-specific rule — `cap_weak_pubkey_dh.vp` pins that.
- `forgeable` — authenticity is lost, so the term is constructible without its secret. Declared by `forgeable_secret`: `SIGN`, `MAC`, `RINGSIGN`, `AEAD_ENC`. Splitting this from `weak` makes `AEAD_ENC[forgeable]` — forgeable but unreadable — expressible; `cap_forgeable_aead.vp` keeps the two apart.
- `malleable` — the ciphertext can be reshaped into another the recipient accepts, under a key the attacker never learns. Declared by `malleable_vary`: only `ENC` (position 1, the plaintext). It needs **two** cooperating halves: `solve/deduce.rs::solve_by_malleability` offers it as a goal, and `solve/validate.rs::malleable_positions` grants the matching derivability exemption — without the second the TCB rejects every such proposal and the rule looks implemented but never fires. Both are gated on the attacker holding a term of the same shape agreeing on every non-varying position. `cap_malleable_enc.vp` against `cap_malleable_absent.vp` (`a1` against `a0`) keeps this from being a no-op or a blanket authenticity break. A primitive declaring `forgeable` is pointed at that instead (`cap_err_aead_malleable.vp`); one declaring neither is a hard error (`cap_err_malleable_unsupported.vp`).

`weak`, `forgeable`, `malleable` and `from` are **contextual keywords**, deliberately absent from `RESERVED`: they are recognised only inside the parameter brackets, so reserving them would gratuitously break models using `weak` or `from` as a constant name.

Comments (`//` and `/* */`) are captured into AST nodes so `pretty` round-trips them. A comment inside a bracket or an argument list (a primitive's arguments, `attacker[…]`, `phase[…]`, a scenario binding, a query option) is kept too, attached as a leading comment of the statement being parsed, so it moves above that statement rather than being dropped. A `\r` before a line comment's newline is not part of the comment, so a CRLF file formats to one line ending. Primitives nest at most `MAX_NESTING` (64) levels; deeper is a parse error rather than a stack overflow, which under `panic = "abort"` took the language server down with it.

## Architecture

### Pipeline

```
parse_file (parser.rs)              hand-written recursive-descent, comment-preserving AST
  → expand_scenarios (scenario.rs)  one model copy per declared peer scenario
  → expand_sessions (sessions.rs)   k copies of that, one per concurrent session
  → sanity (sanity.rs)              model validation; drives construct.rs
      → construct_protocol_trace    "km": ProtocolTrace — global immutable protocol description
      → construct_principal_states  one PrincipalState per principal
  → VerifyContext::new (context.rs) shared mutable state for the whole run
  → verify_passive (verify.rs) | verify_active (solve/mod.rs)      per phase
  → verify_end                      prints results, returns the results code
```

`verify::analyze(&Model)` is the **one** place that sequence exists; it is `analyze_sessions(m, DEFAULT_SESSIONS)`, and `verify::verify(path)` is `verify_with_sessions(path, DEFAULT_SESSIONS)`. The wasm entry points and the language server call `analyze`, so the CLI, the IDE and the website cannot disagree about what a model means — **do not give one entry point its own default.** Throughout, `km` is the `ProtocolTrace` and `ps` a `PrincipalState`.

### Parallel sessions (sessions.rs)

Every principal runs `DEFAULT_SESSIONS` (2) concurrent sessions unless `--sessions k` says otherwise. `expand_sessions` is a *front-end*: it clones every principal and message block `k` times in the parsed `Model` **before** `sanity` runs, so the expanded model is a legal model the user could have typed and the feature inherits the engine's attack-soundness. `generates` constants and assignment outputs get per-session copies (`c#s`, rebanded via `value.rs::copy_value_id`, which takes **one** index over the scenario-by-session grid; `MAX_COPIES` is 30 and band 31 is the minimizer's), while `knows` constants stay shared. Clones are emitted in place; within-phase attacker *knowledge* is atemporal, and causal order is enforced separately at the install by `reexec.rs::CausalOrder`. Each written query is kept verbatim (session 1) and given per-session **variants** (`VerifyResult.variants`) resolving the same `query_index`, so the result code keeps one entry per query and an attack in any session resolves it; `verify_resolve_queries` and `goals_for_query` iterate original + variants.

Sessions make **injective agreement** expressible, and `authentication?` is injective: a received value equal (after the same resolve-and-reduce recipe as `reexec::attacker_authored`) to a session sibling's honest wire value is a cross-session replay, and a replay is an authentication failure even though nothing was forged. `query.rs::session_sibling_replay` *classifies* such a report so the narrator says "replays" rather than "replaces". A scenario clone is a run too, and a flight one scenario's Alice sent to its own Bob, delivered to another scenario's Bob, is the same replay; `ProtocolTrace::copy_siblings` groups every copy of a base constant across **both** expansion axes (`verify.rs::copy_sibling_groups`, over `copy_index_of`) so `copy_sibling_replay` can label it. It is consulted **after** `emitted_by_matching_run` has declined, never before: the session-axis test runs first and skips the exemption, but a cross-scenario replay of an honest run is exactly what the exemption exists to excuse, and testing the copy axis first would flip those `a0`s and break the `scenario` metamorphic invariant (an identity scenario is a no-op only because of that exemption). So the copy axis can turn "replaces" into "replays" on an `a1` and can never move a verdict; the corpus was diffed at both session counts to confirm it. `scenario_replay_is_a_replay.vp` pins it, and `solve/mod.rs::sibling_flight_substitutions` deliberately stays on the session axis, since widening it changes the proposal set rather than a label.

**Expansion clones are runs, not agents, and a delivered value is not attacker-authored merely because it is not the one this run expected.** `install` stamps `ATTACKER_ID` on a slot's sender whenever the value differs from the recipient's pristine expectation, which conflates *rerouting* with *authoring*: routing Alice's challenge to `Bob#2` and its answer back gives Alice a matching run, nothing forged and no send accepted twice, and reporting it is a false attack. `agreement.rs::emitted_by_matching_run` is the third classification: it looks for a trace slot carrying the same base constant, created by a run **interchangeable with** the declared sender and sent to a run of the recipient's own agent, then *re-executes that run* with this recipient's own flight routed into it (`run_copy` takes the recipient slot's copy index, so the routed values are what this recipient actually sent) and confirms it emits the delivered value. Only re-execution decides — over `attacker_can_derive`, `TermBound` and `Controllable`, exactly as `validate.rs` does — so a bug here costs a reported attack and cannot invent a hold. The pristine-sibling replay is tested **first**, so a value the sibling emits in its honest run stays a replay, and installs are limited to slots declared before the target.

`ProtocolTrace::interchangeable` and `ProtocolTrace::actors` define "same run, same agent". Session clones are always interchangeable. Scenario clones are interchangeable only where the scenario left *that* principal's bindings alone (`scenario.rs::peer_binding_key`): a scenario rebinds one named principal, so its clones of every *other* principal are the same configuration while its clones of the named one are a different peer. Canonicalising by base name instead would excuse Lowe's attack — `spore_ns_pk.vp`/`spore_nsl_pk.vp` both keep `a1` on `authentication? Alice -> Bob: m1` for exactly that reason, beside the `a0` this rule earns on `Bob -> Alice: m2`. The recipient side is matched by **agent**: `Bob#2` sending to `Alice#2` is Bob sending to Alice.

`emitted_by_matching_run` now runs at every session count and excuses nothing the attacker could have produced on its own: `forgeable_without_sender` takes every read off the sender's runs out of attacker knowledge, transitively, and if the delivered value is still `derivable` the forgery stands whether or not the sender could have been driven into emitting it. The `unguard` metamorphic property found this: removing the guard from `matching_run_forged_not_emitted.vp` let the attacker drive Alice and the exemption then excused a tag it had forged under the leaked key (`matching_run_forged_unguarded.vp`, `a1`). Only reads of **assignment outputs** are taken away: a `knows` constant is static data whose slot creator is only its first declarer, and a `generates` constant holds the same value whatever the attacker installs, so a leak of either is the attacker's own capability rather than an emission a run was driven into. Stripping a leaked generated key excused a forged tag (`matching_run_leaked_generated_key.vp`, `a1`; `a0` while it was stripped). Past that gate there are three routes, each ending in a re-execution of the sender's run: the **mirror** installs into the sender the values the attacker handed *this recipient* on the wire (`delivered_to`: attacker-tainted slots whose `wire` contains the recipient), the **record** installs the tainted diffs recorded against the delivered value but only where that value was `Obtained` at the sender's own slot (a constructed value's record is inherited ambient and re-running under it excuses forgeries by coincidence; `flawed_pubkey_directory.vp` lost its minimized witness that way), and the **routing** route is the original sibling-flight one. The mirror once read every tainted slot and mirrored a slot the recipient never receives, which made the canonical MitM candidate exempt itself inside the minimizer.

**A duplicate is reported, never silenced, and labelled.** `Subtype::DuplicateAcceptance` marks a replay the recipient could have distinguished because the value carries something it generated (`recipient_contributed`); `Subtype::ReplayableFirstFlight` marks one over a first flight it contributed nothing to, with one `Info` line per query saying so. Suppressing the second kind was implemented and measured: it silences forty verdicts, among them the 0-RTT replay of `tls13-0rtt.vp` that RFC 9846 §2.3 names as a property the protocol does not have. Deferring a duplicate so an origin failure can still be found was also measured: zero verdicts moved and three witnesses stopped minimizing, so a duplicate resolves the query as before and the label is what tells the reader to look at `--sessions 1`.

In `query_authentication_get_pass_indices` the `original ≡ value` guard runs first, so a value carrying no per-session freshness never reaches the sibling test, which is why value-equality is a sound proxy for run-correspondence. `--sessions 1` cannot report a replay at all, and that is the count at which the corpus's "this is not a forgery" models pin their original claim (`a_false_attack_pin_survives_at_one_session`). `k = 1` skips expansion entirely and is bit-for-bit the pre-sessions behavior; across `examples/test/` the corpus costs about 0.9s at one session against 7.3s at two.

At `k > 1` the active search runs in two passes, gated by `VerifyContext`'s `prefer_replication` / `replication_only` / `replication_rejected`. The first pass has `validate.rs` refuse any proposal whose term the principal itself produced *and* that carries its own fresh value (`replays_own_freshness`); the second runs with the flag off only if something was refused and queries remain. This decides which witness the user sees first — genuine cross-session traffic rather than a principal fed its own nonce — and, since both passes use the same validator, can neither find nor lose an attack. `replication_rejected` is sticky across phases by design.

Forty-three models in `examples/test/` answer differently at one session and at two, almost all the pristine-value replay above; `concat_bomb_equiv.vp` is the `equivalence?` one. Re-measure both corpora before touching the default.

### Causal availability (reexec.rs::CausalOrder)

Deriving a term is not the same as holding it *in time*. `attacker_phase_update` publishes every wire value the phase reaches before any principal runs, and that atemporality is what lets one run's traffic be routed into another regardless of block order. Read alone it also lets the validator satisfy a check with a message the protocol only sends *because* that check already passed: `atemporal_forward_value.vp` is that cycle written out, and it is a false attack.

`CausalOrder::of(km, principal)` answers "what could this principal not yet have been handed". `influenced_from` is a fixed point over send events: the receive being attacked happens at `declared_at = at`, so `principal` is influenced from `at`, any message it sends at or after `at` influences its recipient from that point, and so on. A trace slot is **blocked** for that receive when its creator is influenced from at or before the slot's own `declared_at`, `nil` and public constants excepted. `available` then walks attacker knowledge in learning order and keeps a value only when its `DerivationRecord` does not bottom out in a blocked slot. **It has to follow the derivation, not compare against pristine trace values**: `later_value_fed_back.vp` installs `AEAD_ENC(ka, nil, nil)`, no slot's honest value, harvested from Bob's own later slot under a mutation. `validate.rs` re-runs its own `derivable` against the restricted state, so a term the attacker can genuinely *build* from causally available parts is still admitted; only one it could only have *received* from downstream is refused. Results are cached per (blocked set, attacker `known` vector), the vector held by `Arc` and compared by identity, which makes it free. The key was once (blocked set, knowledge *size*): `validate.rs` hands `available` whichever state `Coherence::compatible` returned, and two proposals authoring different slots get two restricted states of equal length with different members, so a size key answered one proposal's derivability question with the other's restriction.

Session and scenario clones never message each other, so no cross-copy edge exists and `session_replay_breaks_injectivity.vp` / `session_peer_run_matches.vp` are untouched. `exa2.vp` and `kem_direction_reflection.vp` are genuine reflections whose source precedes the receive, so nothing is blocked. Across `examples/` the guard moved exactly two verdicts to `a0`: `later_value_fed_back.vp` and `scuttlebutt.vp`'s `secretBox1Bob`.

### History coherence (reexec.rs::Coherence)

Attacker knowledge is global and monotone, and a re-execution installs into a pristine state, so one substitution can supply the knowledge while a *different* execution of the same principal supplies the values it is spent on. `incompatible_histories.vp` is that shape (see the pin table).

`Coherence::of(km, ps)` records, for each slot this principal receives from someone else, the value its creator honestly produces. `compatible` walks attacker knowledge in learning order as `CausalOrder::available` does and refuses an `Obtained`/`Leaked` at one of those slots whose term is not the one being handed over. `validate.rs` uses the restricted state both for derivability and as the state `reexecute` runs against — the second half is not optional, because it is `try_guard_bypass` that spends the incompatible `na`.

**It has to be the derivation and not the `MutationRecord`.** A record is an *ambient snapshot*, not a set of necessary conditions: `compute_slot_diffs` compares each slot against the trace's unresolved declaration, so every resolved slot is a "diff", and reading those as preconditions costs `kem_direction_reflection.vp` its reflection and `forged_statement_rebuilt.vp` its `c1`. Reading only the `tainted` diffs is not the fix either: the reproducer's disagreement is at `e`, an untainted consequence of the tainted `gb`.

`Coherence::execution_agrees` is the second half, for the case `forwards` cannot see: the revealing message went to a third principal, so no slot the target receives was read. It takes the tainted diffs recorded against the held value, re-executes every principal the target is handed values from under the diffs observed in that principal's own state (a `SlotDiff` names its state; installing a diff into every recipient of its slot re-ran principals the substitution never touched), and refuses the value if any slot the target holds from that principal, and this proposal is not itself authoring, comes out different. Re-execution decides, so a bookkeeping error costs a refusal and never invents one; results are memoised per (record pointer, authored set). `history_incompatible_knowledge.vp` against `history_compatible_oracle.vp` is the pair, and across `examples/` it moved no other verdict.

Three conditions keep it narrow, each found by losing something without it. The slot must be one the principal **receives from another principal** (comparing its own outputs would demand that a proposal against Bob carry Alice's mutations). The read must have happened in the run of the slot's **creator** or in another run of the **executing principal itself**; a read while walking a third principal says only what that one received. And it is skipped where the proposal installs an **attacker-authored** value at that slot — but *not* where it reinstalls the honest value, which is a forward by another name. `incompatible_histories_mitm.vp` is the counterweight. Across `examples/` at one session and at two the guard moves exactly one verdict.

### Execution coherence in the closure (deduction.rs::combination_coheres)

`Coherence` and `CausalOrder` filter what the validator may install; the closure and query evaluation read global knowledge. A derivation that closes entirely inside the closure therefore never meets either filter, and knowledge is global and monotone, so a rule can combine a value read out of one execution of a run with one that exists only in another. `learn` now refuses such a combination. For a derivation with ingredients it collects the reads each ingredient bottoms out in (`Obtained`/`Leaked` leaves, each with the tainted substitution it was recorded under), merges those substitutions, and: refuses outright if two reads need **different values at one slot of one principal**; passes without a replay if the union is empty or every read carries the same substitution; otherwise replays the union (`reexec::replay_diffs`, every principal handed part of it re-executed under its own part and the runs carried forward together through `forward_to_fixpoint`, cached in `VerifyContext::replayed` per substitution set and phase) and requires every read recorded under a different substitution to be *reached* there: the slot held, not behind a foreign halt, and its emission not withheld by the reader's own halt (`withheld_by_own_halt`). A union whose seeds cannot execute at all is refused, not admitted for want of a state to check (`closure_cyclic_union.vp`). Re-execution decides, so a bookkeeping error costs a deduction and never invents one, and the metamorphic sweeps are the ratchet against over-refusal.

Three things about the keys. A `SlotDiff` carries the **state** it was observed in, and a need is `(principal, slot, value)`: one constant travels to several recipients, and an execution that hands Bob `t1` and Carol `t2` over the same slot is one execution, not a contradiction (`closure_two_recipients.vp` was `c0` keyed by slot alone). A read's preconditions are keyed to the slot's **creator**, whatever state it was read from: every state holds every constant, so Bob's state re-resolves Carol's answer with Bob's own installed input, and a value Carol computes is often first learned out of Bob's state; recorded against Bob, the need contradicted Bob's other install, and replayed against Bob it seeded the wrong principal. And the union is built from the reads' cone-filtered needs plus the current state's ambient for a derivation that reads it, never from the whole record of every visited term: an ambient lists every install in a state, first-wins, and a read's needs disagreeing with an irrelevant one at the same slot refused sound combinations by traversal order.

Two things were needed for the reads to be *found*. **The `obtainable` cascade rebuilds keys in place** without learning them, rewriting a term and reconstructing from the rewritten arguments (`can_reconstruct_primitive`) or projecting from a sibling output it can open, so the seed sits two layers inside a key nothing in attacker knowledge names; `collect_reads` asks the cascade which arguments it rebuilt from (`ReconstructResult::from`, `DecomposeResult::used`) and follows those, and does not guess at routes, because a route the cascade did not take would refuse sound combinations. **An install is a boundary provenance did not cross**: a value read out of a state whose inputs were attacker installs depends on whatever those installs depended on, so `read_preconditions` follows each installed value in a read's cone into that value's own reads and takes their needs too. The cone of a wire or leaked read runs up to the **emission** (`emitted_at`), not the declaration: a check between the two gates the send, and a slot computed before a failed check and sent after it is held by the truncated run and never left it (`closure_halted_send.vp`, the pinned false attack reached through a change of declaration order). Without it the two-session route through Bob's second run survived: his flight under Alice's real key routed into Alice, the seed from his run under `PUBKEY(nil)`, and `sealed` read out of Alice carrying only her own installs. `history_closure_incompatible.vp` pins both; `junglegym_hybrid_pq.vp` keeps its `c1` through the declared assumption and its witness now minimizes, which is why `TRACE_IS_NOT_A_MINIMIZED_WITNESS` holds one entry only: `closure_two_recipients.vp`, whose attack hands two recipients different values over one slot. The minimizer's vocabulary is `(slot, value)` with a probe that installs the same value into every session controlling the slot, so no candidate reproduces that witness; the verdict is right and the fallback trace says it is unminimized, but its first step names one recipient with the other's value. Keying `witness.rs` installs by principal is the open follow-up.

### Forward execution (reexec.rs::execute_forward)

Atomic replay re-executes one principal against accumulated knowledge, which cannot express a value whose only route to its recipient is the sender computing it: a guard says the attacker did not alter a message in transit, not that the sender computed on honest inputs. `execute_forward` runs the chosen principal, then delivers every message it sends to its recipient *as it actually came out* and runs those recipients too, to a fixed point bounded by the principal count. Only an emission that *differs* from the honest value is delivered, judged by `attacker_authored` against the trace: a pristine state holds the unresolved declaration, so comparing against that forwarded every computed term, re-executed and re-closed every reachable principal on every proposal, and marked honest values as tainted preconditions downstream. Nothing in the corpus changed but the analysis counts. `validate.rs` and `witness.rs::probe_with` both go through it, which is what lets the minimizer pick the *origin* principal as a witness base and have the query resolve downstream. A forwarded state always carries at least one tainted slot, since only a differing emission is forwarded and `install_forwarded` taints it, so `seeded_mutations` is never empty for one; the `driving_substitution` fallback that re-supplied the origin's installs from a context-wide "last execution" record was ablated (a panic on its forwarded branch survived the whole suite) and removed.

A forwarded value is not an attacker choice and is not tested for derivability; it is justified by the sender having sent it, so `forwarded_installs` checks the send event, the phase, that the sender reached the send and that it did not halt before the slot, and `a_forwarded_value_is_only_ever_what_its_sender_sent` pins every one of those. `install_forwarded` sets `attacker_tainted` and nothing else: taint makes the slot a **precondition** of whatever is learned downstream (a record that did not say so let knowledge from a forwarded run be spent in an execution where the substitution never happened, and `piknik.vp`, `ringsign.vp` and `mutual_auth_both_directions.vp` all reported false attacks), while `sender`, `creator` and `original` stay honest, so no authentication claim is disturbed and purification is still total (`forward_emission_is_not_a_forgery.vp`). Pure forwarders are controllable now (`attacker_controllable` admits an unused slot the principal sends on), because a substitution there has a downstream consequence it did not have before.

A forwarded state is faithful about what its principal was handed and unfaithful about the sender's private slots, so `PrincipalState::forwarded` gates `query_start` through `answers_for`: such a state answers only queries over constants it legitimately holds. Propagating the sender's private slots too was tried and handed the Server the Client's session key (`precondition_foreign_halt.vp`); gating every state on `known` was tried and lost `concat_bomb_equiv.vp`, whose `equivalence? a, a_b` compares an Alice value with a Bob one that no single state holds.

### Peer scenarios (scenario.rs)

`scenarios[…]` instantiates a principal's counterparty differently across concurrent runs, which is what makes the role-confusion family (Lowe/Denning-Sacco) expressible. Like `--sessions` it is a **front-end expansion** run *before* session expansion, so `p` principals with `s` scenarios at `k` sessions analyse `p*s*k` principals, under `MAX_PRINCIPALS` (128) and `MAX_COPIES` (30, so `s*k <= 31`).

An entry binds constants inside **one** named principal: `Alice[gpeer = gb]`. Scenario *k* is clone *k* of the whole model with only the named principal's bindings substituted, so N scenarios are N configurations, **not** a cross product. The bound `knows` declaration is dropped from the clone and the constant replaced everywhere in that principal, then freshened like any expansion copy (`gm@2`). An identity binding (`gpeer = gpeer`) is a genuine no-op, which two metamorphic properties rest on.

`sanity_scenarios` rejects, before expansion, a principal the model does not declare, a target that principal does not `knows`, a value no principal declares, a target bound twice, and a target that travels over the wire (the substitution is per-principal, so a recipient would go on naming a constant the sender no longer has). A typo in the principal name once turned the NS-PK `c1` into a passing `c0`.

**Corruption is inferred, not declared.** `compromised_constants` seeds from constants both leaked and secret and closes over assignments mentioning them, so `gm = PUBKEY(mk)` with `leaks mk` marks `gm` compromised while `leaks gb` on a public key does not. A scenario binding a compromised value is a **corrupt-peer run**, which decides two separate things:

- `VerifyContext::is_honest` gates the **honest-run check**. A corrupt-peer clone legitimately fails a checked primitive, so `generate_trace` partitions `perform_all_rewrites`' failures by the failing slot's *creator* and only raises `sanity_fail_on_failed_checked_primitive_rewrite` for honest creators. The suppressed ones still **halt** the clone through `reexec::halt_at_failed_checks`; otherwise it publishes values the protocol cannot reach (the `foreign_halt_no_oracle.vp` shape).
- `VerifyContext::claims_apply_to` gates **query evaluation** (`query_start` returns before touching a corrupt run's state), the analogue of Scyther's `prune_theorems.c:439`. Because knowledge is global and monotone, a *confidentiality* break first noticed inside a corrupt run must still be reported against the honest ones, so `verify_active` and `verify_passive` re-run `verify_standard_run` once at the end of each phase when relativisation is in force and queries remain. The verdict then lands on an honest principal that may have *halted*, which `witness.rs`'s seed bound has to survive.

Both read the same set but differ where it is `Some(empty)`: the honest-run check stays relaxed, query evaluation does **not**, since relativising against nothing would report a vacuous hold. `honest` is `None` with no `scenarios[…]` block, and every predicate answers `true`. The set is computed over the scenario-expanded model and **extended across session expansion** (`SessionExpansion::principal_clones`); forgetting that switched the honest-run check off for every session-2 clone.

**Phase seeding is reachability-aware, and both halves are load-bearing.** `attacker_seed_phase` publishes from the never-truncated `principal_states[0]`, so it once handed the attacker post-halt wire values of a halted corrupt clone. `verify::honest_run_halts` now derives, once per analysis, the earliest failed checked slot per creator in the honest run (`reexec::creator_halts`), and `attacker_phase_update` withholds every wire or leaked slot at or past it. **Withholding alone loses attacks**, because a substitution can make the check pass (`spore_ns_pk.vp`'s `m3@2` is genuinely on the wire under Lowe's substitution), so `attacker_absorb_disclosed`, called from `compute_knowledge_closure`, re-publishes exactly the withheld slots *this* execution reached. `scenario_post_halt_no_oracle.vp` and `scenario_post_halt_leak_no_oracle.vp` (`c0`) pin the false attack shut against `scenario_pre_halt_oracle.vp` (`c1`), with `scenario_honest_peer_only.vp` (`c0`) as the control. Both halves return immediately for a model without scenarios.

Queries **are** cloned per scenario: `expand_scenarios` mints one `variants` entry per *honest* scenario, then `expand_sessions` session-clones each. A corrupt scenario gets no instance — its break is real but not the protocol's to answer for. The block is **normalised honest-first**, because it is a set: the written query names scenario 1's constants and `authentication?` is evaluated against scenario 1's recipient, so a corrupt scenario 1 made the query unfalsifiable and exchanging two entries flipped verdicts (`scenario_order_is_not_a_verdict.vp` against `…_swapped.vp`).

Compromise is **phase-indexed**: the honest set maps a principal to the phase from which its run is corrupt, so a peer whose key leaks at phase 3 is honest for phases 0-2 (`scenario_peer_compromised_later.vp` against `…_throughout.vp`). `claims_apply_to` and `relativises` read the current phase, so where nothing is honest relativisation switches itself off.

Models: `spore_ns_pk.vp` (`c1a1a0`, Lowe's attack, found rather than assumed) against `spore_nsl_pk.vp` (`c0a1a0`). Both declare `scenarios[]`; without a peer axis the two are indistinguishable at every session count, and that pair separating is the acceptance criterion for the feature. Do not add a scenario-free variant of either to `examples/`.

### Verdict envelope

Every `VerifyResult` carries an `Envelope { sessions, truncations }`, printed after a PASS line (`[search exhausted at 2 sessions]` / `[search truncated: term depth]`), serialized into `QueryReport.envelope`, and shown on the HTML verdict row. An attack is never qualified by the envelope, but may carry a `Subtype` (`AttackerSuppliedValue`, `DuplicateAcceptance`, `ReplayableFirstFlight`) printed as a bracketed qualifier on the FAIL line, serialized as `QueryReport.subtype` and as `subtype` on each `wasm_verify` result (omitted when there is none, so the Workbench prints the same bracketed qualifier after the query), and shown in the HTML ruling and the TeX verdict table. The `Note:` lines a trace can end with (not minimized, not causally ordered, feeds back a later value) live in `VerifyResult.notes`, not in `trace`, so `QueryReport.notes` carries them into every format rather than the console alone. A query `--auto-queries` generated has no span; `QueryReport.generated` says so and the HTML and TeX rows print "generated" where a line number would be. Both fields are omitted from the JSON when empty or false, so the contract is additive. `Truncation` has one variant, `TermDepth`, recorded by `context.rs::note_depth_cut` **against the queries still unresolved at that moment**; `finalize_envelopes` stamps each result with only the truncations that could have cost it, so a term declined while solving one query no longer marks an unrelated passing one.

**"Exhausted" means the search space this engine defines was fully explored at these parameters, never that no attack exists.** Never let "proof", "verified", "correct" or "complete" into this output: the completeness inventory lists narrowing sites permanently in force that are *not* reported as truncations.

### `--auto-queries` and `--saturate`

`autoquery.rs::auto_queries` derives a query set and `--auto-queries` **replaces** the model's own block with it after `sanity` has validated the model as written. Three rules, each mirroring a sanity constraint so a generated query can never be rejected (`generated_queries_all_pass_sanity` sweeps the corpus): `confidentiality?` for every `generates` and `knows private` constant with a trace slot; `authentication? S -> R: c` for every wire delivery whose recipient uses `c` inside a primitive; `freshness? c` for every constant actually sent (`sent_by`, not `known_by`) and used. `unlinkability?` and `equivalence?` are skipped.

`verify::saturation_sessions` raises `k` from `DEFAULT_SESSIONS` to `SATURATE_MAX` (4) and stops at the first count whose result code equals the previous one, returning the **analysis** of that count. It starts at the default rather than one because an attack needing three concurrent runs leaves one and two reading alike, and a ladder beginning at one called that saturated before it reached three (`saturation_never_stops_before_it_has_looked_above_the_default`): each run is wrapped in `info::InfoCapture`, so the reported run is replayed rather than analyzed twice. `Saturation` distinguishes saturating from hitting the ceiling, and `attack_disappeared` warns if an attack vanishes at a higher count, which is an engine bug.

### Core data model (types.rs)

- `Value` = `Constant` | `Primitive(Arc)`. Constants are interned per model (`value.rs`; `nil` is id 1); equivalence compares ids. DH uses ordinary `PUBKEY(sk)` and `DH_KEX(pk, sk)`; their commutativity is declared by `PrimitiveSpec::commutativity` and consumed generically by `equivalence.rs`, `hashing.rs` and `solve/matching.rs`.
- `Primitive` carries a `HashCell`: a term's hash is computed once, making `hash_value` O(1) and letting `Value::equivalent` reject on hash inequality first. Terms are immutable once built; the single in-place mutation (`construct.rs`, setting a multi-output `output` index) clears the cell.
- **Invariant: `a.equivalent(b)` ⟹ `a.hash_value() == b.hash_value()`** (`hashing.rs` uses a commutative hash for DH exponents). `AttackerState::knows()` looks up by hash bucket first, so breaking this silently breaks attacker knowledge. Unit tests pin it.
- `Primitive.capabilities` is deliberately **not** consulted by `primitive_hash`, `equivalent_primitives` or `theory.rs::structurally_identical_primitive`: an annotated term and its twin are the same object (`cap_noop_annotated.vp` against `hmac_ok.vp`). The engine reads capabilities from the `CapabilityIndex` on `PrincipalState`, **never** off a held copy, because `AttackerState` dedupes by equivalence and an unannotated copy arriving first would silently disable the rule. `solve/deduce.rs`, whose goals contain free variables, unifies against the index's annotated terms instead. `construct.rs` inserts each annotated call three ways: as written, resolved through the trace, and resolved then reduced. The closure looks up the *rewritten* state value, so a call whose argument reduces (a `SPLIT` projection, a decryption) missed the bucket and its assumption silently never fired (`cap_weak_on_reduced_argument.vp` `c1c1`, `cap_forgeable_on_reduced_key.vp` `a1`, both `0` before). `can_break_weak` and `can_decompose` reduce what they reveal for the same reason.
- `SlotValues` holds **three values per slot**, the most important invariant in the engine: `original` (what the protocol honestly computed, what the principal *believes*), `pre_rewrite` (after mutation, before rewriting; forensics), `value` (after mutation and rewriting; what analysis uses). `PrincipalState::should_use_original`/`effective_value` and `resolution.rs::compute_visibility` decide which a principal sees; getting this wrong causes false authentication attacks. A fourth field, `bypassed: Option<Value>`, holds the key a defeated guard was made to accept, kept separate so `original` has one meaning and `clone_for_depth(true)` is total.
- `Provenance` rides alongside: `creator`, `sender` (`ATTACKER_ID` = 0 when injected), `attacker_tainted`, `bypass_injected`. The last two are **deliberately separate**: taint decides what a principal perceives, and a guard bypass must not change that, but the substitution must still be reportable.
- `SlotMeta` is the immutable half: `constant`, `guard`, `known`, `wire`, `mutatable_to` (recipients it reached *unguarded*), `known_by` as `(recipient, sender)` pairs, `declared_at`, `sent_at`, phases. `mutatable_to` is what `symbolic.rs::reaches` and `compute_visibility` consult.
- `PrincipalState::halted_at` records the `declared_at` of the earliest checked-primitive failure after mutation; `reexec.rs` sets it and truncates there, `deduction.rs::rule_equivalize` uses it to suppress `leaks` never reached.
- `AttackerState`: append-only `known` + `known_map` hash index + `mutation_records` and `derivations`, both parallel to `known`, plus `alternates`, every further `Route` (a derivation with the record of the execution it was found in) that *reads a state* (`reads_from_state`: `Obtained`, `Leaked`, `Reconstructed`) to a term already held. Derived routes are not retained: recording a `ConcatFragment` route per `CONCAT` a fragment sits in made the duplicate-learn path, a hash lookup before, scan every recorded route with `same_route` on each closure pass, and `concat_split_replay.vp` went from 4.5s to 53s. The causal and history filters still follow the primary route only, deliberately: letting any recorded route stand in for it was measured and returns three pinned false attacks (`incompatible_histories.vp`, `history_incompatible_knowledge.vp`, `atemporal_forward_value.vp`), because a route found in one hypothetical is a route only in executions like it. A `MutationRecord` is the set of slot diffs that had to be in force for the attacker to hold that value, plus the principal and phase. A `DerivationRecord` says *how*: `Initial`, `Leaked`, `Obtained`, `Decomposed`, `Reconstructed`, `Recomposed`, `ConcatFragment`, `Rewritten` (a rewrite rule applied forward over held arguments, `tracecheck` re-runs `can_rewrite(of)` against the target), `Broken`. Narration walks this DAG, so **a rule that adds knowledge without recording an honest derivation produces an unexplainable trace.**

### Provenance travels along derivation edges (context.rs)

`derivation_provenance` decides which `MutationRecord` attaches to a newly learned value: one **read out of a principal's state** picks up that state's ambient diffs; one **combined out of held values** inherits *their* records and adopts the session of the ingredient carrying the leverage; `Initial` and `Injected` get an empty record. Snapshotting the ambient state at absorption time instead describes one attack's actions beside another's consequences. `attacker_state_absorb` also *upgrades* an existing record when the stored one explains nothing and the arriving one does; knowledge is unchanged, only the explanation.

**Cancellation has exactly one conversion point.** `VerifyContext` carries an `Arc<AtomicBool>` checked beside every `all_resolved()` short-circuit. Those loops only ever *stop*; the flag becomes `Err(ErrorKind::Cancelled)` at the foot of `analyze_sessions_traced_cancellable` and nowhere else, so an interrupted search reports nothing rather than reporting an unreached query as holding. Adding a second conversion point is how you manufacture false "holds". `scratch_for_query` inherits the flag.

`VerifyContext` is the interior-mutability container shared by `&VerifyContext`. `attacker_put_with` dedupes new knowledge; `results_put` resolves each query at most once; `principal_states()` hands back every principal's pristine starting state; `scratch_for_query(i)` builds a disposable context that can only answer query `i` and cannot write back.

### Standard run (verify.rs)

`verify_standard_run` is shared by both attacker kinds — the active search uses it as its passive baseline. Per principal: **trace generation** (`generate_trace`: `resolve_all_values`, `perform_all_rewrites`, sanity checks — a failed *checked* primitive here is a model error unless its creator is a corrupt-peer clone, which halts), **knowledge closure** (`deduction.rs::compute_knowledge_closure`), **query evaluation** (`query.rs::query_start`). Closure never checks queries. Each phase resets attacker knowledge (`attacker_init`) and re-seeds from `principal_states[0]` resolved and rewritten (`attacker_seed_phase`, then `attacker_phase_update`; seeding the unrewritten spelling gave the attacker two spellings of every wire term): **every** public constant plus every wire or leaked value whose earliest phase has been reached. Skipping an unmentioned public constant once made `confidentiality?` hold over it (`public_constant_is_never_confidential.vp`).

### Knowledge closure (deduction.rs)

A monotone fixed point over three rule groups, each pass running all three over a snapshot of knowledge taken at its top: (1) over attacker-known values: `decompose`, `break_weak`; (2) over principal-assigned values: `reconstruct`, `recompose`, and `rule_rewrite_forward`; (3) over attacker-known values: `equivalize`, `concat_extract`. Termination is Knaster–Tarski. Every rule ends by calling `learn`, which records the value with its `DerivationRecord` and emits the `Deduction ›` line; its message argument is a closure because minimization re-runs the closure with output suppressed. `rule_equivalize` carries one guard: if the principal halted, a `leaks` it declared *after* that point never fired.

`rule_rewrite_forward` is the one rule that reads a slot's `pre_rewrite` rather than its `value`, because it applies a **rewrite rule forward** over a term the attacker can build: for a principal-assigned `pre_rewrite` that `can_rewrite` reduces and whose every argument is `obtainable`, the attacker learns the reduct (`DerivationRecord::Rewritten { of, using }`). `reconstruct` rebuilds a value only from its own arguments, so it could never reach `UNBLIND(r, m, SIGN(sk, BLIND(r, m))) = SIGN(sk, m)` — the one rewrite whose reduct is neither an argument nor `decompose`-reachable — leaving a passive attacker that holds the blinding factor unable to unblind (a missed attack). For every other rewrite the reduct is already learned earlier (`DEC`/`AEAD_DEC`/… by `decompose`, `SPLIT` by `concat_extract`), so `learn`'s dedup makes this a no-op there; only `UNBLIND` actually needs it. `blind_signature_forgeable_with_factor.vp` (`c1`) pins it against `blind_signature_safe_without_factor.vp` (`c0`), where the withheld factor is not `obtainable` so the rule cannot fire.

### Query evaluation (query.rs)

`query_start` returns before touching a corrupt-peer scenario's state (`ctx.claims_apply_to`). Past that, each kind resolves differently, and `solve/mod.rs::goals_for_query` mirrors these exactly:

- **confidentiality** — the attacker knows the slot's resolved `value`. When that value differs from the honest one and, read through the state (`carries_a_secret` follows assignment outputs into their definitions, since a use-site constant carries no declaration), holds nothing generated or private, the result carries `Subtype::AttackerSuppliedValue` and the conclusion says the honest value is not shown to be disclosed. Across the shipped corpus no query earns it.
- **authentication** — **injective agreement**, the only mode. Evaluated only while walking the recipient. Fails when the slot's `provenance.sender` is not the declared sender *and* the constant is successfully used inside a primitive the recipient computed (`query_find_constant_usage_indices`: no rewrite rule, or the rewrite passes, or unchecked) *and* no interchangeable run of the declared sender emits the delivered value (`agreement.rs::emitted_by_matching_run`). **"Used" is visibility-aware**: `resolution::state_mentions` walks the recipient's own computation and counts an occurrence only where it *reaches* the owner of the enclosing term (`owner == ps.id || meta.mutatable_to.contains(owner)`, the same predicate as `compute_visibility` and `symbolic::reaches`). Walking the global trace instead counted a constant buried inside an opaque blob the recipient never opened; `piknik.vp` had two such false attacks. `sanity_queries_check_known` and `autoquery.rs` share the predicate through `resolution::principal_uses_constant`. Two failure shapes carry the same `a1`: a **substitution** and a **replay**; `session_sibling_replay` classifies, `AuthFailure` carries it, `narrate.rs` routes replays into `Step::Replay`, and `witness.rs` has a matching `replayed_from` candidate family.
- **freshness** — the value transitively contains no `fresh` constant yet is used in a primitive. The solver never proposes anything for it.
- **unlinkability** — the attacker exhibits a *link witness* for some pair of the queried constants (`unlink.rs::find_link_witness`). Both must be observable and neither slot attacker-authored (an attacker overwriting two slots with one value manufactures the equality). Four witness kinds, cheapest first: **observed equality**, **identifying check** (a `definition_check` primitive with a declared identifying position succeeds over both under one participant's key), **common secret origin** (`origin_leaves`, which withholds each value from the attacker first — receiving a value explains nothing about whose it is), and **recognized secret** (`recognized_secrets`). The manual's two-world definition is the specification; this is a decision procedure, sound for attacks and incomplete.

  The identifying check names the input the **checking** primitive needs (`unlink.rs::check_input` runs the rule's filter over {the produced argument, its key derivation, its peeled inner}): `KEM_ENCAP`'s argument is already the public key while `KEM_DECAP` needs the private one, and reading the identifier off the producing side linked two KEM ciphertexts to anyone holding the public key (`unlink_kem_needs_the_private_key.vp` against `unlink_kem_leaked_private_key.vp`). `is_key_derivation` is structural: a `PUBKEY`-headed value names a participant, not a session.

  **Observable is not "this constant appeared on a wire".** `carried_observably` asks whether the resolved value occurs as a subterm of some wire or leaked slot **and** whether the attacker holds it. The second half is not optional — `witness_identifying_check` needs only the *key*, so without it two signatures under an unbroken key link on shape alone (`unlink_carried_in_ciphertext.vp` carries both cases). The subterm half is why a merely recomputed value does not count (`unlink_never_sent.vp`, though that model is held by the self-exclusion, so the filter is correct-in-principle and untested). This is what makes `junglegym_threshold_ring.vp`'s two blind signatures `u1`: bundled into `vault`, which `escrow` (`c1`) opens.

  `recognized_secrets` exists because `origin_leaves` stops at any term the attacker can *test* but not *recompute* — `SIGN` and `RINGSIGN` under an unheld key. If the attacker holds the term and can supply every input the undoing check's `matching` pins (`check_input_held`), each pinned argument it independently obtains is confirmed to sit inside that term. The candidate must `depends_on_secret` and must not be a `bypass_key` constructor application, or `RINGSIGNVERIF`'s ring members would link every ring signature (`unlink_ringsign.vp`). `unlink_signature_recognized.vp` pins the rule; `flawed_blind_factor_public.vp` is what the shared-origin witness could never reach. `identifying_positions` is empty for `RINGSIGNVERIF` on purpose (`unlink_ringsign.vp` versus `unlink_signature_links.vp`, structurally identical with opposite verdicts).
- **equivalence** — the queried constants do not all resolve to equivalent values, using the *mutated* value. A `forwarded` state additionally answers only over constants it holds (`answers_for`). It first requires that this state *hold* every queried value: `reexec::drop_after_index` truncates a halted principal, `resolve_constant` answers a missing slot with the bare constant, and comparing that placeholder is a divergence nobody computed. This is why `concat_bomb_equiv.vp` and `triple_dh.vp` hold; in the latter, unguarding `gb_ident` makes the real MitM available and the query fails again.
- **precondition** — `Q[precondition[P -> T: d]]` restricts `Q` to the executions in which P reaches the send of `d` to T, so the property must hold whenever P goes on to send `d`. `preconditions_reached` runs in every evaluator after the violation is detected and before `attack_trace`, and an unreached send returns with no verdict recorded, so the probe re-checks it through the same evaluator and a minimized witness satisfies it by construction. The event is a `sent_by` entry with that sender and recipient, in a phase at or before the current one, that `event_reached` confirms the sender did not halt before; receipt and authenticity of `d` are other queries. Adding an option can only remove violations, which the `restrict` metamorphic property pins over the corpus. The `!` line under a trace, `report.rs`'s `preconditions` and the HTML and TeX renderings all render the conjunct, never an annotation: a query whose precondition is not reached did not fail, so nothing prints. It was an annotation on a failing query until 1.4.1, and the manual's own definition was the one implemented here. The `precondition_*.vp` models cover every query kind (`precondition_freshness_halt.vp` `f1f0`, `precondition_equivalence_accepted.vp` `e1e0` at one session and a genuine `e1e1` at two, where replaying the other session's share-only signature completes the client on a key the server lacks, `precondition_unlink_halt.vp` `u1u0`), a third party's halt against its own earlier send (`precondition_foreign_halt.vp` `c1c0c1c0`), one constant sent to two recipients around a halt (`precondition_two_recipients.vp` `a1a1a0`), several options on one query (`precondition_many.vp` `c1c1c0`), a send in a later phase (`precondition_later_phase.vp`) and scenario expansion (`precondition_scenarios_ns_pk.vp`). The seven `err_precondition_*.vp` models pin the parse and sanity rejections, and `a_gated_query_reports_every_precondition_exactly_when_it_fails` sweeps every model carrying one. Knowledge is global, so a link witness rebuilt from secrets learned in a halting execution still counts against the honest one; `precondition_unlink_halt.vp` derives its key from a DH share the attacker cannot recompute for exactly that reason.

When a query resolves, `attack_trace` minimizes the state (`witness.rs`) and narrates it (`narrate.rs`), seeding the minimizer with the mutations recorded against the *value* rather than whatever state answered.

### Equational theory (theory.rs + primitive/spec.rs)

All cryptographic behavior is **declarative data**: `PrimitiveSpec` entries define decompose (a rule yields a **set**, `Reveal::Argument(i)` or `Reveal::Output(i)`; it must describe everything the legitimate key holder learns — `KEM_ENCAP` reveals **both** shared secret and encapsulation randomness, because ML-KEM's re-encryption check re-derives the coins, while `weak` stays a declared assumption revealing the secret alone), recompose (threshold shares), rewrite (with matching constraints and filters), rebuild (SHAMIR_JOIN), and guard-bypass key extraction. `theory.rs` interprets them (`can_decompose`, `can_reconstruct_primitive`, `can_rewrite`, `can_rebuild`); `obtainable` is the shared "can the attacker get this argument at all" cascade. A rule consuming a multi-output primitive names the projection — `rewrite.from_output`, `decompose.output` — and `build_rewrite_shapes_with` mints its shapes at that output.

A rewrite rule's `matching` is discharged as a **bijection**: `can_rewrite_primitive` assigns each outer position a *distinct* inner one, mirroring the `taken` set on the construction side. Only `RINGSIGNVERIF` has overlapping `inner_idxs`; before, a ring collapsed onto one member still verified (`ringsign_ring_collapse.vp`). `can_reconstruct_primitive` refuses a core primitive whose reduction is the term itself: `ASSERT` denotes a check, and letting it into knowledge printed "Attacker constructs ASSERT(…)" and blocked minimization. `SPLIT` reduces to a field and still reconstructs.

None of it carries a recursion cap, and reintroducing one is a regression: every `to` rule returns a subterm or reassembles strict subterms, and every decompose filter returns an argument or something inside one, so the descent is well-founded on depth. The memo is keyed on the term hash **alone**; keying on depth too took the suite from two seconds to six minutes for the same attacks. `can_rewrite` is the one reducer: it applies `can_rebuild` (`SHAMIR_JOIN`) to the argument-reduced term before the rewrite rule, and `rewrite.rs::reduce_term` is the state-walking wrapper over it. There were two, one rebuilding and one not, so `reduce_once` of a term holding a join disagreed with the state's own value, `attacker_authored` judged an honest reinstall of such a term authored, the minimizer preferred that no-op over the real forgery, and a cross-session replay of it lost its `Subtype`.

**To add a primitive, edit only `src/primitive/spec.rs`** — `build_primitive_specs` is the whole table; the nearest primitive is the template. Core primitives go in `build_core_specs` and need a `core_rule_*`. Add the lowercase name to `RESERVED` in `parser.rs`, then model tests. Several spec fields are read as *direct* slice indices (`rewrite.from`, `recompose.reveal`, `rebuild.reveal`, `bypass_key`), so `every_spec_index_is_within_the_primitive_it_is_declared_on` (`primitive/mod.rs`) holds those to the *narrowest* declared arity and the bound-checked fields to the *widest*, and pins `arg_names` to the widest so signature help never runs out of names.

### Active attacker search (src/solve/)

Goal-directed: the engine asks what the attacker would need in order to learn this and whether it can arrange that, solving backwards from each query; it does **not** enumerate substitutions forwards. There is no per-principal budget and no `SearchConfig`. Termination comes from memoisation, cycle cutting and a finite basis, never from a cap on how hard to look. The one bound on term *shape* is `reexec::TermBound`, and it is **per slot**: the depth of the deepest term the protocol computes, plus the number of layers the recipient itself peels off that slot (`peel_depth` follows the slot through the principal's own rewrite-bearing consumers, `PKE_DEC` then `SPLIT` then `PKE_DEC` is three), with the room above the flat cap spendable only where the excess is carried by the protocol's own subterms (`depth_over_protocol`). The absolute cap is what keeps the search finite: counting held terms as free was tried and an oracle returning a term one layer deeper each round ratcheted forever. `validate` refuses what the bound does not admit and `note_depth_cut` says so on stderr the first time.

Per phase: passive baseline, then rounds to a knowledge fixed point. Each round runs `Pass::Targeted` for every principal, then `Pass::Constructed` for every principal — never interleaved, or a principal offering a large pile of constructible values delays the one that matters.

- `symbolic.rs` — the principal's computation with every attacker-controllable wire slot replaced by a variable, reduced as `perform_all_rewrites` would. `reexec::attacker_controllable`, reached through the `Controllable` token, decides controllability (guarded-unless-`mutatable_to`, self-created, wrong-phase, unused-by-this-principal; `nil` excluded). A DH public key becomes `PUBKEY($x)`, so the MitM shape falls out of the representation. Terms are memoised per slot. `reaches` mirrors `compute_visibility`.

  **The refinement search**: `build` replaces every controllable slot with a variable; `build_assuming_honest` leaves one slot at its honest value. A search seeing only the variable cannot reason *through* the honest value: in `exa.vp` with `msg2` unguarded, `AEAD_DEC(k2, $msg2, c)` stops reducing and the goal yielding `msg1=c` is never generated (`relay_rewrap_oracle.vp` against `relay_rewrap_no_oracle.vp`). It runs **only after** `search_fixpoint` reaches its fixpoint with queries outstanding (`Search::Direct` then `Search::Refined`), **only in `Pass::Targeted`**, and **after** the unrefined pass — offered first it degrades `identity_misbinding_uks.vp` and `ringsign_ring_substituted.vp` into `TRACE_USES_A_GUARD_BYPASS`. Cost lands on the largest models (`piknik.vp` 1.7x, `signal.vp` about 1.5x). `slots_blocking_reduction` picks candidates: a slot whose variable sits in the position a rewrite rule inspects on a primitive that cannot fire. **One slot is held honest at a time**, so a divergence needing two is out of reach; the cost of that is unmeasured.
- `vars.rs` — attacker variables are interned `Constant`s in reserved id ranges (`ATTACKER_VAR_BASE = 0x8000_0000` for slots, `FREE_VAR_BASE = 0xC000_0000` for free choices). Free positions stay variables until materialisation; committing them early makes partial solutions unmergeable, and `ground_free` fills every one with the same `nil`, which is why `diverge::distinguish` exists.
- `matching.rs` — one-sided `match_value`, two-sided `unify`, and `merge` (which unifies conflicting bindings), all modulo DH commutativity as a closed two-case analysis. All three refuse a binding whose variable occurs in what it is bound to (`vars::occurs`), or the unifier answers with rational terms and `vars::apply` never returns; `merge` must repeat the check when it *overwrites* a binding.
- `deduce.rs` — the solver. Goals are discharged by: already-known, bare-variable (`nil`), **replay**, wire unification, oracle (restricted to the finite basis), rewrite-match, primitive-by-arguments, decomposition, `invert` (backwards through rewrite rules and `SPLIT`/`CONCAT`), and `satisfy_check`. Bindings from unification are put under obligation by `require_constructible`, which forces the DH substitution in a real MitM. Goals are memoised on the applied goal's hash, the bucket disambiguated by `equivalent`; results computed while a cycle was cut are not cached. `satisfy_check` inverts through the rewrite position when it is not a bare variable and tries every rewrite shape.

  **Inverting a rewrite solves an equation; it does not fill a hole.** `rewrite_shape_yielding` fills the positions `matching` leaves free with **fresh variables** and unifies `to(shape)` against `target`. Filling them with `target` is right by accident where `to` projects the position verbatim and wrong everywhere else: `UNBLIND` pins only `SIGN`'s *message*, so dropping the target into the key nests it a level deeper on each inversion and enumerates `SIGN(SIGN(…))` chains to `TermBound` — 2.5GB and no finish in ten minutes on an unguarded `junglegym_threshold_ring.vp`, against 24MB and one second. `inverting_a_rewrite_solves_for_the_target_rather_than_nesting_it` pins the shape.
- `diverge.rs` — equivalence queries. `solve_divergent` grounds the variables reaching only one side to `nil`. When both queried values are projections of one installed term, any single value makes them agree, so `distinguish` hands each free position its own value from `fillers()`: `nil`, then `HASH` at every declared arity. Every rung is derivable from nothing (`every_divergence_filler_is_derivable_with_no_attacker_knowledge`), the ladder is injective across a `CONCAT`'s positions (`the_ladder_separates_every_position_a_concat_can_hold`), and it survives `normalise_arguments`. Additive, gated on an unresolved `equivalence?`. Models: `equiv_forged_bundle_projections.vp` (`e1`), `equiv_forged_bundle_far_fields.vp`, `equiv_sealed_bundle_holds.vp`/`equiv_guarded_bundle_holds.vp`, `unlink_forged_bundle_not_a_link.vp`.
- `validate.rs` — **propose and dispose**, the only route from the search into query evaluation. Every proposal is materialised into a concrete `PrincipalState`, re-executed via `reexec.rs`, and re-checked against real attacker knowledge. Its guard order is load-bearing and asserted by `tcb_tests`: controllability, then derivability, then queue the install, then execute. Its `derivable` is an independent proof that knows nothing about the solver, so the two capability exemptions (`forgeable_secret_position`, `malleable_positions`) must be repeated here. `worthwhile` skips any proposal whose every install reduces to the honest value (`reexec::attacker_authored`), today a performance guard. Errors from a hypothetical state are swallowed.

Proposal families, in offer order: goals from each unresolved query; `constraint_goals`; the **blanket** substitution (every controlled slot replaced by the attacker's own value); one single-slot substitution per controlled slot; and, only in `Pass::Constructed`, the **sibling flight** substitutions plus per-slot candidates drawn from held protocol terms and from shapes the recipient's rewrite rules demand — each alone, with the blanket, and with a **relay** forwarding every other slot unchanged. Every proposal still carrying free positions is then offered three more times through `fill_aligned`: `keyed_free`, `preserved_free`, and (only while an `equivalence?` is unresolved) `diverge::distinguish`.

`keyed_free`: **where the protocol put a public key, offer the attacker's own.** A free position is committed to `nil`, and where the honest term holds a `PUBKEY(…)` there `nil` is the one value that cannot be the attack. It keys only aligned positions: keying a plain-value position overwrites a tag the recipient asserts on, and filling every free position costs 1.84x with `concat_split_replay.vp` going 2.4s to over two minutes. `forged_key_swap_bundled.vp` (`c1c0`) is the regression, `forged_key_swap_bare.vp` (`c1`) the case `slot_candidates` already reached, `witness_key_swap_bundled.vp` (`e0`) the same substitution by hand.

`preserved_free`: **keep the field you are not attacking.** A forgery often replaces one position while threading the honest sibling through, so that a statement the verifier reconstructs later still matches a signature harvested earlier. It fills each free position with the honest term's own argument where the attacker holds it — `witness.rs::payload_shapes` already did this for narration, so the family existed in the minimizer's vocabulary and not the search's. `forged_statement_rebuilt.vp` (`c1c1`, from WalletConnect v2 One-Click Auth) was `c0c1` before; `forged_statement_on_wire.vp` (`c1c1`) is the counterweight; `witness_statement_rebuilt.vp` (`e0`) executes it by hand.

`aligned_held_free`: **where a forged shape leaves a ciphertext position free, offer every held protocol ciphertext under the same key.** `preserved_free` fills a free position with its honest occupant only where the attacker holds it; an oracle attack puts something else there, a message the attacker already has under the key the recipient will use, so that what comes back is one layer of a term it was never meant to open. The occupant fixes the head and the key, the basis is the protocol's own subterms as for `slot_candidates`, and `pitoy_depth.vp` (`c1` at two sessions) is the model: its nineteen-step trace nests Alice's whole `m1` where Bob expects an inner ciphertext, with the attacker's key as the peer. Offering every held term rather than protocol subterms made the family grow with what the attacker had assembled; the first attempt took the suite from 136s to 747s, the shipped one to 194s. The held terms are now indexed once per `propose` by (head, output, arity, key hash) and each proposal's free positions look their candidates up (`free_positions`), rather than every proposal walking all of attacker knowledge; the proposal set and its order are unchanged.

`sibling_flight_substitutions` makes injective agreement reachable: `relay_substitution` resolving the *sibling* constant, one proposal per sibling index installing that session's whole honest flight at once, because a replay pairing one session's key share with another's ciphertext fails the recipient's checks. `tls13-0rtt.vp` is the regression (RFC 9846 §8 needs `gce`, `binder` and `earlyData` together). **It belongs in `Pass::Constructed`**: offered early, `bypass_witness_narration.vp` degrades into a shallower replay of the same `a1`.

`constraint_goals` builds a **forged authenticated flight**, the shape of every server-impersonation attack. A `SPLIT` over a decryption it cannot reduce is discharged by materialising the plaintext as a `CONCAT` of exactly the arity the projections demand (`satisfy_split`, `widest_projections`); without that the recipient's own transcript puts the signature position out of reach via the occurs check. The set is then re-solved in **additive refinement rounds** under the bindings found so far, so a Finished MAC over a transcript is reached on a later pass; rounds are bounded by the number of checks. They must only ever **add** proposals, and `bind_from_shape` still refuses a shape with an unbound position; both were tried the other way and cost real attacks (`forged_flight_mitm.vp`).

**The attacker's option set is the thing to be careful with, and narrowing it silently is this engine's characteristic bug.** At every position the options are `{honest value}` plus everything derivable. Four missed attacks came from replacing that set with one representative: `vars::ground_free` narrowed what the search **proposes** (closed by `distinguish`, `keyed_free` and `preserved_free`), `symbolic::build` narrowed what it can **derive** (closed by the refinement search). No one of them subsumes another. The rule: **never commit to one representative where the commitment is unrecoverable; defer it and enumerate**, applied in whichever layer the fifth instance lives. `src/metamorphic.rs` found none of these — no transformation in it turns a shallow forgery into a bundled one. **When a fifth is suspected, look first at whether the minimizer can already say something the search cannot**: twice a family `witness.rs` had was a family the search lacked.

Proposals are deduped by what they would **install** (`solve/mod.rs::install_signature`), not by substitution identity: on `tls13.vp` at the default that collapses 11653 proposals to 3861 distinct states. The dedupe does not span rounds, since knowledge grows between them. Variables the solver never bound are left free and `validate` skips those slots; grounding them would fail an unrelated check.

**Skeletons are gone.** `skeleton.rs` added each primitive's shape with secrets erased to attacker knowledge; those are values the attacker already holds, so removing it changed no verdict and improved ten traces, because a free-floating `ENC(nil, nil)` let `attacker_can_build` accept a degenerate witness before `payload_shapes` offered the explanatory one. Do not reintroduce a rule that hands the attacker a shape it did not derive.

### Re-execution (reexec.rs)

`reexecute` installs attacker-chosen values into a principal and runs it forward: install → check the slot graph is still acyclic → resolve → rewrite → then either bypass guards the attacker can defeat (`try_guard_bypass`, keyed on the spec's `bypass_key`; uncapped, since each round must flip a fresh `bypass_injected` flag) or truncate at the checked primitive that halts the principal and set `halted_at`. Bypass works from the *pre-resolution* state, because injecting into an inlined state does not propagate. It exists because substituting `PUBKEY(nil)` for an identity key fails a signature check while the attacker knows that private key.

`bypass_is_constructible` keeps that from becoming a licence: holding the `bypass_key` is necessary and **not** sufficient; every other position the rule's `matching` pins must be `obtainable` too. `KEM_DECAP` pins only the key; `AEAD_DEC` also pins the associated data, `SIGNVERIF` the message, `RINGSIGNVERIF` the ring and message. `bypass_needs_the_whole_check.vp` and `bypass_needs_the_signed_message.vp` pin the refusal; `…_ad_leaked.vp` and `…_public.vp` are the counterweights. A `bypass_key` is declared only on a primitive that can take `?`, since `try_guard_bypass` runs only on a failed check: the entries `DEC` and `PKE_DEC` carried could never fire and were removed, and `a_bypass_key_is_declared_only_on_a_primitive_that_can_be_checked` holds the table to that.

Four guards decide what the search may touch, all travelling to `validate.rs` inside `Guards`: `Controllable` (`Controllable::of`, one per solving pass; fields private so nothing outside `reexec.rs` can mint one; `admits` re-checks principal and phase), `TermBound`, `CausalOrder`, `Coherence`.

`slot_graph_is_cyclic` is what lets `resolution.rs` carry no depth cap: `install` is the only thing writing a slot out of declaration order, and the search will offer a slot a value naming that same slot (`piknik.vp` proposes `ekid = ENC(DH_KEX(PUBKEY(keygen), ekid), CONCAT(n, m))`). `reexecute` returns `Err` and `validate` drops it. A slot holding a primitive has an edge to every slot the primitive mentions; a slot holding another slot's bare name, which only an install creates, has an edge to that slot, since an alias cycle (`y := x` with `x = HASH(y)`) passed the check and recursed without bound in `resolve_ps_values`. This lives in one place because `validate.rs` and `witness.rs` **must agree exactly**, or the minimizer drops a mutation the engine needs and reports a trace that does not reproduce.

### Attack traces (witness.rs + narrate.rs)

**`witness.rs::minimize_witness`** — the solver installs the union of the bindings for *every* goal it pursued, so a raw witness carries substitutions other queries needed. The minimizer picks a **candidate** per principal's pristine session (the query's own first): the canonical MitM (attacker's key wherever a DH public value arrived over the wire), then the recorded mutations, then those with public keys replaced by `PUBKEY(nil)`, taking the first that still resolves the query; then drops mutations one at a time while the query keeps resolving. If nothing replays it falls back to `unminimized` with `reproduced: false` and claims no attacker actions.

- **"First candidate that resolves" is not "the candidate that explains", so the choice is ranked.** `try_guard_bypass` defeats a checked decryption the moment the attacker holds its key, so `ciphertext := nil` resolves almost any authentication query and narrates as a defeated check when the real attack is that the attacker owns the session key. The minimizer prefers any witness where **no** bypass fired (`needs_guard_bypass`), and `drop_one` refuses a drop reintroducing one. `forged_from` **constructs** a bypass-free witness: it stages a base substitution, asks the recipient's own failed checks what shape they wanted (`perform_all_rewrites` plus `build_rewrite_shapes_with`), and offers that forged term for each controlled non-key slot. Building rather than looking up matters: the good term is often derived *later* than the moment the degenerate witness resolved.
- `payload_shapes` fills a rule's free positions three ways: `nil`, the honest term's own argument where the attacker holds it, and the attacker's own public key where the honest term carries a key derivation. `forged_from`/`forged_alone` offer the explanatory shapes **before** any `nil`-filled one, and `attacker_can_build` keeps the family honest. This is ordering, not searching: every candidate still goes through `probe`, so it changes which witness is shown and never the verdict. It is what makes `test1.vp`, `test3.vp` and `test5.vp` reseal the real `m`/`m2` instead of `nil`. The third filler is currently unexercised and kept because `noise_xx_mutual.vp`'s bypass pin needs it, blocked one layer out in `forged_flight`.
- `examples/silly/cloudbackup.vp` is the model to read: a MitM on `g_file_alice_a_key` transiting Alice → Server → Bob unguarded while both long-term keys are guarded. If a change makes that trace mention `nil` again, it is a regression the verdict will not catch.
- A bypass is not automatically a smell: where the defeated check is a signature over a substituted identity key, the bypass **is** the attack. `TRACE_USES_A_GUARD_BYPASS` (`junglegym_hybrid_pq.vp`, `history_closure_incompatible.vp`, `noise_xx_mutual.vp` twice) plus the unswept `scuttlebutt.vp` keep one; `noise_xx_mutual.vp`'s two are a known gap — forging `static_i` to decrypt to `PUBKEY(nil)` would make `sealed` forgeable, but `forged_flight`'s greedy hill-climb over `scenario_cost` never takes two slots together.
- `narrate.rs::out_of_order_note` is a backstop earned by `out_of_order_harvest`: the witness installs a value the principal itself produced at or after the overwritten slot, *and* renaming that principal's fresh constants to another run's copies stops the query resolving. **No model earns it any more**, because `CausalOrder` refuses the install; if one does, that is a causally impossible trace `CausalOrder` missed.
- **The seed is bounded by the trace, not by the answering state.** `mutations` drops any seeded slot at or past `km.slots.len()`, not `ps.values.len()`: installs go into full-length pristine sessions while `ps` may be truncated at a halt, and bounding by `ps` emptied the seed whenever the answering principal halted (`spore_ns_pk.vp`).
- **A witness is an ordered sequence, and `grounded` is what says so.** `probe_with` sorts installs by the `declared_at` of the slot each fills, requires each to be `attacker_can_derive`-able from knowledge established by **strictly earlier** ones, then executes the prefix (on `base`, and under `Breadth::All` on every other session controlling part of it) and absorbs what that yields. Checking before executing keeps a step from justifying itself. `choose` prefers a grounded witness among the bypass-free ones, and `drop_one` refuses a drop losing groundedness. The Lowe witness used to open `m3@2` for `nr` before installing the payload that is the only reason `m3@2` exists.
- **The seed has to be transitively closed.** `seeded_mutations` closes the tainted diffs of the query subject's record (or the answering state's own tainted slots) over the histories of the values in it: each held **subterm**, then that subterm's tainted diffs, breadth-first, skipping values that `costs_nothing`. Without closure the Lowe witness's enabling install into Bob was in no candidate family; subterms reach `forged_statement_rebuilt.vp`'s harvested signature; skipping cost-free values stops `PUBKEY(nil)`'s arbitrary ambient record winning the first-wins-per-slot race; doing it here covers `blind_signing_oracle.vp`, where the delivered value is `nil`. `the_lowe_witness_replays_through_bob_before_it_learns_the_nonce` pins the order.
- The probe's baseline is **resolved and rewritten**, like `generate_trace`; skipping `perform_all_rewrites` made `knows()` miss every reduced lookup.
- `Minimizer` builds one `TermBound` and one `Controllable` per session at construction (`guards`), and `probe_with` one per other session before its rounds; both were rebuilt per candidate, per slot and per fixpoint round.
- Probes run against a **scratch `VerifyContext`** built by `scratch_for_witness`, which clears the honest set (a cross-scenario witness lives in the corrupt run it goes through), re-seeded from the **passive baseline** rather than end-of-search knowledge, with sessions from `ctx.principal_states()`. `in_minimization()` gates re-entry and `info.rs::InfoQuiet` gates output.

**`narrate.rs::narrate_attack`** renders the witness as numbered causal steps: `Mutations` (per wire message), `Gate` (a checked primitive that passed with an attacker-controlled input), and `Derive` (one line per `DerivationRecord`). A derivation performed while walking another principal is prefixed per line. `NameTable` compresses terms back to slot names, excluding the slots a step touches so a line never reads "replaces `gb` with `gb`"; the summary quotes the same table. The exclusion is the **shadowed** set (`shadowed_names`: installed slots and everything computed from them) at every depth, not only at the top level: compressing an argument to a shadowed name printed Lowe's forged `PKE_ENC(gb, d1)` with `d1` standing for the very `CONCAT(ni@2, ga)` the attack is about. Steps are emitted **per message in the order the installs happen** (`mutation_groups`, keyed on the send event that carries the slot, not the constant's declaration): the derivation of each installed value directly precedes the step that installs it, so a trace no longer narrates a value as observed before the substitution that put it on the wire. A mutation step groups the constants of one message; grouping by the constant's `declared_at` split a message whose constants were declared apart and merged two messages on one leg.

Three smaller rules: a **multi-output primitive carries its projection** (`|n`) wherever `NameTable` renders a term (`equivalence_names_the_projection.vp`), and `Display for Primitive` deliberately does not, being the pretty-printer's model syntax; a **declared weakening assumption must be named** — `Broken` displaces a derivation naming no assumption and `walk` refuses to override it (`cap_forgeable_names_its_assumption.vp`); `Initial` narrates as "it is public" **only at the root**.

**A step may claim only what its own operands establish, and "session" is the word this file gets wrong most easily.** *Which run* a derivation happened in is known only from the `MutationRecord`'s `principal_id`, so only `session_prefix` may name one, and nothing may call the other run *earlier*. *A cross-session replay* is established only by `copy_sibling_replay` (both expansion axes), so `Step::Replay` carries a `sibling` flag and only that arm says "from another session"; the other arm says "unaltered". *A guarded slot being substituted* is not a guard bypass: `attacker_controllable` admits it only when the value reached the sender unguarded upstream, and `Step::Bypass` fires only where `try_guard_bypass` proved the key is held. An `Obtained` value is "on the wire" only when its slot has a `sent_by`.

### The soundness tests (query.rs::tcb_tests)

Theorem 4 of the paper is that a solver bug cannot produce a false attack, *whatever the solver does*, reduced to six facts pinned by reading the source:

| fact | what it says | pinned by |
| --- | --- | --- |
| (i) | one write path: `results_put`, whose token constructor is private to `query.rs`, called once from `emit_query_result` | the `QueryVerdict` type + `a_query_result_has_exactly_one_write_path` |
| (ii) | reached only from query evaluation: five `emit_query_result` callers, one per query kind | `results_are_recorded_only_by_query_evaluation` |
| (iii) | the verdict comes from a state: an evaluator is handed a `PrincipalState` and an `AttackerState` and nothing that could carry a verdict | `a_query_evaluator_is_handed_states_and_nothing_else` |
| (iv) | every state it is handed was executed: three `verify_resolve_queries` call sites, nothing under `src/solve/` reaches evaluation directly | `query_evaluation_is_entered_only_over_an_executed_state`, `the_solver_cannot_reach_query_evaluation_except_through_the_validator`, `the_solver_holds_no_shared_cell_over_analysis_state` |
| (v) | every term the attacker installs was derivable *and causally available*, against knowledge restricted to compatible executions; `validate.rs` proves this before `execute_forward` runs and abandons the *whole* substitution on failure | `an_install_is_proven_controllable_then_derivable_before_it_is_executed` |
| (vi) | every slot the attacker installs into was controlled, tested *first*, against a `Controllable` only `reexec.rs` can mint | the same test, plus `controllability_is_minted_only_by_reexec_and_bound_to_one_session` |
| (vii) | a value that enters a state by forwarding is exactly what its sender sent: over a declared leg, in a reached phase, from a run that reached the send, with sender and creator left honest and taint set so it is a precondition downstream | `a_forwarded_value_is_only_ever_what_its_sender_sent` |

Two are about *order*: testing derivability after queueing an install, or letting a failed test `continue` to the next slot, executes a state the replay system does not permit. Keep `Controllable`'s fields private and `admits` checking both principal and phase. Adding a query kind touches (ii) and (iii): a sixth `emit_query_result` caller and a sixth arm in `query_start`, both counted.

### Supporting modules

`parser.rs` — byte-level recursive descent; comments captured into AST nodes so `pretty` round-trips them (idempotence is unit-tested). A leading UTF-8 byte-order mark is skipped by position, not stripped, so every span stays relative to the text the editor holds; a line comment's token ends before a `\r`, or the semantic token for a CRLF comment ran one column past its line. `pretty.rs` — canonical formatter, golden-tested. `pretty_model` is a pure AST walk, infallible, and deliberately **not** gated on `sanity`: a sanity error means there is a complete tree, and refusing to format then is refusing while the user fixes the error. It also owns the `Display` impls for `Value`/`Constant`/`Primitive`/`Query`/`Expression`, so every engine message and trace is rendered here.

`resolution.rs` — inlining, `compute_visibility`, and `state_mentions`/`principal_uses_constant`. A slot the attacker filled with another slot's *name* now resolves through that name to what it holds (`resolve_ps_values` chases the alias chain with a cycle guard; a received constant's slot holds itself and stops the walk). Stopping at the name left a recipient's own check comparing a label against a term carrying a value, and two different values then compared equal (`matching_run_two_inputs.vp`); the model language cannot write such a chain (`x = y` is a parse error), so only installs create them. It is unbounded otherwise, because it descends only through slots holding a primitive and the slot graph is acyclic (`construct.rs` builds in an order `sanity.rs` made topological, and `slot_graph_is_cyclic` refuses any install closing a loop). `rewrite.rs` — applies rewrite rules over a state, reporting failures as `(Primitive, slot)`. `equivalence.rs`/`hashing.rs` — the equivalence/hash invariant and `collect_subterm_hashes`. `primitive::normalise_arguments` is the one place keeping the term space finite: where `argument_restrictions` forbids a key derivation in a position it unwraps it, so the solver cannot build `PUBKEY(PUBKEY(x))` forever. `construct.rs` — builds the trace and principal states, owns `clone_for_depth(purify)`. `info.rs` — all user-facing output, buffered into JSON under wasm; `InfoQuiet` silences hypothetical re-runs and `InfoCapture` buffers a run for `--saturate`; every stdout write goes through its private `emit`. `agreement.rs`, `scenario.rs`, `autoquery.rs`, `unlink.rs`, `capability.rs` (`Capability`/`Capabilities`, the spec-support queries, and `CapabilityIndex`) are described above. `util.rs` — small helpers (`append_unique`, `edit_distance`/`did_you_mean`, `base_name`, `quoted_list`, `min_int_in_slice`) plus `ColorChoice` and terminal detection. `update.rs` (`cli` only) — `verify` and `about` spawn a thread that GETs the GitHub tags API and prints one stderr line if a strictly newer numeric tag exists; read with `try_recv`, so a slow network never delays a run; the only outbound call the tool makes, and there is no way to turn it off.

`lsp/` — behind the `lsp` feature. `mod.rs` is the stdio loop, using `recv_timeout` as the validation debounce: a document turning dirty stamps `dirty_since`, and `tick_if_due` publishes once that deadline has passed whatever the client is doing, since a tick that fired only on a silent timeout never fired for a client keeping one request in flight. `shutdown` and `exit` are handled in the loop rather than by `lsp_server::handle_shutdown`, so a request in the shutdown window is answered `InvalidRequest` instead of killing the server, and `exit` before `shutdown` is an error exit, as the protocol asks; `workspace/*/refresh` is sent only to a client that advertised `refreshSupport`, and the code action is offered only when `context.only` admits `quickfix`; analysis runs on a worker thread holding a cloned `Sender<Message>`. **Both threads must call `info::set_verbosity(Verbosity::Silent)`**: `VERBOSITY` is thread-local, and engine chatter on stdout desynchronises every client's parser — the symptom is an analysis that never returns. The server never touches the filesystem; documents are keyed by URI. `docs.rs` is the language prose (`CC-BY-SA-4.0`), pinned against the spec registry by a drift test; `line.rs` converts byte offsets to LSP positions in the negotiated encoding; `state.rs` holds `Documents`; `diagnostics.rs` turns errors or a finished `Analysis` into diagnostics; `language.rs` is every position-driven feature; `analysis.rs` owns the worker threads (`Runner` keys one `Live` per URI with a cancel flag and a `finished` flag, so a completed analysis answers `verifpal.cancelAnalysis` with `cancelled: false`); `proto.rs` is the wire shape of the custom `verifpal/*` messages.

`report.rs` — the one serializable description of an analysis behind `--format json`, `--format html` and the LSP notification; ranges are byte offsets plus 1-based line/column, never LSP positions. `QueryReport.query` is `pretty::query_line`, so it carries the option block: rendered with `query_display`, the three gated queries of `precondition_many.vp` were one identical string, and `preconditions` (the reached-precondition sentences of a failing query) is empty on a passing one. `DiagramRow::Leak.values` are `DiagramValue`s like a message row's (`guarded` omitted when false): one key, one shape, where a leak row used to carry bare strings under the same key. That is a contract change, so a client reading leak values as strings needs updating (`verifpal-vscode` and `verifpal-nvim` do not read `diagram`). `describe` draws a principal that **leaks** even if it never appears on a message (`leaks_without_a_message_is_visible.vp`). Each model is parsed exactly once for presentation in `Run::of`, which stores `ModelReport.diagram` (a `Vec<DiagramRow>`) beside the `source` and `tokens` the HTML pane needs; the renderer never touches `crate::parser` (`the_html_layer_never_reaches_for_the_parser`). `Analysis` carries `attacker` and `provenance` (the `--saturate`/`--auto-queries` sentences).

`html/` — renders `Run` into the self-contained page. **No markup is written in Rust** (`no_markup_is_written_in_rust` rejects `"<`, `</`, `/>` and `class="` in `mod.rs` or `diagram.rs`); it lives in the fifteen `tpl/*.html` fragments, `report.css` (mirroring the website's design system, with a `@media print` rendering) and `report.js`, compiled in via `include_str!`.

- The engine is **`src/template.rs`**, shared with `src/tex/` and parameterised by a `Dialect`: delimiters, escaper, partial registry. HTML takes `{{…}}`; LaTeX takes `<<…>>`, since `{{` is unavoidable in LaTeX. `{{key}}` interpolates, `{{#key}}…{{/key}}` is a section, `{{^key}}` inverts, `{{>name}}` includes. **Escaping is a type**: `Val::Text` escapes and `Val::Raw` does not, chosen once where data is built (`Ctx::text`/`raw`/`num`/`flag`/`list`). Values are never rescanned. Templates parse once into `LazyLock<Template>` statics declared by the `templates!` macro, which also generates the partial registry.
- **Both directions of the template/data contract are a red build** under `cfg(test)`: a placeholder nothing supplies panics, and a supplied value the template never reads panics (`audit`). `every_model_in_the_corpus_renders_a_sound_page` renders all of `examples/test/` at one session and pins that no `{{` survives, ids are unique, every `href="#…"` resolves, and `<svg>`/`<details>`/`<button>` balance.
- `diagram.rs` is the one sequence-diagram layer for the protocol and attack diagrams. **Column widths are measured** (monospace, `chars * size * 0.6`, clamped to `[200, 460]`) and the SVG carries its true width inside a `.scroll` container. Accessibility is deliberate: the protocol diagram is `role="img"` with a `<title>` and a hidden `<ol>`; attack diagrams are `aria-hidden` because the step list says the same thing; trace rows are `<button aria-pressed>`; attacked values carry a dagger and guarded ones brackets. Derivation runs fold into one `<details>`; `report.js` is progressive enhancement only.
- The golden page (`examples/test/golden_html/report.html`) is rendered from a **fixture** `Run`, so it moves only when the renderer does; re-bless with `VERIFPAL_BLESS_HTML=1 cargo test the_rendered_page`.

`tex/` — renders `Run` into the LaTeX document behind `--format tex`, compilable by tectonic as it stands. Same discipline: `no_latex_is_written_in_rust` rejects `\\begin{`, `\\end{`, `\\usepackage` and `\\documentclass` in `mod.rs` or `math.rs`; LaTeX lives in the fourteen `tpl/*.tex` fragments and `preamble.tex`.

- **The document is a report whose figures are liftable**: title, abstract, an optional summary table, then per model a message-sequence chart, a query table, one keyed figure and numbered trace per attack, and a scope note; the source as a `listings` appendix; the disclaimer last. Every figure is delimited by paired `%% --- BEGIN verifpal … ---` / `END` markers and built only from `\\vp…` macros in the preamble, so lifting one into a paper is copy the preamble once, copy the figure.
- **Layout is TeX's job.** Rust emits logical rows (`\\vpwire{1}{3}{…}`) and the `vpdiagram` environment lays them out; notes on the outermost lanes anchor *inward* (`\\vplanenode`). The picture sits in a shrink-only `\\resizebox`. Attack diagrams and tables are deliberately **not** floats; the protocol diagram is the one exception.
- **The source appendix cannot be closed from inside a model**: `listing_safe` withholds any line carrying `\end{lstlisting}` (whitespace stripped) and says so in its place. Without it a `//` comment was live LaTeX and `\input` could read arbitrary files into the PDF.
- **Terms are typeset, not escaped.** `math.rs` re-parses the printed form (`report.rs`'s serialization is a published contract and is not widened): a primitive's name splits at its underscore with the tail subscripted (`\\vpprim{AEAD}{ENC}`), a constant's underscores stay; anything unparseable falls back to escaped upright text (`every_term_in_the_corpus_round_trips_through_the_math_parser`).
- `the_document_never_claims_a_proof` rejects "proven", "is verified", "is complete" and "proof of correctness" and requires the disclaimer. `every_non_ascii_character_the_engine_emits_has_a_tex_spelling` holds `template.rs`'s spelling table complete. `the_golden_document_compiles_under_tectonic` is gated on `VERIFPAL_TECTONIC=1` and fails hard if tectonic is missing when set; `make test-tex` sets it. Golden: `examples/test/golden_tex/report.tex`, re-blessed with `VERIFPAL_BLESS_TEX=1`.

`msc.rs` — the sequence-diagram row model (`Row::{Wire,Phase,Leak,Activity,Mark,Run}`, `Value`, `Lanes`) and row construction for both diagrams, including the step-to-row correlation `staged` performs. `Row::Activity` is what a principal does between messages (`report.rs::describe` walks each block for `generates` and assignments, flushed in source order; `knows` and `unnamed_N` are skipped, more than five constants elides to `+N more`). **This is additive to the JSON contract**, so `verifpal-vscode` and `verifpal-nvim` want checking. One row model serves all three renderers.

`tokens.rs` — `TokenKind`/`Token`/`TokenIndex`; `parse_string_indexed` returns the index *even when parsing fails*. `Constant` carries no `Span` and must not gain one.

There is no process-global mutable state. `ValueNames` (`value.rs`) and `PrincipalNames` (`principal.rs`) are interners **owned by the `Parser`**, so ids are per-model; the unnamed-constant counter is a parser field and the analysis counter is thread-local. `PrincipalNames::intern` errors past `PrincipalId::MAX` rather than truncating onto `ATTACKER_ID = 0`, and `ValueNames::intern` errors once ids reach one `COPY_STRIDE`, keeping clear of the copy bands and the ranges `solve::vars` reserves. Principal *names* travel on `Message`/`Principal` and via `ProtocolTrace::principal_name`.

All output is plain text: there is no progress UI, no `tui.rs`, `narrative.rs` or `--character` flag; `inject.rs`, `mutationmap.rs`, `verifyactive.rs` and `skeleton.rs` are gone.

## Testing conventions

- Unit tests live in a `#[cfg(test)] mod tests` at the foot of the module they exercise. `src/testutil.rs` holds shared builders. `src/model_tests.rs` holds the end-to-end model tests: `run_model("foo.vp", "c0a1")` runs `examples/test/foo.vp` through `verify` at the **shipped default** of two sessions and asserts the code; `run_model_sessions("foo.vp", 1, "a0")` pins an explicit count. A model whose verdict depends on session count should be pinned at both `1` and `2`.
- **Result code format**: one letter+digit per query in model order — `c`/`a`/`f`/`u`/`e` for the kind, `0` = holds, `1` = attack found.
- Adding an engine regression test: write a model in `examples/test/`, get the code via `cargo run --release -- verify examples/test/foo.vp --result-code | tail -1`, **verify by reading the trace that each 0/1 is actually correct** (the tool's output is ground truth only for regressions), then add a `run_model` test. Explain *why* the code is right in a `// Expected:` header comment — see `aead_replay_not_forgery.vp`.
- Golden pretty-printer files live in `examples/test/golden_pretty/` (6), compared byte-for-byte. `golden_html/report.html` and `golden_tex/report.tex` are rendered from fixtures and re-blessed with `VERIFPAL_BLESS_HTML=1` / `VERIFPAL_BLESS_TEX=1`.
- The test builders share one interner (`testutil::test_value_id`), so **unit tests must use unique constant names** (prefix per test, e.g. `cbw_m`). A test that both parses a model and builds a value by hand must take the constant from the parsed trace via `testutil::trace_constant`.
- A model *meant* to be rejected gets `run_model_err("foo.vp", "substring of the error")`.
- Every model in `examples/test/` is wired to a `run_model` or `run_model_err` test; keep it that way. The corpus is also swept through the HTML and LaTeX renderers.

### Checking *why* a verdict happened, not just that it did

A result code says nothing about the attack behind a `1`, so a battery of test-only checks sits underneath it (the recording is `#[cfg(test)]`). The sweep runs `examples/test/` (437 models) plus the seven in `SWEPT_MODELS_OUTSIDE_EXAMPLES_TEST`; sanity-error models are skipped. Re-measure the counts below after touching the corpus.

- **Witness replay.** Every `verify` under `cargo test` ends in `witness::assert_reported_attacks_replay`: for each resolved query it re-executes the reporting principal's pristine session with exactly the substitutions the minimizer kept, and fails if the query no longer resolves. A witness with *no* substitutions must resolve the query with nothing installed. It also fails when the printed trace names *fewer* slots than the witness needed. The only exceptions are the unminimized fallbacks pinned by `TRACE_IS_NOT_A_MINIMIZED_WITNESS`.
- **Narration shape.** `attack_traces_keep_their_shape_and_name_only_wires_that_exist` pins five exact sets: `TRACE_USES_A_GUARD_BYPASS` (4 entries), `TRACE_IS_NOT_A_MINIMIZED_WITNESS`, `TRACE_IS_NOT_CAUSALLY_ORDERED`, `TRACE_FEEDS_BACK_A_LATER_VALUE` and `ATTACK_IS_REPORTED_WITHOUT_A_TRACE` (all empty). A new entry means an attack got a worse explanation; a missing one means an explanation improved and the pin should move. `cloudbackup.vp` is swept from outside `examples/test/` for exactly this.
- **Every step is re-derived** (`tracecheck.rs`). `Step` carries its structured operands under `#[cfg(test)]`, and every trace `narrate.rs` produces is checked before it is returned, ~510 attack verdicts and ~2400 steps at the default:
  - **Well-foundedness.** Each ingredient must be produced by an earlier step, installed by a mutation or replay, free (`Initial`/`Injected`), `theory::obtainable` (the predicate that licensed the step), or assembled from justified parts, because a rule may rebuild an ingredient on the spot without absorbing it. `obtainable` is asked against an attacker state **grown step by step** (`Grown`: the `Initial` values, plus what each earlier step produced or installed), because asked against the final knowledge it held for every ingredient of every real derivation and the check could only fire on a value never held at all. A confidentiality trace must reach the claimed value; an authentication trace with steps must show the attacker on the wire.
  - **Each claimed operation holds**, re-derived from the state. A `Reconstructed` step's parts must be among the target's arguments, its commutative swap's, or those of whichever `can_rewrite` reduces to — re-running `can_reconstruct_primitive` instead reads knowledge that has grown since. `Decomposed` re-runs `can_decompose`; `Recomposed` `can_recompose`; `ConcatFragment` must take a fragment of an actual `CONCAT`; `Obtained` must name a slot that travelled, leaked, is public, or holds the value; `Leaked` a slot the model leaks and this run reached; `Broken` a capability `in_force` at the trace's phase; `Gate` a checked primitive whose rewrite succeeds, computed by the named principal, on an attacker-tainted argument; `Bypass` a key `theory::obtainable` confirms.

  A trace may also carry `Resolves`, `Static` and `Received` steps explaining a violation needing no attacker action. **These describe a state, so they must be built from the state the rest of the trace describes**: `attack_trace_with` takes them as a closure evaluated against `witness.ps` *after* minimization, and takes the **target** a `confidentiality?` trace claims the same way (`impl Fn(&PrincipalState) -> Value`), because the canonical MitM candidate resolves a confidentiality query with a *different* value and the trace then never reaches its own target. Building them from the answering state was the largest single fault source the metamorphic sweep ever reported.
- **Holds were searched** (`assert_holds_were_searched`): in an active model offering any controllable slot, every hold must have had `goals_for_query` called for it. Zero goals is fine; zero attempts is an untested claim. Freshness is exempt.
- **Holds are not stale** (`assert_holds_survive_final_knowledge`): every hold is re-evaluated at the end of the run against each principal's fresh trace with everything the attacker knew by then.
- **Both session counts.** The sweep verifies every model at one session and at the default; the narration-shape sets are measured at the default only.
- **Wire coherence and header intent.** The sweep rejects any step claiming the attacker replaced a value on a message the model does not have, or on a message every copy guards without a bypass. It also reads each model's `// Expected:` line and requires the stated code to match. 292 of the 418 analysing models state a code; the ceiling on the rest (`undocumented <= 126`) is a ratchet, and the sweep prints all three counts under `--nocapture`.

### The metamorphic harness (`src/metamorphic.rs`)

The checks above cannot see a *missed* attack. The harness transforms each swept model and asserts a relation between the two result codes; every property is a theorem about the **language**, so a violation is an engine bug. Transformations are AST-level and go parse → transform → `pretty_model` → **re-parse** → `analyze_sessions`; re-parsing is what makes the variant a legal model with its own interner. *Monotone* properties make the attacker strictly stronger, so no `1` may become `0`; *invariant* properties preserve meaning, so codes must match. All run at one session; `compared` is the pair count when last measured, which each property prints under `--nocapture`, and `settle` refuses a count below the property's floor so a sweep cannot pass vacuously. The three with `_exhaustively` twins are measured under `cargo test`, with the exhaustive count in parentheses.

| property | transformation | direction | compared |
| --- | --- | --- | --- |
| `unguard` | remove one `[guard]` | monotone | 282 (296) |
| `leaks` | add `leaks c` | monotone | 1148 (1198) |
| `weaken` | add `weak` / `forgeable` | monotone | 1736 (1850) |
| `sessions` | `--sessions 1` → `2` | monotone | 418 |
| `dephase` | delete the last `phase[N]` | monotone | 31 |
| `promote` | `passive` → `active` | monotone | 80 |
| `demote` | `active` → `passive` | monotone | 311 |
| `rotate` | reorder the `queries` block | invariant | 272 |
| `rename` | alpha-rename every identifier | invariant | 402 |
| `pad` | prepend an unused `knows private` | invariant | 418 |
| `scenario` | add `scenarios[ P[c = c] ]` | invariant | 374 |
| `scenarios` | add a second copy of that scenario | monotone | 261 |
| `restrict` | add `precondition[…]` naming the last message to every query | monotone | 321 |

`dephase` deletes the *last* boundary so nothing needs renumbering; merging a phase into its predecessor hands the attacker later-phase values sooner, so it gains and never loses. `rename` and `pad` probe the interner and the reserved id bands; `rename` renames the `scenarios` block too, or every scenario model was rejected by `sanity_scenarios` and silently never compared. `scenario` is the no-op case for the scenario front-end; `scenarios` is `sessions` monotonicity over the other axis. Both pick a `knows` constant that does not travel. `restrict` is the precondition option's monotonicity: the variant asks the weaker question, so it is compared the way `demote` is, and a `1` appearing only in the variant is an attack the unrestricted search missed.

**Two ratchets, failing in *both* directions, both currently empty.** `KNOWN_MISSED_ATTACKS` once held `exa.vp` under `unguard`; `KNOWN_BAD_TRACES` once held 28 entries that turned out to be four bugs. A violation outside a list fails; an entry that *stops* violating fails too. Staleness is judged only over models a run exercised.

**A transformation that changes which runs are honest is not compared.** `asks_the_same_question` requires every scenario the original declares to keep its corrupt-from phase in the variant: compromising a declared peer moves that run's claims out of the protocol's, so the two codes are not comparable. This is a skip of the same kind as a variant failing `sanity`, not an excused engine result.

**Binding a subterm to a fresh local constant is not an invariant.** A `name_intermediate` transform (`_ = SIGNVERIF(pk, HASH(m), sig)?` into `inner = HASH(m)` and `_ = SIGNVERIF(pk, inner, sig)?`) was written and reported two false attacks; both were false positives. The engine reasons about slots, so a use lifted out of a failing check is a use in a primitive of its own, and `auth_with_signing_false-attack.vp` pins exactly that shape as a genuine `a1` (`ciphertext` decrypted before Bob halts at his signature check): a gate that suppressed the lifted use turned that pin into a missed attack, caught by `a_false_attack_pin_survives_at_one_session`. The other case wanted a value-equality test in `combination_coheres`, which the comment above that gate records as measured and rejected. Do not add the transform, and verify any metamorphic "false attack" against the pinned corpus before touching a gate.

**Nothing is deferred and nothing is timed.** A wall-clock deadline once made which ratchet entries were judged depend on machine load. Every analysis runs to completion; the only skips are a file that does not parse or a variant failing `sanity`. Cost is bounded instead by `spread` running models across `available_parallelism()` workers capped by `worker_cap()` (default 4, `VERIFPAL_METAMORPHIC_WORKERS`; the cap stays because `cargo test -- --ignored` runs all three sweeps at once and a pathological variant multiplies), by skipping models whose baseline holds no attack for monotone-stronger properties, and by `witness::MinimizingGuard` in `Sweep::Fast` runs, which skips minimization and narration. `unguard`, `leaks` and `weaken` run as `Sweep::Fast` under `cargo test` (traces off, the eleven `COSTLY_MODELS` left out); their `_exhaustively` twins carry `#[ignore]` and are what CI runs. `KNOWN_BAD_TRACES` is only asserted where traces are built (`settle_traces`); the missed-attack assertions run for every sweep. `settle` once returned before them for a `Fast` sweep, so under a plain `cargo test` the three properties could fail only on their pair-count floor.

### The completeness inventory

Every site in the analysis path that **collapses** a set to one representative, **memoises** under a key, **gates** with a filter, **bounds** a space, or **orders** work, classified by mutation: loosen it to accept everything and run the suite. Verdicts change → it suppresses real attacks. Nothing changes → dead, redundant, or untested. Runtime explodes → a genuine bound, whatever the comment says.

## Style and licensing

- Every source file starts with an SPDX header (`GPL-3.0-only` for code, `CC-BY-SA-4.0` for prose), including `.vp` test models.
- rustfmt with **hard tabs** and Unix newlines; clippy is a hard gate (`-D warnings`).
- **Do not write comments.** Reasoning belongs in the commit message and in this file, where it cannot drift silently against the source. `sessions.rs` and `value.rs` keep module-level docs from before that rule and are the register to match *if* asked for one; otherwise add none, including to code touched in passing. `.vp` test models are the exception — a new one must carry a `// Expected:` header arguing its code, since the `undocumented` ratchet cannot go up.
