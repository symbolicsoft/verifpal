# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Verifpal is a symbolic formal verification tool for cryptographic protocols. Users write protocol models in the Verifpal language (`.vp` files), and the engine checks security queries (confidentiality, authentication, freshness, unlinkability, equivalence) against a passive or active attacker, with each principal running two concurrent sessions by default (`--sessions k` to change it). Sessions are bounded: a passing query means no attack was found within that many sessions. It is a single Rust crate (`verifpal` 1.2.5, edition 2024, `rust-version 1.98`, GPL-3.0-only) building as a CLI binary and, separately, as a WASM library used by the Verifpal website and the VS Code extension. The [User Manual](https://static.verifpal.com/manual.pdf) is the language reference; `README.md` is the user-facing pitch. [*From Toy to Instrument: Seven Years of Verifpal*](https://eprint.iacr.org/2026/1654) is the paper — it carries the semantics, deduction rules, search, soundness theorem, termination bound and session model, and is the authority when this file and it disagree.

The engine is **sound but incomplete**: any reported attack must be genuine, but the search may miss attacks. Soundness is structural rather than argued — the solver in `src/solve/` only ever *proposes* substitutions, and `validate.rs` re-executes each one concretely before any result can be recorded, so a solver bug costs a missed attack and never a false one. That is Theorem 4 of the paper, which reduces soundness to six facts about this code; `query.rs::tcb_tests` pins all six by reading the source, so breaking one fails the build (see "The soundness tests").

A false attack is the worst possible regression. These models pin past ones:

| model | code | what it pins |
| --- | --- | --- |
| `auth_with_signing_false-attack.vp` | `c0a1a0` | the `signature` authentication query must hold while the `ciphertext` one legitimately fails |
| `concat_split_replay.vp` | `a0` | a `SPLIT(CONCAT(…))` reducing to the honest value is a replay |
| `wire_projection_replay.vp` | `a0` | projecting a wire value back onto itself is a replay |
| `aead_replay_not_forgery.vp` | `a0c0` | a fully attacker-known ciphertext under an unreachable key is not forgeable |
| `equivalence_halt_scope.vp` | `e0` | halting a principal is not a divergence: a state truncated at a failed check cannot answer an `equivalence?` over slots it no longer holds |
| `foreign_halt_no_oracle.vp` | `a0` | a principal's state holds every constant in the model, so an upstream mutation installed there re-resolves *other* principals' values too, and `truncation_point` honors only a failed check whose creator is the principal being re-executed. `PrincipalState::foreign_halts` records a foreign principal's failed check and `slot_unreached` suppresses the values behind it, or `rule_equivalize` harvests them — a MAC forgery oracle. `exa.vp` (`c1`) is the counterweight: the same shape with no check failing is a *genuine* decryption oracle, so refusing every such mutation would lose a real attack |
| `equivalence_halt_at_slot.vp` | `e0` at `--sessions 1`, `e1` at `2` | the other half of that rule: `truncation_point` keeps the *failing* slot, still holding a decryption that did not decrypt, and comparing that is the same false attack. The `e1` at two sessions is the genuine cross-feed, not the bug returning |
| `examples/transport-layer/piknik.vp` | `c0a0a1a1f0` | a substitution the attacker cannot build is not an attack: forging anything under Client1's signature needs `signprivkey` (never leaked) and the confidential plaintext `m`. The two `a1`s are injective-authentication **replays**, not forgeries; a trace saying *replaces* rather than *replays* is the regression |
| `session_replay_breaks_injectivity.vp` | `a1` at `--sessions 2`, `a0` at `1` | `authentication?` is **injective** agreement: replaying another session's honestly-signed pair forges nothing, but the sender sent it once and the recipient accepts it twice, so the query must fail. At one session there is no sibling run to replay from, which is where non-forgeability stays pinned on its own |
| `session_nonce_cross.vp` | `a0` at `1`, `a1` at `2` | session replication finds a genuine cross-session oracle: session 2's responder, fed session 1's nonce, forges a MAC session 1 accepts |
| `concat_bomb_equiv.vp` | `e0…f0` at `1`, `e1…f0` at `2` | halting Bob is not a divergence, but feeding him another session's bundle under the same long-term key is one |

"Known to the attacker" is not "forgeable by the attacker" — that distinction is what `aead_replay_not_forgery.vp` and `piknik.vp` hold down. `piknik.vp` is reached through `run_model_at`, which takes a full path; `run_model` prefixes `examples/test/`.

## Commands

```sh
cargo build --release                  # build (also: make build)
cargo clippy --all-targets -- -D warnings   # exactly what CI runs
make lint                              # the above, plus cargo fmt --check and the wasm clippy
cargo test --release                   # 827 tests (unit + model), ~1m once built (also: make test)
cargo test --release -- --ignored      # the exhaustive metamorphic sweeps (also: make test-exhaustive)
cargo test --release test_ok           # a single end-to-end model test
cargo test --release model_tests::     # only the end-to-end model tests
cargo fmt                              # rustfmt: hard tabs, Unix newlines (rustfmt.toml)
cargo check --lib --no-default-features --features wasm   # fast check that the wasm build isn't broken
make wasm                              # wasm-pack build + copy into ../verifpal-website/res/wasm/
```

CI (`.github/workflows/main.yml`) runs clippy, `cargo test --release` and the exhaustive sweeps on Ubuntu and macOS, plus a job clippying the wasm library for `wasm32-unknown-unknown`. A single warning fails the build. **CI only runs when the commit title contains `[ci]`** (or on manual dispatch) — a push without that marker is skipped, so a green tree means nothing until you tag a commit. Formatting is not gated in CI; `make lint` runs `cargo fmt --check` locally, so keep the tree formatted.

Running the tool:

```sh
cargo run --release -- verify examples/simple.vp             # full analysis
cargo run --release -- verify path/to/model.vp --result-code # appends the compact result code
cargo run --release -- verify path/to/model.vp --format html > report.html  # self-contained report
cargo run --release -- verify path/to/model.vp --sessions 1  # single-session; the default is 2 per principal
cargo run --release -- verify path/to/model.vp --saturate    # raise k until the verdicts stop moving
cargo run --release -- verify path/to/model.vp --auto-queries # replace the queries block with a generated one
cargo run --release -- pretty path/to/model.vp               # canonical formatter, to stdout
VERIFPAL_SOLVE_DEBUG=1 cargo run --release -- verify m.vp    # log every solver proposal to stderr
```

`verify` takes several models at once. `--result-code` only suppresses the banner; the whole analysis still prints and the code is the **last** line (`… | tail -1`). `--fail-on-attack` turns a found attack into a nonzero exit; `--auto-queries` and `--saturate` are described under their own sections below; `-q`/`-v` and `--color auto|always|never` are the remaining flags. Other subcommands: `about`; `diagram <model>` emits mermaid `sequenceDiagram` source; `lsp` is a language server speaking LSP over stdio. `internal-json` is **gone**, replaced by `verify --format json`. The json, html and LSP outputs are all built from `src/report.rs`; `verifpal-vscode` and `verifpal-nvim` are thin clients of it.

Errors carry a `Span` into the model source and print as `file:line:col: kind: message` with the offending line and a caret. Parser errors get the position the parser stopped at automatically; `sanity.rs`/`construct.rs` attach the span of the query or declaration at fault via `VerifpalError::or_span`, which keeps whichever span is narrower. Call `.located(file_name, &model.source)` at an entry point so plain `Display` shows the position — `Model` carries its own source for exactly this.

`VERIFPAL_SOLVE_DEBUG` is the first thing to reach for when an active-attacker result is wrong: it prints each proposal as `[solve] <Principal> ran=<bool> [slot=value …]`, including the ones `validate` rejected as indistinguishable replays, which is otherwise very tedious to reconstruct.

## Crate layout and features

- One crate: lib `verifpal` (`src/lib.rs`, `crate-type = ["cdylib", "rlib"]`) + bin (`src/main.rs`, requires the default `cli` feature). `main.rs` is CLI only and holds no tests.
- **Every engine module is `pub(crate)`**; the public API is what `lib.rs` re-exports — `verify`/`verify_with_sessions`/`verify_report`/`verify_report_with_source`/`verify_report_with_source_opts`/`VerifyReport`, `verify_auto_queries`, `verify_saturating`/`saturation_sessions`/`Saturation`/`SATURATE_MAX`, `pretty_print`/`diagram`, `html_report`, `lsp_run`, `Run` (the `report.rs` root), `Verbosity`/`info_banner`/`info_message`/`info_replay`/`set_verbosity`, `ColorChoice`/`set_color_choice`, the update-check trio (`UpdateCheck`, `update_check_start`, `update_check_report`), the `types` module (also glob-re-exported), and the wasm entry points. `#![warn(unreachable_pub)]` is on, so a stray `pub` on an internal item fails CI; write `pub(crate)`.
- There is no `tests/` directory: an integration-test target collides with this crate's `cdylib` output on one artifact name, and wasm-pack needs the `cdylib`. End-to-end model tests live in `src/model_tests.rs`.
- Features: `cli` (default; pulls in clap, colored, ureq and `lsp`), `lsp` (crossbeam-channel, lsp-server, lsp-types), `wasm` (wasm-bindgen; entry points `wasm_verify`/`wasm_pretty` in `lib.rs`, returning JSON strings and buffering all output through `info::wasm_messages_*`).
- `#![forbid(unsafe_code)]` is on: the soundness argument is an argument about what the code can reach, and `unsafe` would let any of it reach anything. Keep it that way.
- The engine is single-threaded; rayon was dropped with the mutation search that used it. A new parallel code path must be `cli`-only with a sequential `#[cfg(not(feature = "cli"))]` twin for WASM — **when you change one, change the other**, and run the wasm feature check above. `VerifyContext` is already interior-mutable, so it is safe to share.
- Release profile: `opt-level = 3`, fat LTO, 1 codegen unit, `panic = "abort"`, `strip = "symbols"`. See "Performance expectations" for why `--release` is not optional.

## The Verifpal language (enough to write test models)

```verifpal
attacker[active]                    // or passive

principal Alice[
    knows public c0                 // also: private, password
    generates a                     // fresh value
    ga = PUBKEY(a)                  // public key from a private value
    k  = DH_KEX(gb, a)              // DH shared secret; DH_KEX(PUBKEY(b), a) == DH_KEX(PUBKEY(a), b)
    e = AEAD_ENC(k, m, ad)
    x, y = SPLIT(CONCAT(m, n))      // multi-output primitives bind several constants
    _ = HASH(m)                     // `_` is an anonymous constant (becomes unnamed_N)
    leaks something                 // hands value to attacker
]

Alice -> Bob: [ga], e               // [x] = guarded: attacker cannot replace it
                                    // `→` (U+2192) is accepted in place of `->`

phase[1]                            // phases must increment by exactly 1

principal Bob[
    d = AEAD_DEC(k, e, ad)?         // '?' = checked: failure halts this principal
]

scenarios[                          // optional, and it must come before `queries`
    Alice[gpeer = gb]               // run 1: Alice's peer is Bob
    Alice[gpeer = gm]               // run 2: Alice's peer is Mallory
]

queries[
    confidentiality? m
    authentication? Alice -> Bob: e
    freshness? x
    unlinkability? a, b             // ≥2 distinct constants
    equivalence? k1, k2             // ≥2 distinct constants
    // queries take an optional option block, e.g.:
    // confidentiality? m[ precondition[ Bob -> Alice: ack ] ]
]
```

Constraints enforced by the parser and `sanity.rs`:

- Nothing may follow the `queries` block (hard error — it used to be silently ignored and could hide leaks). The block must exist and come last. An optional `scenarios[…]` block goes between the last principal or message and `queries`.
- ≤128 principals (`sanity.rs::MAX_PRINCIPALS`). Principal names are title-cased (`alice` → `Alice`); every other identifier is lower-cased, so the language is case-insensitive throughout.
- Argument restrictions are declared per primitive in `spec.rs` (`argument_restrictions`, on `PUBKEY`, `DH_KEX`, `KEM_ENCAP`, `KEM_DECAP`) and enforced generically by `sanity_check_argument_restrictions`: `DH_KEX`'s second argument may not be a public key (this makes CDH structural), `DH_KEX` may not nest inside `DH_KEX`, `PUBKEY` may not take a public key.
- Primitive names resolve case-insensitively against the spec registry. Arity, output count and "may this be checked" all come from the spec.
- A model file's *name* must end in `.vp` and be ≤64 characters (`parser.rs::parse_file`).
- Constants cannot shadow reserved words: everything in `parser.rs::RESERVED`, plus any name starting with `attacker` or `unnamed`. **Adding a primitive means adding its lowercase name to `RESERVED` too**; `queries` and `scenarios` are in there for the same reason.
- A constant cannot be assigned twice, generated twice, `knows`n two different ways, sent by someone who does not know it, or received by someone who already knows it. `leaks` requires the leaker to know the value.
- Authentication and `precondition` queries are validated at load time: the sender must know the constant, the recipient must receive it, and the recipient must actually *use* it inside a primitive — otherwise it is a sanity error, not a failing query.
- Capability parameters are validated against the spec at load time by `sanity_capabilities`. A capability the primitive does not declare, or a `from phase N` naming a phase the model never reaches, is a hard error naming the right alternative — an assumption that silently does nothing reads as a check that was performed.

Primitives (arity → outputs), all 25: ASSERT(2), CONCAT(2–5), SPLIT(1→1–5), HASH(1–5), PW_HASH(1–5), HKDF(3→1–5), AEAD_ENC/AEAD_DEC(3), ENC/DEC(2), MAC(2), PUBKEY(1), DH_KEX(2), SIGN(2), SIGNVERIF(3), PKE_ENC/PKE_DEC(2), SHAMIR_SPLIT(1→3), SHAMIR_JOIN(2), RINGSIGN(4), RINGSIGNVERIF(5), BLIND(2), UNBLIND(3), KEM_ENCAP(2→2), KEM_DECAP(2). Only primitives with `definition_check` — ASSERT, SPLIT, AEAD_DEC, SIGNVERIF, RINGSIGNVERIF, KEM_DECAP — may take the `?` suffix. ASSERT, CONCAT and SPLIT are *core*: they live in a separate registry (`CORE_SPECS`) whose reduction is a hand-written Rust function rather than a declarative rewrite rule, and several theory functions bail out on them explicitly (`primitive_is_core`). Everything else is data.

**Capability parameters.** A call site may carry a bracketed list of declared weakening assumptions between the name and the arguments: `PUBKEY[weak](a)`, `SIGN[forgeable](sk, m)`, `AEAD_ENC[weak, forgeable from phase 2](k, m, ad)`. `from phase N` means *from phase N onward* and binds to the preceding capability; absent it, the capability is in force from phase 0.

- `weak` — confidentiality is lost, so holding the term yields what it protects. Declared by `weak_reveals`/`weak_reveals_output`: `HASH`, `PW_HASH` (preimage, revealing every argument), `AEAD_ENC`, `ENC`, `PKE_ENC` (plaintext), `KEM_ENCAP` (shared secret), `PUBKEY` (the private key). `PUBKEY[weak]` is discrete log, and the DH cascade falls out of the *existing* `can_reconstruct_primitive` with no DH-specific rule — `cap_weak_pubkey_dh.vp` pins that.
- `forgeable` — authenticity is lost, so the term is constructible without its secret. Declared by `forgeable_secret`: `SIGN`, `MAC`, `RINGSIGN`, `AEAD_ENC`. Splitting this from `weak` is what makes `AEAD_ENC[forgeable]` — forgeable but still unreadable — expressible; `cap_forgeable_aead.vp` keeps the two from collapsing.
- `malleable` — the ciphertext can be reshaped into another the recipient still accepts, so the term is constructible under a key the attacker never learns. Declared by `malleable_vary`, the positions that may be varied: only `ENC` (position 1, the plaintext), the unauthenticated cipher this models. Holding one `ENC(k, m)` the attacker may build `ENC(k, m')` for any `m'` it can construct. This needs **two** cooperating halves: `solve/deduce.rs::solve_by_malleability` offers it as a goal, and `solve/validate.rs::malleable_positions` grants the matching derivability exemption — without the second the TCB re-proves derivability from scratch and rejects every such proposal, so the rule would look implemented and never fire. Both are gated on the attacker actually holding a term of the same shape agreeing on every non-varying position; the assumption licenses reshaping a ciphertext, not conjuring one. `cap_malleable_enc.vp` against `cap_malleable_absent.vp` — one model with the annotation and without it, `a1` against `a0` — keeps this from being either a no-op or a blanket authenticity break. Because malleability is an authenticity loss, a primitive declaring `forgeable` is pointed at that instead (`cap_err_aead_malleable.vp`), and one declaring neither is a hard error (`cap_err_malleable_unsupported.vp`).

`weak`, `forgeable`, `malleable` and `from` are **contextual keywords**, deliberately absent from `RESERVED`: they are recognised only inside the parameter brackets, where no constant can appear, so reserving them would gratuitously break models using `weak` or `from` as a constant name.

Comments (`//` and `/* */`) are captured into AST nodes so `pretty` round-trips them, **except** where deliberately dropped: inside primitive argument lists, inside the `attacker[…]`/`phase[…]` brackets, and inside a query option's inner brackets.

## Architecture

### Pipeline

```
parse_file (parser.rs)              hand-written recursive-descent, comment-preserving AST
  → expand_scenarios (scenario.rs)  one model copy per declared peer scenario
  → expand_sessions (sessions.rs)   k copies of that, one per concurrent session
  → sanity (sanity.rs)              model validation; drives construct.rs
      → construct_protocol_trace    "km": ProtocolTrace — global immutable protocol description
      → construct_principal_states  one PrincipalState per principal
  → VerifyContext::new (context.rs) shared mutable state for the whole run
  → verify_passive (verify.rs) | verify_active (solve/mod.rs)      per phase
  → verify_end                      prints results, returns the results code
```

`verify::analyze(&Model)` is the **one** place that sequence exists: it runs sanity, builds the context, dispatches on attacker kind and returns the `VerifyContext` holding the results. `analyze` is `analyze_sessions(m, DEFAULT_SESSIONS)`; `verify::verify(path)` is `verify_with_sessions(path, DEFAULT_SESSIONS)`. The wasm entry points and the language server call `analyze`, so the CLI, the IDE and the website cannot disagree about what a model means — **that shared default is the point; do not give one entry point its own.** Throughout, `km` is the `ProtocolTrace` (historical name "knowledge map") and `ps` a `PrincipalState`.

### Parallel sessions (sessions.rs)

Every principal runs `DEFAULT_SESSIONS` (2) concurrent sessions unless `--sessions k` says otherwise. This is a *front-end* to the same engine: `expand_sessions` rewrites the parsed `Model` into one where every principal and message block is cloned `k` times **before** `sanity` runs, so everything downstream is unchanged and the feature inherits the engine's attack-soundness — an expanded model is a legal model the user could have typed by hand (the `Alice2`/`na2` workaround, automated), and `sanity` re-validates all of it. The freshening rule falls out of existing syntax: `generates` constants and assignment outputs get per-session copies (`c#s`, rebanded into the expansion-copy id range — `value.rs::copy_value_id`, which takes **one** index over the whole scenario-by-session grid; `MAX_COPIES` is 30 of those and band 31 is the minimizer's), while `knows` constants stay shared. Clones are emitted in place; the lockstep layout loses nothing because within-phase attacker knowledge is atemporal. Each written query is kept verbatim (session 1) and also given per-session **variants** (`VerifyResult.variants`), all resolving the original `query_index`, so the result code keeps one entry per query and an attack in any session resolves it; `verify_resolve_queries` and `goals_for_query` iterate original + variants.

Sessions also make **injective agreement** expressible, and `authentication?` is injective: a received value equal (after the same resolve-and-reduce recipe as `reexec::attacker_authored`) to a session sibling's honest wire value is a cross-session replay, and a replay is an authentication failure even though nothing was forged. `query.rs::session_sibling_replay` no longer suppresses that report; it *classifies* it, so the narrator says "replays" rather than "replaces" and the summary can name injectivity as the property that failed. Note the ordering in `query_authentication_get_pass_indices`: the `original ≡ value` guard runs first, so a value carrying no per-session freshness equals what was already there and never reaches the sibling test — which is why value-equality is a sound proxy for run-correspondence here. Because injectivity needs two runs to be violated, `--sessions 1` cannot report a replay at all, and that is the session count at which the corpus's "this is not a forgery" models still pin their original claim (`a_false_attack_pin_survives_at_one_session`). `attacker_authored` itself stays session-strict so such states remain explorable as oracle stepping stones. `k = 1` skips expansion entirely and is bit-for-bit the pre-sessions behavior, the escape hatch for a model too large to afford replication — across `examples/test/` the corpus costs about 0.9s at one session against about 7.3s at two.

At `k > 1` the active search runs in two passes, gated by three `VerifyContext` flags (`prefer_replication` / `replication_only` / `replication_rejected`). `analyze_sessions_traced_cancellable` sets `prefer_replication` whenever sessions were expanded; `verify_active` then runs `search_rounds` once with `replication_only` on, during which `validate.rs` refuses any proposal whose term the principal itself produced *and* that carries that principal's own fresh value (`replays_own_freshness`), and runs it again with the flag off only if something was refused and queries remain. The point is which witness the user sees first: with `k` sessions a slot can be filled either by genuine cross-session traffic or by feeding a principal its own nonce back, and the second reads as an attack on the replication machinery rather than on the protocol. Both passes go through the same validator, so this only reorders the search — it can neither find nor lose an attack. `replication_rejected` is sticky across phases by design: once one phase has turned a proposal away, every later phase gets the second pass too.

Raising the default from 1 to 2 changed no verdict on any shipped protocol model, and exactly two in `examples/test/` — both genuinely: `session_nonce_cross.vp` and `concat_bomb_equiv.vp`. Re-measure both corpora before touching the default again.

### Peer scenarios (scenario.rs)

`scenarios[…]` instantiates a principal's counterparty differently across concurrent runs, which is what makes the role-confusion family — Lowe/Denning-Sacco — expressible at all. Like `--sessions`, it is a **front-end expansion**: `expand_scenarios` rewrites the parsed `Model` before `sanity` runs, so the expanded model is an ordinary Verifpal model the user could have typed and the feature inherits the engine's attack-soundness. It runs *before* session expansion, so `p` principals with `s` scenarios at `k` sessions analyse `p*s*k` principals, under `MAX_PRINCIPALS` (128) and `MAX_COPIES` (30 value-id copies, so `s*k <= 31`).

A scenario entry binds constants inside **one** named principal: `Alice[gpeer = gb]`. Scenario *k* is clone *k* of the whole model — every principal and message is cloned, and only the named principal's bindings are substituted — so N scenarios are N whole-model configurations, **not** a cross product, and one entry cannot rebind two principals at once. The bound `knows` declaration is dropped from the clone and the constant is replaced everywhere in that principal; the value is then freshened like any other expansion copy, so `Alice[gpeer = gm]` in scenario 2 uses `gm@2`, the copy Mallory@2 assigns. An identity binding (`gpeer = gpeer`) keeps the declaration and is a genuine no-op, which two metamorphic properties rest on.

`sanity_scenarios` rejects, before expansion and against the scenario's own span, a principal the model does not declare, a target that principal does not `knows`, a value no principal declares, a target bound twice, and a target that travels over the wire — that last one because the substitution is per-principal, so a recipient would go on naming a constant the sender no longer has. Accepting any of these silently would move a verdict: a typo in the principal name once turned the NS-PK `c1` into a passing `c0`.

**Corruption is inferred, not declared.** `compromised_constants` seeds from constants that are both leaked and secret (`generates`, `knows private|password`) and closes over assignments mentioning them, so `gm = PUBKEY(mk)` with `leaks mk` marks `gm` compromised while `leaks gb` on a public key does not. A scenario binding any compromised value is a **corrupt-peer run**. That decides two separate things, and conflating them is a bug each way:

- `VerifyContext::is_honest` gates the **honest-run check**. A clone whose peer is corrupt legitimately fails a checked primitive — Alice sealing to a corrupt peer's key means the honest responder cannot decrypt — so `generate_trace` partitions `perform_all_rewrites`' failures by the failing slot's *creator* (not by the walked principal: every state holds every constant, so one clone's failure surfaces in every other clone's state) and only raises `sanity_fail_on_failed_checked_primitive_rewrite` for honest creators. The suppressed ones still **halt** the clone, through `reexec::halt_at_failed_checks`: ignoring the failure would leave the clone computing past a check it never passed and publishing values the protocol cannot reach, which is the `foreign_halt_no_oracle.vp` false-attack shape.
- `VerifyContext::claims_apply_to` gates **query evaluation** (`query_start` returns before touching a state whose run is corrupt). This is the analogue of Scyther's `prune_theorems.c:439`: a corrupt-peer run is explored for what the attacker learns in it, and its own claims are not the protocol's to keep. Because attacker knowledge is global and monotone, a *confidentiality* break first noticed inside a corrupt run must still be reported against the honest ones — so `verify_active` and `verify_passive` re-run `verify_standard_run` once at the end of each phase when relativisation is in force and queries remain. Without that the flagship `c1` would depend on which principal the search happened to reach last. The verdict then lands on an honest principal that may well have *halted*, which is what `witness.rs`'s seed bound has to survive.

Both predicates read the same set, but they differ where it is `Some(empty)` — every declared scenario corrupt. The honest-run check stays relaxed there; query evaluation does **not**, because relativising against nothing would report a vacuous hold for every query. `honest` is `None` when the model declares no scenarios at all, and every predicate answers `true`, so a model without a `scenarios[…]` block behaves bit-for-bit as before.

The honest set is computed over the scenario-expanded model and then **extended across session expansion** (`SessionExpansion::principal_clones`), because `expand_sessions` mints fresh principal ids; forgetting that switched the honest-run check off for every session-2 clone.

**Phase seeding is reachability-aware, and both halves are load-bearing.** `attacker_seed_phase` publishes wire traffic out of the pristine `principal_states[0]`, which is never truncated, so it once handed the attacker every wire and leaked slot whether or not its creator got that far — a halted corrupt clone published what it would have sent after halting, and `confidentiality?` could fail through a ciphertext no execution produces. That is a false attack, so `verify::honest_run_halts` now derives, once per analysis, the slot of the earliest checked primitive each creator fails in the honest run (`reexec::creator_halts` over the failures `generate_trace` would suppress), `VerifyContext` carries it, and `attacker_phase_update` withholds every wire or leaked slot at or past its creator's boundary. **Withholding alone would lose attacks**, because a substitution can make the failing check pass: `spore_ns_pk.vp`'s `m3@2` is post-halt in the honest run and genuinely on the wire under the Lowe substitution. So `attacker_absorb_disclosed`, called from `compute_knowledge_closure` on every executed state, re-publishes exactly the withheld slots that *this* execution reached — slots the walked principal created, surviving its own truncation and `PrincipalState::slot_disclosed`. Filtering the seed without that puts `spore_ns_pk.vp` back to `c0` and collapses the NS/NSL separation. `scenario_post_halt_no_oracle.vp` and `scenario_post_halt_leak_no_oracle.vp` (`c0`) pin the false attack shut against `scenario_pre_halt_oracle.vp` (`c1`), which keeps the suppression from becoming a blanket refusal, and `scenario_honest_peer_only.vp` (`c0`) is the control that makes those `c0`s mean something. The map is empty for a model with no `scenarios[…]` block, and both halves return immediately then, so such models are bit-for-bit as before.

One limitation to state rather than discover: queries are not cloned per scenario — unlike sessions, which mint `VerifyResult.variants` — so every query names scenario 1's constants and an attack on `nr@2` is unreachable.

Models: `spore_ns_pk.vp` (`c1`, Lowe's 1995 attack, found rather than assumed) against `spore_nsl_pk.vp` (`c0`). Both declare `scenarios[]`, because without a peer axis the two protocols are indistinguishable at every session count; that pair separating is the acceptance criterion for the whole feature. Do not add a scenario-free variant of either back to `examples/`: a shipped model that cannot state the attack it is named after teaches the wrong thing.

### Verdict envelope

Every `VerifyResult` carries an `Envelope { sessions, truncations }`, printed after a PASS line (`[search exhausted at 2 sessions]` / `[search truncated: term depth]`), serialized into `QueryReport.envelope`, and shown on the HTML verdict row. An attack is never qualified: an attack is a witness, and the envelope says nothing about it.

`Truncation` currently has one variant, `TermDepth`, recorded by `context.rs::note_depth_cut` — the same call that prints the `TermBound` notice. `finalize_envelopes` stamps the **end-of-run** envelope onto every result from `analyze_sessions_traced_cancellable`, rather than the envelope in force when each verdict was recorded; that is deliberately the conservative direction, since a hold reached before a depth cut fired is still a hold reached inside a search that later stopped short.

**"Exhausted" means the search space this engine defines was fully explored at these parameters, never that no attack exists.** Do not let the word "proof", "verified", "correct" or "complete" into this output: the completeness inventory below lists narrowing sites that are permanently in force and are *not* reported as truncations, so a completeness word here would be false, and it is exactly what the paper accuses others of.

### `--auto-queries` and `--saturate`

`autoquery.rs::auto_queries` derives a query set from a model and `--auto-queries` **replaces** the model's own block with it, after `sanity` has validated the model as written. Three rules, each mirroring an existing sanity constraint so a generated query can never be rejected — `generated_queries_all_pass_sanity` sweeps the whole corpus to hold that: `confidentiality?` for every `generates` and every `knows private|password` constant with a trace slot; `authentication? S -> R: c` for every wire delivery whose recipient uses `c` inside a primitive; `freshness? c` for every constant that is actually sent (`sent_by`, not `known_by` — the latter carries a self-entry for every principal on a public constant) and used. `unlinkability?` and `equivalence?` are skipped: both need a human to say which pair is interesting.

`verify::saturation_sessions` raises `k` from 1 to `SATURATE_MAX` (4) and stops at the first count whose result code equals the previous count's. It returns the **analysis** of the count it stopped at, not just the count: each run is wrapped in `info::InfoCapture`, which buffers what would have been printed, so the reported run is replayed rather than analyzed a second time. `Saturation` distinguishes saturating from hitting the ceiling — reporting "verdicts stopped changing" when they never did is a false claim about the protocol — and `attack_disappeared` warns if an attack found at a lower count vanishes at a higher one, which is an engine bug and not a protocol result.

### Core data model (types.rs)

- `Value` = `Constant` | `Primitive(Arc)`. Constants are interned per model: name → `ValueId` (`value.rs`; `nil` is id 1); equivalence compares ids. Diffie-Hellman uses the ordinary primitives `PUBKEY(sk)` and `DH_KEX(pk, sk)`; their commutativity (`DH_KEX(PUBKEY(a), b) == DH_KEX(PUBKEY(b), a)`) is declared by the `commutativity` field on `PrimitiveSpec` and consumed generically by `equivalence.rs`, `hashing.rs` and `solve/matching.rs`.
- `Primitive` carries a `HashCell`: a term's hash is computed once and cached, making `hash_value` O(1) and letting `Value::equivalent` reject non-equal terms on hash inequality before any deep comparison. Terms are immutable once built; the single in-place mutation (`construct.rs`, setting a multi-output `output` index) clears the cell.
- **Invariant: `a.equivalent(b)` ⟹ `a.hash_value() == b.hash_value()`** (`hashing.rs` uses a commutative hash for DH exponents). `AttackerState::knows()` looks up by hash bucket first, so breaking this silently breaks attacker knowledge. Unit tests pin it.
- `Primitive.capabilities` carries the parsed weakening annotations, and is deliberately **not** consulted by `primitive_hash`, `equivalent_primitives`, or `theory.rs::structurally_identical_primitive`: an annotated term and its unannotated twin are the same cryptographic object, which keeps every existing invariant untouched and makes an unparametrized model behave bit-for-bit as before (`cap_noop_annotated.vp` pins this against `hmac_ok.vp`). The engine reads capabilities from the `CapabilityIndex` on `PrincipalState`, **never** off the copy of a term it happens to hold — `AttackerState` dedupes by equivalence, so if an unannotated copy reached the attacker first the annotated one would be discarded and the rule would silently never fire, making results depend on which principal the engine walked first. The one place that cannot use the index directly is `solve/deduce.rs`, whose goals are patterns containing free variables: it unifies against the index's annotated terms instead.
- `SlotValues` holds **three values per slot** — the single most important invariant in the engine:
  - `original`: what the protocol honestly computed (what the principal *believes*),
  - `pre_rewrite`: after attacker mutation, before cryptographic rewriting (forensics/narration),
  - `value`: after mutation and rewriting (what analysis uses).

  `PrincipalState::should_use_original`/`effective_value` and `resolution.rs::compute_visibility` decide which one a principal sees. Getting this wrong causes false authentication attacks (principals "seeing" the attacker's tampering in their own computations). A fourth field, `bypassed: Option<Value>`, holds the key a defeated guard was made to accept. It used to be written into `original`, which gave that field two meanings and left a bypassed slot impossible to purify; keeping it separate costs one `Option` per slot and makes `clone_for_depth(true)` total.
- `Provenance` rides alongside: `creator`, `sender` (`ATTACKER_ID` = 0 when injected), `attacker_tainted`, `bypass_injected`. The last two are **deliberately separate**: taint decides which value a principal perceives, and a guard bypass must not change that (the principal genuinely computed with what it was handed), but the substitution must still be *reportable*, or the most important step of a MitM trace becomes invisible to the narrator.
- `SlotMeta` is the immutable half of a slot: the `constant`, `guard`, `known`, `wire` (recipients this value travelled to), `mutatable_to` (recipients it reached *unguarded*), `known_by` as `(recipient, sender)` pairs, `declared_at`, `sent_at`, and the phases it appears in. `mutatable_to` is what `symbolic.rs::reaches` and `compute_visibility` consult to decide whether an attacker choice can influence a computation.
- `PrincipalState::halted_at` records the `declared_at` of the earliest checked-primitive failure after mutation. `reexec.rs` sets it and truncates the state there; `deduction.rs::rule_equivalize` uses it to suppress `leaks` the principal never reached.
- `AttackerState`: append-only `known` set + `known_map` hash index + `mutation_records` and `derivations`, both parallel to `known`. A `MutationRecord` is the set of slot diffs (against the trace's initial values) that had to be in force for the attacker to hold that value, plus the principal and phase whose session that was. A `DerivationRecord` says *how* it was obtained: `Initial`, `Leaked`, `Obtained`, `Decomposed`, `Reconstructed`, `Recomposed`, `PasswordExtracted`, `ConcatFragment`, `Broken` (the capability rules). Attack narration walks this DAG, so **a rule that adds knowledge without recording an honest derivation produces an unexplainable trace.**

### Provenance travels along derivation edges (context.rs)

`derivation_provenance` decides which `MutationRecord` attaches to a newly learned value:

- A value **read out of a principal's state** (`Leaked`/`Obtained`/`Reconstructed`, or one whose ingredients a rule rebuilt on the spot) picks up that state's ambient diffs.
- A value **combined out of values the attacker already held** inherits *their* records, and adopts the session of whichever ingredient carried the leverage.
- `Initial` and `Injected` cost the attacker nothing, so they get an empty record.

Snapshotting the ambient state at absorption time instead would describe one attack's actions beside another attack's consequences: the attacker learns a ciphertext in the run where it substituted a public key, then decrypts it in a later run whose substitutions are about something else entirely.

`attacker_state_absorb` also *upgrades* an existing record: if the stored one explains nothing (no tainted diffs) and the arriving one does, the record and derivation are replaced. Knowledge is unchanged either way — only the explanation is. Without this a trace can describe an attack with nothing in it, because the first path to reach a term was one that had already purified the state.

**Cancellation has exactly one conversion point.** `VerifyContext` carries an `Arc<AtomicBool>` checked beside every `all_resolved()` short-circuit — the round and proposal loops in `solve/mod.rs`, the fixed point in `deduction.rs`, the principal loop in `verify_standard_run`. Those loops only ever *stop*; the flag becomes a verdict in one place, at the foot of `analyze_sessions_traced_cancellable`, and becomes `Err(ErrorKind::Cancelled)`. No caller reads a result set out of an `Err`, so an interrupted search reports nothing rather than reporting a query it never reached as holding — which keeps `tracecheck::assert_holds_were_searched` honest. Adding a second conversion point, or returning results alongside a cancellation, is how you manufacture false "holds". `scratch_for_query` inherits the flag so the minimizer's probes stop too.

`VerifyContext` is the interior-mutability container (RwLock/atomics) shared by `&VerifyContext` rather than threaded as `&mut`. `attacker_put_with` dedupes new knowledge; `results_put` resolves each query at most once; `all_resolved()` short-circuits every search loop; `principal_states()` hands back every principal's pristine starting state (used by the minimizer to replay an attack in the session it belongs to); `scratch_for_query(i)` builds a disposable context that can only answer query `i` and cannot write back. `ANALYSIS_COUNT` is a thread-local counter used only to label output, deliberately not incremented while output is quiet.

### Standard run (verify.rs)

`verify_standard_run` is shared by both attacker kinds — the active search uses it as its passive baseline. For each principal, three phases:

1. **Trace generation** (`generate_trace`) — `resolve_all_values` (inline constants per visibility rules), `perform_all_rewrites`, then sanity checks (a failed *checked* primitive here is a model error, not an attack — unless its slot's creator is a corrupt-peer scenario clone, which halts instead; see "Peer scenarios").
2. **Knowledge closure** — `deduction.rs::compute_knowledge_closure`.
3. **Query evaluation** — `query.rs::query_start` for each unresolved query.

Closure never checks queries — that separation is what makes the fixed-point argument clean. Each phase begins by resetting attacker knowledge (`attacker_init`) and re-seeding from `principal_states[0]` resolved purely (`attacker_phase_update`): public constants some principal actually uses, plus every wire or leaked value whose earliest phase has been reached.

### Knowledge closure (deduction.rs)

A monotone fixed point over three rule groups. Each pass runs all three over a snapshot of attacker knowledge taken at the top of the pass, repeating until one adds nothing:

1. over attacker-known values: `decompose`, `break_weak`
2. over principal-assigned values: `reconstruct`, `recompose`
3. over attacker-known values: `equivalize`, `password_extract`, `concat_extract`

Termination is Knaster–Tarski: knowledge grows monotonically, the derivable set is finite, each iteration either adds a value or stops. Every rule ends by calling `learn`, which records the value together with its `DerivationRecord` and emits the matching `Deduction ›` line — routing them all through one function keeps "knowledge and the derivation that explains it are recorded together" true by construction. Its message argument is a closure because minimization re-runs the closure many times with output suppressed.

`rule_equivalize` carries the one non-obvious guard: if the principal halted on a failed checked primitive, a `leaks` this same principal declared *after* that point never fired, so re-resolving through it would let the attacker harvest values from a branch the principal never reached.

### Query evaluation (query.rs)

`query_start` returns before touching a state whose run is a corrupt-peer scenario (`ctx.claims_apply_to`, see "Peer scenarios"); in a model with no `scenarios[…]` block that predicate is always true and nothing changes. Past that guard, each kind resolves differently, and `solve/mod.rs::goals_for_query` mirrors these exactly:

- **confidentiality** — the attacker knows the slot's resolved `value`.
- **authentication** — **injective agreement**, and the only mode: there is no non-injective variant and no opt-out. Evaluated only while walking the recipient. Fails when the slot's `provenance.sender` is not the declared sender *and* the constant is successfully used inside a primitive the recipient computed (`query_find_constant_usage_indices`: the primitive has no rewrite rule, or its rewrite passes, or it is unchecked). Two failure shapes reach this, reported with the same `a1` but different vocabulary: a **substitution** (the attacker built a value the sender never sent) and a **replay** (the attacker re-delivered a value the sender genuinely sent in another session, so nothing is forged but run correspondence is broken). `session_sibling_replay` classifies which, `AuthFailure` carries it into the summary, and `narrate.rs` routes replays into `Step::Replay` so the trace reads "Attacker replays …" — a wording the narration sweep already parses for wire coherence. `witness.rs` carries a matching `replayed_from` candidate family, without which a replay witness has no single-install candidate and falls back to the disclosed unminimized trace.
- **freshness** — the value transitively contains no `fresh` constant, yet is used in a primitive. No attacker choice affects this, so the solver never proposes anything for it.
- **unlinkability** — the attacker exhibits a *link witness* for some pair of the queried constants (`unlink.rs::find_link_witness`). Both must be observable (wire or leaked) and neither slot may be attacker-authored, since an attacker overwriting two slots with one value manufactures the equality it would then report. Three witness kinds, cheapest first: **observed equality** (the attacker holds both and they are the same secret-dependent value), **identifying check** (a `definition_check` primitive with a declared identifying position succeeds over both under one participant's key), and **common secret origin** (both values' reconstructions bottom out on one secret the attacker holds, found by `origin_leaves`, which withholds each value from the attacker first — receiving a value explains nothing about whose it is, only recomputing it does). The manual's two-world definition is the specification; this is the decision procedure, sound for attacks and incomplete. `identifying_positions` is empty for `RINGSIGNVERIF` on purpose — a ring names a set and never a member, and that emptiness is the only thing keeping `unlinkability?` from reporting a false attack on the one primitive whose whole purpose is unlinkability (`unlink_ringsign.vp` versus `unlink_signature_links.vp`, structurally identical models with opposite verdicts).
- **equivalence** — the queried constants do not all resolve to equivalent values, using the *mutated* value rather than `original`. Solved as a divergence rather than a deduction. It first requires that this state actually *hold* every queried value: `reexec::drop_after_index` truncates a halted principal's slots and `resolve_constant` answers for a missing slot with the bare constant, so comparing that placeholder against the other side's real value reports a divergence nobody computed. Making a principal abort is not making two principals disagree. This is why `concat_bomb_equiv.vp` and `triple_dh.vp` hold: in both the attacker can only halt the recipient, and in `triple_dh.vp` unguarding `gb_ident` makes the real MitM available and the query fails again, which keeps that `e0` honest.
- The `precondition[A -> B: c]` option annotates a failing query with "A sends c to B despite the query failing".

When a query resolves, `attack_trace` minimizes the state that resolved it (`witness.rs`) and narrates it (`narrate.rs`), seeding the minimizer with the mutations recorded against the *value* rather than whatever state happened to answer the query.

### Equational theory (theory.rs + primitive/spec.rs)

All cryptographic behavior is **declarative data**: `PrimitiveSpec` entries define decompose ("knows key → learns plaintext"; `reveal_output` makes the rule yield one of the primitive's *outputs* instead of an argument, which is how an attacker holding a decapsulation key opens a `KEM_ENCAP` ciphertext no principal ever decapsulated), recompose (threshold shares), rewrite ("DEC undoes ENC", with matching constraints and filters), rebuild (SHAMIR_JOIN), password protection, and guard-bypass key extraction. `theory.rs` interprets them (`can_decompose`, `can_reconstruct_primitive`, `can_rewrite`, `can_rebuild`, `find_obtainable_passwords`). `obtainable` is the shared "can the attacker get this argument at all" cascade that decomposition and reconstruction both run over each argument.

None of it carries a recursion cap, and reintroducing one is a regression. The descent is well-founded on term depth: every `to` rule in `spec.rs` returns a subterm of its input or reassembles strict subterms of it, and every `decompose` filter returns an argument or something inside one, so each step hands the next a strictly shallower term. The memo is keyed on the term hash **alone** — it once carried the recursion depth beside it, purely an artifact of the cap, and putting depth back splits every answer across as many entries as there are levels: the suite goes from two seconds to six minutes and finds exactly the same attacks.

Password extraction: a `password` constant is recoverable when, at *every* enclosing primitive level, the position is not in `password_hashing` (only `PW_HASH` sets that) **and** the attacker knows every sibling argument — i.e. it can verify a guess offline.

**To add a primitive, edit only `src/primitive/spec.rs`** — `build_primitive_specs` is the whole table, and the nearest primitive to the one you want is the template (`ENC`/`DEC` for a symmetric pair, `KEM_ENCAP`/`KEM_DECAP` for a two-output one). Core primitives go in `build_core_specs` and need a hand-written `core_rule_*`. Also add the lowercase name to `RESERVED` in `parser.rs`. Then add model tests.

The spec table is data the engine trusts, and several fields are read as *direct* slice indices — `rewrite.from`, `decompose.reveal`, `recompose.reveal`, `rebuild.reveal` in `theory.rs`, and `bypass_key` in `primitive_extract_bypass_key` — so a field pointing past a primitive's arity would abort the process rather than fail a test. `every_spec_index_is_within_the_primitive_it_is_declared_on` (`primitive/mod.rs`) makes that a red build instead. It holds those fields to the *narrowest* declared arity, since a variadic call may supply only that many arguments, and holds the bound-checked fields (`decompose.given`, `rewrite.matching`, `rebuild.given`, `weak_reveals`, `malleable_vary`, `identifying_positions`, `password_hashing`, `argument_restrictions`) to the *widest*, where an out-of-range entry cannot panic but can never fire either. It also pins `arg_names` to the widest arity, so signature help never runs out of names.

### Active attacker search (src/solve/)

Goal-directed: the engine asks "what would the attacker need in order to learn this, and can it arrange that", and solves backwards from each query — it does **not** enumerate substitutions forwards. There is no per-principal budget and no `SearchConfig`; an attack needing four simultaneous wire substitutions is the union of four bindings each forced independently, not a four-element subset someone had to afford. Termination comes from memoisation, cycle cutting and a finite basis, never from a cap on how hard to look.

The one bound on term *shape* is `reexec::TermBound` — the depth of the deepest term the protocol itself computes, derived rather than chosen. `validate` refuses deeper proposals, so attacks needing a deeper term are out of reach; `validate.rs::note_depth_cut` says so on stderr the first time it declines one at a slot, and the oracle basis carries a similar notice per active run. Incompleteness the user is told about is the only kind worth having.

Per phase: passive baseline, then rounds to a knowledge fixed point (validation grows attacker knowledge, which can unlock goals). Each round runs `Pass::Targeted` for every principal, then `Pass::Constructed` for every principal — never interleaved per principal, or one principal offering a large pile of constructible values delays ever looking at the principal that matters.

- `symbolic.rs` — the principal's computation with every attacker-controllable wire slot replaced by a variable, then reduced the way `perform_all_rewrites` would. `reexec::attacker_controllable`, reached through the `Controllable` token, decides controllability (guarded-unless-`mutatable_to`, self-created, wrong-phase, unused-by-this-principal; `nil` excluded). A DH public key becomes `PUBKEY($x)`, not a bare `$x`, so the MitM shape falls out of the representation. Terms are memoised per slot, without which nested ciphertexts expand exponentially. `reaches` mirrors `compute_visibility`, so a choice only makeable *after* a principal acted does not appear inside what that principal computed.

  **The refinement search** is the file's second half: `build` replaces every controllable slot with a variable, `build_assuming_honest` leaves one slot at its honest value instead. Both are legitimate — the attacker may replace a wire value or leave it alone — and a search seeing only the variable cannot reason *through* the honest value. `exa.vp` is the case: guarded it finds a decryption oracle in one proposal, and with `msg2` merely unguarded the attack vanishes, because `AEAD_DEC(k2, $msg2, c)` stops reducing and the goal yielding `msg1=c` is never generated. `relay_rewrap_oracle.vp` is the same shape written to be read, with `relay_rewrap_no_oracle.vp` as its counterweight.

  Three things make it affordable, each measured. It runs **only after** `search_fixpoint` reaches its fixpoint with queries outstanding (`Search::Direct` then `Search::Refined`), so a model resolving or exhausting cheaply pays nothing — all of `examples/test/` moves 2.53s to 2.57s. It runs **only in `Pass::Targeted`**, where query goals are generated; a refined abstraction has nothing to offer the constructed families. And it runs **after** the unrefined pass: offered first it resolves queries a man-in-the-middle would otherwise resolve, and `identity_misbinding_uks.vp` and `ringsign_ring_substituted.vp` both degrade into `TRACE_USES_A_GUARD_BYPASS` — the same hazard `sibling_flight_substitutions` carries. Cost lands on the largest models: `piknik.vp` 1.7x, `junglegym_threshold_ring.vp` and `signal.vp` about 1.5x. `slots_blocking_reduction` picks candidates: a slot whose variable sits in the argument position a rewrite rule inspects, on a primitive that has such a rule and cannot fire. Widening it to any argument of a stuck primitive finds the same attacks at the same cost, so the narrower reading is kept because it can be stated. **One slot is held honest at a time**, so a divergence needing two simultaneously is out of reach; an attempt to build a two-hop model exhibiting that found no reachable attack, so the cost of the restriction is unmeasured rather than known to be small.
- `vars.rs` — attacker variables are interned `Constant`s in reserved id ranges (`ATTACKER_VAR_BASE = 0x8000_0000` for slots, `FREE_VAR_BASE = 0xC000_0000` for free choices), so there is no fourth `Value` variant and nothing else needs to know they exist. Free positions stay variables until materialisation — committing them to `nil` early makes two partial solutions for the same forged message unmergeable. Materialisation must not merge them either: distinct free variables are independent attacker choices, and `ground_free` fills every one with the same `nil`, which is why `diverge::distinguish` exists.
- `matching.rs` — one-sided `match_value`, two-sided `unify`, and `merge` (which unifies rather than rejecting conflicting bindings), all modulo DH commutativity (a closed two-case analysis, not AC unification). All three refuse a binding whose variable occurs in what it is bound to (`vars::occurs`): without it the unifier answers with rational terms — `$x = ENC(k, HASH(DEC(k, $x)))` is a solution only if a term may contain itself — and `vars::apply`, which chases a bound variable into its own binding, never returns. `merge` must repeat the check when it *overwrites* a binding, since that path does not go through `bind`.
- `deduce.rs` — the solver proper. Goals are discharged by: already-known, bare-variable (`nil`), **replay** (a held value that is an instance of the pattern), wire unification, oracle (restricted to the finite basis), rewrite-match, primitive-by-arguments, decomposition, `invert` (backwards through rewrite rules and `SPLIT`/`CONCAT`), and `satisfy_check` for checked primitives. Bindings from unification are put under obligation by `require_constructible`, which forces the DH substitution in a real MitM. Goals are memoised by `goal_key`, which **must** include a kind tag or a primitive and a constant sharing a hash collide silently; results computed while a cycle was cut are not cached. `satisfy_check` inverts through the rewrite position when that position is **not** a bare variable — the only way to reach a signature buried under `SPLIT(AEAD_DEC(…))` — and tries every rewrite shape rather than only the first.
- `diverge.rs` — equivalence queries, in two halves. `solve_divergent` grounds the variables reaching only one side to `nil`, which suffices while the other side keeps its honest value. When both queried values are projections of one installed term it cannot help: any single value makes them agree by construction. That case is `distinguish`, a second grounding offered alongside the ordinary one. The solver already mints a distinct free variable per position (`satisfy_split` says so explicitly) and `distinguish` keeps them apart, handing each free position its own value from `fillers()`: `nil`, then `HASH` at every arity the spec declares. Divergence needs only *distinctness*, never a particular value, which makes the ladder cheap: every rung is derivable from nothing, so no proposal carrying one dies in the validator (`every_divergence_filler_is_derivable_with_no_attacker_knowledge` — a ladder the attacker cannot build would leave the rule implemented and never firing). It must stay injective across the positions one `CONCAT` can hold, or two projections land on the same filler and their divergence is missed again (`the_ladder_separates_every_position_a_concat_can_hold`), and it must survive `normalise_arguments`, which unwraps a key derivation wherever the spec forbids one and would collapse a `PUBKEY`-shaped ladder to a single value in that position. The variant is **additive** and gated on an unresolved `equivalence?`, so it can only add attacks and costs nothing on a model asking no equivalence question. Models: `equiv_forged_bundle_projections.vp` (`e0` before, `e1` now) is what was missing, `equiv_forged_bundle_far_fields.vp` holds the ladder to injectivity, `equiv_sealed_bundle_holds.vp`/`equiv_guarded_bundle_holds.vp` keep it from becoming a blanket authenticity break, and `unlink_forged_bundle_not_a_link.vp` keeps an attacker-manufactured equality from being read as a link.
- `validate.rs` — **propose and dispose**, and the only route from the search into query evaluation. Nothing else in `solve/` can record a query result; every proposal is materialised into a concrete `PrincipalState`, re-executed via `reexec.rs`, and re-checked against real attacker knowledge. Its guard order is load-bearing and asserted by `tcb_tests`: controllability first, then derivability, then queue the install, then execute. Its `derivable` is the engine's second, independent proof that a term is buildable and knows nothing about the solver — the two capability exemptions (`forgeable_secret_position`, `malleable_positions`) must be repeated here or a declared assumption is honored by the search and then rejected by the validator. Its `worthwhile` flag is the replay check: a term reducing back to the honest value (`reexec::attacker_authored`) is a replay, not an attack (false-attack issue #18). Errors from analysing a hypothetical state are swallowed — a speculative branch that cannot be analysed answers nothing, and must not abort the run.

Proposal families, in offer order: goals derived from each unresolved query; `constraint_goals` (make every checked primitive succeed, since a check the attacker can satisfy is a check that does not halt the principal); the **blanket** substitution (every controlled slot replaced by the attacker's own value — one substitution, one validation, and the shape most protocol attacks take); one single-slot substitution per controlled slot (for when the blanket would trip some *other* check); and finally, only in `Pass::Constructed`, the **sibling flight** substitutions plus per-slot candidates drawn from protocol terms the attacker holds and from shapes the recipient's own rewrite rules demand — each offered alone, combined with the blanket, and combined with a **relay** substitution forwarding every other slot unchanged. Whichever families ran, every proposal still carrying two or more free positions is offered again with those positions filled apart (`diverge::distinguish`), but only while an `equivalence?` query is unresolved.

`sibling_flight_substitutions` makes injective agreement reachable rather than merely expressible. It is `relay_substitution` resolving the *sibling* constant instead of the slot's own: one proposal per sibling index, installing that session's honest value into every controlled slot at once. Coherence is the point — a replay pairing one session's key share with another's ciphertext fails the recipient's own checks, and the per-slot families only ever offer one sibling value at a time, so before this family a multi-slot flight replay was never proposed. `tls13-0rtt.vp` is the regression: the RFC 9846 §8 attack needs `gce`, `binder` and `earlyData` replayed together or the binder check halts the server. **It belongs in `Pass::Constructed`, not `Pass::Targeted`**: offered early it resolves queries a man-in-the-middle would otherwise resolve, and the witness follows the search — `bypass_witness_narration.vp` degrades from the forged-ciphertext MitM trace it exists to pin into a shallower replay of the same `a1`.

`constraint_goals` does two things beyond offering each check once, both to build a **forged authenticated flight**, the shape of every server-impersonation attack. A `SPLIT` whose argument is a decryption it cannot reduce is a constraint in its own right, discharged by materialising the plaintext as a `CONCAT` of exactly the arity the model's projections demand (`satisfy_split`, `widest_projections` — `core_rule_split` ignores excess arity, so wider shapes are wasted search). Without that, the recipient's own transcript — which in TLS 1.3 hashes the certificate it received *from the flight* — puts the signature position out of reach, because binding the ciphertext in terms of a projection of itself fails the occurs check. Then the whole set is re-solved in **additive refinement rounds**: each check is re-applied and reduced under the bindings found so far, so a check only satisfiable once an earlier one fixed the message — a Finished MAC over a transcript — is reached on a later pass. Rounds are bounded by the number of checks and stop when a round discovers nothing new. They must only ever **add** proposals: making them replace the first pass loses attacks, because one check's constructibility obligation grounds a free position to `nil` and destroys another check's structural requirement for it. For the same reason `bind_from_shape` still refuses a shape with an unbound position — a structure-less partial forgery satisfies the decryption check and stops the search pursuing the structured one. Both were tried the other way and both cost real attacks; `forged_flight_mitm.vp` is the regression that catches it.

**The attacker's option set is the thing to be careful with, and narrowing it silently is this engine's characteristic bug.** At every position the attacker chooses, the options are `{honest value}` plus everything derivable. Two missed attacks came from replacing that set with a single representative where nothing downstream could recover the rest, and both are now closed — in *different layers*, which is why the fixes are separate. `vars::ground_free` narrowed what the search **proposes** (collapsing every free position to `nil`, which is why an `equivalence?` over two projections of one term always held; `diverge::distinguish` restores it). `symbolic::build` narrowed what it can **derive** (collapsing every controllable slot to a variable, so "this slot stays honest" existed when the search *guessed* and not when it *reasoned*; the refinement search restores it). Disabling `distinguish` with refinement in place puts `equiv_forged_bundle_projections.vp` back to `e0`, so neither subsumes the other. What unifies them is a rule, not a function — **never commit to one representative where the commitment is unrecoverable; defer it and enumerate** — and a third instance should be closed by applying that rule in whichever layer it lives, not by a third special case. `src/metamorphic.rs` is the instrument for finding one.

Proposals are deduped by what they would actually **install** (`solve/mod.rs::install_signature`), not by substitution identity: two substitutions differing only in free-var bindings nobody reads materialise to the same concrete state. On `tls13.vp` at the shipped default that collapses 11653 proposals to 3861 distinct states (1681 to 569 at one session), which is what pays for the search above. The dedupe deliberately does not span search rounds — attacker knowledge grows between them, so the same installs can resolve later what they could not earlier.

Variables the solver never bound are deliberately left free and `validate` skips those slots: the attacker has no reason to touch that wire value, and grounding it would fail an unrelated check and halt the principal before the attack could land.

**Skeletons are gone.** `skeleton.rs` added each primitive's shape with secrets erased (constants→`nil`, public keys→`PUBKEY(nil)`) to attacker knowledge during trace generation. Since `nil` and `PUBKEY(nil)` are values the attacker already holds, a skeleton asserted nothing new — and removing it changed no verdict on any model in the tree. It did change ten attack *traces*, all for the better: a skeleton like `ENC(nil, nil)` sitting in attacker knowledge let the minimizer's `attacker_can_build` accept a degenerate witness before `payload_shapes` could offer the explanatory one, so `auth_with_signing.vp` reported "the attacker replaces the ciphertext with `ENC(nil, nil)`" where it now reports the attacker decrypting the real ciphertext and forging a signature over the real plaintext. Do not reintroduce a rule that hands the attacker a shape it did not derive: `witness.rs` ranks candidates by what they explain, and free-floating shapes outrank real ones.

### Re-execution (reexec.rs)

`reexecute` installs attacker-chosen values into a principal and runs it forward: install → check the slot graph is still acyclic → resolve → rewrite → then either bypass guards the attacker can defeat (`try_guard_bypass`, keyed on the spec's `bypass_key`; the loop is uncapped — each round must flip a fresh `bypass_injected` flag, so it terminates structurally) or truncate at the checked primitive that halts the principal and set `halted_at`. Guard bypass must work from the *pre-resolution* state, because injecting into an already-inlined state does not propagate to the slots that referenced the guard's output. The bypass exists because substituting `PUBKEY(nil)` for an identity key fails a signature check — but the attacker knows the private key for `PUBKEY(nil)`, so treating that as a halt would discard the whole man-in-the-middle.

Two guards here are what the search is allowed to touch. `Controllable` (built by `Controllable::of`, one per solving pass) answers "may the attacker replace this slot", and its fields are private so nothing outside `reexec.rs` can mint one; `admits` re-checks it against the principal and phase being validated, because a cached answer is exactly what an untrusted search would forge. `TermBound` (built by `TermBound::of` from the trace) answers "is this term no deeper than the protocol's own deepest term". Both travel to `validate.rs` inside `Guards`.

`slot_graph_is_cyclic` is what lets `resolution.rs` carry no depth cap. `install` is the only thing that rewrites a slot's value out of declaration order, and the search will happily offer a slot a wire value naming that same slot — `piknik.vp` reaches for exactly this, proposing `ekid = ENC(DH_KEX(PUBKEY(keygen), ekid), CONCAT(n, m))`. No execution reaches such a state, so `reexecute` returns `Err` and `validate` drops the proposal, the ordinary propose-and-dispose path. Only slots holding a *primitive* have outgoing edges: resolution stops at a constant-valued slot rather than inlining through it, so a leaf slot is not a cycle of length one.

This lives in one place because **two callers must agree exactly**: `validate.rs` validating a proposal, and `witness.rs` deciding whether a mutation is load-bearing. A minimizer re-executing even slightly differently could drop a mutation the engine needs and report a trace that does not reproduce.

### Attack traces (witness.rs + narrate.rs)

A query result carries a narrated trace, produced in two steps after the query resolves.

**`witness.rs::minimize_witness`** — the solver installs the union of the bindings for *every* goal it was pursuing, so a raw witness routinely contains substitutions only some other query needed. The minimizer first picks a **candidate**: for each principal's pristine session (the query's own principal first) it tries the canonical MitM (attacker's key wherever a DH public value arrived over the wire), then the recorded mutations, then those with public keys replaced by `PUBKEY(nil)` — taking the first that still resolves the query. It then drops mutations one at a time for as long as the query keeps resolving. If nothing replays anywhere it falls back to the `unminimized` witness with `reproduced: false`: report the derivation and claim no attacker actions, rather than name substitutions that may not be the ones that mattered.

- **"First candidate that resolves" is not "the candidate that explains", so the choice is ranked.** A degenerate witness resolves almost any authentication query, because `try_guard_bypass` defeats a checked decryption the moment the attacker holds its key — so `ciphertext := nil` resolves, and the step narrates as *"the check is defeated, accepting `PUBKEY(nil)`"*. That reads as "the recipient accepted `nil`" when the real attack is that the attacker **owns the session key** and could have sent a well-formed ciphertext. The minimizer therefore prefers any witness where **no** guard bypass fired (`needs_guard_bypass`) and falls back to a bypassed one only when nothing else reproduces; the drop-one loop then refuses any drop reintroducing a bypass. To make sure a bypass-free witness is actually on offer, `forged_from` adds a family that **constructs** one: it stages a base substitution, asks the recipient's own failed checks what shape they wanted (`perform_all_rewrites` plus the solver's `build_rewrite_shapes_with`), and offers that forged term for each controlled non-key slot. Staging both the canonical MitM keys and the recorded mutations matters — a forged flight sometimes only becomes constructible once an earlier forged message is in place. Building the term rather than looking it up in attacker knowledge is the point: the good term is often derived *later* in the search than the moment the degenerate witness resolved the query, so it is not in the snapshot yet.
- **A witness that resolves the query is not yet a witness that explains it, and the payload is where that is decided.** `build_rewrite_shapes_with` pins only the positions the recipient's rewrite rule matches — key, associated data — and hands the rest to a filler. Filling those with `nil` always type-checks and always resolves an authentication query, which is exactly why it explains nothing: "Bob accepted an empty record" and "Bob accepted the real file, resealed under a key the attacker owns" carry the same `a1`, and only the second is the attack anyone cares about. So `payload_shapes` builds the forgery a second way, filling each free position with the honest term's own argument whenever the attacker holds it, and `forged_from`/`forged_alone` offer every one of those **before** any `nil`-filled shape. `attacker_can_build` keeps the family honest — a forged term whose parts the attacker cannot assemble would be an explanation nothing derives. This is ordering, not searching: every candidate still goes through `probe`, so it can change which witness is shown and never which verdict is recorded. It is what makes `test1.vp`, `test3.vp` and `test5.vp` reseal the real `m`/`m2` instead of `nil`, and what gave `noise_xx_mutual.vp`'s confidentiality query a bypass-free forged-flight witness in place of a defeated check.
- `examples/silly/cloudbackup.vp` is the model to read for this. Its real attack is a MitM on `g_file_alice_a_key` as it transits Alice → Server → Bob unguarded while both long-term keys are guarded: the attacker computes `DH_KEX(PUBKEY(nil), bob_longterm)` and forges a ciphertext Bob accepts on its own merits. If a change here makes that trace mention `nil` again, it is a regression — the verdict will not move, so the tests will not catch it.
- A bypass in the trace is not automatically a smell. Where the defeated check is a *signature* over an identity key the attacker substituted, the bypass **is** the attack and the narration is right: the whole of `TRACE_USES_A_GUARD_BYPASS` — `flawed_psk_from_serial.vp`, `junglegym_hybrid_pq.vp`, `noise_xx_mutual.vp`, `test3.vp`, `test5.vp` — plus the unswept `scuttlebutt.vp` legitimately keep one, because no bypass-free witness exists for them.
- The trace may end in one caveat, `narrate.rs::out_of_order_note`, and `out_of_order_harvest` is what earns it: the witness installs into a principal a value that principal itself produced (`Obtained`/`Leaked` from a slot it created) at or after the slot being overwritten, *and* re-running the probe with that principal's own fresh constants renamed to another run's copies no longer resolves the query. Both halves are needed: the first alone flags nothing useful, the second alone flags every DH protocol, because a term mentioning `bo` deep under `DH_KEX(PUBKEY(nil), bo)` was built from `gbo` off the wire and never needed `bo` at all. `later_value_fed_back.vp` is the one model that earns it; `exa2.vp` and `kem_direction_reflection.vp` are the counterweights, genuine single-run reflections where the replayed value is on the wire *before* it is fed back.
- **The seed is bounded by the trace, not by the state that answered the query.** `mutations` drops any seeded slot at or past `km.slots.len()`, and it has to be that and not `ps.values.len()`: the installs go into pristine sessions from `ctx.principal_states()`, which are full length, while `ps` is whatever state resolved the query and may have been truncated at a halt. Bounding by `ps` silently emptied the seed whenever the answering principal halted, and an empty seed falls through to `unminimized(true)` — a witness claiming reproduction with no installs at all, which `assert_reported_attacks_replay` then rejects. `spore_ns_pk.vp` is the model that caught it: the honest responder halts under the substitution, so its state is shorter than the slot the Lowe attack installs into.
- Probes run against a **scratch `VerifyContext`** whose results are discarded, so this too cannot record a result — a bug here yields a larger witness, never an attack that does not exist. It is built by `scratch_for_witness`, which clears the honest set: which runs may *record* a verdict and which can *reproduce* one already recorded are different questions, and a cross-scenario attack's witness lives in the corrupt-peer run it goes through. `scratch_for_query` keeps the relativisation and is test-only, for the hold audit. Each probe re-seeds from the **passive baseline**, not end-of-search knowledge: attacker knowledge is monotone, so probing against the snapshot would answer every confidentiality query "yes" immediately and make every mutation look droppable. Sessions come from `ctx.principal_states()`, never from the state in hand: those are the pristine starting states, so purifying one restores exactly what the protocol honestly computed. That is only safe because a guard bypass writes its key to `SlotValues::bypassed` rather than over `original`. `in_minimization()` gates re-entry and `info.rs::InfoQuiet` gates output, so the many hypothetical re-runs neither recurse nor print.

**`narrate.rs::narrate_attack`** renders the minimized witness as numbered causal steps: `Mutations` (grouped per wire message), `Gate` (a checked primitive that passed with at least one attacker-controlled input — the step readers are most likely to disbelieve), and `Derive` (one line per `DerivationRecord`, ingredients before target). A derivation the attacker performed while walking another principal is prefixed with that principal per line, never as a mode switch. `NameTable` compresses terms back to slot names, excluding the slots a step itself touches so a line never reads "replaces `gb` with `gb`"; the returned `Narration` carries that table so the summary quotes the same vocabulary as the steps.

**A step may claim only what its own operands establish, and "session" is the word this file gets wrong most easily.** Three claims are earned separately and must not be borrowed from each other. *Which run* a derivation happened in is known only from the `MutationRecord`'s `principal_id`, so only `session_prefix` may name one — and it names a principal, which is a session only because expansion made it one; nothing may call the other run *earlier*, since the record carries no order. *A cross-session replay* is established only by `session_sibling_replay`, so `Step::Replay` carries a `sibling` flag and only that arm says "from another session"; the other arm fires when `attacker_authored` was false, establishing just that the delivered value reduces to what the sender genuinely sent, and says "unaltered". *A guarded slot being substituted* is not a guard bypass: `attacker_controllable` admits it only when `mutatable_to` holds the sender, i.e. the value reached the sender unguarded upstream, which is what that line must say — `Step::Bypass` reports a defeated check and fires only where `try_guard_bypass` proved the attacker holds the key. Likewise an `Obtained` value is "on the wire" only when its slot has a `sent_by`; leaked and public constants get their own wording. Every one of these was, at some point, a line that said something the engine had not checked.

### The soundness tests (query.rs::tcb_tests)

Theorem 4 of the paper is that a solver bug cannot produce a false attack, *whatever the solver does*. It reduces to six facts about this code, and `tcb_tests` pins every one by reading the source, so violating one fails the build instead of merely contradicting a paragraph.

| fact | what it says | pinned by |
| --- | --- | --- |
| (i) | one write path: `results_put`, whose token constructor is private to `query.rs`, called once from `emit_query_result` | the `QueryVerdict` type (the compiler's half) + `a_query_result_has_exactly_one_write_path` |
| (ii) | that path is reached only from query evaluation: five `emit_query_result` callers, one per query kind | `results_are_recorded_only_by_query_evaluation` |
| (iii) | the verdict comes from a state, not a claim: an evaluator is handed a `PrincipalState` and an `AttackerState` and nothing that could carry a verdict, score or justification | `a_query_evaluator_is_handed_states_and_nothing_else` |
| (iv) | every state it is handed was executed: three `verify_resolve_queries` call sites, and nothing under `src/solve/` reaches query evaluation directly | `query_evaluation_is_entered_only_over_an_executed_state`, `the_solver_cannot_reach_query_evaluation_except_through_the_validator`, `the_solver_holds_no_shared_cell_over_analysis_state` |
| (v) | every term installed was derivable: `validate.rs` proves it before `reexec` runs, and abandons the *whole* substitution on failure | `an_install_is_proven_controllable_then_derivable_before_it_is_executed` |
| (vi) | every slot installed into was controlled: the same loop tests controllability *first*, against a `Controllable` only `reexec.rs` can mint and that is checked against the principal and phase being validated | the same test, plus `controllability_is_minted_only_by_reexec_and_bound_to_one_session` |

Two of these are about *order*, not just presence. Testing derivability after queueing an install, or letting a failed test `continue` to the next slot instead of abandoning the substitution, executes a state the replay system does not permit — the tests assert the ordering inside `fn validate` for exactly that reason. Fact (vi) needed the `Controllable` token because controllability is decided once per solving pass for cost reasons, and a cached answer is precisely what an untrusted search would forge; keep its fields private and keep `admits` checking both `self.principal` and `self.phase`.

Adding a query kind means touching (ii) and (iii): a sixth `emit_query_result` caller and a sixth arm in `query_start`. Both counts are asserted, so the build tells you.

### Supporting modules

`parser.rs` — byte-level recursive descent; comments are captured into AST nodes so `pretty` round-trips them (round-trip idempotence is unit-tested).

`pretty.rs` — canonical formatter, golden-tested. `pretty_model` is a pure AST walk and deliberately **not** gated on `sanity`: a parse error means there is no tree to format, but a sanity error means there is a complete one, and refusing to format then is refusing exactly while the user is fixing the error (it would also silently no-op format-on-save in the language server). It is infallible and returns `String`; only `pretty_print`, which parses first, returns a `VResult`. It also owns the `Display` impls for `Value`/`Constant`/`Primitive`/`Query`/`Expression`, so *every* engine message and attack trace is rendered by this file.

`resolution.rs` — inlining and `compute_visibility`; unbounded, because it descends only through slots holding a primitive and the slot graph is acyclic (`construct.rs` builds in an order `sanity.rs` has already made topological, and `slot_graph_is_cyclic` refuses any install closing a loop). `rewrite.rs` — applies rewrite rules over a whole state, reporting failures as `(Primitive, slot)`. `equivalence.rs`/`hashing.rs` — the equivalence/hash invariant above and `collect_subterm_hashes`. `primitive::normalise_arguments` is the one place keeping the term space finite: where `argument_restrictions` forbids a key-derivation application in a position, it unwraps it, so the solver cannot build `PUBKEY(PUBKEY(x))` and recurse forever. Removing it makes attacker knowledge fail to saturate on models with an unguarded public key. `construct.rs` — builds the trace and principal states under `sanity.rs`, and owns `clone_for_depth(purify)`. `info.rs` — all user-facing output, buffered into JSON messages under wasm; also `InfoQuiet`, the thread-local guard silencing hypothetical re-runs, and `InfoCapture`, which buffers a run's output instead so `--saturate` can replay one analysis rather than repeat it. Every stdout write in the crate goes through its private `emit`, which is what makes both guards total. `scenario.rs` — peer-scenario expansion and its own pre-expansion sanity pass. `autoquery.rs` — the generated query set behind `--auto-queries`.

`lsp/` — the language server, behind the `lsp` feature that `cli` pulls in. `mod.rs` is the stdio loop: one thread doing `recv_timeout` on the LSP receiver, using the timeout as the validation debounce. The analysis runs on a worker thread holding a cloned `Sender<Message>` and publishes its own progress, diagnostics and report, so there is no second channel to poll. **Both threads must call `info::set_verbosity(Verbosity::Silent)`**: `info_message` writes to `println!`, which in a server is the JSON-RPC channel, and `VERBOSITY` is a thread-local so silencing the main thread does not silence a worker. Engine chatter on stdout desynchronises every client's parser, and the symptom is an analysis that never returns. The server never touches the filesystem — documents are keyed by URI string and the display name is the URI's last path segment. `docs.rs` is the language prose (`CC-BY-SA-4.0`), pinned against the spec registry by a drift test; `line.rs` converts byte offsets to LSP positions in the encoding negotiated at `initialize`; `state.rs` holds `Documents`, reparsing and re-running `sanity` on every change and keeping model, token index, trace and sanity error side by side; `diagnostics.rs` turns a `VerifpalError` or finished `Analysis` into LSP diagnostics; `language.rs` is every position-driven feature (hover, definition, references, highlights, symbols, folding, completion, signature help, semantic tokens, inlay hints, rename); `analysis.rs` owns the worker threads — its `Runner` keys one `Live` per URI carrying the cancel flag and a `finished` flag the worker sets on the way out, so a completed analysis answers `verifpal.cancelAnalysis` with `cancelled: false` rather than claiming it stopped work that had already ended; `proto.rs` is the wire shape of the custom `verifpal/*` messages.

`report.rs` — the one serializable description of an analysis, behind `verify --format json`, `verify --format html` and the language server's analysis notification; its ranges are byte offsets plus 1-based line/column, never LSP positions, because the encoding LSP counts in is negotiated at `initialize` and is the server's business.

`html/` — renders `report.rs::Run` plus each model's source into the single self-contained page behind `verify --format html`. `mod.rs` is logic only: every scrap of markup lives in the `tpl/*.html` fragments, all styling in `report.css` (mirroring the Verifpal website's design system), and the one script in `report.js`, compiled in via `include_str!` so the binary stays self-contained and the module builds under wasm. Templates are filled by a single-pass `{{placeholder}}` scan that never rescans inserted values, so model text containing `{{…}}` cannot act as a template, and every dynamic string passes through `escape`. All SVG is hand-rendered: the protocol diagram (numbered hops, guarded values in olive, attacked values in breach, `leaks` notes, phase rules) comes from re-parsing the model source via `parse_string_indexed` — whose token index also drives the source pane's syntax highlighting, so there is no second lexer to drift — and each attack trace gets its own diagram built purely from the structured `TraceStep` fields `narrate.rs::step_data` ships in the report. `report.js` is progressive enhancement only; the tests pin exactly one inline script and zero external resources.

`tokens.rs` — `TokenKind`/`Token`/`TokenIndex` and the join onto `ProtocolTrace`; the parser emits it through `parse_string_indexed`, which returns the index *even when parsing fails* because a model mid-edit is the common case in an editor. `Constant` carries no `Span` and must not gain one — it is half of `Value`. `unlink.rs` — the link-witness decision procedure behind `unlinkability?`. `capability.rs` — `Capability`/`Capabilities` (the parsed annotation), the spec-support queries and their diagnostics, and `CapabilityIndex`, the model-level lookup the engine consults. `util.rs` — six small helpers (`append_unique`, `edit_distance`/`did_you_mean` behind the "did you mean" suggestions, `base_name`, `quoted_list`, `min_int_in_slice`) plus `ColorChoice`/`set_color_choice` and the terminal detection behind them. `update.rs` (`cli` only) — the release check: `verify` and `about` spawn a background thread that GETs the GitHub tags API and, if a strictly newer purely-numeric tag exists, prints one line to stderr. It is read with `try_recv`, so a slow network never delays a run; it is also the only outbound network call the tool makes, and there is currently no way to turn it off.

There is no process-global mutable state. `ValueNames` (`value.rs`) and `PrincipalNames` (`principal.rs`) are interners **owned by the `Parser`**, so ids are per-model and two analyses in one process cannot interfere; the unnamed-constant counter is a parser field and the analysis counter is thread-local. `PrincipalNames::intern` errors past `PrincipalId::MAX` rather than truncating a 256th principal onto `ATTACKER_ID = 0`, and `ValueNames::intern` errors once ids reach one `COPY_STRIDE`, keeping interned ids clear of both the expansion-copy bands and the ranges `solve::vars` reserves above them. Principal *names* travel on `Message`/`Principal` and via `ProtocolTrace::principal_name`, because `Display for Query` cannot take a lookup table.

All output is plain text: there is no alternate-screen progress UI and no attacker-voice easter egg, so don't go looking for `tui.rs`, `narrative.rs`, or a `--character` flag that older docs may still mention. Likewise `inject.rs`, `mutationmap.rs` and `verifyactive.rs` were the forward mutation search and are gone.

## Testing conventions

- Unit tests live in a `#[cfg(test)] mod tests` at the foot of the module they exercise, so they can reach private items directly. `src/testutil.rs` holds the shared value/state builders. `src/model_tests.rs` holds the end-to-end model tests (`run_model("foo.vp", "c0a1")` runs `examples/test/foo.vp` and asserts the result code). `run_model` goes through `verify`, so it exercises the **shipped default** of two sessions. `run_model_sessions("foo.vp", 1, "a0")` pins an explicit count; a model whose verdict depends on session count should be pinned at both `1` and `2`, so single-session behavior stays a regression guard rather than becoming untested.
- **Result code format**: one letter+digit per query, in model order — `c`/`a`/`f`/`u`/`e` for the kind, `0` = holds, `1` = attack found. `"c1a0"` means the confidentiality query failed and the authentication query passed.
- Adding an engine regression test: write a model in `examples/test/`, get the code via `cargo run --release -- verify examples/test/foo.vp --result-code | tail -1`, **verify by reading the attack trace that each 0/1 is actually correct** (the tool's own output is only ground truth for regressions, not correctness), then add a `run_model` test. Explaining *why* the expected code is right in a `// Expected:` header comment is the house style — see `aead_replay_not_forgery.vp`.
- Golden pretty-printer files live in `examples/test/golden_pretty/` (6 of them), compared byte-for-byte via `include_str!`. Update them deliberately when changing the formatter.
- The engine interns names per model, but the test builders share one table (`testutil::test_value_id`), so **unit tests must still use unique constant names** (existing tests prefix per-test, e.g. `cbw_m`, `hcm_x`, `ps_fbm_a`). A test that both parses a model *and* builds a value by hand must take the constant from the parsed trace via `testutil::trace_constant` — ids from the shared test table will not match the model's own.
- A model that is *meant* to be rejected gets `run_model_err("foo.vp", "substring of the error")` instead, which pins the diagnostic and not just the refusal.
- Every model in `examples/test/` is wired to a `run_model` or `run_model_err` test; keep it that way when you add one.

### Checking *why* a verdict happened, not just that it did

A result code pins one bit per query and says nothing about the attack behind a `1`, so a battery of checks sits underneath it. All are test-only: the recording is `#[cfg(test)]` and a shipping build carries none of it. The sweep runs `examples/test/` (368 models) plus the seven in `SWEPT_MODELS_OUTSIDE_EXAMPLES_TEST`, so 375 in all; the rest are sanity-error models, which the sweep skips. Re-measure the analysing count and the per-check tallies below after touching the corpus — they were last taken at 357 models.

- **Witness replay.** Every `verify` under `cargo test` ends in `witness::assert_reported_attacks_replay`: for each resolved query it re-executes the reporting principal's pristine session with exactly the substitutions the minimizer kept, and fails if the query no longer resolves. A witness with *no* substitutions is not skipped — it must resolve the query with nothing installed at all, which is what an attack the honest run already reaches actually claims. It also fails, with no exceptions list, when the printed trace names *fewer* slots than the witness needed, so a trace cannot silently omit a load-bearing step. The only query-instances not replay-checked are those falling back to the disclosed unminimized witness, which `TRACE_IS_NOT_A_MINIMIZED_WITNESS` pins. Dropping one substitution from the replay fails well over a hundred tests.
- **Narration shape.** `attack_traces_keep_their_shape_and_name_only_wires_that_exist` sweeps the corpus and pins four exact sets: traces explaining themselves with a defeated check (`TRACE_USES_A_GUARD_BYPASS`, 6), traces the minimizer could not confirm (`TRACE_IS_NOT_A_MINIMIZED_WITNESS`, 5), traces feeding a principal a value it only computes later in the same run (`TRACE_FEEDS_BACK_A_LATER_VALUE`, 1), and attacks reported with no trace at all (`ATTACK_IS_REPORTED_WITHOUT_A_TRACE`, currently empty). These are exactly the narration regressions a verdict cannot catch — the `cloudbackup.vp` hazard above, which is why that model is one of the seven swept from outside `examples/test/`. A new entry means some attack got a worse explanation; a missing one means an explanation improved and the pin should move.
- **Every step is re-derived** (`tracecheck.rs`). `Step` carries its structured operands under `#[cfg(test)]` — a `Derive` step its target, ingredients and `DerivationRecord`; a `Mutations`/`Replay` step the installed term; a `Gate` step its primitive; a `Bypass` step its key — and every trace `narrate.rs` produces is checked before it is returned. All ~510 attack verdicts at the shipped default print a trace, and all ~2400 of their steps are checked for two properties:
  - **Well-foundedness.** Each step's ingredients must be produced by an earlier step, installed by a mutation or replay, free to the attacker (`Initial`/`Injected`), `theory::obtainable` — the same predicate that licensed the step, so a key `can_decompose` accepted because the attacker could rebuild it on the spot is not then rejected for never having been absorbed — or assembled from parts themselves justified. That last case matters because a deduction rule may rebuild an ingredient on the spot without absorbing it (`derivation_provenance` tests for exactly this), and `walk` used to skip such values silently, printing a step whose input nothing supplied. A confidentiality trace must also reach the value the attacker is claimed to have learned; an authentication trace with steps must show the attacker acting on the wire.
  - **Each claimed operation actually holds**, re-derived from the state rather than trusted. A `Reconstructed` step's parts must be among the arguments of the target, of its commutative swap, or of whichever of those two `can_rewrite` reduces to — checking the swap rather than skipping the check whenever commutativity applies would exempt every DH term and so most MitM traces, and the rewritten form has to be there because `can_reconstruct_primitive_directly` draws its ingredients from `can_rewrite(p).1` while the record attaches to the unreduced term. Re-running `can_reconstruct_primitive` instead is the obvious-looking fix and is wrong: it reads attacker knowledge, which has grown by the time the trace is checked, so it does not reproduce the reconstruction that was recorded. `Decomposed` is re-run through `can_decompose` and must yield the target; `Recomposed` through `can_recompose`; `PasswordExtracted` through `find_obtainable_passwords`, so the offline-guessing conditions are re-proved and not merely the password's occurrence; `ConcatFragment` must take a fragment of an actual `CONCAT`; `Obtained` must name a slot that travelled, leaked, is public, or genuinely holds the value; `Leaked` a slot the model leaks and this run reached; `Broken` a capability `in_force` at the trace's phase, so a `from phase N` assumption cannot be invoked early; `Gate` a checked primitive whose rewrite succeeds, computed by the principal it names, on at least one attacker-tainted argument; `Bypass` a key `theory::obtainable` confirms.

  A trace may also carry steps explaining a violation needing no attacker action: `Resolves` (what each side of an `equivalence?` resolves to), `Static` (the non-fresh leaves behind a `freshness?` failure), and `Received` (who actually sent a value an `authentication?` query attributes elsewhere). **These describe a state, so they must be built from the state the rest of the trace describes.** `attack_trace_with` takes them as a closure and evaluates it against `witness.ps` *after* `minimize_witness` has chosen a witness; building them earlier, from the state that answered the query, made the prelude describe one run and the body another, and was the largest single source of faults the metamorphic sweep ever reported. Each is checked against the state too, and their arrival is why `ATTACK_IS_REPORTED_WITHOUT_A_TRACE` is now empty. These checks are heavily load-bearing, but a count is only meaningful next to the exact mutation that produced it: measure the one you are about to weaken rather than trusting a number.
- **Holds were searched** (`assert_holds_were_searched`). In an active-attacker model offering the attacker any slot it controls, every query reported as holding must have been aimed at by the solver at least once — `goals_for_query` having been called for it. Zero *goals* is fine and means the solver found no route; zero *attempts* means the search skipped the query, and a hold nothing was aimed at is an untested claim. Freshness is exempt: the solver deliberately proposes nothing for it.
- **Holds are not stale** (`assert_holds_survive_final_knowledge`). Every query reported as holding is re-evaluated at the end of the run against each principal's freshly generated trace with everything the attacker knew by then. A hold that resolves under that is a verdict reached before the knowledge defeating it existed. All of them survive.
- **Both session counts.** The sweep verifies every model at one session as well as at the shipped default, so the per-`verify` trace and hold checks run over both. The four narration-shape sets are measured at the default only.
- **Wire coherence and header intent.** The same sweep rejects any trace step claiming the attacker replaced a value on a message the model does not have, or replaced a value every message guards without saying a guard was bypassed. It also reads each model's `// Expected:` header line and requires the stated code to be what the model actually produces — the header is where a verdict is argued, so a header disagreeing with the run is either a stale claim or a verdict nobody re-justified. 211 of the 352 swept models that analyse state a code; the ceiling on the 141 that do not (`undocumented <= 141`) is a ratchet, currently sitting exactly on the line.

### The metamorphic harness (`src/metamorphic.rs`)

The checks above all measure one run of one model. They cannot see a *missed* attack, because the tool's own output is their only oracle. The harness closes that: it transforms each swept model and asserts a relation between the two result codes. Every property is a theorem about the **language**, so a violation is an engine bug and never a judgment call.

Transformations are AST-level and go back through the printer: parse → transform → `pretty_model` → **re-parse** → `analyze_sessions`. Re-parsing is not ceremony: `ValueNames` and `PrincipalNames` are owned by the `Parser`, so a hand-mutated AST carries ids from the interner that read the *original*; rendering and re-parsing makes the variant a legal model a user could have typed. The no-op case is its own test, and it is why every number below measures the engine rather than the printer.

*Monotone* properties transform the model so the attacker is strictly stronger, and no `1` may become a `0`. *Invariant* properties preserve meaning, so codes must match exactly. All run at one session (`SESSIONS = 1`); `compared` is the number of variant pairs reached when last measured.

| property | transformation | direction | compared |
| --- | --- | --- | --- |
| `unguard` | remove one `[guard]` | monotone | 227 |
| `leaks` | add `leaks c` | monotone | 1016 |
| `weaken` | add `weak` / `forgeable` | monotone | 1505 |
| `sessions` | `--sessions 1` → `2` | monotone | 341 |
| `dephase` | delete the last `phase[N]` | monotone | 37 |
| `promote` | `passive` → `active` | monotone | 99 |
| `demote` | `active` → `passive` | monotone | 245 |
| `rotate` | reorder the `queries` block | invariant | 253 |
| `rename` | alpha-rename every identifier | invariant | 346 |
| `pad` | prepend an unused `knows private` | invariant | 346 |
| `scenario` | add `scenarios[ P[c = c] ]` | invariant | 300+ |
| `scenarios` | add a second copy of that scenario | monotone | 240+ |

`sessions` is the only property changing the analysis parameter rather than the model. `dephase` deletes the *last* phase boundary so nothing needs renumbering — deleting a middle one would, since phases must increment by exactly one; its direction is the one that is not obvious, but merging a phase into its predecessor hands the attacker every later-phase value sooner, since `attacker_phase_update` withholds a value only while its earliest phase exceeds the current one, so the attacker gains and never loses. `promote` and `demote` are the same theorem over different populations, which is why both exist. `rename` and `pad` probe the interner, the reserved id bands and slot indexing; both are clean, so no verdict depends on an id or a position. `scenario` binds a constant to itself, which must expand to the model as written — it is the no-op case for the whole scenario front-end; `scenarios` adds a duplicate of it, which is `sessions` monotonicity over the other expansion axis. Both pick a `knows` constant that does not travel, since `sanity_scenarios` rejects binding one that does.

**Two ratchets, both failing in *both* directions, and both currently empty.** `KNOWN_MISSED_ATTACKS` held one entry, `exa.vp` under `unguard`, closed by the refinement search. `KNOWN_BAD_TRACES` held 28 entries across 18 models — each a trace the engine's own `tracecheck` assertions rejected under transformation — and they turned out to be four bugs, not twenty-eight: the prelude built from the wrong state, a forged term listed as its own input, a reconstruction the check could not follow through a rewrite, and a walk stricter than the rule it was checking. A violation outside a list fails the build; an entry that *stops* violating also fails, so a fix cannot leave a stale exception behind and quietly stop meaning anything. Staleness is judged only over models a run actually exercised, so a model near the cost budget cannot flap the gate between machines.

**Nothing is deferred and nothing is timed.** An earlier version gave each analysis a wall-clock deadline through the engine's cancellation flag; because whether a model finished depended on machine load, so did which ratchet entries were judged, and the suite flapped between runs. A correctness gate whose verdict depends on the clock is worse than no gate. Every analysis now runs to completion through the uncancellable `analyze_sessions`, and the only skips left are properties of the model: a file that does not parse, or a variant failing `sanity` and so not a legal model to analyse.

**Cost is bounded by three deterministic decisions instead.** `spread` runs each property's models across `available_parallelism()` worker threads — safe because every analysis owns its interner and `VerifyContext`, and `theory.rs`'s memos are `thread_local`. A monotone-*stronger* property skips models whose baseline holds no attack at all, which is exact rather than heuristic: with nothing to lose, no variant of them can violate the property. And each analysis in a `Sweep::Fast` run is wrapped in `witness::MinimizingGuard`, making `attack_trace_with` return immediately, so no witness is minimized and no trace narrated — the property compares result codes and needs neither.

**The three multi-variant properties run in two forms.** `unguard`, `leaks` and `weaken` expand to hundreds of variants each, so `cargo test` runs them as `Sweep::Fast`: traces off, and the dozen models in `COSTLY_MODELS` left out. Their `_exhaustively` twins carry `#[ignore]`, cover every model with traces on, and are what `cargo test --release -- --ignored`, `make test-exhaustive` and CI run. `KNOWN_BAD_TRACES` is only asserted where traces are actually built, so the fast form cannot report a stale entry it never had the chance to fire.

### The completeness inventory

Every site in the analysis path that **collapses** a set to one representative, **memoises** under a key, **gates** with a filter, **bounds** a space, or **orders** work. Each was classified by mutation: loosen it to accept everything and run the suite. Verdicts change and attacks appear → it suppresses real ones. Nothing changes → it is dead, redundant, or untested. Runtime or memory explodes → it is a genuine bound, whatever the comment says.

| site | kind | loosened | reading |
| --- | --- | --- | --- |
| `symbolic::build` slot → variable | collapse | — | was a **leak** (`exa.vp`); closed by the refinement search |
| `vars::ground_free` | collapse | — | **leak**; `diverge::distinguish` covers the equivalence half |
| `slot_candidates` protocol-term basis | collapse | **stack overflow** | not a heuristic at all: a second finiteness guard beside `normalise_arguments`, and undocumented until now |
| `solve_divergent` `in_a == in_b` skip | gate | no change | redundant — the fallback substitution already grounds those variables |
| `validate::worthwhile` | gate | no change | **no model depends on it.** Described above as what stops false-attack #18, yet nothing in the corpus or the metamorphic variants notices its removal. Either the protection moved or the regression is untested; write the model before trusting the comment |
| `deduce::goal_key` kind tag | memo | no change | defensive against a primitive and a constant colliding on one hash, and **untested** — no model exercises the collision |
| `rule_equivalize` halt guard | gate | 2 fail | soundness guard, pinned by `halted_principal_false-attack.vp` |
| `unlink` attacker-authored refusal | gate | 6 fail | soundness guard, well covered |
| `bind_from_shape` unbound refusal | gate | 4 fail, 3 metamorphic | search-shaping and load-bearing. The result-code corpus alone catches one of the four; the harness catches the rest |
| `validate::replays_own_freshness` | gate | 1 fail | narration-shaping; the two-pass replication search already reorders around it |
| `Pass::Targeted` before `Constructed` | order | 13 fail | load-bearing, and the ordering argument above is correct |
| `deduce::forgeable_shapes` core exclusion | gate | not loosenable | `primitive_get` fails for core primitives, so no `SPLIT`, `CONCAT` or `ASSERT` shape is ever offered. `satisfy_split` and `concat_shapes` cover `SPLIT` separately; whether `ASSERT` needs the same is open |

Two rows say *no model depends on it* about a guard described above as load-bearing. That is the audit's most useful output: a comment asserting a protection is not evidence the protection is still wired up, and a mutation that changes nothing is the cheapest way to find out.

One invariant is still worth re-running by hand after an engine change and is not automated: a two-session run's attacks must be a subset of a three-session run's, clean across `examples/test/` when last measured. One and two sessions are covered by the `sessions` property above.

## Performance expectations

Wall clock on an Apple-silicon laptop, release build; re-measure rather than trusting these after an engine change.

`cargo test --release` was ~57s once built at 357 corpus models and wants re-measuring at 364. The two long poles run concurrently: `attack_traces_keep_their_shape_and_name_only_wires_that_exist` (~28s, since it re-runs the corpus at one session *and* at the default to audit narration) and the whole metamorphic module (~22s wall, itself heavily threaded).

Nearly every model in `examples/test/` runs in milliseconds. The exceptions are the five `junglegym_*.vp` stress models — deliberately convoluted — plus one the forged-flight search made expensive: `junglegym_threshold_ring.vp` ~4.8s, `concat_split_replay.vp` ~2.5s, `junglegym_deep_ratchet.vp` ~1.2s, `junglegym_hybrid_pq.vp` ~0.5s, `junglegym_password_maze.vp` ~0.3s, `junglegym_phase_cascade.vp` ~0.2s. The junglegym models lean on resolution, the theory descent, `normalise_arguments`, guard bypass and the unlinkability witness search all at once; each carries its expected result code and reasoning in a header comment.

Two of those are the price of the forged-flight search, worth knowing before you try to "fix" them. `junglegym_threshold_ring.vp` grew several-fold because it now finds a genuine extra attack (the `vault` authentication query, `a1`: `escrow` is already `c1`, so the attacker decrypts the honest vault for Anchor's real signature and re-seals it under a key it forces Cipher to derive by swapping the unguarded Shamir shares — it forges no signature). `concat_split_replay.vp` grew because the stuck-`SPLIT` constraint is no longer gated on the decryption being checked. Both are search cost, not a leak.

Twenty protocol models ship outside `examples/test/`, across `contact-tracing/`, `hpke/`, `messaging/`, `silly/`, `transport-layer/` and `simple.vp`. The slowest that completes is `piknik.vp` (~8s), then `tls13.vp` (~2.1s), `signal.vp` (~0.97s), `needham-schroeder.vp` (~0.6s), `scuttlebutt.vp` (~0.42s), `userbase.vp` (~0.4s), `tls13-0rtt.vp` (~0.29s), `pqxdh-weak.vp` (~0.17s), `pqxdh.vp` (~0.13s); `firefox-sync.vp`, `cloudbackup.vp`, `cen.vp`, `lc-dp-3t.vp`, `simple.vp` and the five `hpke/` models are all a few tens of milliseconds. A slice of `tls13.vp` and most of `scuttlebutt.vp`'s cost is the minimizer probing the extra forged-witness candidates, buying the narration quality described under `witness.rs` — do not trade it away without reading a trace afterwards. `tls13.vp` was ~2.9s before `install_signature` deduped proposals by what they install, a reminder that in this engine wall clock tracks the number of *validations*, not the size of the search. `needham-schroeder.vp` used to run for many minutes without resolving a query; the self-feeding replay cut in `validate.rs` brought it down. The slowest model in the tree is `examples/messaging/signal_twelve.vp` at roughly a minute — 24 queries over twelve ratchet steps, expected to be slow. It is also the only model large enough for `solve/vars.rs::dedupe` to matter, so it is the one to measure after touching the solver, and the one not to put in a timing loop.

Use `--release` for anything that actually runs analysis: the debug build is more than an order of magnitude slower.

## Style and licensing

- Every source file starts with an SPDX header (`GPL-3.0-only` for code, `CC-BY-SA-4.0` for prose). Keep it on new files, including `.vp` test models.
- rustfmt with **hard tabs** and Unix newlines; clippy is a hard gate (`-D warnings`).
- **Do not write comments.** The tree carries about a hundred comment lines across 26,000, deliberately: reasoning belongs in the commit message and in this file, where it can be read without opening the source and cannot drift silently against it. `sessions.rs` and `value.rs` keep module-level `//!`/`///` docs from before that rule and are the register to match *if* you are asked for one; otherwise add none, including to code you are only touching in passing. `.vp` test models are the exception — a new one must carry a `// Expected:` header arguing its code, since the `undocumented` ratchet cannot go up.
- Commit messages are short imperative summaries, usually scope-prefixed (`parser: …`, `witness: …`, `narrate: …`). Prefix the title with `[ci]` when you want CI to actually run.

## Packaging (usually not your concern, but don't break it)

- Releases are cut with goreleaser (`.goreleaser.yml`, cargo-zigbuild, 6 targets: windows/linux/darwin/freebsd across x86_64 and aarch64). The repo doubles as its own Homebrew tap (`HomebrewFormula/verifpal.rb`) and Scoop bucket (`verifpal.json`). Goreleaser's `scoops` block rewrites `verifpal.json`; there is no `brews` block, so the formula is rewritten by `scripts/release.sh`. Don't hand-edit either with code changes.
- `pkg/` is wasm-pack output (the npm package) and is untracked — wasm-pack writes a `.gitignore` with `*` into it; regenerate via `make wasm`, which also copies artifacts into the sibling checkout `../verifpal-website`. `../verifpal-manual` holds the manual source, and `../verifpal-vscode` the VS Code extension — nothing checks that the extension tracks a language change, so update it by hand.
- `assets/releasenotes.txt` is the human-written release-notes text and `assets/pgp.txt` the project signing key.
- `default.nix` exists for Nix users; `scripts` is a symlink to a private directory outside the repo (gitignored) — it may be broken on other machines, and nothing in the build depends on it.
