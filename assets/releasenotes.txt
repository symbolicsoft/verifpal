In Verifpal 0.60.0, Verifpal's active attacker has been rebuilt around a goal-directed search.

Previously, the active attacker worked forwards: it enumerated combinations of substitutions it might make to messages on the wire and tried them. The number of such combinations grows quickly, so the search had to be held back by a depth limit and a per-principal budget — and those limits, rather than the protocol itself, ended up deciding which attacks Verifpal could reach. Signal's X3DH handshake is the clearest example: the man-in-the-middle against it requires three public keys to be replaced at the same time, and no affordable budget reliably got there, so whether the attack was found depended on a number nobody could justify from the model. The new engine asks the opposite question — what would the attacker need in order to learn this, and can it arrange that — and solves backwards from each query. There is no depth limit, no budget and no tuning: an attack requiring four simultaneous substitutions is not a combination that has to be afforded, it is simply four requirements each forced on its own. The old search, along with the parallelism it needed to be tolerable, has been removed.
