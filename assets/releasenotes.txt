Verifpal 0.80.1 runs every principal as two concurrent sessions, removes the
last artificial limits from the analysis, and closes several sources of false
attacks. Each principal a model declares now runs two sessions at once, each
drawing its own fresh values while sharing long-term material, with the attacker
free to route any session's traffic into any other. This reaches a class of
attack Verifpal could not express at all before: anything that needs two of a
role's fresh values to coexist, such as nonce swaps between instances of the
same role, oracle interleavings, reflections and confusion between parallel
runs. The language is untouched and no existing model needs editing, since
`generates` versus `knows` already says which values are per-session and which
are long-term.

The analysis no longer carries arbitrary limits. The recursion cap in the
equational theory, the resolution depth cap and the guard-bypass round cap are
gone, replaced by structural termination arguments: a well-founded descent on
term depth, an occurs check in the unifier, and a refusal to install an attacker
value that would make a principal's own computation cyclic. Where a bound is
still needed, it is derived from the model rather than picked in advance, so a
result no longer depends on whether a term happened to fit inside a number
somebody chose. One consequence is visible in the examples: the symmetric-key
Needham-Schroeder model used to run for many minutes without resolving a single
query, and now finishes in milliseconds, reporting the classic Denning-Sacco
replay.

Several false attacks are fixed. Halting a principal is not the same as making
two principals disagree, so an `equivalence?` query asked of a state truncated
at a failed check no longer reports a divergence nobody computed. A failed check
belonging to *another* principal used to be invisible, so values sitting behind
it were harvested as though that principal had reached them, which handed the
attacker a message authentication forgery oracle it did not have. And replaying
a value another session honestly sent is non-injective agreement rather than a
forgery; without that distinction, every protocol lacking replay protection
would have reported an authentication attack the moment the default moved to two
sessions. Each fix ships with a regression model, and so does its counterweight,
because tightening the analysis must not quietly lose a genuine attack.

Finally, attack traces read better. A substitution is no longer described in
terms of its own consequences: on Millen's FFGG, the trace used to say that the
attacker replaces a message with the encryption of that same message's
decryption, which was accurate about the tampered state and useless to a reader.
It now states the rotation outright. Every value the attacker injects is
accompanied by how it obtained that value, so a substitution no longer arrives
from nowhere, and a checked primitive with several outputs no longer prints the
same step once per output.
